# expect

<ApiMeta addedVersion="0.11.6" />

- **Type:** `ExpectConfig`
- **Default:** `{ poll: { interval: 50, timeout: 1000 } }` (`timeout: 5000` in Browser Mode)

Configure the defaults used by [`expect.poll()`](/api/runtime-api/test-api/expect#expectpoll) and the default timeout for Browser Mode [`expect.element()`](/api/runtime-api/browser-mode/assertion). Browser Mode uses a `5000ms` default poll timeout, while Node Mode uses `1000ms`. When omitted at the call site, the configured timeout is capped by the remaining time in the current test phase; options passed directly to `expect.poll()` take precedence and are not capped. `expect.poll()` can use the active timeout of per-test hooks and fixtures, but is not available in `beforeAll` or `afterAll`.

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  expect: {
    poll: {
      interval: 100,
      timeout: 5000,
    },
  },
});
```

## expect.poll

Global configuration for polling assertions.

### expect.poll.interval

- **Type:** `number`
- **Default:** `50`

The interval between `expect.poll()` retry attempts, in milliseconds. This option does not control the retry interval of Browser Mode `expect.element()` assertions; the browser provider controls those retries. `@rstest/playwright` locator/page assertions also retain their fixed `50ms` retry interval.

### expect.poll.timeout

- **Type:** `number`
- **Default:** `1000` (`5000` in Browser Mode)

The maximum total polling time before the assertion fails, in milliseconds. When omitted at the call site, the configured value is also capped by the remaining current test phase.

This timeout applies to these APIs:

| API                                                                                  | Uses `expect.poll.timeout`? | Per-call override                  |
| ------------------------------------------------------------------------------------ | --------------------------- | ---------------------------------- |
| `expect.poll(fn).toBe(...)` in Node or Browser Mode                                  | Yes                         | `expect.poll(fn, { timeout })`     |
| `expect.element(locator).toContainText(...)` and other Browser Mode element matchers | Yes                         | `toContainText(text, { timeout })` |
| Ordinary assertions such as `expect(value).toBe(...)`                                | No; they do not retry       | —                                  |
| `expect(locator).toContainText(...)` from `@rstest/playwright`                       | Yes, since 0.12.0           | `toContainText(text, { timeout })` |

An explicit per-call timeout overrides this setting (for `expect.poll()`, it can still be ended by the outer test or hook timeout; Browser Mode `expect.element()` and `@rstest/playwright` locator/page assertions cap it by the remaining active test or hook time). When omitted, Rstest uses the smaller of the configured timeout and the remaining active time.

- **Browser Mode:** Defaults to `5000ms`; in concurrent tests, use the test-scoped `expect` fixture to bound assertions by that test's remaining time (see [Browser Mode assertion timeouts](/api/runtime-api/browser-mode/assertion)).
- **`@rstest/playwright`:** [`definePlaywrightConfig`](/guide/basic/e2e-testing#e2e-defaults) defaults `expect.poll.timeout` to `5000ms` (otherwise Node Mode defaults to `1000ms`), and an explicit setting overrides both polling and Playwright locator/page assertions.
- **Parallel hooks:** With [`sequence.hooks: 'parallel'`](/config/test/sequence#sequencehooks), assertions inside lifecycle hooks use the configured timeout rather than inheriting a sibling hook's remaining time.
