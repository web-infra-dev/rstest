# coverage

<ApiMeta addedVersion="0.4.0" />

- **Type:**

```ts
type CoverageOptions = {
  enabled?: boolean;
  provider?: 'istanbul' | 'v8';
  include?: string[];
  changed?: boolean | string;
  exclude?: string[];
  reporters?: CoverageReporter[];
  reportsDirectory?: string;
  reportOnFailure?: boolean;
  clean?: boolean;
  allowExternal?: boolean;
  thresholds?: CoverageThresholds;
};

type ReportWithOptions<Name extends keyof ReportOptions = keyof ReportOptions> =
  Name extends keyof ReportOptions
    ? [Name, Partial<ReportOptions[Name]>]
    : [Name, Record<string, unknown>];

type CoverageReporter =
  | keyof ReportOptions
  | ReportWithOptions
  | ReportBase
  | string
  | [string, Record<string, unknown>];
```

- **Default:**

```ts
{
  enabled: false,
  provider: 'istanbul',
  reporters: ['text', 'html', 'clover', 'json'],
  reportsDirectory: './coverage',
  clean: true,
  reportOnFailure: false,
  allowExternal: false,
  exclude: [
    '**/node_modules/**',
    '**/__tests__/**',
    '**/__mocks__/**',
    '**/*.d.ts',
    '**/*.{test,spec}.[jt]s',
    '**/*.{test,spec}.[cm][jt]s',
    '**/*.{test,spec}.[jt]sx',
    '**/*.{test,spec}.[cm][jt]sx',
  ],
}
```

Collect code coverage and generate coverage reports.

```bash
$ npx rstest --coverage

```

### provider

- **Type:** `'istanbul' | 'v8'`
- **Default:** `'istanbul'`
- **CLI:** `--coverage.provider <provider>`

Coverage provider to use:

- `'istanbul'`: SWC-based transform instrumentation with stable Istanbul semantics. Higher runtime memory usage because executed modules hold coverage counters.
- `'v8'`: Native V8 coverage via Node.js inspector or Chromium, remapped to Istanbul format. Lower runtime memory usage—prefer this for large suites hitting memory pressure.

```ts title='rstest.config.ts'
import { defineConfig } from '@rstest/core';

export default defineConfig({
  coverage: {
    enabled: true,
    provider: 'v8',
  },
});
```

#### Istanbul provider

Install [@rstest/coverage-istanbul](https://github.com/web-infra-dev/rstest/tree/main/packages/coverage-istanbul) to use [Istanbul](https://istanbul.js.org/) instrumentation:

<PackageManagerTabs command="add @rstest/coverage-istanbul -D" />

`@rstest/coverage-istanbul` uses [swc-plugin-coverage-instrument](https://github.com/kwonoj/swc-plugin-coverage-instrument) during SWC transform.

##### Excluding code

Use `coverage.exclude` (or repeat `--coverage.exclude` on CLI) to skip whole files, generated files, or injected scripts:

```ts title='rstest.config.ts'
import { defineConfig } from '@rstest/core';

export default defineConfig({
  coverage: {
    enabled: true,
    provider: 'istanbul',
    exclude: ['**/src/injected-script.ts', '**/src/**/*.{worker,evaluate}.ts'],
  },
});
```

Use Istanbul ignore comments only for small snippets inside covered files (`/* istanbul ignore file */`, `/* istanbul ignore next */`, `/* istanbul ignore if */`, `/* istanbul ignore else */`):

```ts
/* istanbul ignore next */
function browserEvaluateFn() {
  return window.location.href;
}

/* istanbul ignore if */
if (process.env.NODE_ENV === 'test') {
  setupTestOnlyState();
}

/* istanbul ignore else */
if (hasNativeFeature()) {
  useNativeFeature();
} else {
  useFallback();
}
```

If an ignored snippet still receives an injected `cov_*` call, exclude the file via `coverage.exclude` instead.

##### Known limitations

- **Legacy decorators and metadata:** Generated statements and branches may be counted, lowering reported coverage even when all source branches are tested. See [SWC #5535](https://github.com/swc-project/swc/issues/5535).
- **TypeScript runtime code:** Enums, namespaces, and constructor parameter properties may produce generated coverage entries, including at line `0`. See [swc-plugin-coverage-instrument #300](https://github.com/kwonoj/swc-plugin-coverage-instrument/issues/300).
- **Module reloading:** Re-importing a module after `rs.resetModules()` can reset its coverage counters and lose earlier counts. See [swc-plugin-coverage-instrument #295](https://github.com/kwonoj/swc-plugin-coverage-instrument/issues/295).
- **Serialized functions:** Running a serialized instrumented function in another realm (such as `page.evaluate` or a `Worker`) may throw `ReferenceError: cov_... is not defined`.

#### V8 provider

<ApiMeta addedVersion="0.10.2" />

Install [@rstest/coverage-v8](https://github.com/web-infra-dev/rstest/tree/main/packages/coverage-v8) to collect native V8 coverage:

<PackageManagerTabs command="add @rstest/coverage-v8 -D" />

Because raw data comes from Node.js / Chromium V8 directly, remapped branch coverage and uncovered line details can differ slightly across engine versions.

You can use V8 coverage data to see how much of the generated test bundle actually runs in Node.js. See [Inspect bundle coverage](/guide/debug/debugging#inspect-bundle-coverage).

##### Ignore hints

The `v8` provider recognizes ignore hints using `istanbul`, `c8`, `v8`, or `node:coverage` prefixes (`next`, `if`, `else`, `start`/`stop`, `file`). Use one prefix consistently:

```ts
/* v8 ignore next */
const value = optionalExpensivePath();

/* v8 ignore if */
if (process.env.NODE_ENV === 'test') {
  setupTestOnlyState();
}

/* v8 ignore else */
if (hasNativeFeature()) {
  useNativeFeature();
} else {
  useFallback();
}

/* v8 ignore start */
const generatedLookup = createGeneratedLookup();
/* v8 ignore stop */
```

`ignore file` applies to the generated coverage entry before source-map remapping; since a single generated chunk can contain multiple source files, prefer `coverage.exclude` to skip whole source files.

The `v8` provider works in `node`, `jsdom`, and `happy-dom` environments. Stable Browser Mode support is limited to headless, non-watch Chromium runs with Playwright, where Chromium collects coverage from HTTP(S) scripts (classic, module, and query-bearing URLs) and remaps via source maps without instrumentation.

Headed and watch Browser Mode V8 coverage is experimental: reports may include container or inactive runner frame execution, and watch rebuilds may mismatch script/source-map pairs. Firefox and WebKit do not expose the native coverage API. Native browser V8 coverage also excludes `blob:`, `data:`, non-HTTP/anonymous scripts (`eval`, `new Function`), and code running only in dedicated `Worker` or `SharedWorker` targets. Use `istanbul` in those cases.

### include

- **Type:** `string[]`
- **Default:** `undefined`
- **CLI:** `--coverage.include <pattern>`

Glob patterns for files included in coverage collection. Repeat the CLI flag for multiple patterns.

By default, Rstest collects coverage only for files executed by tests. Set `include` to include untested source files in the report.

Use standard glob syntax without single-value braces—write `src/**/*.ts`, not `src/**/*.{ts}` (glob libraries treat single-value braces literally).

```ts title='rstest.config.ts'
import { defineConfig } from '@rstest/core';

export default defineConfig({
  coverage: {
    enabled: true,
    include: ['src/**/*.{js,jsx,ts,tsx}'],
  },
});
```

### changed

<ApiMeta addedVersion="0.10.0" />

- **Type:** `boolean | string`
- **Default:** `undefined`
- **CLI:** `--coverage.changed`, `--coverage.changed=<commit>`

Collect coverage only for files changed in the current Git repository, or since a specified commit or branch ref.

`coverage.changed` only filters the coverage report scope; it does not change which tests run:

- `--changed` selects and runs only tests related to changed files.
- `--coverage.changed` runs the normal test suite and limits coverage reporting to changed source files.

```ts title='rstest.config.ts'
import { defineConfig } from '@rstest/core';

export default defineConfig({
  coverage: {
    enabled: true,
    changed: 'origin/main',
  },
});
```

```bash
# Filter both tests and coverage to changed files
npx rstest run --changed --coverage

# Run all tests, report coverage only for uncommitted changes / changes since a ref
npx rstest run --coverage.changed
npx rstest run --coverage.changed=HEAD~1
```

#### Interaction with `--changed`

- When [`--changed`](/guide/basic/cli#run-changed-tests) is used and `coverage.changed` is unset, coverage inherits the changed files collected by `--changed`.
- If `--changed` hits [`forceRerunTriggers`](/config/test/force-rerun-triggers), Rstest reruns the full suite and reports full coverage unless `coverage.changed` is explicitly enabled.
- Set `coverage.changed: false` in config to keep full coverage reports when running with `--changed`.

### exclude

- **Type:** `string[]`
- **CLI:** `--coverage.exclude <pattern>`
- **Default:**

```ts
[
  '**/node_modules/**',
  '**/__tests__/**',
  '**/__mocks__/**',
  '**/*.d.ts',
  '**/*.{test,spec}.[jt]s',
  '**/*.{test,spec}.[cm][jt]s',
  '**/*.{test,spec}.[jt]sx',
  '**/*.{test,spec}.[cm][jt]sx',
];
```

Glob patterns to exclude from coverage collection. Custom patterns merge with the defaults. Repeat the CLI flag to pass multiple patterns.

Rstest does not exclude directories named `test` by default so packages with `test` in their path (such as `packages/test/src/index.ts`) are not dropped accidentally. Add `test/**` or `**/test/**` explicitly if needed.

```ts title='rstest.config.ts'
import { defineConfig } from '@rstest/core';

export default defineConfig({
  coverage: {
    enabled: true,
    exclude: ['**/node_modules/**', '**/dist/**'],
  },
});
```

### reporters

- **Type:** `CoverageReporter[]`
- **Default:** `['text', 'html', 'clover', 'json']`
- **CLI:** `--coverage.reporters <reporter>`

Reporters used for coverage output. Rstest uses the standard [Istanbul reporter API](https://istanbul.js.org/docs/advanced/alternative-reporters/).

Each entry can be a reporter name, a `[name, options]` tuple, or an Istanbul-compatible reporter object with an `execute(context)` method. On the CLI, pass reporter names by repeating the flag:

```bash
npx rstest run --coverage.reporters text --coverage.reporters=json
```

See [Istanbul Reporters](https://istanbul.js.org/docs/advanced/alternative-reporters/) for built-in reporter names and [@types/istanbul-reports](https://github.com/DefinitelyTyped/DefinitelyTyped/blob/master/types/istanbul-reports/index.d.ts) for reporter options.

```ts title='rstest.config.ts'
import { defineConfig } from '@rstest/core';

export default defineConfig({
  coverage: {
    enabled: true,
    reporters: ['html', 'text', ['json', { file: 'coverage-final.json' }]],
  },
});
```

#### Custom coverage reporters

Custom coverage reporters follow the Istanbul reporter contract. A package or file path is loaded by the coverage provider, constructed with the tuple options, and called with an `istanbul-lib-report` `Context`:

```js title='custom-coverage-reporter.mjs'
export default class CustomCoverageReporter {
  constructor(options = {}) {
    this.options = options;
  }

  /** @param {import('istanbul-lib-report').Context} context */
  execute(context) {
    const summary = context.getTree('flat').getRoot().getCoverageSummary();
    console.log('Coverage summary:', summary.toJSON());
  }
}
```

Reference it by package name or path, or pass an inline reporter object directly in `rstest.config.ts`:

```ts title='rstest.config.ts'
import { defineConfig } from '@rstest/core';

export default defineConfig({
  coverage: {
    enabled: true,
    reporters: [
      'text',
      ['./custom-coverage-reporter.mjs', { outputFile: 'summary.json' }],
      {
        execute(context) {
          const summary = context
            .getTree('flat')
            .getRoot()
            .getCoverageSummary();
          console.log(summary.toJSON());
        },
      },
    ],
  },
});
```

### thresholds

- **Type:**

```ts
type CoverageThreshold = {
  statements?: number;
  functions?: number;
  branches?: number;
  lines?: number;
};

type CoverageThresholds =
  | CoverageThreshold
  | (CoverageThreshold &
      Record<
        string,
        CoverageThreshold & {
          /** Check thresholds per file */
          perFile?: boolean;
        }
      >);
```

- **Default:** `undefined`

Minimum coverage requirements for statements, functions, branches, and lines:

- **Positive number**: minimum required coverage percentage.
- **Negative number**: maximum allowed number of uncovered items.

```ts title='rstest.config.ts'
import { defineConfig } from '@rstest/core';

export default defineConfig({
  coverage: {
    enabled: true,
    thresholds: {
      statements: 80,
      functions: 80,
      branches: 80,
      lines: -10,
    },
  },
});
```

When coverage falls short, the run fails and prints the unmet thresholds:

```bash
Error: Coverage for statements 75% does not meet global threshold 80%
Error: Coverage for functions 75% does not meet global threshold 80%
Error: Coverage for branches 75% does not meet global threshold 80%
Error: Uncovered lines 20 exceeds maximum global threshold allowed 10
```

#### Glob pattern

Specify per-glob thresholds alongside global thresholds. If a specified file path does not exist, an error is returned.

```ts title='rstest.config.ts'
import { defineConfig } from '@rstest/core';

export default defineConfig({
  coverage: {
    enabled: true,
    thresholds: {
      'src/**': {
        statements: 100,
      },
      'node/**/*.js': {
        statements: 90,
      },
      statements: 80,
    },
  },
});
```

With the config above, Rstest fails if total statement coverage is below 100% for `src/**`, below 90% for `node/**/*.js`, or below 80% globally.

#### Per-file thresholds

Set `perFile: true` inside a glob entry to enforce thresholds on each matched file individually:

```ts title='rstest.config.ts'
import { defineConfig } from '@rstest/core';

export default defineConfig({
  coverage: {
    enabled: true,
    thresholds: {
      'src/**': {
        statements: 90,
        perFile: true,
      },
    },
  },
});
```
