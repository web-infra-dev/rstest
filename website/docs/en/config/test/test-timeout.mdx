# testTimeout

- **Type:** `number`
- **Default:** `5_000` (`15_000` in Browser Mode)
- **CLI:** `--testTimeout=5000`

Maximum time in milliseconds a test case may run before failing with a timeout error. Set to `0` to disable the timeout.

Rstest resolves a test's timeout in the following order (highest to lowest):

1. Per-test `timeout` via [`TestOptions.timeout`](/api/runtime-api/test-api/test#testoptions) or the trailing timeout argument on `test`
2. Enclosing `describe` suite's [`TestOptions.timeout`](/api/runtime-api/test-api/describe#testoptions) (nearest enclosing suite wins)
3. File-level timeout set via [`rs.setConfig({ testTimeout })`](/api/runtime-api/rstest/utilities#rssetconfig)
4. `--testTimeout` CLI option or `run({ testTimeout })`
5. `testTimeout` in the configuration file
6. Default of `5_000` ms (`15_000` ms in Browser Mode)

Browser Mode also defaults `expect.poll.timeout` to `5_000` ms, compared to `1_000` ms in Node Mode; see [`expect.poll`](/config/test/expect).
