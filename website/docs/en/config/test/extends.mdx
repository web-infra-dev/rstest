# extends

- **Type:** `ExtendConfig | ExtendConfigFn | (ExtendConfig | ExtendConfigFn)[]`
- **Default:** `undefined`

Extend your Rstest configuration from shared presets, async factory functions, or adapters (such as `@rstest/adapter-rslib`) that translate other build tools' configs into Rstest options.

## Basic usage (object)

```ts
type LooseRstestConfig = Omit<RstestConfig, 'reporters'> & {
  reporters?: any;
};

type ExtendConfig = Omit<LooseRstestConfig, 'projects'>;
```

`ExtendConfig` is a subset of `RstestConfig` without `projects`, with `reporters` widened to `any` so adapters built against different `@rstest/core` versions remain compatible. Rstest merges the extended config with your local config following the [configuration merging rules](#configuration-merging).

```ts
import { defineConfig } from '@rstest/core';
import { sharedConfig } from './shared.config';

export default defineConfig({
  extends: sharedConfig,
  // Local configuration
  testTimeout: 10000,
  retry: 2,
});
```

## Function usage

```ts
type ExtendConfigFn = (
  userConfig: Readonly<LooseRstestConfig>,
) => ExtendConfig | Promise<ExtendConfig>;
```

`ExtendConfigFn` receives the user's Rstest config and returns (synchronously or asynchronously) an `ExtendConfig`. Use it to load external config files, fetch remote configs, or derive options from user settings:

```ts
import { defineConfig } from '@rstest/core';

export default defineConfig({
  extends: async (user) => {
    const useJsdom = user.testEnvironment === 'jsdom';
    return {
      setupFiles: useJsdom ? ['<rootDir>/setupDomTests.ts'] : undefined,
      source: {
        define: {
          BUILD_TARGET: '"test"',
        },
      },
    };
  },
  testTimeout: 10_000,
});
```

## Multiple extends

Pass an array to `extends` to compose multiple presets. Rstest merges entries from left to right so later entries override earlier ones, while the local config keeps highest priority.

When an array contains functions, each `ExtendConfigFn` receives the original user config independently; array order only controls merge precedence.

```ts
import { defineConfig } from '@rstest/core';
import { withRslibConfig } from '@rstest/adapter-rslib';
import { sharedConfig } from './shared.config';

export default defineConfig({
  extends: [
    sharedConfig,
    withRslibConfig({}),
    (userConfig) => ({
      globals: userConfig.retry !== undefined,
    }),
  ],
  testTimeout: 10_000,
});
```

## Configuration merging

Rstest deep-merges object fields and overrides primitives, with the local config taking precedence. When `extends` is an array, precedence is:

```ts
extends[0] < extends[1] < ... < extends[n] < local config
```

Merge rules:

- Primitive fields such as `testTimeout`, `retry`, and `globals` are overridden by the later value.
- `setupFiles`, `globalSetup`, and `plugins` are concatenated across presets.
- `include`, `reporters`, and `coverage.reporters` are replaced by the later value.
- Object fields such as `source`, `resolve`, `output`, `tools`, `env`, and `coverage` are deep-merged.
- `browser` deep-merges plain objects, including nested `providerOptions`; arrays, functions, and class instances are replaced by the later value (for example, overriding `providerOptions.launch.args` replaces the array while preserving `launch.timeout` and `context.locale`).
- `projects` is ignored in every extended config.

Example:

```ts
import { defineConfig } from '@rstest/core';

export default defineConfig({
  extends: [
    {
      testEnvironment: 'jsdom',
      setupFiles: ['./setup-a.ts'],
      testTimeout: 5000,
      source: {
        define: {
          BASE_URL: '"https://example.com"',
        },
      },
    },
    {
      globals: true,
      setupFiles: ['./setup-b.ts'],
      source: {
        define: {
          API_URL: '"https://api.example.com"',
        },
      },
    },
  ],
  // Local configuration
  testTimeout: 10000,
  retry: 2,
});

// Result:
// {
//   testEnvironment: 'jsdom',
//   globals: true,
//   testTimeout: 10000,
//   retry: 2,
//   setupFiles: ['./setup-a.ts', './setup-b.ts'],
//   source: {
//     define: {
//       BASE_URL: '"https://example.com"',
//       API_URL: '"https://api.example.com"',
//     },
//   },
// }
```

## Using adapters

Adapters such as `@rstest/adapter-rslib` map compatible options (like `source.define`, `source.include`, `source.exclude`, and `source.transformImport`) from an existing build config into Rstest:

```ts
import { defineConfig } from '@rstest/core';
import { withRslibConfig } from '@rstest/adapter-rslib';

export default defineConfig({
  extends: withRslibConfig({}),
  // Additional rstest-specific configuration
  coverage: {
    enabled: true,
    reporters: ['text', 'html'],
  },
});
```

## Limitations

An extended config cannot define `projects`. To configure multiple projects, pass `extends` on each project individually:

```ts
export default defineConfig({
  projects: [
    {
      name: 'node',
      extends: withRslibConfig({ libId: 'node' }),
      include: ['tests/node/**/*.{test,spec}.?(c|m)[jt]s'],
    },
    {
      name: 'react',
      extends: withRslibConfig({ libId: 'react' }),
      include: ['tests/react/**/*.{test,spec}.?(c|m)[jt]s?(x)'],
    },
  ],
});
```
