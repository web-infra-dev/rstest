# teardownTimeout

<ApiMeta addedVersion="0.12.2" />

- **Type:** `number`
- **Default:** `10_000`
- **CLI:** `--teardownTimeout=10000`

After a run finishes — all test files have run, `globalSetup` teardown has completed, and reporters have written their output — Rstest lets the process exit on its own. Normally it exits right away.

If something is still running in the Rstest process itself (an open server or socket, a timer, or an unfinished request created by a reporter, a plugin, or your config file), the process cannot exit. Test files and `setupFiles` run in workers that Rstest stops on its own, so leaks there do not keep the process alive. `teardownTimeout` is how long Rstest waits in that situation, in milliseconds. When the time is up, Rstest prints a warning and exits the process. The exit code still reflects the test results.

Set it to `0` to exit immediately after the run finishes, without waiting or printing a warning. This is equivalent to Jest's `forceExit: true`.

**This option does not limit your teardown code.** The timer starts only after `globalSetup` teardown and hooks such as `afterAll` have finished. Use [`hookTimeout`](/config/test/hook-timeout) to limit hooks.

If the warning shows up, look for an unclosed handle in your reporters, plugins, or config. [`detectAsyncLeaks`](/config/test/detect-async-leaks) is a different tool: it finds leaks inside test files, which do not block the exit.

Applies to `rstest run` only, not the programmatic API. Watch mode keeps the process alive on purpose. Set this option in the root config; individual projects cannot override it.
