# reporters

- **Type:**

```ts
type ReporterItem =
  | Reporter
  | BuiltInReporterNames
  | (string & {})
  | ReporterWithOptions
  | [string]
  | [string, Record<string, unknown>];

type Reporters =
  Reporter | BuiltInReporterNames | (string & {}) | ReporterItem[];
```

- **Default:**

```ts
process.env.GITHUB_ACTIONS === 'true'
  ? ['default', 'github-actions']
  : ['default'];
```

- **CLI:** `--reporters=<name> --reporters=<name1>` (`--reporter` is also accepted as an alias)

Configure which reporters to use for test result output.

Built-in reporter names: `default`, `dot`, `verbose`, `md`, `github-actions`, `junit`, `json`, and `blob`.

:::info AI agent environments
When no `reporters` are configured (neither in config nor via `--reporters`), Rstest defaults to `['md']` in AI agent environments and writes agent-friendly Markdown to stdout.
:::

### Configuring reporters with options

Pass `[reporterName, options]` inside the `reporters` array to configure a reporter:

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: [
    ['default', { summary: false }],
    ['github-actions', { summary: { maxCharsPerField: 1000 } }],
    ['junit', { outputPath: './test-results.xml' }],
  ],
});
```

### Built-in reporter options

Full type definitions live in [`packages/core/src/types/reporter.ts`](https://github.com/web-infra-dev/rstest/blob/main/packages/core/src/types/reporter.ts).

- **`default`**:
  - `summary?: boolean` (default: `true`) — print the test run summary.
  - `logger?: { outputStream: Writable; errorStream: Writable; getColumns: () => number }` (default: `process.stdout` / `process.stderr`) — custom output streams (`Writable` from `node:stream`).
  - `showProjectName?: boolean` (default: `true` for multi-project or multi-browser runs, `false` otherwise) — print the project name in test file titles.
- **`dot`**: supports `summary` and `logger` (same defaults as `default`).
- **`verbose`**: supports `logger` and `showProjectName` (same defaults as `default`).
- **`github-actions`**:
  - `annotations?: boolean` (default: `true`) — output `::error` workflow annotations for failed tests.
  - `summary?: boolean | { maxCharsPerField?: number }` (default: `true`; `maxCharsPerField` defaults to `400`) — append a Markdown summary to `GITHUB_STEP_SUMMARY`.
- **`junit`**:
  - `outputPath?: string` — write the JUnit XML report to a file instead of stdout.
- **`json`**:
  - `outputPath?: string` — write the JSON report to a file instead of stdout.
- **`blob`**:
  - `outputDir?: string` (default: `'.rstest-reports'`) — directory for blob report files. Not supported in watch mode.
- **`md`**:
  - `preset?: 'normal' | 'compact' | 'full'` (default: `'normal'`) — output detail preset.
  - `header?: boolean | { env?: boolean }` (default: `{ env: true }`) — control runtime/environment frontmatter.
  - `reproduction?: boolean | 'file' | 'file+name'` (default: `'file+name'`) — control failure reproduction commands.
  - `testLists?: 'auto' | 'always'` (default: `'auto'`) — when to include Passed / Skipped / Todo lists.
  - `failures?: { max?: number }` (default: `{ max: 50 }`) — maximum expanded failure details.
  - `codeFrame?: boolean | { linesAbove?: number; linesBelow?: number }` (default: `{ linesAbove: 2, linesBelow: 2 }`) — code frame line window.
  - `stack?: number | false | 'full' | 'top'` (default: `'top'`) — stack frames per error.
  - `candidateFiles?: boolean | { max?: number }` (default: `{ max: 5 }`) — candidate files extracted from stack traces.
  - `console?: boolean | { maxLogsPerTestPath?: number; maxCharsPerEntry?: number }` (default: `{ maxLogsPerTestPath: 10, maxCharsPerEntry: 500 }`) — console log limits.
  - `errors?: boolean | { unhandled?: boolean }` (default: `{ unhandled: true }`) — unhandled error output.

### Custom reporters

Pass a module specifier (or `[specifier, options]`) whose default export is a class implementing [`Reporter`](/api/javascript-api/reporter). Rstest instantiates it with `(options, { rootPath, config })` (passing `{}` when no options are provided). On Node.js 22.18+ or 24 with type stripping enabled, `.ts` and `.mts` reporter modules load directly:

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: './custom-reporter.js',
});

// With options:
export const configWithOptions = defineConfig({
  reporters: [['./custom-reporter.js', { outputPath: './report.json' }]],
});
```

You can also pass an already constructed object implementing `Reporter`. Reporter classes cannot be passed directly.
