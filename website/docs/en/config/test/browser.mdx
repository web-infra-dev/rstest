Browser Mode configuration. When enabled, tests run in a real browser instead of the Node.js environment.

## Options

### screenshotFailures

<ApiMeta addedVersion="0.12.4" />

Capture a PNG screenshot for each failed browser test. Defaults to the `headless` setting. Screenshots are saved under `.rstest/screenshots/` in the project root, with the test file and test name in the filename. Set this to `false` to disable capture.

- **Type:** `boolean`
- **Default:** `browser.headless`
- **CLI:** `--browser.screenshotFailures`

### enabled

- **Type:** `boolean`
- **Default:** `false`
- **CLI:** `--browser`, `--browser.enabled`

Enable Browser Mode.

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
  },
});
```

:::tip
Enabling Browser Mode requires installing the `@rstest/browser` package and Playwright browsers.

```bash
npm add @rstest/browser -D
npx playwright install chromium
```

:::

### provider

- **Type:** `'playwright'`
- **Default:** `'playwright'`

Browser driver provider. Currently only [Playwright](https://playwright.dev/) is supported.

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
  },
});
```

### browser

<ApiMeta addedVersion="0.13.0" />

- **Type:** `'chromium' | 'firefox' | 'webkit'`
- **Default:** `'chromium'`
- **CLI:** `--browser.name <name>` (deprecated)
- **Deprecated:** use [`browsers`](#browsers) instead. Will be removed in 1.0.

The single browser type to use for testing. Setting this field emits a deprecation warning once per run and is normalized to `browsers: [browser]`:

> `browser.browser` is deprecated and will be removed in 1.0: use `browser.browsers` instead, e.g. `browsers: ['chromium']` or `[{ browserName: 'firefox' }]`.

Setting both `browser` and `browsers` on a browser project is a config error.

- `chromium` - Google Chrome, Microsoft Edge
- `firefox` - Mozilla Firefox
- `webkit` - Safari

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    browser: 'firefox', // deprecated; prefer browsers: ['firefox']
  },
});
```

You need to install the corresponding browser before use:

```bash
# Install chromium
npx playwright install chromium

# Install Firefox
npx playwright install firefox

# Install WebKit
npx playwright install webkit

# Install all browsers
npx playwright install
```

### browsers

<ApiMeta addedVersion="0.13.0" />

- **Type:** `BrowserName | (BrowserName | BrowserEntry)[]`
- **Default:** `'chromium'`
- **CLI:** `--browser.browsers <names>` (comma-separated and/or repeatable)

Browsers this project runs on. Every browser of a project shares one build and one dev server — multi-browser runs do not multiply build time.

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    browsers: ['chromium', 'firefox'],
  },
});
```

Each entry is either a browser name (a plain entry inheriting every project-level default) or a `BrowserEntry` object that overrides fields per browser:

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    providerOptions: {
      launch: { slowMo: 100 },
      context: { locale: 'en-US' },
    },
    browsers: [
      'firefox',
      {
        browserName: 'chromium',
        viewport: { width: 800, height: 600 },
        providerOptions: {
          launch: { channel: 'chrome' },
        },
      },
    ],
  },
});
```

`BrowserEntry` accepts only runtime-effective overrides; build-scoped options (`enabled`, `provider`, `port`, `strictPort`) stay on the project-level `browser` config:

| Field                | Default                              |
| -------------------- | ------------------------------------ |
| `browserName`        | required                             |
| `headless`           | project `browser.headless`           |
| `viewport`           | project `browser.viewport`           |
| `screenshotFailures` | project `browser.screenshotFailures` |
| `expect`             | project `browser.expect`             |
| `providerOptions`    | project `browser.providerOptions`    |

Merge rules per entry: an entry field wins, then the project-level `browser.*` field, then the built-in default. `providerOptions` merges per top-level key (`launch`, `context`) instead of whole-field: an entry `launch` replaces the project `launch` key entirely (Playwright options may contain functions and class instances, so sibling keys under it are not merged), while keys the entry does not set keep the project value — in the example above the chromium entry launches with `channel: 'chrome'` alone, and its context keeps the project-level `locale: 'en-US'`.

A project runs exactly one browser per entry; two result rows come back for the same file. Reporters tag file rows with the owning browser name when the run selects more than one browser — see [Multi-browser reporting](#multi-browser-reporting).

Validation rules:

- The same `browserName` may be configured at most once per project (duplicate names are a config error).
- `browsers` must not be empty — remove the option to run the default Chromium instead.
- At most one `(project, browser)` pair may run headed (`headless: false`) per run; see [Launch rules](#launch-rules).
- [`coverage.provider: 'v8'`](/config/test/coverage) requires every selected browser to be Chromium; see [Launch rules](#launch-rules).

### headless

- **Type:** `boolean`
- **Default:** `true` in CI environments, `false` for local development
- **CLI:** `--browser.headless`

Whether to run the browser in headless mode (without UI). Entries in [`browsers`](#browsers) can override it per browser, subject to the [one headed browser per run](#launch-rules) rule.

### viewport

<ApiMeta addedVersion="0.8.4" />

- **Type:** `BrowserViewport`
- **Default:** `undefined`

Set the default runner iframe viewport for Browser Mode tests. When not specified, the Browser UI fills the preview panel. Entries in [`browsers`](#browsers) can override the viewport per browser.

```ts
type BrowserViewport =
  | {
      width: number;
      height: number;
    }
  | DevicePreset;
```

Use an explicit size when you want all files in a browser project to run with the same viewport:

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    viewport: { width: 390, height: 844 },
  },
});
```

You can also use a built-in device preset:

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    viewport: 'iPhone12Pro',

});
```

### port

- **Type:** `number`
- **Default:** `undefined` (automatically selects an available port)
- **CLI:** `--browser.port <port>`

The port number for the Browser Mode Dev Server.

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    port: 5173,
  },
});
```

If you set `port` and the port is already in use, the behavior is controlled by `strictPort`: when `strictPort: true`, Rstest throws an error and exits; when `strictPort: false`, it falls back to another available port. If `port` is not specified, an available port is always selected automatically.

### strictPort

- **Type:** `boolean`
- **Default:** `false`
- **CLI:** `--browser.strictPort`

When `port` is specified, whether the port must be available:

- `true`: throw an error and exit if the port is in use
- `false`: fall back to another available port if the port is in use

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    port: 5173,
    strictPort: true,
  },
});
```

### providerOptions

<ApiMeta addedVersion="0.9.3" />

- **Type:** `Record<string, unknown>`
- **Default:** `{}`
- **CLI:** `--browser.providerOptions.*`

Playwright options passed through to browser launch and context creation. Rstest does not validate or interpret the contents of this object — it forwards the values as-is to Playwright.

Each `BrowserEntry` in [`browsers`](#browsers) can carry its own `providerOptions`: top-level keys (`launch`, `context`) set on the entry replace the project-level keys, and keys the entry does not set keep the project-level value.

See [Playwright provider options](#provider-options) below for the supported fields.

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    providerOptions: {
      launch: {
        timeout: 60_000,
      },
    },
  },
});
```

You can also pass nested Playwright options from the CLI:

```bash
npx rstest --browser.providerOptions.launch.channel=chrome
```

### expect.toMatchScreenshot

<ApiMeta addedVersion="0.12.4" />

- **Type:** `BrowserScreenshotMatcherConfig`
- **Default:**

```ts
{
  comparatorOptions: {
    threshold: 0.1,
    maxDiffPixels: 0,
  },
  stabilityTimeout: 2000,
  maskColor: '#FF00FF',
  caret: 'hide',
  scale: 'device',
  omitBackground: false,
}
```

`maxDiffPixelRatio` also defaults to `0`; configure it instead of `maxDiffPixels` when you want to set a ratio. `style` is not injected by default. `mask` is assertion-only and defaults to no masks.

Configure defaults for [`toMatchScreenshot()`](/api/runtime-api/browser-mode/assertion#screenshot-matching) across a Browser Mode project. Put pixel-comparison tolerances under `comparatorOptions`; capture and path options are siblings of it. Assertion-level values override the corresponding global values. `mask` remains assertion-specific because it uses browser `Locator` objects.

The defaults below apply when an option is omitted. Playwright supplies the capture defaults for `maskColor`, `caret`, `scale`, and `omitBackground`.

| Option                                | Default           | Description                                                          |
| ------------------------------------- | ----------------- | -------------------------------------------------------------------- |
| `comparatorOptions.threshold`         | `0.1`             | Per-pixel color distance threshold from `0` (strict) to `1` (loose). |
| `comparatorOptions.maxDiffPixels`     | `0`               | Maximum number of pixels allowed to differ.                          |
| `comparatorOptions.maxDiffPixelRatio` | `0`               | Maximum fraction of pixels allowed to differ.                        |
| `stabilityTimeout`                    | `2000`            | Maximum time to wait for consecutive captures to match, in ms.       |
| `maskColor`                           | `#FF00FF`         | Color used to cover masked content.                                  |
| `style`                               | Not set           | No additional CSS is injected.                                       |
| `caret`                               | `hide`            | Hides the text caret during capture.                                 |
| `scale`                               | `device`          | Captures at the device pixel ratio.                                  |
| `omitBackground`                      | `false`           | Keeps the page background in the screenshot.                         |
| `screenshotDirectory`                 | `__screenshots__` | Directory for references beside each test file.                      |
| `resolveScreenshotPath`               | Built-in          | Uses the path layout described below.                                |

Set either `comparatorOptions.maxDiffPixels` or `comparatorOptions.maxDiffPixelRatio`, not both. A relative `screenshotDirectory` is resolved from each test file's directory. If omitted, it defaults to `__screenshots__`. A shared directory keeps references separate by project name and test file, so paths stay stable across checkouts. When the chosen directory is the test file's own directory, Rstest places references in its `__screenshots__` subdirectory.

By default, references are stored in this layout:

```text
<test-directory>/__screenshots__/<test-file>/<reference-name>-<browser>-<platform>.png
```

The reference name comes from the explicit name or the test name, sanitized for use as a path. Names that could collide after sanitization receive a stable suffix. Every unnamed assertion gets a sequence number starting at `1`, including a test's only screenshot (for example, `<test-name>-1`). Explicitly named assertions do not get this number.

Project names are not part of the default path, so projects using the same test file, screenshot name, browser, and platform share a reference. Use `resolveScreenshotPath` to isolate project-specific references. Existing references from Rstest's previous hashed layout are not moved automatically; move them to the new paths or regenerate them with `--update`.

Use `resolveScreenshotPath` when you need a different layout. It receives the absolute test file path, project and test names, browser, platform, and an optional ordinal for unnamed assertions. The first unnamed assertion receives no ordinal; later ones start at `2`. Return an absolute path or a path relative to the project root. When configured, the resolver takes precedence over `screenshotDirectory`.

```ts title="rstest.config.ts"
import path from 'node:path';
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    expect: {
      toMatchScreenshot: {
        comparatorOptions: {
          threshold: 0.1,
          maxDiffPixels: 10,
        },
        resolveScreenshotPath: ({
          testFilePath,
          projectName,
          testName,
          browserName,
          platform,
        }) =>
          path.join(
            'visual-baselines',
            projectName,
            path.relative(process.cwd(), testFilePath),
            `${testName}-${browserName}-${platform}.png`,
          ),
      },
    },
  },
});
```

## Launch rules

Every `rstest` run launches one browser per `(provider, browserName, headless, providerOptions.launch)` combination across all Browser Mode projects. Two projects that configure the same browser with the same launch key share one browser instance; different `providerOptions.launch` values or a different `headless` setting produce separate launches. Within a project, every browser of the project shares one build and one dev server.

The following rules are validated before any browser launches:

- **One headed browser per run.** Browser mode opens a single debug window, so at most one `(project, browser)` pair may set `headless: false`; every other browser must set `headless: true`. The error names the concrete fix:

  > Only one (project, browser) pair can run headed per run: "web" ("chromium"). Browser mode opens one debug window, so every other browser must set headless: true. Most often this comes from `--browser.headless=false` on a multi-browser run: select a single headless pair with `--browser.browsers <name>` or narrow the projects with `--project`.

- **Watch mode does not support mixing headed and headless browsers.** A watch session where one browser runs headed and another headless is rejected at validation; every configured browser must set `headless: true`, or run without watch.

- **Coverage provider `v8` requires Chromium.** With `coverage.enabled` and `coverage.provider: 'v8'`, a browser project selecting a non-Chromium browser fails validation. Switch to `coverage.provider: 'istanbul'`, or select Chromium only (`--browser.browsers chromium`).

For strict browser-per-environment coverage you can still run separate executions (for example, in a CI matrix) with the `--browser.browsers` filter:

```bash
npx rstest --browser.browsers chromium
npx rstest --browser.browsers firefox
npx rstest --browser.browsers webkit
```

## CLI browser filters

`--browser.browsers <names>` (repeatable and/or comma-separated) overrides and filters the configured browsers: a listed name with a configured entry keeps that entry together with its overrides, and a listed name the project does not configure falls back to a plain entry — a single name inheriting every project-level default. The resolved list replaces the project's `browsers`.

`--browser.name <name>` stays as a deprecated alias of `--browser.browsers` and emits a deprecation warning once per run.

## Multi-browser reporting

When a project selects more than one browser, Rstest attributes every payload to the browser that produced it:

- Reporter payloads (`onTestFileStart`, `onTestFileReady`, `onTestFileResult`, `onTestCaseStart`/`onTestCaseResult`, `onConsoleLog`, `onTestRunStart` files entries) carry `browserName` for browser projects and leave it absent on the node pool. Case and suite task ids are rooted at `file:project:browserName:testPath` in browser mode (and `file:project:testPath` on the node pool), so the same file run by two browsers yields two distinct results instead of overwriting each other.
- Built-in reporters tag file rows with a gray `[chromium]`-style suffix (junit suite names and markdown titles include it after the file path, and `rstest list` rows tag browser names the same way) only when the run selects several browsers for a project; single-browser output is unchanged. Custom reporters and reporter options can control this through the `showBrowserName` option on the built-in reporters — Rstest sets it automatically for multi-browser runs before user options, so user options win.
- The blob reporter stores per-file keys as `[project, browserName, testPath]`, and the blob format version is bumped to suffix `:3` of the Rstest version; blobs recorded by older versions are rejected by `merge-reports` and must be regenerated.

## Multi-project config isolation

When using `projects` in Browser Mode, each project still compiles and executes with its own build config (for example `plugins`, `include`, and framework-specific setup).

Browser build-scoped options stay per project (`provider`, `port`, `strictPort`), while the browser list, defaults, and per-browser overrides (`browsers`, `headless`, `viewport`, `providerOptions`) are project-owned: two browser projects may run different browsers in one run, and two projects configuring the same `(provider, browserName, headless, providerOptions.launch)` share one launched browser.

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  projects: ['./project-b/rstest.config.ts', './project-a/rstest.config.ts'],
});
```

```ts title="project-a/rstest.config.ts"
import { pluginReact } from '@rsbuild/plugin-react';
import { defineConfig } from '@rstest/core';

export default defineConfig({
  name: 'project-a',
  plugins: [pluginReact()],
  include: ['tests/**/*.test.tsx'],
  browser: {
    enabled: true,
    provider: 'playwright',
  },
});
```

## Mixing with node tests

You can configure both browser tests and Node.js tests together:

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  projects: [
    {
      name: 'browser',
      include: ['src/**/*.browser.test.ts'],
      browser: {
        enabled: true,
        provider: 'playwright',
      },
    },
    {
      name: 'node',
      include: ['src/**/*.node.test.ts'],
      testEnvironment: 'node',
    },
    {
      name: 'jsdom',
      include: ['src/**/*.test.ts'],
      exclude: ['src/**/*.browser.test.ts', 'src/**/*.node.test.ts'],
      testEnvironment: 'jsdom',
    },
  ],
});
```

## Provider options

### Playwright

When using `provider: 'playwright'`, the Playwright provider recognizes the following fields in `providerOptions`:

1. **`launch`** — Passed to Playwright's [`browserType.launch()`](https://playwright.dev/docs/api/class-browsertype#browser-type-launch). Controls how the browser process is started.
2. **`context`** — Passed to Playwright's [`browser.newContext()`](https://playwright.dev/docs/api/class-browser#browser-new-context). Controls the browser context created for each test file.

Since `providerOptions` is typed as `Record<string, unknown>`, you won't get IntelliSense out of the box. To get type checking and autocompletion, import types directly from the `playwright` package and use TypeScript's `satisfies` operator:

```ts title="rstest.config.ts"
import type { LaunchOptions, BrowserContextOptions } from 'playwright';
import { defineConfig } from '@rstest/core';

type PlaywrightProviderOptions = {
  launch?: LaunchOptions;
  context?: BrowserContextOptions;
};

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    providerOptions: {
      launch: {
        timeout: 60_000,
      },
      context: {
        locale: 'en-US',
        colorScheme: 'dark',
      },
    } satisfies PlaywrightProviderOptions,
  },
});
```
