# browser

- **Type:**

```ts

  | {

  | 'iPhoneSE'
  | 'iPhoneXR'
  | 'iPhone12Pro'
  | 'iPhone14ProMax'
  | 'Pixel7'
  | 'SamsungGalaxyS8Plus'
  | 'SamsungGalaxyS20Ultra'
  | 'iPadMini'
  | 'iPadAir'
  | 'iPadPro'
  | 'SurfacePro7'
  | 'SurfaceDuo'
  | 'GalaxyZFold5'
  | 'AsusZenbookFold'
  | 'SamsungGalaxyA51A71'
  | 'NestHub'
  | 'NestHubMax';

type BrowserModeConfig = {
  enabled?: boolean;
  provider: 'playwright';
  /** @deprecated Use `instances` instead. Will be removed in 1.0. */
  browser?: BrowserName;
  headless?: boolean;
  screenshotFailures?: boolean;
  port?: number;
  viewport?: BrowserViewport;
  strictPort?: boolean;
  providerOptions?: Record<string, unknown>;
  /** @default [{ browserName: 'chromium' }] */
  instances?: BrowserInstanceConfig[];
  expect?: BrowserExpectConfig;
};

type BrowserExpectConfig = {
  toMatchScreenshot?: BrowserScreenshotMatcherConfig;
};

type BrowserInstanceConfig = {
  browserName: BrowserName;
  headless?: boolean;
  viewport?: BrowserViewport;
  screenshotFailures?: boolean;

type BrowserScreenshotPathOptions = {

```

- **Default:**

```ts
const defaultBrowser = {
  enabled: false,
  provider: 'playwright',
  instances: [{ browserName: 'chromium' }],
  headless: true, // CI environment; false for local development
  screenshotFailures: true, // Defaults to browser.headless (true in CI, false locally)
  port: undefined, // Random available port
  viewport: undefined, // Browser UI fills the preview panel
  strictPort: false,
  providerOptions: {},
};
```

Configures Browser Mode so tests run in a real browser instead of Node.js.

## Options

### enabled

- **Type:** `boolean`
- **Default:** `false`
- **CLI:** `--browser`, `--browser.enabled`

Enable Browser Mode.

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
  },
});
```

:::tip
Browser Mode requires [@rstest/browser](https://github.com/web-infra-dev/rstest/tree/main/packages/browser), `playwright`, and Playwright browsers:

```bash
npm add @rstest/browser playwright -D
npx playwright install chromium
```

:::

### provider

- **Type:** `'playwright'`
- **Default:** `'playwright'`

Browser driver provider. Currently only [Playwright](https://playwright.dev/) is supported. `provider` is required in `BrowserModeConfig` TypeScript types; at runtime it defaults to `'playwright'`.

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
  },
});
```

### instances

<ApiMeta addedVersion="0.13.0" />

- **Type:** `BrowserInstanceConfig[]`
- **Default:** `[{ browserName: 'chromium' }]`
- **CLI:** `--browser.instances <names>` (comma-separated and/or repeatable; filters the configured instances)

Browser instances this project runs on, one per browser. Every instance in a project shares one build and one dev server, so multi-browser runs do not multiply build time.

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    instances: [{ browserName: 'chromium' }, { browserName: 'firefox' }],
  },
});
```

Each entry is a `BrowserInstanceConfig` object: `browserName` is required, and all other fields override the project-level value for that browser. A bare string such as `instances: ['chromium']` is a config error; write `{ browserName: 'chromium' }`:

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    providerOptions: {
      launch: { slowMo: 100 },
      context: { locale: 'en-US' },
    },
    instances: [
      { browserName: 'firefox' },
      {
        browserName: 'chromium',
        viewport: { width: 800, height: 600 },
        providerOptions: {
          launch: { channel: 'chrome' },
        },
      },
    ],
  },
});
```

`BrowserInstanceConfig` accepts only runtime overrides; build-scoped options (`enabled`, `provider`, `port`, `strictPort`) stay on the project-level `browser` config:

| Field                | Default                              |
| -------------------- | ------------------------------------ |
| `browserName`        | required                             |
| `headless`           | project `browser.headless`           |
| `viewport`           | project `browser.viewport`           |
| `screenshotFailures` | project `browser.screenshotFailures` |
| `expect`             | project `browser.expect`             |
| `providerOptions`    | project `browser.providerOptions`    |

Merge precedence per instance: instance field > project-level `browser.*` > built-in default. `providerOptions` merges per top-level key (`launch`, `context`) rather than deep-merging inside them: setting `launch` on an instance replaces the project `launch` object (Playwright options can contain functions and class instances), while unset keys keep the project value. In the example above, `chromium` launches with `channel: 'chrome'` alone and keeps `locale: 'en-US'` from the project `context`.

Each instance runs the project's test files independently and reports results under its own project label — see [Multi-browser reporting](#multi-browser-reporting).

Validation rules:

- Each `browserName` may appear at most once per project.
- `instances` cannot be empty — omit the option to run the default Chromium instance.
- At most one `(project, browser)` pair may run headed (`headless: false`) per run; see [Launch rules](#launch-rules).
- [`coverage.provider: 'v8'`](/config/test/coverage) requires every selected browser to be Chromium; see [Launch rules](#launch-rules).

### browser (deprecated) \{#browser-deprecated}

<ApiMeta addedVersion="0.13.0" />

:::warning Deprecated
`browser.browser` is deprecated and will be removed in 1.0. Use [`instances`](#instances) instead, e.g. `instances: [{ browserName: 'firefox' }]`. Rstest prints a deprecation warning once per run when this field is set. `--browser.name` is the deprecated CLI form.
:::

- **Type:** `'chromium' | 'firefox' | 'webkit'`
- **Default:** `'chromium'`
- **CLI:** `--browser.name <name>` (deprecated)

Single browser type to use for testing. Normalized to `instances: [{ browserName: browser }]`.

Setting both `browser` and `instances` on a project is a config error.

- `chromium`: Google Chrome, Microsoft Edge
- `firefox`: Mozilla Firefox
- `webkit`: Safari

Install the matching Playwright browser (for example, `npx playwright install firefox`) before running tests.

### headless

- **Type:** `boolean`
- **Default:** `true` in CI environments, `false` for local development
- **CLI:** `--browser.headless`

Run browsers in headless mode (without a UI window). Items in [`instances`](#instances) can override this per browser, subject to the [one headed browser per run](#launch-rules) rule.

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    headless: true,
  },
});
```

Set `headless: process.env.CI === 'true'` if you want headed mode locally and headless mode in CI. See [CI setup](/guide/advanced/ci) for GitHub Actions workflow examples.

### screenshotFailures

<ApiMeta addedVersion="0.12.4" />

- **Type:** `boolean`
- **Default:** `browser.headless`
- **CLI:** `--browser.screenshotFailures`

Capture a PNG screenshot for each failed browser test. Screenshots are saved under `.rstest/screenshots/` in the project root with the test file and test name in the filename. Set to `false` to disable capture.

### viewport

<ApiMeta addedVersion="0.8.4" />

- **Type:** `BrowserViewport`
- **Default:** `undefined`

Default runner iframe viewport for Browser Mode tests. When unset, the Browser UI fills the preview panel. Items in [`instances`](#instances) can override this per browser.

Pass explicit dimensions or a built-in device preset:

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    viewport: { width: 390, height: 844 },
    // Or a device preset:
    // viewport: 'iPhone12Pro',
  },
});
```

### port

- **Type:** `number`
- **Default:** `undefined` (selects an available port automatically)
- **CLI:** `--browser.port <port>`

Port number for the Browser Mode dev server.

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    port: 5173,
  },
});
```

When `port` is already in use, [`strictPort`](#strictport) determines whether Rstest fails or falls back to another available port.

### strictPort

- **Type:** `boolean`
- **Default:** `false`
- **CLI:** `--browser.strictPort`

When `port` is specified, fail if the port is already in use (`true`), or fall back to another available port (`false`).

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    port: 5173,
    strictPort: true,
  },
});
```

### providerOptions

<ApiMeta addedVersion="0.9.3" />

- **Type:** `Record<string, unknown>`
- **Default:** `{}`
- **CLI:** `--browser.providerOptions.*`

Options forwarded as-is to the browser provider for browser launch and context creation. Rstest does not validate or interpret these fields.

Each `BrowserInstanceConfig` in [`instances`](#instances) can define its own `providerOptions`: top-level keys (`launch`, `context`) replace the project-level keys on that instance, while unset keys inherit the project-level values.

See [Playwright provider options](#provider-options) for the supported fields.

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    providerOptions: {
      launch: {
        timeout: 60_000,
      },
    },
  },
});
```

You can also pass nested Playwright options via CLI:

```bash
npx rstest --browser.providerOptions.launch.channel=chrome
```

### expect.toMatchScreenshot

<ApiMeta addedVersion="0.12.4" />

- **Type:** `BrowserScreenshotMatcherConfig`
- **Default:**

```ts
{
  comparatorOptions: {
    threshold: 0.1,
  },
  stabilityTimeout: 5000,
  maskColor: '#FF00FF',
  caret: 'hide',
  scale: 'device',
  omitBackground: false,
}
```

Configures project-wide defaults for [`toMatchScreenshot()`](/api/runtime-api/browser-mode/assertion#toMatchScreenshot). Pixel-comparison tolerances (`threshold`, `maxDiffPixels`, `maxDiffPixelRatio`) belong under `comparatorOptions`; capture and path options (`stabilityTimeout`, `maskColor`, `style`, `caret`, `scale`, `omitBackground`, `screenshotDirectory`, `resolveScreenshotPath`) are siblings of it (`mask` is assertion-only).

Assertion-level options override these defaults; see [`toMatchScreenshot()`](/api/runtime-api/browser-mode/assertion#toMatchScreenshot) for per-option defaults and pixel-limit precedence.

A relative `screenshotDirectory` resolves from each test file's directory (defaulting to `__screenshots__`). When a shared directory is used, Rstest separates references by project name and test file; when the chosen directory is the test file's own directory, references are placed in its `__screenshots__` subdirectory.

Default reference path layout:

```text
<test-directory>/__screenshots__/<test-file>/<reference-name>-<browser>-<platform>.png
```

The reference name comes from the explicit name or the sanitized test name (with a stable suffix if sanitization could collide). Every unnamed assertion receives a sequence number starting at `1` (for example, `<test-name>-1`), even when a test has only one screenshot; explicitly named assertions have no sequence number.

Because project names are not included in the default layout, projects sharing a test file, screenshot name, browser, and platform share one reference. Use `resolveScreenshotPath` to isolate per-project references. Existing references from Rstest's previous hashed layout are not migrated automatically—move them or regenerate them with `--update`.

`resolveScreenshotPath` receives the absolute test file path, project and test names, browser, platform, and an optional ordinal for unnamed assertions (`undefined` for the first unnamed assertion, starting at `2` afterward). Return an absolute path or a path relative to the project root. When set, it takes precedence over `screenshotDirectory`.

```ts title="rstest.config.ts"
import path from 'node:path';
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    expect: {
      toMatchScreenshot: {
        comparatorOptions: {
          threshold: 0.1,
          maxDiffPixels: 10,
        },
        resolveScreenshotPath: ({
          testFilePath,
          projectName,
          testName,
          browserName,
          platform,
        }) =>
          path.join(
            'visual-baselines',
            projectName,
            path.relative(process.cwd(), testFilePath),
            `${testName}-${browserName}-${platform}.png`,
          ),
      },
    },
  },
});
```

## Launch rules

Each `rstest` run launches one browser process per unique `(provider, browserName, headless, providerOptions.launch)` combination across all Browser Mode projects. Projects with matching launch keys share one browser instance; differing `providerOptions.launch` or `headless` values produce separate launches. Within a project, all browsers share one build and one dev server.

Browsers launch on demand when the first test file needs them, so a broken launch (such as a missing executable) fails when that file runs. At most [`pool.maxWorkers`](/config/test/pool#poolmaxworkers) headless browsers stay open concurrently; when another launch needs a slot, the least recently used idle browser closes. In watch mode, idle browsers remain open between runs until a slot is needed. Headed browsers are not counted against this limit and stay open for the entire run.

Before any browser launches, Rstest validates:

- **One headed browser per run.** Browser Mode opens a single debug window, so at most one `(project, browser)` pair may set `headless: false`; all others must use `headless: true`:

  > Only one (project, browser) pair can run headed per run: "web" ("chromium"). Browser mode opens one debug window, so every other browser must set headless: true. Most often this comes from `--browser.headless=false` on a multi-browser run: select a single headless pair with `--browser.instances <name>` or narrow the projects with `--project`.

- **Watch mode cannot mix headed and headless browsers.** If one browser is headed and another is headless, watch mode rejects the run during validation; set `headless: true` on all browsers or run without watch mode.

- **Coverage provider `v8` requires Chromium.** With `coverage.enabled` and `coverage.provider: 'v8'`, selecting any non-Chromium browser fails validation. Switch to `coverage.provider: 'istanbul'`, or filter to Chromium (`--browser.instances chromium`).

To collect coverage or run tests per browser separately (for example, in a CI matrix), filter with `--browser.instances`:

```bash
npx rstest --browser.instances chromium
npx rstest --browser.instances firefox
npx rstest --browser.instances webkit
```

## CLI browser filters

`--browser.instances <names>` (repeatable and/or comma-separated) filters configured instances by `browserName`, like `--project`; it never creates new instances. The default Chromium instance (when `instances` is omitted) and an instance from the deprecated `browser.browser` field count as configured instances.

- A browser project with no matching instances is skipped for the run; Node projects are unaffected.
- Listing a browser name that no selected browser project configures throws an error naming the invalid name and each project's configured browsers.
- Duplicate names and names other than `chromium`, `firefox`, and `webkit` are errors.

`--browser.name <name>` remains as a deprecated alias and prints a deprecation warning once per run. It selects that single browser (reusing the matching configured `instances` entry's overrides if present, or project-level defaults otherwise) and cannot be combined with `--browser.instances`.

## Multi-browser reporting

Reporters are browser-agnostic. When a project runs more than one browser, each `(project, browser)` pair reports as its own project named `<project> (<browserName>)`, such as `web (chromium)` and `web (firefox)`. A project running a single browser keeps its configured name.

- Reporter payloads, `rstest list` output, and blob reports use this name as `project`, so running one file across two browsers produces two distinct results (for example, `✓ [web (chromium)] tests/basic.test.ts`).
- This naming is reporting-only: all browsers in a project still share one build and one dev server, and `--project` filters by the configured project name.
- Configured project names must not collide with a generated `<project> (<browserName>)` name; collisions are a config error.

## Multi-project config isolation

With `projects` in Browser Mode, each project compiles and runs with its own build config (`plugins`, `include`, framework setup, etc.). Build-scoped options (`provider`, `port`, `strictPort`) remain per-project, while instances, defaults, and per-browser overrides (`instances`, `headless`, `viewport`, `screenshotFailures`, `expect`, `providerOptions`) are owned by each project. See [Projects in browser mode](/guide/basic/projects#projects-in-browser-mode) for a multi-project config example.

## Mixing with node tests

Browser tests and Node.js tests can run together in one config:

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  projects: [
    {
      name: 'browser',
      include: ['src/**/*.browser.test.ts'],
      browser: {
        enabled: true,
        provider: 'playwright',
      },
    },
    {
      name: 'node',
      include: ['src/**/*.node.test.ts'],
      testEnvironment: 'node',
    },
  ],
});
```

## Provider options

### Playwright

With `provider: 'playwright'`, `providerOptions` recognizes:

1. **`launch`** — Passed to Playwright's [`browserType.launch()`](https://playwright.dev/docs/api/class-browsertype#browser-type-launch) to control browser process startup.
2. **`context`** — Passed to Playwright's [`browser.newContext()`](https://playwright.dev/docs/api/class-browser#browser-new-context) to control the browser context created for each test file.

Because `providerOptions` is typed as `Record<string, unknown>`, import Playwright's types and use `satisfies` for IntelliSense and type checking:

```ts title="rstest.config.ts"
import type { LaunchOptions, BrowserContextOptions } from 'playwright';
import { defineConfig } from '@rstest/core';

type PlaywrightProviderOptions = {
  launch?: LaunchOptions;
  context?: BrowserContextOptions;
};

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    providerOptions: {
      launch: {
        timeout: 60_000,
      },
      context: {
        locale: 'en-US',
        colorScheme: 'dark',
      },
    } satisfies PlaywrightProviderOptions,
  },
});
```
