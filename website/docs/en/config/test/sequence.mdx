# sequence

<ApiMeta addedVersion="0.12.6" />

- **Type:** `{ hooks?: 'stack' | 'list' }`
- **Default:** `{ hooks: 'stack' }`

Configure the execution order of Rstest lifecycle hooks.

## sequence.hooks

- **Type:** `'stack' | 'list'`
- **Default:** `'stack'`

Controls the order of hooks within each suite:

- `'stack'`: `beforeAll` and `beforeEach` run in declaration order; `afterAll` and `afterEach` run in reverse declaration order.
- `'list'`: all four hooks run in declaration order. Use this when migrating from Jest if cleanup depends on hook registration order, such as unmounting components before resetting stores.

For nested suites, `beforeEach` still runs from parent to child, and `afterEach` still runs from child to parent. This option does not change cleanup callbacks returned by `beforeAll` or `beforeEach`, fixture teardown, `onTestFinished`, or `onTestFailed`.

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  sequence: {
    hooks: 'list',
  },
});
```
