# projects

- **Type:**

```ts
import type { ProjectConfig } from '@rstest/core';

type InlineProjectConfig = ProjectConfig & { name: string };

type Projects = (string | InlineProjectConfig)[];
```

- **Default:** `undefined` (runs the root directory as a single project)

Run multiple test projects in a single Rstest process and combine all results in the output. Each entry in the array can be a directory path, config file path, glob pattern, or inline project configuration object.

```ts title="rstest.config.ts"
import { defineConfig, defineInlineProject } from '@rstest/core';

export default defineConfig({
  projects: [
    // Monorepo: each package directory is a project
    'packages/*',

    // All projects under apps/ that provide an rstest config file
    'apps/**/rstest.config.ts',

    // Specific project directory
    '<rootDir>/services/auth',

    // Specific project config file
    './projects/web/rstest.config.ts',

    // Inline project configs
    defineInlineProject({
      name: 'node',
      include: ['tests/node/**/*.{test,spec}.{js,cjs,mjs,ts,tsx}'],
    }),
    defineInlineProject({
      name: 'react',
      include: ['tests/react/**/*.{test,spec}.{js,cjs,mjs,ts,tsx}'],
      testEnvironment: 'jsdom',
    }),
  ],
});
```

Use `defineInlineProject()` for object items in any `projects` array, including nested `projects`. Use `defineProject()` only for the top-level export of a project config file.

`defineProject()` can omit `name` on the exported project and let Rstest infer it using the [name](/config/test/name) option rules. `defineInlineProject()` requires `name` for each inline project item.

To run only specific projects from the command line, pass `--project <name>` (supports wildcards). See [Test projects](/guide/basic/projects) for sharing configs, global options, and nested projects.
