# resolve

Options for module resolution.

## resolve.aliasStrategy <RsbuildDocBadge path="/config/resolve/alias-strategy" text="resolve.aliasStrategy" />

- **Type:** `'prefer-tsconfig' | 'prefer-alias'`
- **Default:** `'prefer-tsconfig'`

Controls precedence between `resolve.alias` and `compilerOptions.paths` in `tsconfig.json`:

- `'prefer-tsconfig'`: `tsconfig.json` `paths` take precedence over `resolve.alias`.
- `'prefer-alias'`: `resolve.alias` takes precedence over `tsconfig.json` `paths`.

## resolve.alias <RsbuildDocBadge path="/config/resolve/alias" text="resolve.alias" />

- **Type:** `ConfigChain<Record<string, string | false | (string | false)[]>>`
- **Default:** `{}`

Redirects or simplifies module import paths, matching Rspack's [resolve.alias](https://rspack.rs/config/resolve#resolvealias).

For TypeScript projects, Rstest automatically reads `compilerOptions.paths` from `tsconfig.json`, so you do not need to duplicate those mappings in `resolve.alias`.

## resolve.dedupe <RsbuildDocBadge path="/config/resolve/dedupe" text="resolve.dedupe" />

- **Type:** `string[]`
- **Default:** `undefined`

Forces Rstest to resolve the specified packages from the project root, preventing duplicate package copies in the bundle.

## resolve.extensions <RsbuildDocBadge path="/config/resolve/extensions" text="resolve.extensions" />

- **Type:** `string[]`
- **Default:** `['.ts', '.tsx', '.mjs', '.js', '.jsx', '.json', '.cjs']`

File extensions resolved automatically when importing modules without an explicit extension. Rstest inherits Rsbuild's defaults and appends `.cjs`.

## resolve.conditionNames <RsbuildDocBadge path="/config/resolve/condition-names" text="resolve.conditionNames" />

- **Type:** `string[]`
- **Default:** Depends on the test environment and dependency type.

Controls the condition names used when resolving a package's `exports` field.

For `node`, `jsdom`, and `happy-dom` tests, Rstest inherits Rspack's default conditions. With the default `NODE_ENV=test`, bundled JavaScript dependencies use:

| Test environment      | ESM `import`                                                    | CommonJS `require`                                               |
| --------------------- | --------------------------------------------------------------- | ---------------------------------------------------------------- |
| `node`                | `import`, `module`, `webpack`, `development`, `node`            | `require`, `module`, `webpack`, `development`, `node`            |
| `jsdom` / `happy-dom` | `browser`, `import`, `module`, `webpack`, `development`, `node` | `browser`, `require`, `module`, `webpack`, `development`, `node` |

Rstest treats `NODE_ENV=test` as development mode for bundling, so `development` is active even though `NODE_ENV` is `'test'`. The package's `exports` key order determines which matching entry wins, rather than the order of `conditionNames`.

When customizing this option, include `'...'` to keep Rspack's default conditions—for example, `conditionNames: ['custom', '...']` in `node` tests, or `conditionNames: ['browser', 'custom', '...']` in `jsdom` / `happy-dom` tests. Once this option is set explicitly, Rstest no longer adds `browser` automatically.

Providing a list without `'...'` replaces the defaults across all dependency types, including the distinction between `import` and `require`.

To remove a default condition while keeping separate ESM and CommonJS resolution, configure `tools.rspack.resolve.byDependency`. See the [Jest migration example](/guide/migration/jest#dependency-export-conditions), which excludes `development` and explains when to include `browser`.

## resolve.mainFields <RsbuildDocBadge path="/config/resolve/main-fields" text="resolve.mainFields" />

- **Type:** `string[]`
- **Default:** `['main']` (`node`); `['module', 'main']` (`jsdom` / `happy-dom`); `['browser', 'module', 'main']` (Browser Mode)

Controls the priority order of `package.json` entry fields such as `main`, `module`, and `browser`.

- In the `node` test environment, Rstest strips `'module'` from `mainFields` (defaulting to `['main']`) because a package's `module` entry is not always native Node ESM.
- For CommonJS `require` calls across `node`, `jsdom`, and `happy-dom`, Rstest also prepends `'main'` to `resolve.byDependency.commonjs.mainFields`.
