# Rslint

[Rslint](https://rslint.rs/) is an ESLint-compatible linter for JavaScript and TypeScript. Its built-in `rstestPlugin` checks Rstest test definitions, assertions, mocks, and snapshots for common mistakes.

Install [@rslint/core](https://github.com/web-infra-dev/rslint) as a dev dependency:

import { PackageManagerTabs } from '@theme';

<PackageManagerTabs command="add @rslint/core -D" />

## Presets

`rstestPlugin.configs` exports four presets:

| Preset        | Contents                                                                                      |
| ------------- | --------------------------------------------------------------------------------------------- |
| `recommended` | 17 rules covering common mistakes in test structure, assertions, mocks, and snapshots         |
| `style`       | 3 stylistic rules (`prefer-to-be`, `prefer-to-contain`, `prefer-to-have-length`)              |
| `all`         | All Rstest rules (mostly enabled as warnings)                                                 |
| `env`         | Declares Rstest global APIs (`describe`, `test`, `it`, `expect`, `rs`, `rstest`, hooks, etc.) |

If you enable [`globals: true`](/config/test/globals) in Rstest, include `rstestPlugin.configs.env` so Rslint recognizes global test APIs without explicit imports:

```ts title="rslint.config.ts"
import { defineConfig, rstestPlugin } from '@rslint/core';

export default defineConfig([
  {
    ...rstestPlugin.configs.recommended,
    ...rstestPlugin.configs.env,
    files: ['**/*.{test,spec}.{js,jsx,ts,tsx,cjs,cts,mjs,mts}'],
  },
]);
```

## Dedicated test files

If your tests live in dedicated `*.test.*` or `*.spec.*` files, scope the preset with `files`:

```ts title="rslint.config.ts"
import { defineConfig, rstestPlugin } from '@rslint/core';

export default defineConfig([
  {
    ...rstestPlugin.configs.recommended,
    files: ['**/*.{test,spec}.{js,jsx,ts,tsx,cjs,cts,mjs,mts}'],
  },
]);
```

None of the `rstestPlugin` presets declare a `files` pattern by default, so adding `files` keeps Rstest rules scoped to test files without affecting production code.

## In-source tests

With [in-source testing](/config/test/include-source), tests live inside production files and use `import.meta.rstest`. Apply the preset without restricting `files` so Rslint checks both in-source and dedicated tests:

```ts title="rslint.config.ts"
import { defineConfig, rstestPlugin } from '@rslint/core';

export default defineConfig([rstestPlugin.configs.recommended]);
```

No extra globals configuration is required for `import.meta.rstest`.

## Run Rslint

Run Rslint from your project root:

<PackageManagerTabs command="exec rslint" />

A passing run prints a summary like this:

```text
start   Linting...
success Lint passed in 92ms (1 file, 17 rules, 14 threads)
```

When a rule fails, Rslint prints the rule name, source location, code frame, and summary:

```text
start   Linting...

  rstest/no-identical-title  — [error] Test title is used multiple times in the same describe block
  ╭─┴──────────( invalid.test.ts:8:8 )─────
  │ 7 │
  │ 8 │  test('same title', () => {
  │ 9 │    expect(false).toBeFalsy();
  ╰────────────────────────────────

error   Lint failed with 1 error in 31ms (1 file, 17 rules, 14 threads)
```

You can also add `rslint` to `scripts` in `package.json` and run it through your package manager's lint script.
