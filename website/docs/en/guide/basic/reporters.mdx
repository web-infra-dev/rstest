# Reporters

Reporters control how Rstest formats and outputs test results. Use built-in reporters for terminal output, CI annotations, or machine-readable artifacts, or load a custom reporter for your own workflow.

## Using reporters

Configure reporters via `--reporters=<name>` (`--reporter` alias, repeatable) on the CLI or [reporters](/config/test/reporters) in `rstest.config.ts`. See [reporters configuration](/config/test/reporters) for all config shapes and combinations.

## Built-in reporters

| Reporter         | Purpose                    | Use case                 |
| ---------------- | -------------------------- | ------------------------ |
| `default`        | Console output with colors | Local development        |
| `dot`            | Compact per-test markers   | Fast local feedback      |
| `verbose`        | Detailed test case output  | Debugging test failures  |
| `github-actions` | CI error annotations       | GitHub Actions workflows |
| `junit`          | JUnit XML format           | CI/CD integration        |
| `json`           | Structured JSON report     | CI tooling and scripting |
| `md`             | Markdown agent report      | Agent / LLM integrations |
| `blob`           | Serialized JSON output     | Merging sharded reports  |

### Default reporter

Displays test run status, failures, and a summary in the terminal with colored output.

**Output example:**

```bash
 ✓ test/index.test.ts (2)

 Test Files 1 passed
      Tests 2 passed
   Duration 112ms (build 19ms, tests 93ms)
```

**Options:**

| Option            | Type      | Default                                                      | Description                                         |
| ----------------- | --------- | ------------------------------------------------------------ | --------------------------------------------------- |
| `summary`         | `boolean` | `true`                                                       | Display failure details and the run summary footer. |
| `showProjectName` | `boolean` | `true` for multi-project or multi-browser runs, else `false` | Print `[project]` before each test file path.       |

#### Progress reporting

The default reporter adapts progress output to the terminal type:

**TTY environments (interactive terminal)**

Updates a live status footer at the bottom of the terminal every second with active test files and any test case running longer than 2 seconds, then clears it when the run finishes:

```bash
 RUNS  src/database.test.ts
   > should handle concurrent writes 5s

 Test Files 12 passed | 1 running
      Tests 45 passed
   Duration 30s
```

**Non-TTY environments (CI, piped output, AI agents)**

Emits a progress log whenever there has been no console output for 30 seconds, including cases running longer than 10 seconds. Progress logging stops after 20 reports (~10 minutes of idle time) so truly stuck runs still trigger CI timeouts:

```bash
[PROGRESS] test files: 20 done, 4 running | tests: 380 passed, 3 failed | 2m 30s
            Running: src/heavy.test.ts > database > concurrent writes 45s
            Running: src/other.test.ts
```

### Verbose reporter

Extends the default reporter to list every test case, including passing ones, and breaks down environment prebundle duration inside build time when pre-bundling runs.

<Tabs defaultValue='rstest.config.ts'>
  <Tab label="CLI">
```bash
npx rstest --reporters=verbose
```
  </Tab>
  <Tab label="rstest.config.ts">
```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: 'verbose',
});
```
  </Tab>
</Tabs>

**Output example:**

```bash
 ✓ test/index.test.ts (2) 2ms
  ✓ Index > should add two numbers correctly (1ms)
  ✓ Index > should test source code correctly (1ms)

 Test Files 1 passed
      Tests 2 passed
   Duration 112ms (build 19ms, tests 93ms)
```

**Options:** Accepts `showProjectName` (same as [Default reporter](#default-reporter); the summary footer is always shown).

### Dot reporter

<ApiMeta addedVersion="0.9.7" />

Emits one character per test case as it finishes:

- `·` for passed tests
- `x` for failed tests
- `-` for skipped tests
- `*` for todo tests

<Tabs defaultValue='rstest.config.ts'>
  <Tab label="CLI">
```bash
npx rstest --reporters=dot
```
  </Tab>
  <Tab label="rstest.config.ts">
```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: 'dot',
});
```
  </Tab>
</Tabs>

After the marker stream, it prints the failure details and duration summary unless `summary: false` is set.

**Options:** Accepts `summary` (default: `true`; same as [Default reporter](#default-reporter)).

### GitHub Actions reporter

Emits [GitHub Actions workflow commands](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-commands#setting-an-error-message) for failed tests so errors annotate the pull request diff in CI.

Failed assertions emit workflow commands like:

```bash
::error file=src/index.ts,line=4,col=17,title=test/index.test.ts > should add two numbers correctly::expected 2 to be 4
```

When an error has a `cause`, each error in the cause chain is appended to the message as `Caused by: <name>: <message>`.

![rstest-github-actions-example](https://assets.rspack.rs/rstest/assets/rstest-github-actions-example.jpg)

When `GITHUB_STEP_SUMMARY` is set, Rstest appends a collapsible Markdown summary (`✅` collapsed by default on clean passes, `⚠️` expanded when flaky tests passed on retry, or `❌` expanded on failure) containing:

- A summary table (`Test Files`, `Tests`, `Duration`, and `Flaky Tests` when present)
- Up to 20 flaky tests that passed after retries, with previous failure summaries
- Up to 20 failures with error message, diff, stack trace (including each error in the `cause` chain), and a repro command per test
- The project root path shortened relative to `GITHUB_WORKSPACE` as `<ROOT>/...` when inside the workspace

#### Auto-enablement

When no reporter is explicitly set in config or via CLI flags, Rstest enables `['default', 'github-actions']` whenever `process.env.GITHUB_ACTIONS === 'true'`.

#### Manual enablement

<Tabs defaultValue='rstest.config.ts'>
  <Tab label="CLI">
```bash
npx rstest --reporters=github-actions
```
  </Tab>
  <Tab label="rstest.config.ts">
```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: ['github-actions'],
});
```
  </Tab>
</Tabs>

#### Options

| Option        | Type                                       | Default | Description                                               |
| :------------ | :----------------------------------------- | :------ | :-------------------------------------------------------- |
| `annotations` | `boolean`                                  | `true`  | Whether to output `::error` annotations for failed tests. |
| `summary`     | `boolean \| { maxCharsPerField?: number }` | `true`  | Controls Markdown summary output and per-field length.    |

<ApiMeta addedVersion="0.11.6" />

`summary.maxCharsPerField` defaults to `400` and caps each failure message, diff, and unhandled error message/stack. GitHub limits a step summary to [1 MiB](https://docs.github.com/en/actions/writing-workflows/choosing-what-your-workflow-does/workflow-commands-for-github-actions#step-isolation-and-limits), so keep this bounded. Set `summary: false` to disable the step summary.

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: [
    [
      'github-actions',
      {
        annotations: true,
        summary: {
          maxCharsPerField: 2_000,
        },
      },
    ],
  ],
});
```

### JUnit reporter

Generates test reports in JUnit XML format for CI/CD integration and test result aggregation.

<Tabs defaultValue='rstest.config.ts'>
  <Tab label="CLI">
```bash
npx rstest --reporters=junit
```
  </Tab>
  <Tab label="rstest.config.ts">
```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: [['junit', { outputPath: './junit.xml' }]],
});
```
  </Tab>
</Tabs>

**Options:**

- `outputPath`: `string` — Output file path (defaults to stdout).

Generated XML structure:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<testsuites name="rstest tests" tests="3" failures="1" errors="0" skipped="1" time="0.3" timestamp="2024-01-01T00:00:00.000Z">
  <testsuite name="test1.test.ts" tests="3" failures="1" errors="0" skipped="1" time="0.3" timestamp="2024-01-01T00:00:00.000Z">
    <testcase name="should pass" classname="test1.test.ts" time="0.1">
    </testcase>
    <testcase name="should fail" classname="test1.test.ts" time="0.2">
      <failure message="Test failed" type="AssertionError">expected 'hi' to be 'hii' // Object.is equality - Expected + Received - hii + hi at test1.test.ts:10:21</failure>
    </testcase>
    <testcase name="should skip" classname="test1.test.ts" time="0.0">
      <skipped/>
    </testcase>
  </testsuite>
</testsuites>
```

Status mapping:

- `passed`: Empty `<testcase>` element
- `failed`: `<failure>` element inside `<testcase>`
- `skipped` / `todo`: `<skipped/>` element inside `<testcase>`
- File-level errors (load errors or `beforeAll`/`afterAll` failures): Adds a `<testcase>` with an `<error>` element and increments `errors`
- Top-level `unhandledErrors`: Adds `<testsuite name="rstest unhandled errors">` with `<system-err>` and increments `errors`

### JSON reporter

<ApiMeta addedVersion="0.9.6" />

Generates a structured JSON document for CI tooling, dashboards, or post-processing scripts.

<Tabs defaultValue='rstest.config.ts'>
  <Tab label="CLI">
```bash
npx rstest --reporters=json
```
  </Tab>
  <Tab label="rstest.config.ts">
```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: [['json', { outputPath: './reports/rstest.json' }]],
});
```
  </Tab>
</Tabs>

**Options:**

- `outputPath`: `string` — Output file path (defaults to stdout).

**Output shape:**

- `tool`: Always `'rstest'`
- `version`: Rstest version string
- `status`: Overall run status (`'passed' | 'failed' | 'error'`)
- `summary`: Counts for test files and tests (`testFiles`, `failedFiles`, `tests`, `failedTests`, `passedTests`, `skippedTests`, `todoTests`)
- `durationMs`: `{ total, build, prebundle?, tests }` in milliseconds (`prebundle` appears when environment packages are pre-bundled; `total` reflects elapsed time when multi-project builds and tests overlap; see [onTestRunEnd](/api/javascript-api/reporter#ontestrunend))
- `snapshot`: Snapshot summary from the run
- `files`: Test-file results with nested test cases
- `tests`: Flattened test-case results, each with `fullName`
- `consoleLogs`: Captured user console output (omitted when no logs were captured)
- `unhandledErrors`: Array of top-level unhandled errors (`[]` when none occurred)

`testPath` values are written relative to the root directory so reports remain consistent across machines and CI workspaces.

### Markdown reporter

Outputs a single structured Markdown document to stdout for AI agents and LLMs.

When no reporter is explicitly configured in the config file or CLI flags, Rstest automatically enables `['md']` inside AI agent environments. Set `RSTEST_NO_AGENT=1` to disable agent detection and keep the default console reporter.

The default preset is `normal`:

- Each failure includes a repro command (`file+name`) to rerun the single failing test.
- Stack traces default to `'top'` (only the top frame) to save tokens.
- Console output is enabled and capped per test path and per entry.
- When failures exceed `failures.max`, Rstest prints a minimal `Failure List` for all failures (`type`, `message`, `expected`, `actual`, `repro`) and expands full `Failure Details` only for the first `failures.max` items.

Presets control how much failure context is expanded:

| Preset    | Best for                                  | Failure details                      | Console logs                                          | Code frames                  |
| --------- | ----------------------------------------- | ------------------------------------ | ----------------------------------------------------- | ---------------------------- |
| `normal`  | Default agent workflows                   | `stack: 'top'`, `failures.max: 50`   | Enabled, max 10 logs per test path, 500 chars/entry   | Enabled, 2 lines above/below |
| `compact` | CI logs, agent loops, tight token budgets | `stack: 'top'`, `failures.max: 20`   | Disabled                                              | Disabled                     |
| `full`    | Deep debugging with maximum context       | `stack: 'full'`, `failures.max: 200` | Enabled, max 200 logs per test path, 5000 chars/entry | Enabled, 3 lines above/below |

<Tabs defaultValue='rstest.config.ts'>
  <Tab label="CLI">
```bash
npx rstest --reporters=md
```
  </Tab>
  <Tab label="rstest.config.ts">
```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: ['md'],
});
```
  </Tab>
</Tabs>

#### Options

| Option           | Type                                                                    | Default                                             | Description                                                                      |
| ---------------- | ----------------------------------------------------------------------- | --------------------------------------------------- | -------------------------------------------------------------------------------- |
| `preset`         | `'normal' \| 'compact' \| 'full'`                                       | `'normal'`                                          | Output detail preset.                                                            |
| `header`         | `boolean \| { env?: boolean }`                                          | `{ env: true }`                                     | Controls `runtime` metadata (`node`, `platform`, `cwd`) in YAML frontmatter.     |
| `reproduction`   | `boolean \| 'file' \| 'file+name'`                                      | `'file+name'`                                       | Controls per-failure repro commands (`true` maps to `'file+name'`).              |
| `testLists`      | `'auto' \| 'always'`                                                    | `'auto'`                                            | Print Passed/Skipped/Todo lists (`'auto'` prints only for passing focused runs). |
| `failures`       | `{ max?: number }`                                                      | `{ max: 50 }`                                       | Maximum number of failures with expanded details.                                |
| `codeFrame`      | `boolean \| { linesAbove?: number; linesBelow?: number }`               | `{ linesAbove: 2, linesBelow: 2 }`                  | Code frame context around the top error frame.                                   |
| `stack`          | `number \| false \| 'full' \| 'top'`                                    | `'top'`                                             | Stack frames to include (`'full'` caps at 50 frames).                            |
| `candidateFiles` | `boolean \| { max?: number }`                                           | `{ max: 5 }`                                        | Best-effort suspect files extracted from stack traces.                           |
| `console`        | `boolean \| { maxLogsPerTestPath?: number; maxCharsPerEntry?: number }` | `{ maxLogsPerTestPath: 10, maxCharsPerEntry: 500 }` | Captured console logs per failure.                                               |
| `errors`         | `boolean \| { unhandled?: boolean }`                                    | `{ unhandled: true }`                               | Include the `## Unhandled Errors` section.                                       |

#### Output structure

Each report starts with YAML frontmatter and `# Rstest Test Execution Report`, followed by `## Summary`, optional `## Tests` (on focused passing runs or `testLists: 'always'`), `## Failures`, and `## Unhandled Errors` when applicable. When all tests pass on a full run, `## Failures` omits test lists for brevity; when tests fail, each failure includes a `repro` command, JSON `details`, and `diff`:

````md
## Summary

```json
{
  "status": "failed",
  "counts": {
    "testFiles": 1,
    "failedFiles": 1,
    "tests": 1,
    "failedTests": 1,
    "passedTests": 0,
    "skippedTests": 0,
    "todoTests": 0
  },
  "durationMs": { "total": 84, "build": 18, "tests": 66 }
}
```

## Failures

### [F01] tests/math.test.ts :: math > adds numbers

repro:

```bash
pnpm exec rstest 'tests/math.test.ts' --testNamePattern 'math > adds numbers'
```

diff:

```diff
- Expected
+ Received

- 3
+ 2
```
````

Override preset fields directly to tune payload size:

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: [
    [
      'md',
      {
        preset: 'compact',
        failures: { max: 20 },
        reproduction: 'file+name',
      },
    ],
  ],
});
```

### Blob reporter

<ApiMeta addedVersion="0.9.3" />

Serializes test results into JSON files for later merging with [`rstest merge-reports`](/guide/basic/cli#rstest-merge-reports). Designed for [test sharding](/guide/basic/cli#sharding-tests) in CI; not supported in watch mode.

<Tabs defaultValue='CLI'>
  <Tab label="CLI">
```bash
npx rstest run --shard 1/3 --reporters=blob
```
  </Tab>
  <Tab label="rstest.config.ts">
```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: ['blob'],
});
```
  </Tab>
</Tabs>

**Options:**

- `outputDir`: `string` — Directory to store blob report files (default: `.rstest-reports`).

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: [['blob', { outputDir: './custom-blob-output' }]],
});
```

With coverage enabled, each blob stores only that shard's coverage; providers with deferred finalization skip report generation and threshold checks until [`rstest merge-reports`](/guide/basic/cli#rstest-merge-reports) runs across all blobs. Keep coverage finalization options in `rstest.config.ts` or repeat them on `merge-reports`, and see [split tests with shards](/guide/advanced/ci#split-tests-with-shards) for a full CI workflow.

## Custom reporters

Pass a module specifier (`'./custom-reporter.js'` or `['./custom-reporter.js', options]`) whose default export is a `Reporter` class, or pass a constructed `Reporter` instance; passing a class constructor directly is not supported. Node 22.18+ / 24 loads `.ts` and `.mts` reporter modules directly with type stripping.

See the [Reporter API reference](/api/javascript-api/reporter) for lifecycle hooks, configuration examples, and payload types.
