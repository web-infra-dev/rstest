# Mocking

Mocking replaces dependencies in tests, controls return values, and records how functions or modules are called. All mocking, stubbing, and timer APIs live on `rs` (an alias for `rstest`) imported from `@rstest/core` or injected via [`globals`](/config/test/globals); Rstest does not provide `vi` or `jest` globals.

## Mock modules

Module mocking works the same in Node mode and [browser mode](/guide/browser-testing). Choose an API based on how the dependency is loaded and when the mock should take effect.

### Mock ESM modules

For dependencies loaded through `import`, use [rs.mock()](/api/runtime-api/rstest/mock-modules#rsmock) or [rs.doMock()](/api/runtime-api/rstest/mock-modules#rsdomock).

#### Use `rs.mock()`

`rs.mock()` is hoisted to the top of the file so static `import` statements receive the mocked module before the module under test runs. Factory functions must be synchronous; returning a `Promise` throws an error.

```ts title="user-service.test.ts"
import { expect, rs, test } from '@rstest/core';
import { loadUserName } from './user-service';
import { fetchUser } from './api';

rs.mock('./api', () => ({
  fetchUser: rs.fn().mockResolvedValue({ id: '1', name: 'Alice' }),
}));

test('returns the fetched user name', async () => {
  await expect(loadUserName('1')).resolves.toBe('Alice');
  expect(fetchUser).toHaveBeenCalledWith('1');
});
```

Pass a dynamic `import()` (`Promise<T>`) as the first argument to enable IDE type inference on the factory return value without changing runtime behavior:

```ts
rs.mock(import('./api'), () => ({
  fetchUser: rs.fn().mockResolvedValue({ id: '1', name: 'Alice' }),
}));
```

If you share mock registration through a separate module and your project declares `sideEffects: false`, mark that registration module as having side effects so the build keeps it. See [Module side effects](/guide/advanced/side-effects).

#### Use `rs.doMock()`

`rs.doMock()` is not hoisted and only affects `import()` calls that run after it. Use it when earlier `import` statements should keep the real implementation and later ones should use the mock:

```ts title="feature.test.ts"
import { expect, rs, test } from '@rstest/core';
import { readFeatureFlag } from './feature';

test('only mocks later imports', async () => {
  expect(readFeatureFlag()).toBe('real');

  rs.doMock('./feature', () => ({
    readFeatureFlag: () => 'mocked',
  }));

  const { readFeatureFlag: mockedReadFeatureFlag } = await import('./feature');
  expect(mockedReadFeatureFlag()).toBe('mocked');
});
```

### Share values with a hoisted mock factory

Because `rs.mock()` is hoisted, its factory cannot read variables initialized later during normal module execution. Use [rs.hoisted()](/api/runtime-api/rstest/mock-modules#rshoisted) when the factory and test assertions share the same mock function or value:

```ts title="api.test.ts"
import { expect, rs, test } from '@rstest/core';
import { fetchUser } from './api';

const mocks = rs.hoisted(() => ({
  fetchUser: rs.fn().mockResolvedValue({ id: '1', name: 'Alice' }),
}));

rs.mock('./api', () => ({ fetchUser: mocks.fetchUser }));

test('shares the mock with the factory', async () => {
  await fetchUser('1');
  expect(mocks.fetchUser).toHaveBeenCalledWith('1');
});
```

### Mock CommonJS modules

Use [rs.mockRequire()](/api/runtime-api/rstest/mock-modules#rsmockrequire) or [rs.doMockRequire()](/api/runtime-api/rstest/mock-modules#rsdomockrequire) to target the CommonJS entry loaded through `require()`. When both `import` and `require()` resolve to the same bundled module, `rs.mock()` applies to `require()` as well; when a package exposes separate ESM and CommonJS entries, mocking one entry does not affect the other.

These APIs also work in browser tests, though ESM APIs (`rs.mock` / `rs.doMock`) are preferred there.

#### Use `rs.mockRequire()`

`rs.mockRequire()` is hoisted to the top of the file for file-level mocking of CommonJS modules:

```js title="math.test.cjs"
const { expect, rs, test } = require('@rstest/core');
const { sum } = require('./math.cjs');

rs.mockRequire('./math.cjs', () => ({
  sum: (a, b) => a + b + 100,
}));

test('mocks a CommonJS module loaded with require', () => {
  expect(sum(1, 2)).toBe(103);
});
```

#### Use `rs.doMockRequire()`

`rs.doMockRequire()` is not hoisted and only affects `require()` calls that run after it.

### Auto-mock modules

To replace a module's exported functions with mock functions and configure selected exports inside each test, call `rs.mock()` with only the module path. Rstest checks for a matching manual mock in `__mocks__` first and falls back to auto-mocking when none exists. Pass `{ mock: true }` to skip the `__mocks__` lookup and request auto-mocking directly:

```ts title="math.test.ts"
import { expect, rs, test } from '@rstest/core';
import { add } from './math';

rs.mock('./math');

test('overrides one export', () => {
  rs.mocked(add).mockReturnValue(100);
  expect(add(1, 2)).toBe(100);
});
```

### Load a registered mock

When a test needs to load a mocked module object imperatively instead of via `import` or `require()`, use:

- [rs.importMock()](/api/runtime-api/rstest/mock-modules#rsimportmock): asynchronously loads an ESM module mock and returns a `Promise`.
- [rs.requireMock()](/api/runtime-api/rstest/mock-modules#rsrequiremock): synchronously loads a CommonJS module mock.

Neither API auto-mocks an unmocked module on its own. Each resolves an already-registered mock (`rs.mock` / `rs.doMock` or `rs.mockRequire` / `rs.doMockRequire`) or, when passed a string literal path, a matching file in `__mocks__`. If none exists, it throws a `Cannot find module` error. When a factory function was registered, its returned exports are returned as-is.

To obtain an auto-mocked module through `rs.importMock()`, register the auto-mock first:

```ts title="math.test.ts"
import { expect, rs, test } from '@rstest/core';

test('loads an auto-mocked module', async () => {
  rs.doMock('./math', { mock: true });
  const math = await rs.importMock<typeof import('./math')>('./math');

  math.add.mockReturnValue(100);
  expect(math.add(1, 2)).toBe(100);
});
```

In TypeScript, pass a returned module whose static type is unchanged to `rs.mocked(module, true)` before calling mock methods such as `mockReturnValue`. Match `importMock` vs. `requireMock` to the module entry your code uses.

### Spy on a whole module

Pass `{ spy: true }` to keep the original implementations while tracking calls to exported functions:

```ts title="calculator.test.ts"
import { expect, rs, test } from '@rstest/core';
import { calculate } from './calculator';

rs.mock('./calculator', { spy: true });

test('keeps the real implementation while tracking calls', () => {
  expect(calculate(1, 2)).toBe(3);
  expect(calculate).toHaveBeenCalledWith(1, 2);
});
```

This wraps the module's **exports** — calls between functions inside the same module use local bindings and are not tracked.

### Partially mock modules

Use the matching API when a mocked module needs some or all of its real exports:

- Add `with { rstest: 'importActual' }` to a static ESM import when a hoisted, synchronous `rs.mock()` factory needs the real exports.
- Use [rs.importActual()](/api/runtime-api/rstest/mock-modules#rsimportactual) to load the original ESM module asynchronously inside a test.
- Use [rs.requireActual()](/api/runtime-api/rstest/mock-modules#rsrequireactual) to load the original CommonJS module synchronously, including inside a synchronous mock factory.

When the module graph does not use top-level `await`, the static ESM form lets you override specific exports while keeping the rest. The example below dynamically imports the mocked module inside the test, which also works when the real module graph uses top-level `await`:

```ts title="date-utils.test.ts"
import { expect, rs, test } from '@rstest/core';
import * as actualDateUtils from './date-utils' with { rstest: 'importActual' };

rs.mock('./date-utils', () => ({
  ...actualDateUtils,
  formatDate: rs.fn().mockReturnValue('2026-03-19'),
}));

test('keeps parseDate real', async () => {
  const { formatDate, parseDate } = await import('./date-utils');
  expect(formatDate(new Date())).toBe('2026-03-19');
  expect(parseDate('2026-03-19')).toBeInstanceOf(Date);
});
```

Because `rs.mock()` factories are hoisted, values shared with the factory must come from a static `importActual` import or [`rs.hoisted()`](#share-values-with-a-hoisted-mock-factory).

If the real module graph uses top-level `await`, do not statically import the mocked module in the same test file — the factory may run before the actual exports are ready. Dynamically import it with `await import()` inside an async test instead; see [partial mock with `importActual`](/api/runtime-api/rstest/mock-modules#partial-mock-with-importactual).

### Mock virtual modules

Rstest does not use Jest's third `{ virtual: true }` argument. To mock a module that does not exist on disk, map the specifier to `false` in `resolve.alias` so the bundler skips disk resolution, then provide its exports with `rs.mock()` or a `__mocks__` file. See [Mock virtual modules](/api/runtime-api/rstest/mock-modules#mock-virtual-modules).

### Reuse manual mocks from `__mocks__`

Place shared fake implementations in `__mocks__` and call `rs.mock()` without a factory. Manual mocks take precedence over the auto-mock fallback:

```txt
src/
  api.ts
  __mocks__/
    api.ts
tests/
  user-service.test.ts
```

```ts title="user-service.test.ts"
import { rs } from '@rstest/core';

rs.mock('../src/api');
```

### Reset module state

To restore the original module for later `import` or `require()` calls or clear the module cache:

- [rs.unmock()](/api/runtime-api/rstest/mock-modules#rsunmock) / [rs.doUnmock()](/api/runtime-api/rstest/mock-modules#rsdounmock): stop mocking an `import`-based module.
- [rs.unmockRequire()](/api/runtime-api/rstest/mock-modules#rsunmockrequire) / [rs.doUnmockRequire()](/api/runtime-api/rstest/mock-modules#rsdounmockrequire): stop mocking a `require()`-based module.
- [rs.resetModules()](/api/runtime-api/rstest/mock-modules#rsresetmodules): clear the module cache so the next import or require re-evaluates the module.

`rs.resetModules()` does not cancel module mocking; use the matching `unmock` API for the way the module is loaded.

For the full API and more examples, see [Mock modules](/api/runtime-api/rstest/mock-modules).

## Mock functions

Use [rs.fn()](/api/runtime-api/rstest/mock-functions#rsfn) to create a mock function for callbacks or injected dependencies:

```ts title="user.test.ts"
import { expect, rs, test } from '@rstest/core';

test('passes the selected id to the callback', () => {
  const onSelect = rs.fn();

  onSelect('user-1');

  expect(onSelect).toHaveBeenCalledTimes(1);
  expect(onSelect).toHaveBeenCalledWith('user-1');
});
```

Override per-call or default behavior with mock instance methods:

```ts
const fetchUser = rs.fn(async (id: string) => ({ id, role: 'guest' }));

fetchUser.mockResolvedValueOnce({ id: '1', role: 'admin' });
```

See [Mock functions](/api/runtime-api/rstest/mock-functions) and [MockInstance](/api/runtime-api/rstest/mock-instance).

## Spy on existing methods

Use [rs.spyOn()](/api/runtime-api/rstest/mock-functions#rsspyon) to keep the real object while tracking calls or temporarily overriding a method or accessor:

```ts title="logger.test.ts"
import { expect, rs, test } from '@rstest/core';

test('logs a warning when validation fails', () => {
  const warn = rs.spyOn(console, 'warn').mockImplementation(() => undefined);

  console.warn('invalid payload');

  expect(warn).toHaveBeenCalledWith('invalid payload');
  warn.mockRestore();
});
```

Pass `'get'` or `'set'` as the third argument (`rs.spyOn(obj, 'prop', 'get')`) to spy on a property getter or setter.

### `using` syntax

<ApiMeta addedVersion="0.10.2" />

Rstest supports `using` to restore a spy automatically when its block exits:

```ts title="logger.test.ts"
import { expect, rs, test } from '@rstest/core';

test('logs a warning when validation fails', () => {
  {
    using warn = rs.spyOn(console, 'warn').mockImplementation(() => undefined);

    console.warn('invalid payload');

    expect(warn).toHaveBeenCalledWith('invalid payload');
  }

  // console.warn is restored here
});
```

## Deep-mock objects

Use [rs.mockObject()](/api/runtime-api/rstest/mock-functions#rsmockobject) to recursively convert methods on an existing object into mocks:

```ts title="service.test.ts"
import { expect, rs, test } from '@rstest/core';

test('mocks nested methods', async () => {
  const service = rs.mockObject({
    user: {
      fetch: async (id: string) => ({ id, name: 'real' }),
    },
    version: 'v1',
  });

  service.user.fetch.mockResolvedValue({ id: '1', name: 'mocked' });

  expect(service.version).toBe('v1');
  await expect(service.user.fetch('1')).resolves.toEqual({
    id: '1',
    name: 'mocked',
  });
});
```

By default, `rs.mockObject()` replaces arrays with empty arrays (`[]`). Pass `{ spy: true }` to keep original implementations, preserve array elements, and wrap nested functions and plain objects in spies while still recording calls.

See [Mock functions](/api/runtime-api/rstest/mock-functions) and [MockInstance](/api/runtime-api/rstest/mock-instance).

## Stub environment variables and globals

Use [rs.stubEnv()](/api/runtime-api/rstest/utilities#rsstubenv) and [rs.stubGlobal()](/api/runtime-api/rstest/utilities#rsstubglobal) to override `process.env` / `import.meta.env` or `globalThis` properties during a test:

```ts title="env.test.ts"
import { expect, rs, test } from '@rstest/core';

test('stubs env and global values', () => {
  using _env = rs.stubEnv('API_URL', 'https://test.example.com');
  using _fetch = rs.stubGlobal(
    'fetch',
    rs.fn().mockResolvedValue(new Response('ok')),
  );

  expect(process.env.API_URL).toBe('https://test.example.com');
  expect(import.meta.env.API_URL).toBe('https://test.example.com');
  expect(rs.isMockFunction(globalThis.fetch)).toBe(true);
});
```

Both APIs return a `Disposable` for `using`, and can also be restored manually with [`rs.unstubAllEnvs()`](/api/runtime-api/rstest/utilities#rsunstuballenvs) and [`rs.unstubAllGlobals()`](/api/runtime-api/rstest/utilities#rsunstuballglobals) or automatically before each test with [`unstubEnvs`](/config/test/unstub-envs) and [`unstubGlobals`](/config/test/unstub-globals).

## Mock timers

Use [Fake timers](/api/runtime-api/rstest/fake-timers) to replace global timer functions and `Date` so tests can advance time deterministically:

```ts title="timer.test.ts"
import { expect, rs, test } from '@rstest/core';

test('advances timers without waiting', () => {
  using _timers = rs.useFakeTimers();
  const callback = rs.fn();

  setTimeout(callback, 1000);
  rs.advanceTimersByTime(1000);

  expect(callback).toHaveBeenCalledTimes(1);
});
```

Use `rs.setSystemTime()` to pin the current system time and `rs.useRealTimers()` when restoring timers manually.

## Type and identify mock functions

[rs.mocked()](/api/runtime-api/rstest/mock-functions#rsmocked) returns the same value at runtime and only tells TypeScript to treat it as mocked. Use it when an auto-mocked module or object still has its original static type.

[rs.isMockFunction()](/api/runtime-api/rstest/mock-functions#rsismockfunction) performs a runtime check to determine whether a function is currently a mock and narrows its type to `MockInstance` in TypeScript.

## Clear mock state

Configure automatic cleanup before every test in `rstest.config.ts`:

- [clearMocks](/config/test/clear-mocks): clear call history (`mock.calls`, `mock.results`, etc.).
- [resetMocks](/config/test/reset-mocks): clear call history and reset mock implementations to their initial state. When both `resetMocks` and `clearMocks` are enabled, `resetMocks` takes precedence.
- [restoreMocks](/config/test/restore-mocks): restore original property descriptors on objects spied with `rs.spyOn()`. Does not clear call history, reset implementations, or affect standalone mocks created with `rs.fn()`.
- [unstubEnvs](/config/test/unstub-envs) / [unstubGlobals](/config/test/unstub-globals): restore `process.env` / `import.meta.env` and `globalThis` stubs created with `rs.stubEnv()` and `rs.stubGlobal()`.

For manual cleanup, call `rs.clearAllMocks()`, `rs.resetAllMocks()`, `rs.restoreAllMocks()`, `rs.unstubAllEnvs()`, and `rs.unstubAllGlobals()`.
