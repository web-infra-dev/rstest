# Configure Rstest

## Configuration file

When you run the Rstest CLI, Rstest resolves the configuration file in the project root directory in the following order:

- `rstest.config.mts`
- `rstest.config.mjs`
- `rstest.config.ts`
- `rstest.config.js`
- `rstest.config.cjs`
- `rstest.config.cts`

Use `.ts` or `.mts` with [`defineConfig`](/api/javascript-api/rstest-core#defineconfig) from `@rstest/core` for TypeScript type checking and autocompletion, or `.mjs` for JavaScript projects:

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  testEnvironment: 'node',
});
```

`defineConfig` also accepts a synchronous or asynchronous factory function when you need to compute configuration dynamically:

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig(async () => ({
  testTimeout: process.env.CI ? 10_000 : 5_000,
}));
```

For multi-project workspaces and programmatic config composition, `@rstest/core` also exports [`defineProject`](/api/javascript-api/rstest-core#defineproject), [`mergeRstestConfig`](/api/javascript-api/rstest-core#mergerstestconfig), and [`mergeProjectConfig`](/api/javascript-api/rstest-core#mergeprojectconfig). `defineProject` also accepts both sync and async functions.

### Specify config file

Use `--config` (or `-c`) to point Rstest to a relative or absolute config file path:

```json title="package.json"
{
  "scripts": {
    "test": "rstest --config scripts/rstest.config.mjs"
  }
}
```

```bash
rstest -c scripts/rstest.config.mjs
```

- Use `-r, --root <root>` to override the project root directory (which sets where Rstest looks for config files and resolves `<rootDir>`).
- Use `--config-loader <loader>` to choose how Rstest loads the config file: `auto` (default), `jiti`, or `native`. See [Rsbuild - Specify config loader](https://rsbuild.rs/guide/configuration/rsbuild#specify-config-loader).

## Configure Rsbuild

Rstest builds test files with Rsbuild and exposes most Rsbuild build options directly:

- Register Rsbuild plugins via [plugins](/config/build/plugins)
- Read or modify the resolved Rstest project config from Rsbuild plugins via [Rstest plugin APIs](/config/build/plugins#get-rstest-config) (see [modify Rstest config](/config/build/plugins#modify-rstest-config))
- Configure module resolution via [resolve](/config/build/resolve)
- Customize Rspack via [tools.rspack](/config/build/tools#toolsrspack)
- Customize `builtin:swc-loader` via [tools.swc](/config/build/tools#toolsswc)

See [Build configurations](/config/#build-configurations) for all supported options.

## Configure Rspack

Rstest uses Rspack under the hood, so you can pass Rspack configuration options through `tools.rspack`. See [Configure Rspack](https://rsbuild.rs/guide/configuration/rspack) for details.

## Configure SWC

Rstest transforms JavaScript and TypeScript with Rspack's [builtin:swc-loader](https://rspack.rs/guide/features/builtin-swc-loader) by default. Configure it with:

- [tools.swc](/config/build/tools#toolsswc): options passed to `builtin:swc-loader`
- [source.include](/config/build/source#sourceinclude): additional files to compile with SWC
- [source.exclude](/config/build/source#sourceexclude): files to skip during SWC compilation

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  tools: {
    swc: {
      jsc: {
        transform: {
          react: {
            runtime: 'automatic',
          },
        },
        experimental: {
          plugins: [['@swc/plugin-emotion', {}]],
        },
      },
    },
  },
});
```

### SWC plugin version

SWC Wasm plugins are experimental and not backward compatible across `swc_core` versions. Use a plugin version that matches the `swc_core` version bundled with Rspack; otherwise, the build fails. See [Rspack FAQ - SWC plugin version mismatch](https://rspack.rs/errors/swc-plugin-version).

## Detect Rstest environment

Use `import.meta.env.RSTEST` or `process.env.RSTEST` to check whether code is running under Rstest. Both values are `'true'` in every test environment, including Browser Mode.

Prefer `import.meta.env.RSTEST` in browser-compatible ESM source code. Browser Mode replaces these expressions at build time without defining a global `process` object, so do not guard access with `typeof process !== 'undefined'`.

```ts
if (import.meta.env.RSTEST === 'true') {
  // do something...
}
```

When building source code for production, define the expressions you check as `false` in your build configuration (such as `rsbuild.config.ts`) so the bundler eliminates test-only branches as dead code:

```diff title="rsbuild.config.ts"
import { defineConfig } from '@rsbuild/core';

export default defineConfig({
  source: {
    define: {
+      'process.env.RSTEST': false,
+      'import.meta.env.RSTEST': false,
    },
  },
});
```

### Detect Rstest in Rsbuild plugins

In Rsbuild plugins, check `api.context.callerName` for `'rstest'`. See [Detect whether a plugin is running in Rstest](/config/build/plugins#detect-rstest-environment).

## Configuration integration

To reuse existing build configurations (aliases, globals, plugins, or framework presets) without duplicating them, use [adapters](/guide/advanced/adapters) with the [extends](/config/test/extends) option:

- `extends` accepts an object, a function (adapter), or an array of entries, and deep-merges the resolved configuration into your Rstest config.
- Use it to adapt configs from Rsbuild, Rslib, or Rspack, or to share preset test environments and setup files across projects.
