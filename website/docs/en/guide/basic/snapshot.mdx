# Snapshot testing

Snapshot testing serializes a value and compares it against a stored reference on subsequent runs. When an intentional change alters the output, you update the snapshot; unexpected diffs fail the test.

## Basic usage

### Creating snapshots

Use `toMatchSnapshot()` to save and verify a value in an external `.snap` file:

```ts
import { expect, test } from '@rstest/core';

test('component snapshot', () => {
  const user = { name: 'Alice', age: 25 };
  expect(user).toMatchSnapshot();
});
```

By default, Rstest writes snapshots into a `.snap` file starting with `// Rstest Snapshot v1`:

```js
// Rstest Snapshot v1

exports[`component snapshot 1`] = `
{
  "age": 25,
  "name": "Alice",
}
`;
```

### Inline snapshots

For short outputs, `toMatchInlineSnapshot()` stores the serialized value directly inside the test file:

```ts
import { expect, test } from '@rstest/core';

test('inline snapshot', () => {
  const message = 'Hello World';
  expect(message).toMatchInlineSnapshot(`"Hello World"`);
});
```

### Error snapshots

Use `toThrowErrorMatchingSnapshot()` or `toThrowErrorMatchingInlineSnapshot()` to snapshot the error thrown by a function (or a rejected promise via `rejects`):

```ts
import { expect, test } from '@rstest/core';

test('error snapshot', () => {
  const fail = () => {
    throw new Error('Invalid input');
  };
  expect(fail).toThrowErrorMatchingInlineSnapshot(`[Error: Invalid input]`);
});
```

### Property matchers

When an object contains dynamic values such as IDs or timestamps, pass a property matcher object as the first argument to `toMatchSnapshot()` or `toMatchInlineSnapshot()`:

```ts
import { expect, test } from '@rstest/core';

test('dynamic fields', () => {
  const user = { id: Math.random(), name: 'Alice', createdAt: new Date() };
  expect(user).toMatchSnapshot({
    id: expect.any(Number),
    createdAt: expect.any(Date),
  });
});
```

### File snapshots

Use `toMatchFileSnapshot(filepath)` to store large or syntax-highlighted outputs (such as HTML, CSS, or JSON) in a dedicated file. Unlike `toMatchSnapshot()`, `toMatchFileSnapshot()` is asynchronous and must be awaited:

```ts
import { expect, test } from '@rstest/core';

test('file snapshot', async () => {
  const result = renderHTML(h('div', { class: 'foo' }));
  await expect(result).toMatchFileSnapshot('./basic.output.html');
});
```

:::note
Snapshot matchers do not support `.not`. Calling `expect(value).not.toMatchSnapshot()` (or any other snapshot matcher with `.not`) throws an error.
:::

### Configuration options

- [update](/config/test/update): Controls whether changed and obsolete snapshots are updated (default: `false`).
- [snapshotFormat](/config/test/snapshot-format): `pretty-format` options for snapshot serialization (default: `{ printShadowRoot: false }`).
- [resolveSnapshotPath](/config/test/resolve-snapshot-path): Customizes where `.snap` files are stored.

## Updating snapshots

By default (`update: false`), new snapshots are written locally (disabled when `process.env.CI` is set) and mismatches fail. Update changed snapshots and remove obsolete ones with `npx rstest -u`, `update: true`, or pressing `u` in interactive watch mode; see [update](/config/test/update).

## Serialization output

Register custom snapshot serializers with [expect.addSnapshotSerializer](/api/runtime-api/test-api/expect#expectaddsnapshotserializer) to normalize dynamic paths, mask secrets, or format custom types:

```ts
import { expect, test } from '@rstest/core';

expect.addSnapshotSerializer({
  test: (val) => typeof val === 'string' && val.startsWith('secret:'),
  print: () => '***MASKED***',
});

test('masked secret', () => {
  expect('secret:123').toMatchSnapshot();
});
```

For snapshots containing file system paths, [path-serializer](https://www.npmjs.com/package/path-serializer) normalizes absolute paths relative to your project root so snapshots stay portable across machines:

```ts
import path from 'node:path';
import { expect, test } from '@rstest/core';
import { createSnapshotSerializer } from 'path-serializer';

expect.addSnapshotSerializer(
  createSnapshotSerializer({
    root: path.join(import.meta.dirname, '..'),
  }),
);

test('serialized snapshot', () => {
  const filePath = path.join(import.meta.dirname, '../data/file.txt');
  expect({ filePath }).toMatchSnapshot();
  // before: "/path/to/repo/examples/node/data/file.txt"
  // after: "<ROOT>/examples/node/data/file.txt"
});
```

## Snapshot output path

By default, `.snap` files live in a `__snapshots__` directory beside each test file. To store snapshots elsewhere, configure [resolveSnapshotPath](/config/test/resolve-snapshot-path).
