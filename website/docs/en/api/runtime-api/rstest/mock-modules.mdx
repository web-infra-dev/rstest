# Mock modules

Rstest provides module mocking APIs on `rs` (`rstest`) for ESM and CommonJS modules.

## rs.mock

- **Type:** `<T = unknown>(moduleName: string | Promise<T>, factoryOrOptions?: (() => Partial<T>) | { spy: true } | { mock: true }) => void`

Mocks the module specified by `moduleName` across `import` (and shared `require()`) calls.

:::tip Hoisting
`rs.mock` is hoisted to the top of the current module, so static `import` statements in the same file receive the mocked module.
:::

### With factory function

When a factory function is passed as the second argument, the module resolves to the factory's return value. Factory functions must be synchronous; to keep some original exports, see [Partial mock with `importActual`](#partial-mock-with-importactual).

#### Basic example

<div style={{ display: 'flex', gap: '1rem' }}>
  <div>
    ```ts title="src/sum.test.ts"
    import { expect, rs } from '@rstest/core';
    import { sum } from './sum';

    rs.mock('./sum', () => ({
      sum: (a: number, b: number) => a + b + 100,
    }));

    expect(sum(1, 2)).toBe(103);
    ```

  </div>
  <div>
    ```ts title="src/sum.ts"
    export const sum = (a: number, b: number) => a + b;
    ```
  </div>
</div>

#### Mock virtual modules

Rstest can mock modules that do not exist on disk (such as generated or native modules) in both Node and Browser mode:

1. Declare the module types for TypeScript:

```ts title="src/types/native-runtime.d.ts"
declare module 'native-runtime' {
  export const platform: string;
}
```

2. Map the specifier to `false` so the bundler ignores resolving it from disk:

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  resolve: {
    alias: {
      'native-runtime': false,
    },
  },
});
```

3. Provide runtime exports with a factory (or a matching `__mocks__` file):

```ts title="src/native-runtime.test.ts"
import { expect, rs, test } from '@rstest/core';
import { platform } from 'native-runtime';

rs.mock('native-runtime', () => ({
  platform: 'test',
}));

test('uses the virtual module', () => {
  expect(platform).toBe('test');
});
```

Rstest does not use Jest's third `{ virtual: true }` argument. Keep the same specifier in the declaration, alias, mock call, and import. Indirect imports from source files under test are also mocked.

`rs.mock` covers static `import` statements; call `rs.doMock` before dynamic `import()` calls, and use `rs.mockRequire` / `rs.doMockRequire` when `require()` resolves to a separate CommonJS entry. Because an alias mapped to `false` has no underlying module, use a factory or manual mock instead of `{ mock: true }`, `{ spy: true }`, or `rs.importActual`.

#### With `rs.fn()` for call tracking

Return `rs.fn()` mocks from the factory to track calls and configure return values:

```ts title="src/api.test.ts"
import { expect, rs, test } from '@rstest/core';
import { fetchUser, fetchPosts } from './api';

rs.mock('./api', () => ({
  fetchUser: rs.fn().mockResolvedValue({ id: 1, name: 'John' }),
  fetchPosts: rs.fn().mockResolvedValue([{ id: 1, title: 'Hello' }]),
}));

test('fetch user data', async () => {
  const user = await fetchUser(1);
  expect(user).toEqual({ id: 1, name: 'John' });
  expect(fetchUser).toHaveBeenCalledWith(1);
});
```

#### With `rs.mockObject()` for auto-mocking

```ts title="src/service.test.ts"
import { expect, rs, test } from '@rstest/core';
import { userService } from './userService';

rs.mock('./userService', () => ({
  userService: rs.mockObject({
    getUser: () => {},
    updateUser: () => {},
    deleteUser: () => {},
  }),
}));

test('service methods are mocked', () => {
  userService.getUser(1);
  expect(userService.getUser).toHaveBeenCalledWith(1);
});
```

#### Partial mock with `importActual`

Add the [import attribute](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/import/with) `with { rstest: 'importActual' }` to load the unmocked module and spread its exports into the factory:

```ts title="src/utils.test.ts"
import { expect, rs, test } from '@rstest/core';
import * as dateUtils from './dateUtils' with { rstest: 'importActual' };
import { formatDate, parseDate } from './dateUtils';

rs.mock('./dateUtils', () => ({
  ...dateUtils,
  formatDate: rs.fn().mockReturnValue('2024-01-01'),
}));

test('formatDate is mocked, parseDate is real', () => {
  expect(formatDate(new Date())).toBe('2024-01-01');
  expect(parseDate('2024-01-01')).toBeInstanceOf(Date);
});
```

If the actual module or one of its dependencies uses top-level `await`, do not statically import the mocked module in the same file — the mock factory may run before the actual module finishes evaluating. Keep the `importActual` import, then dynamically import the mocked module inside an async test:

```ts title="src/api.test.ts"
import { expect, it, rs } from '@rstest/core';
import * as apiActual from './api' with { rstest: 'importActual' };

rs.mock('./api', () => ({ ...apiActual, extra: true }));

it('uses the real exports', async () => {
  const api = await import('./api');
  expect(api.answer()).toBe(42);
});
```

### With `__mocks__` directory

When `rs.mock` is called with no second argument, Rstest looks for a matching manual mock in `__mocks__`. If none is found, it falls back to auto-mocking (equivalent to `{ mock: true }`).

**Resolution rules:**

1. **Local modules**: A sibling `__mocks__` directory next to the target file containing a file with the same name.
2. **npm dependencies**: A `__mocks__` directory at the project root containing a file matching the package name.
3. **Node.js built-in modules**: A `__mocks__` directory at the project root containing a file matching the module name (for example, `__mocks__/fs.mjs` or `__mocks__/path.ts`). Any `node:` prefix is ignored.

**Example:**

```txt
├── __mocks__
│   └── lodash.js
├── src
│   ├── multiple.ts
│   └── __mocks__
│       └── multiple.ts
└── __test__
    └── multiple.test.ts
```

```ts title="src/multiple.test.ts"
import { rs } from '@rstest/core';
import lodash from 'lodash';
import { multiple } from '../src/multiple';

rs.mock('lodash');
rs.mock('../src/multiple');

lodash.random(multiple(1, 2), multiple(3, 4));
```

If no manual mock exists, Rstest auto-mocks the module:

```ts title="src/math.test.ts"
import { expect, rs, test } from '@rstest/core';
import { add } from './math';

rs.mock('./math');

test('falls back to auto-mocking', () => {
  expect(rs.isMockFunction(add)).toBe(true);
  expect(add(1, 2)).toBeUndefined();
});
```

### With `{ spy: true }` option \{#with-spy-true-option}

Wraps all module exports in spy functions while keeping their original implementations.

```ts title="src/calculator.test.ts"
import { expect, rs, test } from '@rstest/core';
import { calculate } from './calculator';

rs.mock('./calculator', { spy: true });

test('keeps the real implementation while tracking calls', () => {
  const result = calculate(1, 2);
  expect(result).toBe(3);

  expect(calculate).toHaveBeenCalledWith(1, 2);
  expect(calculate).toHaveReturnedWith(3);
});
```

:::note Internal calls are not tracked

The spy wraps the module's **exports**. When one export calls another function inside the same module, that call uses the module's local binding rather than the wrapped export, so it is not tracked.

:::

:::note ESM and CommonJS modules

- **ESM modules**: All named exports are wrapped in spy functions.
- **CommonJS modules**: In addition to wrapping exports, a `default` export pointing to the module object is added if none exists, preserving `import x from 'cjs-module'`.

:::

### With `{ mock: true }` option

Auto-mocks the module directly without checking `__mocks__`, replacing all exported functions with mock functions that return `undefined` by default.

```ts title="src/math.test.ts"
import { expect, rs, test } from '@rstest/core';
import { add, multiply } from './math';

rs.mock('./math', { mock: true });

test('mock functions return undefined by default', () => {
  expect(add(1, 2)).toBeUndefined();
  expect(multiply(3, 4)).toBeUndefined();
  expect(rs.isMockFunction(add)).toBe(true);
});

test('can configure mock implementations', () => {
  rs.mocked(add).mockReturnValue(100);
  expect(add(1, 2)).toBe(100);

  rs.mocked(multiply).mockImplementation((a, b) => a * b * 2);
  expect(multiply(3, 4)).toBe(24);
});
```

### Type enhancement with `Promise<T>`

Passing a dynamic `import()` expression (`Promise<T>`) as the first argument enables IDE type inference for the factory return value without changing runtime behavior:

```ts
rs.mock(import('../src/b'), () => ({
  b: 222,
}));
```

## rs.doMock

- **Type:** `<T = unknown>(moduleName: string | Promise<T>, factoryOrOptions?: (() => Partial<T>) | { spy: true } | { mock: true }) => void`

Non-hoisted version of `rs.mock`. Takes effect only when executed, so imports evaluated earlier keep the original module while subsequent dynamic `import()` calls receive the mock.

Accepts the same second argument as `rs.mock` (factory function, `__mocks__` fallback, `{ spy: true }`, or `{ mock: true }`).

```ts title="src/sum.test.ts"
import { expect, it, rs } from '@rstest/core';
import { sum } from './sum';

it('only mocks subsequent imports', async () => {
  expect(sum(1, 2)).toBe(3);

  rs.doMock('./sum');
  const { sum: mockedSum } = await import('./sum');

  expect(mockedSum(1, 2)).toBeUndefined();
});
```

## rs.mockRequire

- **Type:** `<T = unknown>(moduleName: string, factoryOrOptions?: (() => T) | { spy: true } | { mock: true }) => void`

Mocks modules loaded via CommonJS `require()`. Like `rs.mock`, calls are hoisted to the top of the current module.

:::tip Dual packages (ESM + CJS)
When a package exposes separate ESM and CommonJS entries:

- `rs.mock()` mocks the **ESM entry** (used by `import`).
- `rs.mockRequire()` mocks the **CJS entry** (used by `require()`).
  :::

```ts title="src/math.test.cjs"
const { sum } = require('./math.cjs');

rs.mockRequire('./math.cjs', () => ({
  sum: (a, b) => a + b + 100,
}));

test('mock cjs module with require', () => {
  expect(sum(1, 2)).toBe(103);
});
```

## rs.doMockRequire

- **Type:** `<T = unknown>(moduleName: string, factoryOrOptions?: (() => T) | { spy: true } | { mock: true }) => void`

Non-hoisted version of `rs.mockRequire`. Applies only to `require()` calls executed after `rs.doMockRequire`.

```ts title="src/math.test.cjs"
test('doMockRequire only affects later require calls', () => {
  const { sum } = require('./math.cjs');
  expect(sum(1, 2)).toBe(3);

  rs.doMockRequire('./math.cjs', () => ({
    sum: (a, b) => a + b + 100,
  }));

  const { sum: mockedSum } = require('./math.cjs');
  expect(mockedSum(1, 2)).toBe(103);
});
```

## rs.unmockRequire

- **Type:** `(path: string) => void`

Removes the mock for a module loaded via `require()`. Like `rs.mockRequire`, calls are hoisted to the top of the file so later `require()` calls load the original CommonJS module.

```ts title="src/math.test.cjs"
const { sum } = require('./math.cjs');

rs.mockRequire('./math.cjs', () => ({
  sum: (a, b) => a + b + 100,
}));

rs.unmockRequire('./math.cjs');

test('unmockRequire restores the original CommonJS module', () => {
  expect(sum(1, 2)).toBe(3);
});
```

## rs.doUnmockRequire

- **Type:** `(path: string) => void`

Non-hoisted version of `rs.unmockRequire`. Only subsequent `require()` calls load the original module.

```ts title="src/math.test.cjs"
test('doUnmockRequire only affects later require calls', () => {
  rs.doMockRequire('./math.cjs', () => ({
    sum: (a, b) => a + b + 100,
  }));

  const { sum: mockedSum } = require('./math.cjs');
  expect(mockedSum(1, 2)).toBe(103);

  rs.doUnmockRequire('./math.cjs');

  const { sum } = require('./math.cjs');
  expect(sum(1, 2)).toBe(3);
});
```

## rs.hoisted

- **Type:** `<T = unknown>(fn: () => T) => T`

Hoists `fn` to the top of the module (with `rs` available) and returns its result. Use it to create mock functions or values shared between a hoisted `rs.mock` factory and test assertions.

```ts title="src/sum.test.ts"
import { expect, it, rs } from '@rstest/core';
import { foo } from './sum';

const mocks = rs.hoisted(() => ({
  hoistedFn: rs.fn(),
}));

rs.mock('./sum', () => ({
  foo: mocks.hoistedFn,
}));

it('hoisted', () => {
  mocks.hoistedFn(42);
  expect(mocks.hoistedFn).toHaveBeenCalledOnce();
  expect(mocks.hoistedFn).toHaveBeenCalledWith(42);
  expect(foo).toBe(mocks.hoistedFn);
});
```

## rs.importActual

- **Type:** `<T = Record<string, unknown>>(path: string) => Promise<T>`

Asynchronously loads the original implementation of an ESM module, bypassing any registered mock. For CommonJS modules loaded with `require()`, use [`rs.requireActual`](#rsrequireactual). For partial mocks inside a synchronous `rs.mock` factory, use `with { rstest: 'importActual' }` (see [Partial mock with `importActual`](#partial-mock-with-importactual)).

```ts title="src/sum.test.ts"
import { expect, it, rs } from '@rstest/core';

rs.mock('./sum');

it('loads the actual module', async () => {
  const actualModule = await rs.importActual<typeof import('./sum')>('./sum');
  expect(actualModule.sum(1, 2)).toBe(3);
});
```

## rs.requireActual

- **Type:** `<T = Record<string, unknown>>(path: string) => T`

Synchronously loads the original implementation of a CommonJS module, bypassing any registered mock. Throws if the module's dependency graph uses top-level `await`; use [`rs.importActual`](#rsimportactual) in that case.

```js title="src/math.test.cjs"
const { expect, rs, test } = require('@rstest/core');

rs.mockRequire('./math.cjs', () => ({
  sum: () => 100,
}));

test('loads the original CommonJS module', () => {
  const actualMath = rs.requireActual('./math.cjs');

  expect(rs.isMockFunction(actualMath.sum)).toBe(false);
  expect(actualMath.sum(1, 2)).toBe(3);
});
```

## rs.importMock

- **Type:** `<T = Record<string, unknown>>(path: string) => Promise<T>`

Asynchronously loads the mocked exports of an ESM module. For synchronous CommonJS loading, use [`rs.requireMock`](#rsrequiremock).

Resolution order:

- If a mock is registered with `rs.mock` or `rs.doMock`, returns that registered mock (a registered factory takes precedence over `__mocks__`, and its exports are returned as-is without wrapping functions in `rs.fn()`).
- If no mock is registered and `path` is a string literal, loads the matching `__mocks__` file if one exists.
- Otherwise, rejects with a module-not-found error.

To obtain an auto-mocked module, register it with `rs.mock('./sum', { mock: true })` first.

```ts title="src/sum.test.ts"
import { expect, rs, test } from '@rstest/core';

rs.mock('./sum', () => ({
  sum: () => 100,
}));

test('loads the registered mock', async () => {
  const mocked = await rs.importMock<typeof import('./sum')>('./sum');

  expect(mocked.sum(1, 2)).toBe(100);
});
```

### Variable paths

When `path` is a variable, `rs.importMock` looks up mocks previously registered with a literal path via `rs.mock` (hoisted) or `rs.doMock` (must run before `rs.importMock`). Relative paths resolve from the calling file. Variable paths do not discover unmocked modules or `__mocks__` files at runtime.

```ts title="src/sum.test.ts"
import { expect, rs, test } from '@rstest/core';

test('loads an auto-mocked module through a variable', async () => {
  rs.doMock('./sum', { mock: true });

  const path = './sum';
  const mocked = await rs.importMock<typeof import('./sum')>(path);

  expect(rs.isMockFunction(mocked.sum)).toBe(true);
  expect(mocked.sum(1, 2)).toBeUndefined();
});
```

## rs.requireMock

- **Type:** `<T = Record<string, unknown>>(path: string) => T`

Synchronously loads the mocked exports of a CommonJS module registered via `rs.mockRequire` or `rs.doMockRequire` (or a matching `__mocks__` file when `path` is a string literal). Throws synchronously if no mock is found.

When given a variable path, `rs.requireMock` only looks up already-registered mocks (resolving relative paths from the calling file) and does not discover `__mocks__` files at runtime.

```js title="src/math.test.cjs"
const { expect, rs, test } = require('@rstest/core');

rs.mockRequire('./math.cjs', () => ({
  sum: () => 100,
}));

test('loads the registered CommonJS mock', () => {
  const path = './math.cjs';
  const mockedMath = rs.requireMock(path);

  expect(mockedMath.sum(1, 2)).toBe(100);
});
```

## rs.unmock

- **Type:** `(path: string) => void`

Cancels the mock for the specified module so subsequent `import` calls load the original module. Like `rs.mock`, `rs.unmock` is hoisted to the top of the file, allowing it to undo mocks registered in `setupFiles` or earlier hoisted `rs.mock` calls.

<div style={{ display: 'flex', gap: '1rem' }}>
  <div>
    ```ts title="sum.test.ts"
    import { expect, rs } from '@rstest/core';
    import { sum } from './src/sum';

    rs.unmock('./src/sum');

    expect(sum(1, 2)).toBe(3);
    ```

  </div>
  <div>
    ```ts title="rstest.setup.ts"
    import { rs } from '@rstest/core';

    rs.mock('./src/sum', () => ({
      sum: (a: number, b: number) => a + b + 100,
    }));
    ```

  </div>
</div>

## rs.doUnmock

- **Type:** `(path: string) => void`

Non-hoisted version of `rs.unmock`. Only subsequent imports of the module load the original implementation; already-imported bindings are unaffected.

## rs.resetModules

- **Type:** `() => RstestUtilities`

Clears the module cache so modules re-execute on their next import or `require()`, isolating shared module state between tests.

:::warning
Does not clear registered module mocks. To restore the original module, use [`rs.unmock`](#rsunmock), [`rs.doUnmock`](#rsdounmock), [`rs.unmockRequire`](#rsunmockrequire), or [`rs.doUnmockRequire`](#rsdounmockrequire).
:::
