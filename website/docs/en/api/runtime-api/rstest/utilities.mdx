# Utilities

Runtime utilities on `rs` (`rstest`) for stubbing environment variables and globals, modifying runtime config, and polling async conditions.

## rs.stubEnv

- **Alias:** `rstest.stubEnv`

- **Type:** `(name: string, value: string | undefined) => RstestUtilities & Disposable`

Temporarily sets an environment variable on `process.env` and `import.meta.env`.

- Passing `undefined` deletes the variable from `process.env` and `import.meta.env`.
- Subsequent calls stack; [`rs.unstubAllEnvs()`](#rsunstuballenvs) restores all stubbed variables.

```ts
rs.stubEnv('NODE_ENV', 'test');
expect(process.env.NODE_ENV).toBe('test');
expect(import.meta.env.NODE_ENV).toBe('test');

rs.stubEnv('MY_VAR', undefined);
expect(process.env.MY_VAR).toBeUndefined();
expect(import.meta.env.MY_VAR).toBeUndefined();
```

- **`using` syntax**

<ApiMeta addedVersion="0.10.3" />

`rs.stubEnv()` returns a `Disposable` that restores that stub when the `using` block exits (`using` requires a binding variable such as `_env`):

```ts
{
  using _env = rs.stubEnv('NODE_ENV', 'test');
  expect(process.env.NODE_ENV).toBe('test');
}

// NODE_ENV is restored to its original value.
```

## rs.unstubAllEnvs

- **Alias:** `rstest.unstubAllEnvs`

- **Type:** `() => RstestUtilities`

Restores all environment variables changed by [`rs.stubEnv`](#rsstubenv) to their original values. Automatically runs before each test when [`unstubEnvs`](/config/test/unstub-envs) is enabled.

```ts
const originalNodeEnv = process.env.NODE_ENV;
rs.stubEnv('NODE_ENV', 'production');
// ... run code under stubbed env
rs.unstubAllEnvs();
expect(process.env.NODE_ENV).toBe(originalNodeEnv);
```

To restore manually after every test instead of enabling [`unstubEnvs`](/config/test/unstub-envs), call `rs.unstubAllEnvs()` in [`afterEach`](/api/runtime-api/test-api/hooks#aftereach).

## rs.stubGlobal

- **Alias:** `rstest.stubGlobal`

- **Type:** `(name: string | number | symbol, value: unknown) => RstestUtilities & Disposable`

Temporarily sets a property on `globalThis` to `value`. Subsequent calls stack; use [`rs.unstubAllGlobals()`](#rsunstuballglobals) to restore all stubbed globals.

```ts
rs.stubGlobal('myGlobal', 123);
expect(globalThis.myGlobal).toBe(123);

rs.stubGlobal(Symbol.for('foo'), 'bar');
expect(globalThis[Symbol.for('foo')]).toBe('bar');
```

- **`using` syntax**

<ApiMeta addedVersion="0.10.3" />

`rs.stubGlobal()` returns a `Disposable` that restores that stub when the `using` block exits:

```ts
{
  using _global = rs.stubGlobal('myGlobal', 123);
  expect(globalThis.myGlobal).toBe(123);
}

// myGlobal is restored to its original value.
```

## rs.unstubAllGlobals

- **Alias:** `rstest.unstubAllGlobals`

- **Type:** `() => RstestUtilities`

Restores all global properties changed by [`rs.stubGlobal`](#rsstubglobal) to their original descriptors (or deletes properties that did not exist). Automatically runs before each test when [`unstubGlobals`](/config/test/unstub-globals) is enabled.

```ts
rs.stubGlobal('myGlobal', 123);
// ... run code under stubbed global
rs.unstubAllGlobals();
expect(globalThis.myGlobal).toBeUndefined();
```

To restore manually after every test instead of enabling [`unstubGlobals`](/config/test/unstub-globals), call `rs.unstubAllGlobals()` in [`afterEach`](/api/runtime-api/test-api/hooks#aftereach).

## rs.setConfig

- **Alias:** `rstest.setConfig`

- **Type:**

```ts
type RuntimeOptions = {
  testTimeout?: number;
  hookTimeout?: number;
  clearMocks?: boolean;
  resetMocks?: boolean;
  restoreMocks?: boolean;
  maxConcurrency?: number;
  retry?: number;
};

type SetConfig = (config: RuntimeOptions) => void;
```

Updates the runtime configuration for the current test file.

```ts
rs.setConfig({ testTimeout: 1000, retry: 2 });
// ... run tests with the updated config
rs.resetConfig();
```

## rs.resetConfig

- **Alias:** `rstest.resetConfig`

- **Type:** `() => void`

Resets runtime configuration fields modified by [`rs.setConfig`](#rssetconfig) back to their initial values for the test file.

## rs.getConfig

- **Alias:** `rstest.getConfig`

- **Type:**

```ts
type GetConfig = () => RuntimeOptions & {
  expect: {
    poll: {
      interval: number;
      timeout: number;
    };
  };
};
```

Returns the active runtime configuration for the current test file.

<ApiMeta addedVersion="0.12.0" />

The return value also includes a copy of the resolved `expect.poll` configuration. Mutating this copy does not affect runtime behavior.

```ts
const config = rs.getConfig();
console.log(config);
```

## rs.waitFor

- **Alias:** `rstest.waitFor`

- **Type:**

```ts
type WaitForOptions = {
  timeout?: number; // default: 1000
  interval?: number; // default: 50
};

type WaitFor = <T>(
  callback: () => T | Promise<T>,
  options?: number | WaitForOptions,
) => Promise<T>;
```

Polls `callback` until it succeeds without throwing, or until `timeout` expires.

- Passing a number for `options` sets `timeout`.
- On timeout, throws the last error from `callback` (or a timeout error if `callback` has not thrown yet).

```ts
await rs.waitFor(
  async () => {
    const res = await fetch(url);
    expect(res.ok).toBe(true);
  },
  { timeout: 30_000, interval: 1_000 },
);
```

When [fake timers](/api/runtime-api/rstest/fake-timers) are enabled, `rs.waitFor` advances them by `interval` before each check, and every `interval` while an async `callback` is still running, so the timers `callback` waits for can fire.

## rs.waitUntil

- **Alias:** `rstest.waitUntil`

- **Type:**

```ts
type Falsy = false | 0 | 0n | '' | null | undefined;
type Truthy<T> = Exclude<T, Falsy>;

type WaitUntilOptions = {
  timeout?: number; // default: 1000
  interval?: number; // default: 50
};

type WaitUntil = <T>(
  callback: () => T | Promise<T>,
  options?: number | WaitUntilOptions,
) => Promise<Truthy<Awaited<T>>>;
```

Polls `callback` while it returns a falsy value and resolves with the first truthy return value.

- Passing a number for `options` sets `timeout`.
- If `callback` throws, polling stops immediately and the error is rethrown.
- On timeout, throws a timeout error.

```ts
const serverReady = await rs.waitUntil(
  async () => {
    const status = await getServerStatus();
    return status.ready ? status : null;
  },
  { timeout: 10_000, interval: 200 },
);
```

When [fake timers](/api/runtime-api/rstest/fake-timers) are enabled, `rs.waitUntil` advances them by `interval` before each check, and every `interval` while an async `callback` is still running, so the timers `callback` waits for can fire.
