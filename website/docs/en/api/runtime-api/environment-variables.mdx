# Environment variables

Rstest sets runtime variables in the test and worker processes and reads several optional variables to configure output, agent detection, and debug logging.

## `NODE_ENV`

Set to `'test'` when the test runner starts if not already defined. Existing values are preserved, so you can override it from your shell or `package.json` script.

Available as both `process.env.NODE_ENV` and `import.meta.env.NODE_ENV` across all test environments, including [browser mode](/guide/browser-testing/). Prefer `import.meta.env.NODE_ENV` in ESM source code where `process` may not exist.

```ts
if (import.meta.env.NODE_ENV === 'test') {
  // running under Rstest
}
```

## `RSTEST`

Available as both `process.env.RSTEST` and `import.meta.env.RSTEST` across all test environments, including [browser mode](/guide/browser-testing/). Set to `'true'` while the test runner is active.

In browser mode, Rstest replaces these expressions at build time without adding a global `process` object. Prefer `import.meta.env.RSTEST` in browser-compatible ESM source code, and do not guard access with `typeof process !== 'undefined'` because that check remains `false` in the browser.

```ts
if (import.meta.env.RSTEST === 'true') {
  // running under Rstest
}
```

For production builds, define the expression used by your source code as `false` so the bundler can eliminate the dead branch — see [Detect Rstest environment](/guide/basic/configure-rstest#detect-rstest-environment).

For [in-source tests](/config/test/include-source), prefer `import.meta.rstest` — it exposes the Rstest test API directly and is `undefined` in production builds.

## `RSTEST_WORKER_ID`

A stringified integer identifying the Node worker running the current test file, starting at `'1'`. Equivalent to Jest's [`JEST_WORKER_ID`](https://jestjs.io/docs/environment-variables#jest_worker_id).

Use it to isolate external resources across concurrent workers — such as database schemas, ports, or temporary directories.

```ts title="db.test.ts"
import { afterAll, beforeAll, test } from '@rstest/core';

const dbName = `myapp_test_${process.env.RSTEST_WORKER_ID}`;

beforeAll(async () => {
  await createDatabase(dbName);
});

afterAll(async () => {
  await dropDatabase(dbName);
});

test('inserts a row', async () => {
  // ...
});
```

Worker IDs are bounded to `[1, pool.maxWorkers]`. Rstest assigns the lowest unused ID in that range when spawning a worker and reuses an ID only after the previous worker has fully exited. Under `isolate: false`, a reused idle worker keeps its existing ID. Concurrent workers never share the same ID.

## `RSTEST_NO_AGENT`

Set `RSTEST_NO_AGENT=1` to disable AI coding agent detection.

When no reporter is configured in config or CLI flags, Rstest detects AI coding agents and automatically switches the default reporter to `md` while disabling default terminal colors. Setting `RSTEST_NO_AGENT=1` keeps the `default` console reporter and normal TTY color detection.

```bash
RSTEST_NO_AGENT=1 npx rstest run
```

## `DEBUG`

Comma-separated debug scopes (case-insensitive) that enable verbose debug logging, persist temporary build artifacts and resolved configs to disk, and print full error stack traces. Recognized scopes include `rstest`, `rsbuild`, `builder`, and `*`.

Set `DEBUG=rstest:bundle-coverage` alongside V8 coverage to write raw Node.js bundle coverage data to `.rstest/bundle-coverage-<timestamp>.json` (see [Inspect bundle coverage](/guide/debug/debugging#inspect-bundle-coverage)).

```bash
DEBUG=rstest npx rstest run
```

See [Debugging](/guide/debug/debugging) and [Profiling](/guide/debug/profiling) for details.
