# Expect

`expect` creates assertions in tests with built-in matchers, negation, soft assertions, polling, snapshot matchers, and custom matchers.

Import `expect` from `@rstest/core`, or destructure it from [`TestContext`](/api/runtime-api/test-api/test#testcontext) to bind assertions to the current test in concurrent runs:

```ts
import { expect, test } from '@rstest/core';

test('adds two numbers', () => {
  expect(1 + 1).toBe(2);
});

test('concurrent-safe expect', ({ expect }) => {
  expect(1 + 2).toBe(3);
});
```

## expect

- **Type:** `<T>(actual: T, message?: string) => Assertion<T>`

Creates an assertion for `actual`, with an optional custom failure `message`.

```ts
import { expect } from '@rstest/core';

expect(1 + 1).toBe(2);
expect('hello').toBeDefined();
expect([1, 2, 3]).toContain(2);
```

## expect.element (Browser mode)

- **Type:** `(locator: Locator | Element) => BrowserElementExpect`

In Browser Mode, `expect.element` creates a DOM assertion against a `Locator` or DOM `Element` (such as `toBeVisible`, `toHaveText`, or `toHaveValue`).

```ts
import { page } from '@rstest/browser';
import { expect, test } from '@rstest/core';

test('asserts by locator', async () => {
  document.body.innerHTML = '<button>Save</button>';
  await expect
    .element(page.getByRole('button', { name: 'Save' }))
    .toBeVisible();
});
```

`expect.element` is available only in Browser Mode after importing `@rstest/browser`. See [Assertion (Browser Mode)](/api/runtime-api/browser-mode/assertion) for all element matchers and timeout rules.

## expect.not

Negates the chained matcher via `expect(actual).not`:

```ts
expect(1 + 1).not.toBe(3);
expect('foo').not.toBeUndefined();
```

## expect.soft

- **Type:** `<T>(actual: T, message?: string) => Assertion<T>`

Records assertion failures without aborting the test, reporting all failures at the end.

```ts
expect.soft(1 + 1).toBe(3); // Does not stop the test
expect.soft(1 + 2).toBe(4);
```

## expect.poll

- **Type:**

```ts
<T>(
  actual: () => T,
  options?: { interval?: number; timeout?: number; message?: string },
) =>
  Omit<
    PromisifyAssertion<Awaited<T>>,
    | 'rejects'
    | 'resolves'
    | 'toThrow'
    | 'toThrowError'
    | 'throw'
    | 'throws'
    | 'matchSnapshot'
    | 'toMatchSnapshot'
    | 'toMatchInlineSnapshot'
    | 'toThrowErrorMatchingSnapshot'
    | 'toThrowErrorMatchingInlineSnapshot'
  >;
```

Repeatedly invokes `actual` and retries the chained matcher until it passes or times out. Each matcher returns `Promise<void>` and **must** be awaited (`Awaited<T>` unwraps async `actual` callbacks).

- **Default `interval`:** `50` ms
- **Default `timeout`:** `1000` ms (`5000` ms in Browser Mode)

Configure defaults via [`expect.poll`](/config/test/expect#expectpoll); per-call `options` override the defaults:

- `interval`: Delay between attempts in milliseconds.
- `timeout`: Maximum polling duration in milliseconds before failing.
- `message`: Custom error message on timeout.

`expect.poll` does not support `.resolves`, `.rejects`, `.toThrow*`, or snapshot matchers. Use [`rs.waitFor`](/api/runtime-api/rstest/utilities#rswaitfor) for those cases.

```ts
await expect.poll(() => getStatus()).toBe('ready');

await expect
  .poll(
    async () => {
      const response = await fetch('/api/health');
      const data = await response.json();
      return data.status;
    },
    {
      interval: 100,
      timeout: 5000,
      message: 'Service should become healthy within 5s',
    },
  )
  .toBe('healthy');
```

## expect.unreachable

- **Type:** `(message?: string) => never`

Throws immediately when reached.

```ts
if (shouldNotHappen) {
  expect.unreachable('This should never happen');
}
```

## expect.assertions

- **Type:** `(expected: number) => void`

Verifies that `expected` assertions execute during the current test, typically to ensure async branches or `catch` blocks ran.

```ts
expect.assertions(1);

try {
  await someAsyncFunction();
} catch (e) {
  expect(e).toBeInstanceOf(Error);
}
```

## expect.hasAssertions

- **Type:** `() => void`

Verifies that at least one assertion executes during the current test.

```ts
expect.hasAssertions();
expect(1 + 1).toBe(2);
```

## expect.addEqualityTesters

- **Type:** `(testers: Tester[]) => void`

Registers custom equality testers for deep-equality matchers. Each tester returns `true` (equal), `false` (not equal), or `undefined` (fall through to the next tester or default equality).

Follows the same [file isolation rules](#expectaddsnapshotserializer) as snapshot serializers.

```ts
expect.addEqualityTesters([
  (a, b) => {
    if (typeof a === 'number' && typeof b === 'number') {
      return Math.abs(a - b) < 0.01;
    }
  },
]);
expect(0.1 + 0.2).toEqual(0.3);
```

## expect.addSnapshotSerializer

- **Type:** `(plugin: Parameters<ExpectStatic['addSnapshotSerializer']>[0]) => void`

Adds a custom serializer plugin (from `pretty-format`) for snapshot testing. Applies to the current test file and its hooks, with later serializers tried first. To register a serializer across all files in a project, add it in `setupFiles`.

In `vmThreads` and `vmForks` pools, the serializer list is restored after each file completes or fails (even when `isolate` is `false`). With `forks` or `threads` and `isolate: false`, serializers remain shared by files in the same worker, including across projects.

```ts
expect.addSnapshotSerializer({
  test: (val) => typeof val === 'string' && val.startsWith('secret:'),
  print: () => '***MASKED***',
});
expect('secret:123').toMatchSnapshot();
```

## expect.getState / expect.setState

- **Type:**
  - `getState: () => MatcherState`
  - `setState: (state: Partial<MatcherState>) => void`

Reads or updates the current matcher state (`MatcherState` is exported from `@rstest/core`).

```ts
const state = expect.getState();
console.log(state.currentTestName);
expect.setState({ currentTestName: 'custom name' });
```

## Matchers

### Common matchers

Equality and identity:

- `toBe(value)`: Strict equality using `Object.is`.
- `toEqual(value)`: Deep equality for objects and arrays.
- `toStrictEqual(value)`: Stricter deep equality (checks `undefined` properties and sparse arrays).
- `toBeOneOf(array)`: Value matches one of the candidates in `array`.

Type and existence:

- `toBeTruthy()` / `toBeFalsy()`: Truthiness checks.
- `toBeNull()` / `toBeUndefined()` / `toBeDefined()`: Nullish and defined checks.
- `toBeNaN()`: `NaN` check.
- `toBeInstanceOf(class)`: Prototype instance check.
- `toBeTypeOf(type)`: Runtime `typeof` check (for example `'string'`).

Numbers:

- `toBeGreaterThan(number)` / `toBeGreaterThanOrEqual(number)`
- `toBeLessThan(number)` / `toBeLessThanOrEqual(number)`
- `toBeCloseTo(number, numDigits?)`: Floating-point comparison within precision.

Collections and strings:

- `toContain(item)`: Array or string contains `item`.
- `toContainEqual(item)`: Array contains an element deep-equal to `item`.
- `toMatch(stringOrRegExp)`: String matches a substring or `RegExp`.
- `toMatchObject(object)`: Object matches a subset of properties.
- `toHaveLength(length)`: Checks `.length`.
- `toHaveProperty(path, value?)`: Checks property existence at `path` and optional value.

Custom predicates and errors:

- `toSatisfy(fn)`: Passes the user-defined predicate `fn`.
- `toThrowError(expected?)`: Wrapped function throws a matching error (string, `RegExp`, error instance, or constructor).

```ts
expect(1 + 1).toBe(2);
expect({ id: 1, name: 'a' }).toEqual({ id: 1, name: 'a' });
expect({ a: undefined, b: 1 }).toStrictEqual({ a: undefined, b: 1 });

expect(0.1 + 0.2).toBeCloseTo(0.3, 5);
expect(10).toBeGreaterThan(5);

expect([1, 2, 3]).toContain(2);
expect([{ id: 1 }]).toContainEqual({ id: 1 });
expect({ user: { role: 'admin' } }).toHaveProperty('user.role', 'admin');
expect({ id: 1, role: 'admin', active: true }).toMatchObject({
  id: 1,
  role: 'admin',
});

expect('request id: 42').toMatch(/id:\s\d+/);
expect(21).toSatisfy((n) => n % 3 === 0);

expect(() => {
  throw new TypeError('invalid input');
}).toThrowError(TypeError);
```

### Mock matchers

Verify calls, order, return values, and promise resolutions on `rs.fn` / `rs.spyOn` mocks (`Nth` matchers are 1-based):

Call assertions:

- `toHaveBeenCalled()`
- `toHaveBeenCalledTimes(times)`
- `toHaveBeenCalledWith(...args)`
- `toHaveBeenLastCalledWith(...args)`
- `toHaveBeenNthCalledWith(n, ...args)`
- `toHaveBeenCalledExactlyOnceWith(...args)`
- `toHaveBeenCalledBefore(mock, failIfNoFirstInvocation?)` / `toHaveBeenCalledAfter(mock, failIfNoFirstInvocation?)`

Return assertions:

- `toHaveReturned()`
- `toHaveReturnedTimes(times)`
- `toHaveReturnedWith(value)`
- `toHaveLastReturnedWith(value)`
- `toHaveNthReturnedWith(n, value)`

Promise resolution assertions:

- `toHaveResolved()`
- `toHaveResolvedTimes(times)`
- `toHaveResolvedWith(value)`
- `toHaveLastResolvedWith(value)`
- `toHaveNthResolvedWith(n, value)`

```ts
const sum = rs.fn((a: number, b: number) => a + b);
sum(1, 2);
sum(2, 3);

expect(sum).toHaveBeenCalledTimes(2);
expect(sum).toHaveBeenNthCalledWith(1, 1, 2);
expect(sum).toHaveBeenLastCalledWith(2, 3);
expect(sum).toHaveReturnedWith(3);
expect(sum).toHaveLastReturnedWith(5);

const fetchUser = rs.fn(async (id: number) => ({ id, name: 'alice' }));
await fetchUser(1);
await fetchUser(2);

expect(fetchUser).toHaveResolvedTimes(2);
expect(fetchUser).toHaveNthResolvedWith(1, { id: 1, name: 'alice' });

const before = rs.fn();
const after = rs.fn();
before();
after();
expect(before).toHaveBeenCalledBefore(after);
```

### Snapshot matchers

See [Snapshot](/guide/basic/snapshot) for snapshot configuration, updates, and serialization rules.

- `toMatchSnapshot(propertiesOrMessage?, message?)`: Compares against a saved `.snap` file.
- `toMatchInlineSnapshot(propertiesOrSnapshot?, snapshotOrMessage?, message?)`: Compares against an inline snapshot in the test file.
- `toThrowErrorMatchingSnapshot(message?)`: Checks that a thrown error matches a saved snapshot.
- `toThrowErrorMatchingInlineSnapshot(snapshot?, message?)`: Checks that a thrown error matches an inline snapshot.
- `toMatchFileSnapshot(filepath, message?)`: Async matcher comparing against a dedicated file.

```ts
expect('hello world').toMatchSnapshot();

expect(() => {
  throw new Error('fail');
}).toThrowErrorMatchingSnapshot();

await expect('hello world').toMatchFileSnapshot(
  '__snapshots__/file.output.txt',
);
```

### Promise matchers

- `resolves`: Unwraps a fulfilled promise before applying the chained matcher.
- `rejects`: Unwraps a rejected promise before applying the chained matcher.

```ts
await expect(Promise.resolve('ok')).resolves.toBe('ok');
await expect(Promise.reject(new Error('fail'))).rejects.toThrow('fail');
```

### Asymmetric matchers

Match partial shapes, constructors, or patterns inside equality assertions:

- `expect.anything()`: Any value except `null` and `undefined`.
- `expect.any(constructor)`: Any value matching `constructor`.
- `expect.closeTo(number, precision?)`: Number within floating-point precision.
- `expect.arrayContaining(array)`: Array containing all elements in `array`.
- `expect.objectContaining(object)`: Object containing all properties in `object`.
- `expect.stringContaining(string)`: String containing `string`.
- `expect.stringMatching(stringOrRegExp)`: String matching `stringOrRegExp`.

```ts
expect({ a: 1 }).toEqual({ a: expect.anything() });
expect(1).toEqual(expect.any(Number));
expect(0.1 + 0.2).toEqual(expect.closeTo(0.3, 5));
expect([1, 2, 3]).toEqual(expect.arrayContaining([2, 1]));
expect({ a: 1, b: 2 }).toEqual(expect.objectContaining({ a: 1 }));
expect('hello world').toEqual(expect.stringContaining('world'));
expect('hello world').toEqual(expect.stringMatching(/^hello/));
```

### Custom matchers

Register custom matchers with `expect.extend`. In VM pools, custom matchers (including overrides of built-in matchers and asymmetric `expect.<matcher>` / `expect.not.<matcher>`) follow the same [file isolation rules](#expectaddsnapshotserializer) as snapshot serializers.

```ts
expect.extend({
  toBeDivisibleBy(received, argument) {
    const pass = received % argument === 0;
    return {
      pass,
      message: () =>
        pass
          ? `expected ${received} not to be divisible by ${argument}`
          : `expected ${received} to be divisible by ${argument}`,
    };
  },
});

expect(10).toBeDivisibleBy(2);
```

Augment `Assertion` in `@rstest/core` to add TypeScript types for custom matchers:

```ts
declare module '@rstest/core' {
  interface Assertion<T> {
    toBeDivisibleBy(argument: number): void;
  }
}
```
