# Describe

`describe` groups tests and nested suites into a test suite.

## describe

- **Type:**

```ts
(name: string | Function, fn?: () => void | Promise<void>, timeout?: number): void;
(name: string | Function, options: TestOptions, fn?: () => void | Promise<void>): void;
```

Defines a test suite containing test cases or nested `describe` blocks. If `fn` is async, Rstest awaits it during test collection before running the tests declared inside.

```ts
import { describe, expect, test } from '@rstest/core';

describe('math', () => {
  test('add', () => {
    expect(1 + 2).toBe(3);
  });
});
```

```ts
describe('async setup', async () => {
  const data = await loadFixtureData();

  test('uses collected data', () => {
    expect(data).toBeDefined();
  });
});
```

<ApiMeta addedVersion="0.12.3" />

You can pass a function as `name`. Rstest reads its `name` property without calling it (anonymous functions display as `<anonymous>`). This also applies to `describe.each` and `describe.for`.

```ts
function add(a: number, b: number) {
  return a + b;
}

describe(add, () => {
  test('adds numbers', () => {
    expect(add(1, 2)).toBe(3);
  });
});
```

### TestOptions

<ApiMeta addedVersion="0.11.0" />

Pass a [`TestOptions`](/api/runtime-api/test-api/test#testoptions) object as the **second argument** (before the suite callback) to set inheritable defaults (`timeout`, `retry`, `repeats`, and `meta`) for descendant suites and tests. Passing a number as the **last argument** sets `{ timeout: n }`.

- A test-level option always overrides the suite-level value.
- Nested `describe` blocks inherit parent options; the nearest enclosing value wins.
- If no `timeout` is set on a test or enclosing suite, Rstest falls back to [`test.testTimeout`](/config/test/test-timeout).
- `meta` <ApiMeta sup addedVersion="0.11.1" /> merges from parent suite to child suite or test: child top-level keys override parent keys, and inherited values are copied per descendant. See [Add metadata to a suite](/guide/advanced/metadata#add-metadata-to-a-suite).

```ts
describe('parent', { retry: 2, timeout: 100 }, () => {
  test('a', () => {
    /* retry: 2, timeout: 100 */
  });

  describe('child', { timeout: 200 }, () => {
    test('b', () => {
      /* retry: 2 (inherited), timeout: 200 (nearest wins) */
    });

    test('c', { retry: 0 }, () => {
      /* retry: 0 (own value wins), timeout: 200 */
    });
  });
});
```

## describe.only

Runs only the `describe` block(s) marked with `only` in the file.

```ts
describe.only('only this suite', () => {
  // ...
});
```

## describe.skip

Marks all tests in the `describe` block as skipped.

```ts
describe.skip('skipped suite', () => {
  // ...
});
```

The suite callback itself still executes during collection so Rstest can discover the skipped tests and track their snapshots. Test bodies inside it do not run:

```ts
describe.skip('a', () => {
  console.log('runs during collection');
  test('b', () => {
    console.log('will not run');
    expect(0).toBe(0);
  });
});
```

## describe.todo

Marks a `describe` block as todo.

```ts
describe.todo('should implement this suite');
```

## describe.each

- **Type:**

```ts
type DescribeCall<Fn> = {
  (name: string | Function, fn?: Fn, timeout?: number): void;
  (name: string | Function, options: TestOptions, fn?: Fn): void;
};

// Object rows: each row is passed as a single argument
describe.each<T extends Record<string, unknown>>(
  cases: readonly T[],
): DescribeCall<(param: T) => void | Promise<void>>;
// Tuple / array rows: every row is an array, spread into the arguments
describe.each<T extends readonly [unknown, ...unknown[]]>(
  cases: readonly T[],
): DescribeCall<(...args: [...T]) => void | Promise<void>>;
describe.each<T extends readonly unknown[]>(
  cases: readonly T[],
): DescribeCall<(...args: [...T]) => void | Promise<void>>;
// Mixed or scalar rows: each row is passed as a single argument
describe.each<T>(
  cases: readonly T[],
): DescribeCall<(param: T) => void | Promise<void>>;
// Tagged template literal table
describe.each<T extends Record<string, unknown>>(
  strings: TemplateStringsArray,
  ...expressions: unknown[]
): DescribeCall<(param: T) => void | Promise<void>>;
```

Creates a `describe` block for each entry in `cases` or in a tagged template table. Accepts the same optional [`TestOptions`](#testoptions) second argument and applies it to every generated suite.

```ts
describe.each([
  { a: 1, b: 2 },
  { a: 2, b: 3 },
])('math $a + $b', ({ a, b }) => {
  test('add', () => {
    // ...
  });
});
```

Rows are spread into `fn` arguments only when every row is an array. If any row is not an array, every row is passed as a single argument.

With tagged template literals, pass an explicit generic type parameter when you want typed row properties:

```ts
describe.each<{ a: number; b: number; expected: number }>`
  a    | b    | expected
  ${1} | ${2} | ${3}
  ${2} | ${3} | ${5}
`('$a + $b = $expected', ({ a, b, expected }) => {
  test('add', () => {
    expect(a + b).toBe(expected);
  });
});
```

## describe.for

- **Type:**

```ts
type DescribeCall<Fn> = {
  (name: string | Function, fn?: Fn, timeout?: number): void;
  (name: string | Function, options: TestOptions, fn?: Fn): void;
};

describe.for<T>(
  cases: readonly T[],
): DescribeCall<(param: T) => void | Promise<void>>;
describe.for<T extends Record<string, unknown>>(
  strings: TemplateStringsArray,
  ...expressions: unknown[]
): DescribeCall<(param: T) => void | Promise<void>>;
```

Alternative to `describe.each` that always passes each case as a single `param` argument without spreading array rows. Accepts the same optional [`TestOptions`](#testoptions) second argument.

```ts
describe.for([
  [1, 2],
  [2, 3],
])('math %i + %i', ([a, b]) => {
  test('add', () => {
    // ...
  });
});
```

Also supports tagged template literals with an optional explicit generic parameter:

```ts
describe.for<{ a: number; b: number; expected: number }>`
  a    | b    | expected
  ${1} | ${2} | ${3}
  ${2} | ${3} | ${5}
`('$a + $b = $expected', ({ a, b, expected }) => {
  test('add', () => {
    expect(a + b).toBe(expected);
  });
});
```

## describe.runIf

Runs the `describe` block only when `condition` is truthy.

```ts
describe.runIf(process.env.RUN_EXTRA === '1')('conditionally run', () => {
  // ...
});
```

## describe.skipIf

Skips the `describe` block when `condition` is truthy.

```ts
describe.skipIf(process.platform === 'win32')('skip on Windows', () => {
  // ...
});
```

## describe.concurrent

Runs the tests inside the `describe` block concurrently.

```ts
describe.concurrent('concurrent suite', () => {
  test('test 1', async () => {
    /* ... */
  });
  test('test 2', async () => {
    /* ... */
  });
});
```

## describe.sequential

Runs the tests inside the `describe` block sequentially (the default behavior).

```ts
describe.sequential('sequential suite', () => {
  test('test 1', async () => {
    /* ... */
  });
  test('test 2', async () => {
    /* ... */
  });
});
```

## Chainable modifiers

`describe` modifiers can be chained in any order before calling the suite function:

- `describe.only.runIf(condition)` / `describe.runIf(condition).only`
- `describe.skipIf(condition).concurrent` / `describe.concurrent.skipIf(condition)`
- `describe.runIf(condition).concurrent` / `describe.concurrent.runIf(condition)`
- `describe.only.concurrent` / `describe.concurrent.only`
- `describe.concurrent.each(cases)` / `describe.each(cases)` chained with `.only`, `.skip`, `.runIf`, or `.skipIf`
