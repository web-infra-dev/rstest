# Reporter API

Create custom test result processors and output formatters by implementing the `Reporter` interface. See the [Reporters guide](/guide/basic/reporters) for built-in reporters and configuration options.

## Using a custom reporter

Pass an object implementing `Reporter` to [`reporters`](/config/test/reporters):

```ts
import type { Reporter } from '@rstest/core';

export const customReporter: Reporter = {
  onTestFileStart(test) {
    console.log(`Starting: ${test.testPath}`);
  },

  onTestFileResult(result) {
    console.log(`Finished: ${result.testPath}`);
  },

  onTestRunEnd({ duration }) {
    console.log(`All tests completed in ${duration.totalTime}ms`);
  },
};
```

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';
import { customReporter } from './path/to/custom-reporter';

export default defineConfig({
  reporters: [customReporter],
});
```

When loading a reporter by module specifier (`reporters: [['./custom-reporter.js', options]]`), export a `Reporter` class as the default export. Rstest instantiates it with `(options, context)` where `context` is [`ReporterContext`](#reportercontext).

## Interface overview

`Reporter` exposes lifecycle hooks called during test execution:

- **File hooks**: `onTestFileStart`, `onTestFileReady`, `onTestFileResult`
- **Suite hooks**: `onTestSuiteStart`, `onTestSuiteResult`
- **Case hooks**: `onTestCaseStart`, `onTestCaseResult`
- **Run hooks**: `onTestRunStart`, `onTestRunEnd`, `onUserConsoleLog`, `onExit`

```ts
interface Reporter {
  /** Set to `false` when the reporter does not write to process stdout/stderr. Default: `true`. */
  flushOutputStreams?: boolean;
  onTestRunStart?(payload: TestRunStartPayload): MaybePromise<void>;
  onTestFileStart?(test: TestFileInfo): MaybePromise<void>;
  onTestFileReady?(test: TestFileInfo): MaybePromise<void>;
  onTestFileResult?(test: TestFileResult): MaybePromise<void>;
  onTestSuiteStart?(test: TestSuiteInfo): MaybePromise<void>;
  onTestSuiteResult?(result: TestResult): MaybePromise<void>;
  onTestCaseStart?(test: TestCaseInfo): MaybePromise<void>;
  onTestCaseResult?(result: TestResult): MaybePromise<void>;
  onTestRunEnd?(payload: TestRunEndPayload): MaybePromise<void>;
  onUserConsoleLog?(log: UserConsoleLog): MaybePromise<void>;
  onExit?(): MaybePromise<void>;
}
```

- `flushOutputStreams`: By default, Rstest flushes `process.stdout` and `process.stderr` after each reporter's `onTestRunEnd` hook. Set `flushOutputStreams: false` when a reporter does not write to stdio streams.
- `onTestSuiteResult`: `result.errors` contains only suite hook errors (`beforeAll` and `afterAll`).
- **Metadata** <ApiMeta sup addedVersion="0.11.1" />: Runtime metadata written via `context.task.meta` is available on `TestResult.meta` in `onTestCaseResult`. Hook metadata written via `ctx.meta` is available on the corresponding `TestResult.meta` in `onTestSuiteResult`, and file-level hook metadata is available on `TestFileResult.meta` in `onTestFileResult`.
- **`onExit`** <ApiMeta sup addedVersion="0.12.0" />: Called when the reporter's owning context is released after a normal run or merge completion, watch close, startup failure, or abnormal CLI exit. Use it to release resources such as streams or renderers. Errors thrown by `onExit` do not replace the operation's result or error. (List contexts do not attach reporters, so `onExit` does not run for `listTests`.)

### onTestRunStart

<ApiMeta addedVersion="0.13.0" />

Called before test execution begins. In watch mode, `files` contains only the files selected for the current rerun cycle, not accumulated session results. Import `TestRunStartPayload` from `@rstest/core`.

- **Type:**

```ts
interface TestRunStartPayload {
  files: {
    testPath: string;
    project: string;
    testId: string;
  }[];
}
```

### onTestRunEnd

<ApiMeta addedVersion="0.12.0" /> <ApiMeta addedVersion="0.13.0" />

Called when a run cycle finishes with that cycle's results, summary, duration, and status. See [`rstest.run`](/api/javascript-api/instance#rstestrun) for the meaning of each `status` value.

- **Type:**

```ts
type TestRunStatus = 'passed' | 'failed' | 'error';

interface TestRunEndPayload {
  status: TestRunStatus;
  results: TestFileResult[]; // File results; in watch mode, accumulated over the session.
  testResults: TestResult[]; // All test case results, not grouped by file.
  summary: {
    tests: {
      total: number;
      passed: number;
      failed: number;
      skipped: number;
      todo: number;
      flaky: number; // Passed tests that required a retry.
    };
    files: {
      total: number;
      failed: number;
    };
  };
  duration: {
    totalTime: number; // Total elapsed duration in milliseconds.
    buildTime: number; // Compilation and environment preparation duration in milliseconds.
    prebundleTime?: Record<string, number>; // Prebundle time per environment package in milliseconds, included in buildTime.
    testTime: number; // Test execution duration in milliseconds.
  };
  snapshotSummary: SnapshotSummary;
  unhandledErrors: SerializedError[];
  coverage?: CoverageMapData; // Present when coverage is enabled.
  rerunTestPaths?: string[]; // Watch only: files executed in the current cycle.
  getSourcemap: (sourcePath: string) => Promise<SourceMapInput | null>; // Resolves the source map of a built file.
}
```

In watch mode, `results`, `testResults`, and `summary` accumulate over the session: each file keeps its latest result and deleted files are removed. `rerunTestPaths` lists the files executed in the current cycle and is absent for one-shot runs. Every entry in `unhandledErrors` is a plain JSON-serializable object.

`duration.prebundleTime` <ApiMeta sup addedVersion="0.12.7" /> reports the time spent building each environment package prebundle in milliseconds and is included in `duration.buildTime`.

When test groups start as their build outputs become ready, `buildTime` runs from the start of the run until the last group is ready (including environment preparation). `testTime` covers the rest of the timed run after that point (including worker cleanup), plus any earlier time while at least one test group was executing (including worker preparation). Concurrent groups count once, and build-only gaps count toward `buildTime`. Because the two phases can overlap, their sum is at least `totalTime`; use `totalTime` for elapsed wall-clock duration.

### TestResult

Passed to `onTestSuiteResult` and `onTestCaseResult`. Exported from `@rstest/core`.

- **Type:**

```ts
type TestResultStatus = 'skipped' | 'passed' | 'failed' | 'todo';

interface SerializedError {
  name?: string;
  message: string;
  stack?: string;
  diff?: string;
  expected?: string;
  actual?: string;
  retryCount?: number;
  fullStack?: boolean;
  cause?: SerializedError;
}

interface TestResult {
  testId: string;
  status: TestResultStatus;
  name: string;
  fullName: string; // Parent suite names and name joined with ` > `.
  testPath: string; // Absolute path of the owning test file.
  relativeTestPath: string; // POSIX path relative to rootPath.
  parentNames?: string[];
  duration?: number; // Execution duration in milliseconds.
  errors?: SerializedError[]; // Errors from the final attempt (or suite hooks for suites).
  retryErrors?: SerializedError[]; // Errors from earlier retry attempts.
  retryCount?: number;
  project: string;
  meta?: TaskMeta;
  heap?: number; // Heap usage in bytes when logHeapUsage is enabled.
}
```

### TestFileResult

Passed to `onTestFileResult` and included in `onTestRunEnd`. Extends `TestResult` with file-level results and summary. Exported from `@rstest/core`.

- **Type:**

```ts
interface TestFileResult extends TestResult {
  loadDuration?: number;
  results: TestResult[];
  summary: {
    total: number;
    passed: number;
    failed: number;
    skipped: number;
    todo: number;
    flaky: number;
  };
  snapshotResult?: SnapshotResult; // From @vitest/snapshot.
  coverage?: Record<string, FileCoverageData>; // From istanbul-lib-coverage when coverage is enabled.
}
```

#### File timing

<ApiMeta addedVersion="0.12.6" />

In Node pools, `loadDuration` measures worker-side asset loading, setup file execution, and test module evaluation and collection in milliseconds. It is recorded even when loading fails, and is absent if loading did not start or in browser mode. `duration` measures test execution, including hooks and snapshot finalization. Their sum is used for Node test file scheduling and excludes worker startup, environment initialization, queue wait, and worker teardown.

## Examples

### Simple custom reporter

```ts
import type { Reporter } from '@rstest/core';

const simpleReporter: Reporter = {
  onTestFileStart(test) {
    console.log(`Starting: ${test.testPath}`);
  },

  onTestCaseResult(result) {
    const status = result.status === 'passed' ? 'PASS' : 'FAIL';
    console.log(`${status} ${result.name}`);
  },

  onTestRunEnd({ results }) {
    const passed = results.filter((r) => r.status === 'passed').length;
    const failed = results.filter((r) => r.status === 'failed').length;
    console.log(`\n${passed} passed, ${failed} failed`);
  },
};
```

### File output reporter

```ts
import { writeFileSync } from 'node:fs';
import type { Reporter } from '@rstest/core';

const jsonReporter: Reporter = {
  flushOutputStreams: false,
  onTestRunEnd({ results }) {
    const report = {
      timestamp: new Date().toISOString(),
      results: results.map((r) => ({
        path: r.testPath,
        status: r.status,
        duration: r.duration,
        errors: r.errors,
      })),
    };

    writeFileSync('test-report.json', JSON.stringify(report, null, 2));
  },
};
```

### Reading runtime metadata

```ts
import type { Reporter } from '@rstest/core';

const metadataReporter: Reporter = {
  onTestCaseResult(result) {
    console.log(result.name, result.meta);
  },

  onTestSuiteResult(result) {
    console.log(result.name, result.meta);
  },

  onTestFileResult(result) {
    console.log(result.testPath, result.meta);
  },
};
```
