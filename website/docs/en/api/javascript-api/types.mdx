# Rstest types

Rstest exports its public TypeScript types from `@rstest/core`. Use `import type` so these imports are erased from runtime output.

```ts
import type { Mock, Mocked, RstestConfig } from '@rstest/core';
```

## Configuration types

Use these types when typing config objects, config factories, adapters, or custom coverage providers outside [`defineConfig`](/api/javascript-api/rstest-core#defineconfig), [`defineProject`](/api/javascript-api/rstest-core#defineproject), and [`defineInlineProject`](/api/javascript-api/rstest-core#defineinlineproject).

```ts
import type {
  BrowserExpectConfig,
  BrowserInstanceConfig,
  BrowserName,
  BrowserViewport,
  CoverageOptions,
  CoverageProvider,
  ExpectConfig,
  ExpectPollConfig,
  ExtendConfig,
  ExtendConfigFn,
  NormalizedConfig,
  NormalizedCoverageOptions,
  ProjectConfig,
  ResolvedRstestConfig,
  RstestCommand,
  RstestConfig,
  RstestConfigAsyncFn,
  RstestConfigExport,
  RstestConfigSyncFn,
} from '@rstest/core';
```

- `RstestConfig`: Top-level Rstest configuration object.
- `RstestConfigSyncFn` / `RstestConfigAsyncFn`: Synchronous and asynchronous config factory functions returning `RstestConfig`.
- `RstestConfigExport`: Union of `RstestConfig`, `RstestConfigSyncFn`, and `RstestConfigAsyncFn`.
- `ProjectConfig`: Configuration type for a standalone [Rstest Project](/guide/basic/projects).
- `NormalizedConfig`: Normalized configuration exposed on `rstest.context.config` and `ReporterContext.config`.
- `ResolvedRstestConfig`: `RstestConfig` after CLI flags (such as `shard`) are merged in.
- `ExtendConfig` / `ExtendConfigFn`: Return value and callback types accepted by [`extends`](/config/test/extends) and config adapters.
- `RstestCommand`: Active CLI command (`'watch' | 'run' | 'list' | 'merge-reports'`).
- `ExpectConfig` / `ExpectPollConfig`: Configuration types for [`expect`](/config/test/expect) and `expect.poll`.
- `CoverageOptions` / `CoverageProvider` / `NormalizedCoverageOptions`: Coverage config and custom coverage provider types (`KnownCoverageStructure` and `RawCoverageResolveOptions` are also exported for custom provider implementations).
- `BrowserInstanceConfig` / `BrowserExpectConfig` / `BrowserName` / `BrowserViewport`: Browser Mode instance, assertion, browser name, and viewport types.

## Test API types

Use these types when extending test APIs, defining reusable helpers, or typing custom fixtures.

```ts
import type {
  Describe,
  Expect,
  ExpectStatic,
  FileFixtureOptions,
  FixtureCleanup,
  FixtureLifecycle,
  Fixtures,
  MaybePromise,
  Rstest,
  RstestUtilities,
  TaskMeta,
  TaskMetaValue,
  TestAPIs,
  TestContext,
  TestForFn,
  TestOptions,
  Use,
  WorkerFixtureOptions,
} from '@rstest/core';
```

<ApiMeta addedVersion="0.10.1" /> <ApiMeta addedVersion="0.11.7" />

- `Rstest`: Full runtime API surface (`test`, `it`, `describe`, `expect`, `assert`, hooks, `rs`, and `rstest`).
- `RstestUtilities`: Type of the `rs` and `rstest` utility objects.
- `TestContext`: Context object passed to test callbacks and per-test hooks (`TestContext` is exported since `0.10.1`).
- `TestOptions`: Per-test and per-suite options (`timeout`, `retry`, `repeats`, `meta`).
- `TestAPIs`: Return type of `test.extend(...)`, exposing `test` modifiers and chained `.extend()`.
- `TestForFn`: Call signature type of `test.for`.
- `Describe`: Type of the `describe` API.
- `Expect` / `ExpectStatic`: Callable `expect` API type (`Expect` is an alias of `ExpectStatic`).
- `TaskMeta` / `TaskMetaValue`: JSON-serializable metadata map and value types.
- `Fixtures` / `Use`: Fixtures object map and `use(value)` callback type for `test.extend`.
- `FileFixtureOptions` / `WorkerFixtureOptions`: Scope options (`{ scope: 'file' }` and `{ scope: 'worker' }`) for named fixtures.
- `FixtureCleanup` / `FixtureLifecycle`: Cleanup callback and `{ onCleanup }` lifecycle parameter for named fixtures (added in `0.11.7`).
- `MaybePromise<T>`: Utility union `T | Promise<T>`.

## Mock and timer types

Use these types when helpers accept mock functions, spies, mocked modules, or real timers.

```ts
import type { Mock, Mocked, MockInstance, RealTimers } from '@rstest/core';
```

### Mock

`Mock<T>` represents a callable mock function created by [`rs.fn`](/api/runtime-api/rstest/mock-functions#rsfn). It preserves the parameters and return type of `T` and adds mock control methods.

```ts
import { rs } from '@rstest/core';
import type { Mock } from '@rstest/core';

type LoadUser = (id: string) => Promise<{ name: string }>;

const loadUser: Mock<LoadUser> = rs.fn<LoadUser>();
loadUser.mockResolvedValue({ name: 'Jack' });
```

### MockInstance

<ApiMeta addedVersion="0.10.1" />

`MockInstance<T>` represents the shared mock control interface on `rs.fn()` mocks and `rs.spyOn()` spies. Use it when a helper only calls control methods (`mockClear`, `mockReset`, `mockRestore`, etc.) without invoking the mock directly.

```ts
import type { MockInstance } from '@rstest/core';

function resetTrackedMock(mock: MockInstance) {
  mock.mockReset();
}
```

### Mocked

`Mocked<T>` wraps an object or module type so its methods are typed as mocks. Use it with [`rs.mock`](/api/runtime-api/rstest/mock-modules#rsmock), [`rs.mockObject`](/api/runtime-api/rstest/mock-functions#rsmockobject), or [`rs.mocked`](/api/runtime-api/rstest/mock-functions#rsmocked).

```ts
import { rs } from '@rstest/core';
import type { Mocked } from '@rstest/core';
import * as userApi from './userApi';

rs.mock('./userApi');

const mockedUserApi: Mocked<typeof userApi> = rs.mocked(userApi);
mockedUserApi.loadUser.mockResolvedValue({ name: 'Jack' });
```

### RealTimers

`RealTimers` is the return type of [`rs.getRealTimers()`](/api/runtime-api/rstest/fake-timers#rsgetrealtimers), exposing the unmocked `setTimeout`, `clearTimeout`, and optional `setImmediate` functions.

## Reporter and result types

Use these types when building custom reporters or consuming Rstest run results. See [Reporter](/api/javascript-api/reporter) for full interface definitions.

```ts
import type {
  CoverageMapData,
  Duration,
  GetSourcemap,
  Reporter,
  ReporterContext,
  SerializedError,
  SnapshotSummary,
  SourceMapInput,
  TestCaseInfo,
  TestFileInfo,
  TestFileResult,
  TestInfo,
  TestResult,
  TestResultStatus,
  TestRunEndPayload,
  TestRunStartPayload,
  TestRunStatus,
  TestRunSummary,
  TestSuiteInfo,
  UserConsoleLog,
} from '@rstest/core';
```

- `Reporter` / `ReporterContext`: Custom reporter interface and constructor context (`{ rootPath, config }`).
- `TestFileInfo` / `TestSuiteInfo` / `TestCaseInfo` / `TestInfo`: Discovery and lifecycle task metadata passed to reporter start/ready hooks.
- `TestResult` / `TestFileResult` / `TestResultStatus`: Per-case, per-suite, and per-file execution results and status union (`'skipped' | 'passed' | 'failed' | 'todo'`).
- `TestRunStartPayload` / `TestRunEndPayload` / `TestRunStatus` / `TestRunSummary`: Run-level hook payloads, run status (`'passed' | 'failed' | 'error'`), and aggregate counts.
- `Duration` / `SerializedError` / `UserConsoleLog`: Phase timings, JSON-serializable errors, and captured stdio log records.
- `GetSourcemap` / `SourceMapInput` / `SnapshotSummary` / `CoverageMapData`: Source map resolver, snapshot summary, and Istanbul coverage map types.

<ApiMeta addedVersion="0.11.1" />

`meta` fields hold JSON-serializable metadata initialized from `TestOptions.meta` and updated via `context.task.meta` or hook `ctx.meta`. Suite metadata propagates to descendant suites and tests (copied per descendant, with child top-level keys overriding parent keys).

```ts
import { afterAll, test } from '@rstest/core';

afterAll((ctx) => {
  ctx.meta.fileTag = 'mutation-run';
});

test('records metadata', { meta: { owner: 'stryker' } }, (ctx) => {
  ctx.task.meta.hitCount = 1;
});
```

## Assertion types

Use these types when typing custom assertion helpers or augmenting matchers.

```ts
import type {
  Assertion,
  AsymmetricMatchersContaining,
  ExpectStatic,
  Matchers,
} from '@rstest/core';

function expectVisible(
  expect: ExpectStatic,
  value: HTMLElement,
): Assertion<HTMLElement> {
  return expect(value);
}
```

- `Assertion<T>`: Chainable assertion object returned by `expect(value)`.
- `ExpectStatic`: Callable `expect` function type with static helpers (`poll`, `soft`, `extend`, etc.).
- `Matchers<R, T>` / `AsymmetricMatchersContaining`: Matcher interfaces from `@vitest/expect` for module augmentation or custom matcher typing.

## Rsbuild and plugin types

Rstest re-exports `Rspack` and `RsbuildPlugin` from `@rsbuild/core`, along with `RstestExposeAPI` for Rsbuild plugins that read or modify the resolved Rstest config via `api.useExposed('rstest')`.

```ts
import type { RsbuildPlugin, Rspack, RstestExposeAPI } from '@rstest/core';
```
