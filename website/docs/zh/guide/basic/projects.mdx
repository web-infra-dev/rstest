# 多项目测试

Rstest 支持在单个进程中同时运行多个测试项目，每个项目可以有独立的测试配置与运行环境。

在 Node.js 模式下单次全量运行时，如果没有开启覆盖率、bail 或失败筛选，先完成构建的项目可以在其他项目构建期间开始测试。配置了 `globalSetup` 或使用需要在 `onTestRunStart` 接收完整文件清单的 reporter 时，Rstest 会等所有项目构建完成再派发测试。

## 适用场景

- **Monorepo 项目**：各子包或应用需要各自的测试配置与构建设置。
- **混合测试环境**：在同一仓库里同时运行 Node.js、`jsdom` 与 Browser Mode 测试。
- **按目录区分配置**：为不同测试目录指定不同的超时时间、setup 文件或插件。

## 示例

在根配置中通过 [projects](/config/test/projects) 指定工作区目录。Rstest 会把匹配的每个子目录识别为独立测试项目，并加载子目录中的 [rstest.config.ts](/guide/basic/configure-rstest#配置文件)（如果存在）：

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  projects: [
    // 将 packages 下的每个子目录作为独立测试项目
    'packages/*',
  ],
});
```

## 配置说明

配置了 [projects](/config/test/projects) 后，Rstest 会按各个项目的配置运行对应测试，并把结果合并输出。

- 未配置 `projects` 时，Rstest 将当前目录视为单个项目。
- 将 `projects` 设为空数组（`[]`）时，Rstest 会抛出 `No projects found` 错误。
- 所有解析出的项目必须具有唯一的 `name`，重名会在启动时报错并列出冲突项目。

### 配置语法

`projects` 支持以下配置形式：

- **目录路径**：加载指定目录下的项目及其配置文件（如果存在）。
- **配置文件路径**：按指定配置文件运行一个项目。
- **glob 模式**：批量匹配多个项目目录或配置文件。
- **内联配置对象**：通过 `defineInlineProject` 直接在 `projects` 中声明项目配置，无需单独新建配置文件。
- **嵌套 projects**：在子项目的配置文件中继续定义 `projects`。

```ts title="rstest.config.ts"
import { defineConfig, defineInlineProject } from '@rstest/core';

export default defineConfig({
  projects: [
    // packages 下的每个子目录作为一个项目
    'packages/*',

    // apps 目录下所有包含 rstest 配置文件的项目
    'apps/**/rstest.config.ts',

    // 指定的项目目录
    '<rootDir>/services/auth',

    // 指定的项目配置文件
    './projects/web/rstest.config.ts',

    // 内联项目配置
    defineInlineProject({
      name: 'node',
      include: ['tests/node/**/*.{test,spec}.{js,cjs,mjs,ts,tsx}'],
    }),
    defineInlineProject({
      name: 'react',
      include: ['tests/react/**/*.{test,spec}.{js,cjs,mjs,ts,tsx}'],
      testEnvironment: 'jsdom',
    }),
  ],
});
```

### 根目录配置

当根目录的配置文件声明了 `projects` 时，根目录本身不再作为测试项目，该文件仅用于定义 `projects` 和[全局配置](#全局配置)。

如果需要同时运行根目录下的测试，可以在 `projects` 中为根目录添加一个内联项目：

```ts title="rstest.config.ts"
import { defineConfig, defineInlineProject } from '@rstest/core';

export default defineConfig({
  projects: [
    defineInlineProject({
      name: 'root',
      include: ['<rootDir>/tests/**/*.{test,spec}.{js,cjs,mjs,ts,tsx}'],
    }),
    'packages/*',
  ],
});
```

#### 全局配置

以下选项属于全局配置，在单个 project 中设置无效。请在根目录配置文件中设置，或通过对应的 [CLI 选项](/guide/basic/cli#cli-选项)（如 `--reporters`、`--pool`、`--isolate`、`--coverage`、`--bail`、`--teardownTimeout`）在命令行覆盖：

- `reporters`：全局报告器配置。
- `pool`：worker pool 配置。
- `isolate`：环境隔离开关。
- `coverage`：代码覆盖率配置。
- `bail`：失败次数达到阈值时提前中止运行。
- `teardownTimeout`：`rstest run` 结束后的进程退出超时时间。
- `resolveSnapshotPath`：快照文件路径解析函数（仅配置文件支持）。
- `onConsoleLog`：控制台日志过滤函数（仅配置文件支持）。
- `output.distPath`：全局输出目录路径（仅配置文件支持）。

### Project 配置

#### 配置定义

Project 配置支持除[全局配置](#全局配置)之外的大部分 Rstest 选项。

在任何 `projects` 数组（包括嵌套 `projects`）中声明内联项目时，请使用 [defineInlineProject](/api/javascript-api/rstest-core#defineinlineproject)；在独立项目配置文件的顶层导出时，请使用 [defineProject](/api/javascript-api/rstest-core#defineproject)。

- `defineProject` 接受配置对象或同步/异步工厂函数（`() => ...` / `async () => ...`），且可省略 `name`（Rstest 会按 [name](/config/test/name) 规则自动推导）。
- `defineInlineProject` 要求每个内联项目都显式提供 `name`。

```ts title="packages/pkg-a/rstest.config.ts"
import { defineProject } from '@rstest/core';

export default defineProject({
  name: 'pkg-a',
  include: ['tests/**/*.{test,spec}.{js,cjs,mjs,ts,tsx}'],
});
```

#### 配置复用

Project 配置不会继承根目录的配置，根配置中只有 `projects` 和[全局配置](#全局配置)对整个运行生效。

如需在多个子项目间复用配置，可以抽离共享配置并通过 [mergeProjectConfig](/api/javascript-api/rstest-core#mergeprojectconfig) 或 [mergeRstestConfig](/api/javascript-api/rstest-core#mergerstestconfig) 合并：

```ts title="packages/pkg-a/rstest.config.ts"
import { mergeProjectConfig } from '@rstest/core';
import sharedConfig from '../shared/rstest.config';

export default mergeProjectConfig(sharedConfig, {
  name: 'pkg-a',
});
```

通过 [CLI 选项](/guide/basic/cli#cli-选项)（例如 `--testTimeout`、`--testEnvironment`、`--globals`）传入的参数会覆盖所有项目中的对应字段。

### 嵌套 projects

子项目的配置文件也可以嵌套定义 `projects`，无需把所有变体都写在根目录配置里。

例如，在 `packages/pkg-a` 下拆分 Node.js 和 `jsdom` 两个测试项目：

```ts title="packages/pkg-a/rstest.config.ts"
import { defineProject, defineInlineProject } from '@rstest/core';

export default defineProject({
  projects: [
    defineInlineProject({
      name: 'node',
      include: ['tests/node/**/*.{test,spec}.?(c|m)[jt]s?(x)'],
    }),
    defineInlineProject({
      name: 'react',
      include: ['tests/react/**/*.{test,spec}.?(c|m)[jt]s?(x)'],
      testEnvironment: 'jsdom',
    }),
  ],
});
```

### Browser mode 中的 projects

每个 Browser Mode 项目都会使用各自的构建配置独立编译并运行，不同技术栈或插件配置的项目可以在同一个 Rstest 进程中执行。

目前唯一支持的 `provider` 是 `'playwright'`。同一次运行中可以通过 `browser.instances` 在不同项目间使用不同浏览器，或将 Browser Mode 项目与 `testEnvironment: 'node'` / `'jsdom'` 项目混跑，但需满足以下约束：

- **每次运行最多只能有一个 headed 浏览器**：最多只能有一对 `(project, browser)` 以 `headless: false` 运行，其余所有浏览器必须设为 `headless: true`。若多浏览器运行搭配 `--browser.headless=false` 报错，可用 `--browser.instances <name>` 或 `--project` 缩小到单个浏览器。
- **Watch 模式不支持混用 headed 与 headless**：`rstest watch` 下所有配置的浏览器都必须为 `headless: true`。如需混用 headed 与 headless，请使用 `rstest run`。
- **汇报名称不能冲突**：运行多个浏览器的项目会以 `<project> (<browser>)` 的名称汇报结果，请避免该名称与其他项目的 `name` 重复。

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  projects: ['./project-a/rstest.config.ts', './project-b/rstest.config.ts'],
});
```

```ts title="project-a/rstest.config.ts"
import { pluginReact } from '@rsbuild/plugin-react';
import { defineProject } from '@rstest/core';

export default defineProject({
  name: 'project-a',
  plugins: [pluginReact()],
  include: ['tests/**/*.test.tsx'],
  browser: {
    enabled: true,
    provider: 'playwright',
    instances: [{ browserName: 'chromium' }],
  },
});
```

```ts title="project-b/rstest.config.ts"
import { defineProject } from '@rstest/core';

export default defineProject({
  name: 'project-b',
  include: ['tests/**/*.test.ts'],
  browser: {
    enabled: true,
    provider: 'playwright',
    instances: [{ browserName: 'firefox', headless: true }],
  },
});
```

### 查看配置

如需查看各项目最终生效的配置，可通过 `DEBUG=rstest` 开启[调试模式](/guide/debug/debugging#开启调试模式)，Rstest 会把最终的 Rstest 配置和构建配置写入输出目录。

## 过滤项目

可通过 [`--project`](/guide/basic/test-filter#根据项目名称过滤) 按名称或通配符筛选项目，也可以结合文件名或路径筛选具体测试文件。详见[过滤测试](/guide/basic/test-filter)。
