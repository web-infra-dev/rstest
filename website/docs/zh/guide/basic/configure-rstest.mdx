# 配置 Rstest

## 配置文件

运行 Rstest CLI 时，Rstest 会按以下顺序自动查找项目根目录下的配置文件：

- `rstest.config.mts`
- `rstest.config.mjs`
- `rstest.config.ts`
- `rstest.config.js`
- `rstest.config.cjs`
- `rstest.config.cts`

TypeScript 项目建议使用 `.ts` 或 `.mts` 配置文件，并从 `@rstest/core` 导入 [`defineConfig`](/api/javascript-api/rstest-core#defineconfig) 以获得类型检查和自动补全；非 TypeScript 项目可使用 `.mjs`：

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  testEnvironment: 'node',
});
```

如果需要动态计算配置，`defineConfig` 也支持传入同步或异步工厂函数：

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig(async () => ({
  testTimeout: process.env.CI ? 10_000 : 5_000,
}));
```

针对多 project 工作区和编程式组合配置，`@rstest/core` 还导出了 [`defineProject`](/api/javascript-api/rstest-core#defineproject)、[`mergeRstestConfig`](/api/javascript-api/rstest-core#mergerstestconfig) 和 [`mergeProjectConfig`](/api/javascript-api/rstest-core#mergeprojectconfig)。其中 `defineProject` 同样支持同步和异步函数写法。

### 指定配置文件

通过 `--config`（或缩写 `-c`）指定配置文件的相对路径或绝对路径：

```json title="package.json"
{
  "scripts": {
    "test": "rstest --config scripts/rstest.config.mjs"
  }
}
```

```bash
rstest -c scripts/rstest.config.mjs
```

- 使用 `-r, --root <root>` 覆盖项目根目录（决定配置文件查找起点和 `<rootDir>` 的解析基准）。
- 使用 `--config-loader <loader>` 指定配置文件加载器：`auto`（默认值）、`jiti` 或 `native`。详见 [Rsbuild - 指定加载方式](https://rsbuild.rs/zh/guide/configuration/rsbuild#specify-config-loader)。

## 配置 Rsbuild

Rstest 基于 Rsbuild 构建测试文件，支持直接配置大部分 Rsbuild 构建选项：

- 通过 [plugins](/config/build/plugins) 注册 Rsbuild 插件
- 在 Rsbuild 插件中[读取](/config/build/plugins#get-rstest-config)或[修改](/config/build/plugins#modify-rstest-config)当前 Rstest project 配置
- 通过 [resolve](/config/build/resolve) 配置模块解析行为
- 通过 [tools.rspack](/config/build/tools#toolsrspack) 自定义 Rspack 配置
- 通过 [tools.swc](/config/build/tools#toolsswc) 配置 `builtin:swc-loader`

全部可用构建选项详见[构建配置](/config/#build-configurations)。

## 配置 Rspack

Rstest 底层使用 Rspack 打包，可通过 `tools.rspack` 直接传入 Rspack 配置项。详情参考[配置 Rspack](https://rsbuild.rs/zh/guide/configuration/rspack)。

## 配置 SWC

Rstest 默认使用 Rspack 的 [builtin:swc-loader](https://rspack.rs/zh/guide/features/builtin-swc-loader) 编译 JavaScript 和 TypeScript，可通过以下选项配置：

- [tools.swc](/config/build/tools#toolsswc)：传给 `builtin:swc-loader` 的选项
- [source.include](/config/build/source#sourceinclude)：指定需要经由 SWC 编译的文件
- [source.exclude](/config/build/source#sourceexclude)：排除不需要 SWC 编译的文件

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  tools: {
    swc: {
      jsc: {
        transform: {
          react: {
            runtime: 'automatic',
          },
        },
        experimental: {
          plugins: [['@swc/plugin-emotion', {}]],
        },
      },
    },
  },
});
```

### SWC 插件版本

SWC Wasm 插件目前仍属实验性功能，在不同 `swc_core` 版本之间不向后兼容。请使用与 Rspack 内置 `swc_core` 版本匹配的 SWC 插件，否则构建会报错。排查方法参考 [Rspack 常见问题 - SWC 插件版本不匹配](https://rspack.rs/zh/errors/swc-plugin-version)。

## 检测 Rstest 环境

可以使用 `import.meta.env.RSTEST` 或 `process.env.RSTEST` 判断代码是否运行在 Rstest 中。在所有测试环境（包括 Browser Mode）下，两者的值均为 `'true'`。

兼容浏览器的 ESM 源码建议优先使用 `import.meta.env.RSTEST`。Browser Mode 会在构建时替换这些表达式，但不会注入全局 `process` 对象，因此不要用 `typeof process !== 'undefined'` 做前置判断。

```ts
if (import.meta.env.RSTEST === 'true') {
  // do something...
}
```

生产构建源码时，需要在构建配置（如 `rsbuild.config.ts`）中将用到的表达式定义为 `false`，以便打包工具将测试分支作为死代码消除：

```diff title="rsbuild.config.ts"
import { defineConfig } from '@rsbuild/core';

export default defineConfig({
  source: {
    define: {
+      'process.env.RSTEST': false,
+      'import.meta.env.RSTEST': false,
    },
  },
});
```

### 在 Rsbuild 插件中判断 Rstest 环境

在 Rsbuild 插件中可通过检查 `api.context.callerName` 是否为 `'rstest'` 来区分环境。详见[判断插件是否运行在 Rstest 中](/config/build/plugins#detect-rstest-environment)。

## 配置集成

为了复用已有的构建配置（别名、全局变量、插件或框架预设）而避免重复维护，可以通过 [extends](/config/test/extends) 选项结合[适配器（Adapter）](/guide/advanced/adapters)引入外部配置：

- `extends` 支持传入对象、函数（适配器）或数组，解析后的配置会与当前 Rstest 配置深度合并。
- 适用于复用 Rsbuild、Rslib、Rspack 等工具的配置，或为项目预设默认测试环境和 setup 脚本。
