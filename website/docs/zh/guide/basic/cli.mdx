# 命令行工具

Rstest 提供了一个轻量级的命令行工具，包含 [rstest watch](#rstest-watch) 和 [rstest run](#rstest-run) 等命令。

## rstest -h

`rstest -h` 用于查看所有可用的 CLI 命令及选项：

```bash
npx rstest -h
```

```bash
Usage:
  $ rstest [...filters]

Commands:
  [...filters]              run tests
  run [...filters]          run tests without watch mode
  watch [...filters]        run tests in watch mode
  list [...filters]         lists all test files that Rstest will run
  merge-reports [path]      Merge blob reports from multiple shards into a unified report
  init [project]            Initialize rstest configuration

Options:
  -h, --help                Display this message
  -v, --version             Display version number
```

可以通过 `npx rstest <command> -h` 查看命令专属参数。例如，`npx rstest init -h` 只会显示初始化相关参数，而 `npx rstest merge-reports -h` 只会显示合并报告相关参数。

## rstest [...filters]

直接运行 `rstest` 会在当前目录执行测试：

```bash
$ npx rstest

✓ test/index.test.ts (2 tests) 1ms

  Test Files 1 passed (1)
       Tests 2 passed (2)
    Duration 189 ms (build 22 ms, tests 167 ms)
```

位置参数匹配、完整路径精确匹配及测试名称过滤详见[过滤测试](/guide/basic/test-filter)。

### Watch 模式

如果希望在文件更改时自动重新运行测试，可以使用 `--watch` 或 `rstest watch` 命令：

```bash
$ npx rstest --watch
```

## rstest run

`rstest run` 执行单次测试而不进入监听模式，适合 CI 环境或无需边改边测的场景。

### 运行相关测试

<ApiMeta addedVersion="0.10.0" />

当需要把命令行位置参数视为源码文件，并只运行依赖这些源码的测试时，可以使用 `--related`：

```bash
npx rstest run --related src/button.ts
```

Rstest 会基于构建得到的 module graph 解析相关测试，因此同一套过滤逻辑同时适用于 Node mode 和 Browser Mode。也可以使用兼容 Jest 的别名：

```bash
npx rstest run --findRelatedTests src/button.ts
```

与请求源无关的文件出现编译错误时，`--related` 和 `--changed` 不会失败退出。如果测试文件自身编译失败，Rstest 无法分析它的依赖，可能漏选并打印警告。`passWithNoTests` 只允许选择结果为空。

如果只想查看受影响的测试文件，可以配合 `rstest list` 使用：

```bash
npx rstest list --related src/button.ts --filesOnly
```

`--related` 和 `--findRelatedTests` 不支持在 watch 模式下使用，watch 模式本身已经会重跑受文件变更影响的测试。

### 运行变更相关测试

<ApiMeta addedVersion="0.10.0" />

使用 `--changed` 可以从当前 Git 仓库收集变更文件，并运行这些文件相关的测试。默认会包含 unstaged、staged 和 untracked 文件：

```bash
npx rstest run --changed
```

也可以传入 commit 或 branch。Rstest 会包含该 ref 与 `HEAD` 之间的变更文件，以及本地 staged、unstaged 和 untracked 文件：

```bash
npx rstest run --changed=HEAD~1
npx rstest run --changed=origin/main
```

当变更文件命中 [`forceRerunTriggers`](/config/test/force-rerun-triggers) 时，Rstest 会运行完整测试套件，而不是只运行相关测试。

开启覆盖率且未配置 [`coverage.changed`](/config/test/coverage#changed) 时，`--changed` 也会将覆盖率报告限制在变更的源文件范围内。如果变更文件命中 [`forceRerunTriggers`](/config/test/force-rerun-triggers)，Rstest 会运行完整测试套件，并生成完整覆盖率报告，除非显式启用了 `coverage.changed`。

如果只想预览将要执行哪些测试，可以配合 `rstest list` 使用：

```bash
npx rstest list --changed --filesOnly
```

`--changed` 不能和位置参数、`--related` / `--findRelatedTests` 一起使用，因为它已经从 Git 状态提供了源码文件过滤条件。它同样不支持在 watch 模式下使用。

### 测试选择的限制 \{#test-selection-limitations}

`--related` 和 `--changed` 根据构建时找到的文件依赖选择测试，不会先运行测试来查看实际加载了哪些文件。以下情况可能漏跑测试：

- **Node mode 下通过变量拼出的加载路径。** 例如 ``import(`./shipping/${method}.mjs`)``、``require(`./shipping/${method}.cjs`)`` 或 `import(modulePath)`。即使代码里写明了目录，目前也无法可靠追踪。修改实际加载的文件，或这个文件的子依赖，都可能不会触发对应测试。
- **只通过 `require.resolve()` 引用的文件。** 例如调用 `require.resolve('./provider.cjs')`，不会记录对 `provider.cjs` 的依赖。修改这个文件，可能不会触发对应测试。
- **构建时看不到的文件依赖。** 例如通过 `fs.readFile()` 读取文件、通过自定义 Node 加载 hook 加载模块，或用 `noParse` 跳过文件分析。这些文件或依赖发生变化时，可能不会触发对应测试。
- **删除文件。** `--changed` 目前不会收集已暂存或已提交的删除记录。即使把删除的路径传给 `--related`，构建时也可能已经找不到它与测试之间的依赖关系。

这些依赖没有被识别时，Rstest 不会自动改跑全部测试，也不一定会打印警告。遇到上述情况，请用 `npx rstest run` 运行全部测试。对于构建时看不到的文件依赖，也可以配置 [`forceRerunTriggers`](/config/test/force-rerun-triggers)，让 `--changed` 在检测到匹配的文件改动时运行全部测试。

### 运行分片 \{#sharding-tests}

使用 `--shard <index>/<count>` 将测试文件拆分为多个分片并行运行。`count` 表示总的分片数量，`index`（从 1 开始）表示要运行的分片：

```bash
# 将测试分成 3 个分片，运行第 1 个分片
npx rstest run --shard 1/3
```

在 CI/CD 中，可以将测试套件拆分到多个 job 以缩短整体运行时间，然后用 [`rstest merge-reports`](#rstest-merge-reports) 合并各分片的报告。

测试文件会按相对于本次 Rstest 运行根目录的路径计算 SHA-1，并按 hash 排序，路径分隔符统一为 `/`。这样可以打散同一目录中的文件，并在多次运行或更换检出目录时保持分片结果一致。分片发生在测试文件扫描阶段，早于构建过程。请确保 `1 <= index <= count`。

文件会均匀分配到各个分片，余数从第一个分片开始，每片多分配一个文件。例如，10 个文件拆分为 3 个分片时，各片分别包含 4、3、3 个文件。

## rstest watch

`rstest watch` 以监听模式运行测试，当测试文件或其依赖发生变化时重新执行受影响的测试文件。

## rstest list

`rstest list` 列出所有匹配的测试而不执行它们。默认情况下，输出每个匹配测试的完整名称：

```bash
$ npx rstest list

a.test.ts > test a > test a-1
a.test.ts > test a-2
b.test.ts > test b > test b-1
b.test.ts > test b-2
```

`rstest list` 继承 `rstest` 的过滤选项（`-f, --onlyFailures` 除外），可以直接过滤文件或使用 `-t` 匹配测试名称：

```bash
$ npx rstest list -t='test a'

a.test.ts > test a > test a-1
a.test.ts > test a-2
```

使用 `--filesOnly` 仅打印测试文件路径：

```bash
$ npx rstest list --filesOnly

a.test.ts
b.test.ts
```

使用 `--json` 以 JSON 格式输出测试，或将结果写入文件：

```bash
$ npx rstest list --json

$ npx rstest list --json=./output.json
```

在 Browser Mode 下，`rstest list` 会在每个选中的 browser instance 中求值测试文件，但不执行测试主体。使用 `--filesOnly` 时，每个匹配的文件会按选中的 instance 各列一次，且不会启动浏览器。一个项目选中多个 instance 时，`--json` 会用各自的 instance 项目名来区分，例如 `web (chromium)` 或 `web (firefox)`。

使用 `--includeSuites` 在输出测试用例的同时包含测试套件：

```bash
$ npx rstest list --includeSuites

a.test.ts > test a
a.test.ts > test a > test a-1
a.test.ts > test a-2
b.test.ts > test b
b.test.ts > test b > test b-1
b.test.ts > test b-2
```

使用 `--printLocation` 输出文件路径及行列位置信息：

```bash
$ npx rstest list --printLocation

a.test.ts:4:5 > test a > test a-1
a.test.ts:9:3 > test a-2
b.test.ts:4:5 > test b > test b-1
b.test.ts:9:3 > test b-2
```

使用 `--summary` 在列表输出后追加一段简要统计：

```bash
$ npx rstest list --summary

a.test.ts > test a > test a-1
a.test.ts > test a-2
b.test.ts > test b > test b-1
b.test.ts > test b-2
c.test.ts > test c it each 0
c.test.ts > test c it for 0
c.test.ts > test c it runIf
c.test.ts > test c it skipIf

 Test Files 3 matched
      Tests 8 matched
```

与 `--json` 一起使用时，`--summary` 会把 JSON 输出从数组切换为包含 `items` 和 `summary` 字段的对象。

## rstest merge-reports

<ApiMeta addedVersion="0.9.3" />

`rstest merge-reports` 将使用 [`--shard`](#sharding-tests) 在多台 CI 机器上并行运行生成的 blob 报告合并为统一报告。

### 工作流程

1. 使用 `blob` 报告器运行每个分片以生成 blob 报告文件：

```bash
# 在 CI 机器 1 上
npx rstest run --shard 1/3 --reporters=blob

# 在 CI 机器 2 上
npx rstest run --shard 2/3 --reporters=blob

# 在 CI 机器 3 上
npx rstest run --shard 3/3 --reporters=blob
```

2. 将所有 `.rstest-reports/` 目录收集到同一位置，然后合并：

```bash
npx rstest merge-reports
```

默认情况下，blob 报告从项目根目录的 `.rstest-reports/` 读取。你可以指定自定义路径：

```bash
npx rstest merge-reports ./custom-reports-dir
```

合并命令将：

- 合并所有 blob 中的测试结果
- 使用配置的报告器（如 `default`、`junit`）输出合并后的数据
- 合并所有生成 blob 的运行实际采集的覆盖率（如果启用了覆盖率）
- 统一应用一次 `coverage.include`，补齐这些运行都未测试的文件
- 基于统一结果生成覆盖率报告并检查阈值

支持延迟最终处理的 coverage provider 会让使用 blob 报告器的运行跳过覆盖率报告生成和阈值检查。未使用 blob 报告器的运行会正常完成覆盖率最终处理，包括分片运行。旧版 provider 保持原有的单次运行最终处理行为。请通过配置或 `--coverage` 参数为 `merge-reports` 启用覆盖率，让合并 job 完成覆盖率最终处理。`merge-reports` 支持与 `rstest run` 相同的 `--coverage.*` 参数。只传给生成 blob 的运行的覆盖率参数不会写入 blob，因此请在配置文件中定义 `coverage.include`、`coverage.reporters` 和 `coverage.reportsDirectory` 等最终处理参数，或在执行 `merge-reports` 时再次传入。

使用 `--cleanup` 在合并完成后删除 blob 报告输入。目录为空时也会一并删除。如果 `coverage.reportsDirectory` 是 blob 目录或其子目录，则会保留生成的覆盖率报告及其所在目录：

```bash
npx rstest merge-reports --cleanup
```

## rstest init

`rstest init` 用于为支持的项目类型生成初始配置：

```bash
npx rstest init
```

当前可用的初始化目标是 `browser`：

```bash
npx rstest init browser
```

使用 `--yes` 可以跳过交互式提问，直接应用默认配置：

```bash
npx rstest init browser --yes
```

| `--source.tsconfigPath <path>`      | 指定 tsconfig.json 文件路径，详见 [source.tsconfigPath](/config/build/source#sourcetsconfigpath)                                                                               |
| `--teardownTimeout <value>`         | 设置 `rstest run` 结束后等待进程退出的时间（毫秒）；`0` 立即退出，`Infinity` 不强制退出（默认：`10000`），详见 [teardownTimeout](/config/test/teardown-timeout)                |

`rstest` 默认命令还额外支持 `-w, --watch`，可直接切换到 watch 模式。

### rstest list

`rstest list` 支持上面测试命令的过滤和配置参数（`-f, --onlyFailures` 除外），并额外提供：

| 参数                    | 说明                        |
| ----------------------- | --------------------------- |
| `--filesOnly`           | 仅输出匹配到的测试文件      |
| `--includeSuites`       | 在输出中包含 suite          |
| `--json [boolean/path]` | 以 JSON 输出，或写入文件    |
| `--printLocation`       | 输出测试和 suite 的位置信息 |
| `--summary`             | 在列表后输出简要统计        |

### rstest merge-reports

`rstest merge-reports` 与[测试命令](#测试命令)共享 `-h/--help`、`-c/--config`、`--config-loader`、`-r/--root`、`--reporters`、`--coverage` 和 `--coverage.*` 参数，并额外提供：

| 参数        | 说明                         |
| ----------- | ---------------------------- |
| `--cleanup` | 合并完成后删除 blob 报告输入 |

### rstest init

`rstest init` 只接受初始化相关参数：

| 参数         | 说明                       |
| ------------ | -------------------------- |
| `-h, --help` | 显示帮助信息               |
| `--yes`      | 使用默认选项并跳过交互界面 |

### 布尔选项取反

对于布尔类型的选项，可以使用 `--no-<option>` 前缀将其设为 `false`：

```bash
# 以下两种写法等价：
npx rstest --isolate false
npx rstest --no-isolate

# 更多示例：
npx rstest --no-coverage      # 禁用覆盖率
npx rstest --no-globals       # 禁用全局 API
npx rstest --no-clearMocks    # 禁用自动清除 mock
```

## CLI 快捷键

在交互式终端的 watch 模式下，按 `h` 可打印可用的键盘快捷键列表：

```bash
  Shortcuts:
  f  rerun failed tests
  a  rerun all tests
  u  update snapshot
  t  filter by a test name regex pattern
  p  filter by a filename regex pattern
  c  clear screen
  q  quit process
```

随时按 `h` 即可显示上述快捷键帮助。在纯 Browser Mode（无 Node 测试项目）的 watch 模式下，`t` 和 `p` 会以灰色提示显示，因为终端中的文件名和测试名过滤暂不支持 Browser Mode 重跑。

:::note
CLI 快捷键仅在 watch 模式下运行 Rstest（`rstest watch` 或 `rstest --watch`）且标准输入为交互式 TTY 时可用。
:::
