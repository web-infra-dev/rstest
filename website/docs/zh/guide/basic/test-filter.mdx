# 过滤测试

Rstest 支持通过命令行参数、配置选项、watch 快捷键或测试 API 修饰符来筛选要运行的测试文件、project 和测试用例。

## 根据文件名过滤

运行所有测试：

```bash
rstest
```

位置参数支持子字符串（不区分大小写）、相对或绝对文件路径以及目录路径（传入多个参数时匹配其中任意一个）：

```bash
rstest foo
rstest test/foo.test.ts test/bar.test.ts
rstest packages/core
```

用引号包裹参数可启用完整路径精确匹配（例如只运行 `foo.test.ts` 而不匹配 `foo.test.tsx`）。Shell 会去掉一层引号，因此需要两层：

```bash
rstest '"test/foo.test.ts"'
```

Rstest 不会将位置参数解析为 glob 模式。需要 glob 匹配时请使用 `--include`，并加上引号防止 shell 提前展开：

```bash
rstest --include "test/**/*.test.ts"
```

### include/exclude

位置参数会在 [`include`](/config/test/include) 和 [`exclude`](/config/test/exclude) 选出的文件范围基础上进一步筛选。你也可以通过 CLI 覆盖 `include` 和 `exclude`：

```bash
# 匹配 test/a 目录下路径包含 index 的测试文件
rstest index --include "test/a/*.test.ts"

# 匹配 test/a 或 test/b 目录下的测试文件
rstest --include "test/a/*.test.ts" --include "test/b/*.test.ts"

# 排除指定目录
rstest --exclude "test/legacy/**"
```

默认情况下，未匹配到任何测试文件时 Rstest 会以失败退出。传入 `--passWithNoTests`（或在配置中开启 [`passWithNoTests`](/config/test/pass-with-no-tests)）可在无匹配文件时以退出码 `0` 通过。

## 根据测试名称过滤

使用 `--testNamePattern`（简写为 `-t`）或配置项 [`testNamePattern`](/config/test/test-name-pattern)，可以只运行名称匹配给定字符串或正则表达式的测试。

### 按关键字匹配

传入关键字即可运行名称包含该关键字的测试用例或测试套件。当套件名称匹配时，该套件内的所有测试都会运行：

```bash
rstest -t bar
```

Rstest 会将 `-t` / `testNamePattern` 编译为单个 `RegExp`。当模式中不包含 `>` 时，Rstest 会用单个空格拼接外层到内层的套件名和测试用例名（例如 `suite-foo suite-bar test-baz`）。因此，包含空格的字符串匹配的是完整名称中**连续出现**的这段字符：

```bash
# 匹配 "suite-foo > suite-bar > test-baz"，
# 不会匹配 "suite-foo > suite-bar > suite-bar1 > test-baz"
rstest -t 'suite-bar test-baz'
```

如果需要跨嵌套层级匹配不相邻的关键字，请使用 `.*` 连接：

```bash
rstest -t 'suite-bar.*test-baz'
```

### 按完整测试名称匹配

在终端输出中，Rstest 会使用 `>` 连接从外到内的测试套件名和测试用例名。当模式中包含 `>` 时，Rstest 会直接针对这条以 `>` 分隔的完整名称进行匹配。

例如，对于以下测试文件及其输出：

```ts title="foo.test.ts"
import { describe, test } from '@rstest/core';

describe('suite-foo', () => {
  describe('suite-bar', () => {
    test('test-baz', () => {
      // ...
    });

    describe('suite-bar1', () => {
      test('test-baz', () => {
        // ...
      });
    });
  });
});
```

输出：

```bash
✓ foo.test.ts
  ✓ suite-foo > suite-bar > test-baz
  ✓ suite-foo > suite-bar > suite-bar1 > test-baz
```

如果只运行 `suite-bar` 下直接包含的 `test-baz`：

```bash
rstest foo.test.ts -t 'suite-foo > suite-bar > test-baz'
```

### 按正则表达式匹配

因为模式会按正则表达式求值，可以使用起止锚点 `^` 和 `$` 精确匹配完整测试名称，避免命中包含该子串的其他测试：

```bash
rstest foo.test.ts -t '^suite-foo > suite-bar > test-baz$'
```

也可以在 `rstest.config.ts` 中通过 [`testNamePattern`](/config/test/test-name-pattern) 直接传入 `RegExp`，例如用 `/^(?!.*slow).*$/` 排除名称中包含 `slow` 的测试。

## 根据项目名称过滤

在通过 [`projects`](/config/test/projects) 配置了多个测试项目的工作区中，使用 `--project` 按项目 [`name`](/config/test/name) 筛选要运行的项目。

匹配指定的项目名称：

```bash
rstest --project '@test/a' --project '@test/b'
```

使用 `*` 通配符匹配项目名称：

```bash
rstest --project '@test/*'
```

使用前缀 `!` 排除指定项目：

```bash
rstest --project '!@test/a'
```

## 失败重跑、变更检测与分片 \{#failed-tests-changes-and-shards}

- **重跑失败的测试文件**：传入 `-f` 或 `--onlyFailures`（详见 [`onlyFailures`](/config/test/only-failures)），仅重新运行上一次完整运行中失败的测试文件。
- **运行源文件关联的测试**：传入 `--related`（或 `--findRelatedTests`）和源文件路径，仅运行依赖这些源文件的测试；详见[运行相关测试](/guide/basic/cli#运行相关测试)。
- **运行 Git 变更相关的测试**：传入 `--changed`，运行受本地或指定提交范围内 Git 变更影响的测试；详见[运行变更相关测试](/guide/basic/cli#运行变更相关测试)。
- **在 CI 中分片执行**：传入 `--shard <index>/<count>` 将测试文件拆分到多个并行任务中；详见[运行分片](/guide/basic/cli#sharding-tests)。
- **在 watch 模式下交互过滤**：在 Node watch 模式中，按 `t` 设置测试名称过滤模式，按 `p` 设置文件过滤条件，按 `f` 重跑失败文件，按 `a` 清除当前过滤条件并重跑全部测试；详见 [CLI 快捷键](/guide/basic/cli#cli-快捷键)。

## 组合过滤

文件、项目和测试名称过滤条件可以组合使用：

```bash
rstest --include "test/**/*.test.ts" --exclude "test/legacy/**" --testNamePattern login
```

该命令会在 `test/` 目录下除 `test/legacy/` 之外的所有 `.test.ts` 文件中，只运行名称包含 `login` 的测试用例。

## 通过测试 API 过滤

在测试代码中，可以通过 [`test`](/api/runtime-api/test-api/test) 和 [`describe`](/api/runtime-api/test-api/describe) 的修饰符控制要执行的套件或用例：

- `.only`：仅运行当前文件内标记了 `.only` 的套件或测试用例（只调试单个文件时可配合 CLI 文件过滤使用）。
- `.skip` / `.todo`：跳过套件或测试用例，或将其标记为待实现。
- `.skipIf(condition)` / `.runIf(condition)`：根据布尔表达式按条件跳过或运行套件和测试用例。
- `context.skip()`：在测试执行过程中动态跳过当前测试。

```ts
import { describe, test } from '@rstest/core';

describe.only('suite A', () => {
  test('runs only this suite in the file', () => {});
});

describe.skip('suite B', () => {});
test.todo('pending case');
test.skipIf(process.platform === 'win32')('POSIX only', () => {});
test.runIf(Boolean(process.env.CI))('CI only', () => {});

test('skips dynamically', (context) => {
  if (!process.env.API_TOKEN) {
    context.skip();
  }
});
```
