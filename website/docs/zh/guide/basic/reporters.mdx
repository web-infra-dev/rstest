# Reporters

Reporter 控制 Rstest 如何格式化与输出测试结果。你可以使用内置报告器输出终端日志、CI 注解或机器可读产物，也可以接入自定义报告器。

## 配置方式

可通过以下方式配置报告器：

1. **CLI**：`--reporters=<name>`（可多次使用；同时支持别名 `--reporter`）
2. **配置文件**：在 `rstest.config.ts` 中设置 [reporters](/config/test/reporters)

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';
import { customReporter } from './path/to/custom-reporter';

export default defineConfig({
  reporters: [
    'default',
    ['junit', { outputPath: './test-results.xml' }],
    customReporter,
  ],
});
```

完整配置方式见[报告器配置](/config/test/reporters)，内置报告器选项类型定义见 [`packages/core/src/types/reporter.ts`](https://github.com/web-infra-dev/rstest/blob/main/packages/core/src/types/reporter.ts)（其中 `junit` 在公开联合类型中声明为 `Record<string, unknown>`，实际选项见下方 [JUnit 报告器](#junit-报告器)）。

## 内置报告器

| 报告器           | 用途                | 使用场景              |
| ---------------- | ------------------- | --------------------- |
| `default`        | 带颜色的控制台输出  | 本地开发              |
| `dot`            | 紧凑的逐测试标记流  | 快速本地反馈          |
| `verbose`        | 详细的测试用例输出  | 调试测试失败          |
| `github-actions` | CI 错误注释         | GitHub Actions 工作流 |
| `junit`          | JUnit XML 格式      | CI/CD 集成            |
| `json`           | 结构化 JSON 报告    | CI 工具与脚本处理     |
| `md`             | Markdown agent 报告 | Agent / LLM 集成      |
| `blob`           | 序列化 JSON 输出    | 合并分片报告          |

### 默认报告器

在终端以彩色格式输出测试运行状态、失败详情和汇总信息。

**输出示例：**

```bash
 ✓ test/index.test.ts (2)

 Test Files 1 passed
      Tests 2 passed
   Duration 112ms (build 19ms, tests 93ms)
```

**选项：**

| 选项              | 类型                                                                          | 默认值                                        | 说明                                   |
| ----------------- | ----------------------------------------------------------------------------- | --------------------------------------------- | -------------------------------------- |
| `summary`         | `boolean`                                                                     | `true`                                        | 是否输出失败详情和运行汇总。           |
| `logger`          | `{ outputStream: Writable; errorStream: Writable; getColumns: () => number }` | `process.stdout` / `process.stderr`           | 自定义输出流与列宽获取函数。           |
| `showProjectName` | `boolean`                                                                     | 多项目或多浏览器运行时为 `true`，否则 `false` | 是否在测试文件路径前显示 `[project]`。 |

#### 进度报告

默认报告器会根据终端环境自动切换进度输出方式：

**TTY 环境（交互式终端）**

在终端底部每秒刷新一次实时状态，展示正在运行的测试文件及耗时超过 2 秒的测试用例，运行结束后自动清除：

```bash
 RUNS  src/database.test.ts
   > should handle concurrent writes 5s

 Test Files 12 passed | 1 running
      Tests 45 passed
   Duration 30s
```

**非 TTY 环境（CI、管道输出、AI agents）**

当控制台连续 30 秒无输出时自动打印一条进度日志，并列出耗时超过 10 秒的测试用例。输出满 20 次（约 10 分钟空闲）后停止打印，避免测试真正卡死时阻塞 CI 的超时机制：

```bash
[PROGRESS] test files: 20 done, 4 running | tests: 380 passed, 3 failed | 2m 30s
            Running: src/heavy.test.ts > database > concurrent writes 45s
            Running: src/other.test.ts
```

### 详细报告器

继承自默认报告器，输出包括通过用例在内的全部测试用例，并在预打包测试环境时于构建耗时中列出各环境包的预打包耗时。

<Tabs defaultValue='rstest.config.ts'>
  <Tab label="CLI">
```bash
npx rstest --reporters=verbose
```
  </Tab>
  <Tab label="rstest.config.ts">
```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: 'verbose',
});
```
  </Tab>
</Tabs>

**输出示例：**

```bash
 ✓ test/index.test.ts (2) 2ms
  ✓ Index > should add two numbers correctly (1ms)
  ✓ Index > should test source code correctly (1ms)

 Test Files 1 passed
      Tests 2 passed
   Duration 112ms (build 19ms, tests 93ms)
```

**选项：** 支持 `logger` 和 `showProjectName`（与[默认报告器](#默认报告器)一致；汇总信息始终输出）。

### Dot 报告器

<ApiMeta addedVersion="0.9.7" />

每个测试用例完成后输出一个紧凑字符：

- `·`：通过
- `x`：失败
- `-`：跳过
- `*`：todo

<Tabs defaultValue='rstest.config.ts'>
  <Tab label="CLI">
```bash
npx rstest --reporters=dot
```
  </Tab>
  <Tab label="rstest.config.ts">
```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: 'dot',
});
```
  </Tab>
</Tabs>

标记行输出结束后会继续打印失败详情和耗时汇总（除非设置 `summary: false`）。

**选项：** 支持 `summary`（默认：`true`）和 `logger`（与[默认报告器](#默认报告器)一致）。

### GitHub Actions 报告器

在测试失败时通过 [GitHub Actions 工作流命令](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-commands#setting-an-error-message) 输出错误注解，用于在 PR diff 中直接定位失败位置。

**自动启用：** 当 `process.env.GITHUB_ACTIONS === 'true'` 且未手动配置报告器时，自动与 `default` 一并启用。

<Tabs defaultValue='rstest.config.ts'>
  <Tab label="CLI">
```bash
npx rstest --reporters=github-actions
```
  </Tab>
  <Tab label="rstest.config.ts">
```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: ['github-actions'],
});
```
  </Tab>
</Tabs>

失败断言会输出如下工作流命令：

```bash
::error file=src/index.ts,line=4,col=17,title=test/index.test.ts > should add two numbers correctly::expected 2 to be 4
```

当错误带有 `cause` 时，cause 链中的每个错误都会以 `Caused by: <name>: <message>` 形式追加到消息中。

![rstest-github-actions-example](https://assets.rspack.rs/rstest/assets/rstest-github-actions-example.jpg)

当环境中存在 `GITHUB_STEP_SUMMARY` 时，Rstest 还会追加一个可折叠的 Markdown 摘要（状态图标为 `✅`、存在重试后通过的 flaky 测试时为 `⚠️`，失败时为 `❌`），包含：

- 汇总表（`Test Files`、`Tests`、`Duration`，存在 flaky 测试时包含 `Flaky Tests`）
- 最多 20 条重试后通过的 flaky 测试及之前失败的简要原因
- 最多 20 条失败用例详情（错误信息、diff、堆栈，包含 `cause` 链中每个错误的详情，以及单条复现命令）
- 若项目根目录位于 `GITHUB_WORKSPACE` 内，路径会缩写为 `<ROOT>/...`

#### 自动启用

当配置文件和 CLI 都未显式指定报告器，且 `process.env.GITHUB_ACTIONS === 'true'` 时，Rstest 会自动启用 `['default', 'github-actions']`。

#### 手动启用

<Tabs defaultValue='rstest.config.ts'>
  <Tab label="CLI">
```bash
npx rstest --reporters=github-actions
```
  </Tab>
  <Tab label="rstest.config.ts">
```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: ['github-actions'],
});
```
  </Tab>
</Tabs>

#### 选项

| 选项          | 类型                                       | 默认值 | 说明                                  |
| :------------ | :----------------------------------------- | :----- | :------------------------------------ |
| `annotations` | `boolean`                                  | `true` | 是否为失败的测试输出 `::error` 注解。 |
| `summary`     | `boolean \| { maxCharsPerField?: number }` | `true` | 控制 Markdown 摘要输出和单字段长度。  |

<ApiMeta addedVersion="0.11.6" />

`summary.maxCharsPerField` 默认为 `400`，用于限制每条失败消息、diff 以及每个未处理错误消息和堆栈的最大字符数。GitHub 限制单个 step 的 Summary 总大小为 [1 MiB](https://docs.github.com/zh/actions/writing-workflows/choosing-what-your-workflow-does/workflow-commands-for-github-actions#步骤隔离和限制)，请合理控制上限；设为 `summary: false` 可关闭 Markdown 摘要。

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: [
    [
      'github-actions',
      {
        annotations: true,
        summary: {
          maxCharsPerField: 2_000,
        },
      },
    ],
  ],
});
```

### JUnit 报告器

生成 JUnit XML 格式的测试报告，用于 CI/CD 集成和结果聚合。

<Tabs defaultValue='rstest.config.ts'>
  <Tab label="CLI">
```bash
npx rstest --reporters=junit
```
  </Tab>
  <Tab label="rstest.config.ts">
```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: [['junit', { outputPath: './junit.xml' }]],
});
```
  </Tab>
</Tabs>

**选项：**

- `outputPath`：`string` — 输出文件路径（默认输出到控制台）。

生成的 XML 格式如下：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<testsuites name="rstest tests" tests="3" failures="1" errors="0" skipped="1" time="0.3" timestamp="2024-01-01T00:00:00.000Z">
  <testsuite name="test1.test.ts" tests="3" failures="1" errors="0" skipped="1" time="0.3" timestamp="2024-01-01T00:00:00.000Z">
    <testcase name="should pass" classname="test1.test.ts" time="0.1">
    </testcase>
    <testcase name="should fail" classname="test1.test.ts" time="0.2">
      <failure message="Test failed" type="AssertionError">expected 'hi' to be 'hii' // Object.is equality - Expected + Received - hii + hi at test1.test.ts:10:21</failure>
    </testcase>
    <testcase name="should skip" classname="test1.test.ts" time="0.0">
      <skipped/>
    </testcase>
  </testsuite>
</testsuites>
```

状态映射规则：

- `passed`：空的 `<testcase>` 节点
- `failed`：在 `<testcase>` 内生成 `<failure>` 节点
- `skipped` / `todo`：在 `<testcase>` 内生成 `<skipped/>` 节点
- 文件级错误（文件加载失败或 `beforeAll` / `afterAll` 报错）：追加一个包含 `<error>` 的 `<testcase>` 节点，并累加 `errors` 计数
- 顶层 `unhandledErrors`：追加 `<testsuite name="rstest unhandled errors">` 与 `<system-err>` 节点，并累加 `errors` 计数

### JSON 报告器

<ApiMeta addedVersion="0.9.6" />

生成结构化的 JSON 文档，供 CI 工具、dashboard 或后处理脚本读取。

<Tabs defaultValue='rstest.config.ts'>
  <Tab label="CLI">
```bash
npx rstest --reporters=json
```
  </Tab>
  <Tab label="rstest.config.ts">
```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: [['json', { outputPath: './reports/rstest.json' }]],
});
```
  </Tab>
</Tabs>

**选项：**

- `outputPath`：`string` — 输出文件路径（默认输出到 stdout）。

**输出结构：**

- `tool`：固定为 `'rstest'`
- `version`：Rstest 版本号
- `status`：本次运行状态（`'passed' | 'failed' | 'error'`）
- `summary`：文件和测试计数（`testFiles`、`failedFiles`、`tests`、`failedTests`、`passedTests`、`skippedTests`、`todoTests`）
- `durationMs`：`{ total, build, prebundle?, tests }`（单位毫秒；存在环境预打包时包含 `prebundle`；多项目运行中构建与测试可能重叠，总耗时以 `total` 为准；详见 [onTestRunEnd](/api/javascript-api/reporter#ontestrunend)）
- `snapshot`：本次运行的 snapshot 汇总
- `files`：按测试文件聚合的结果及嵌套测试用例
- `tests`：扁平化测试用例结果，每项包含 `fullName`
- `consoleLogs`：捕获到的用户 console 输出（无日志时省略该字段）
- `unhandledErrors`：顶层 unhandled errors 数组（无错误时为空数组 `[]`）

`testPath` 均写作相对根目录的路径，确保在不同机器和 CI workspace 下保持一致。

### Markdown 报告器

向 stdout 输出结构化的单份 Markdown 文档，便于 AI agent 和 LLM 消费。

当配置文件和 CLI 均未显式指定报告器时，Rstest 在 AI agent 环境中会自动启用 `['md']`。设置环境变量 `RSTEST_NO_AGENT=1` 可关闭 agent 检测，恢复默认的控制台报告器。

默认 preset 为 `normal`：

- 每个失败用例附带 `repro` 命令（`file+name`），方便单条复现。
- 堆栈默认使用 `'top'`（仅保留顶层栈帧），控制输出体积。
- 默认开启 console 采集，并按文件和条目限制长度。
- 失败数超过 `failures.max` 时，先输出包含最小字段的完整 `Failure List`（`type`、`message`、`expected`、`actual`、`repro`），再只展开前 `failures.max` 条的完整 `Failure Details`。

各 preset 决定了失败上下文的展开程度：

| Preset    | 适用场景                             | 失败详情                             | Console logs                                  | Code frames       |
| --------- | ------------------------------------ | ------------------------------------ | --------------------------------------------- | ----------------- |
| `normal`  | 默认 agent 工作流                    | `stack: 'top'`、`failures.max: 50`   | 开启，每个路径最多 10 条、每条最多 500 字符   | 开启，上下各 2 行 |
| `compact` | CI 日志、多轮 agent 调用、控制 token | `stack: 'top'`、`failures.max: 20`   | 关闭                                          | 关闭              |
| `full`    | 深度排查问题、保留完整上下文         | `stack: 'full'`、`failures.max: 200` | 开启，每个路径最多 200 条、每条最多 5000 字符 | 开启，上下各 3 行 |

<Tabs defaultValue='rstest.config.ts'>
  <Tab label="CLI">
```bash
npx rstest --reporters=md
```
  </Tab>
  <Tab label="rstest.config.ts">
```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: ['md'],
});
```
  </Tab>
</Tabs>

#### 选项

| 选项             | 类型                                                                    | 默认值                                              | 说明                                                                     |
| ---------------- | ----------------------------------------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------ |
| `preset`         | `'normal' \| 'compact' \| 'full'`                                       | `'normal'`                                          | 输出详略预设。                                                           |
| `header`         | `boolean \| { env?: boolean }`                                          | `{ env: true }`                                     | 控制 YAML frontmatter 中的 `runtime` 信息（`node`、`platform`、`cwd`）。 |
| `reproduction`   | `boolean \| 'file' \| 'file+name'`                                      | `'file+name'`                                       | 控制失败用例的复现命令（`true` 等同于 `'file+name'`）。                  |
| `testLists`      | `'auto' \| 'always'`                                                    | `'auto'`                                            | 控制 Passed/Skipped/Todo 列表（`'auto'` 仅在聚焦且全部通过时输出）。     |
| `failures`       | `{ max?: number }`                                                      | `{ max: 50 }`                                       | 最多展开完整详情的失败用例数。                                           |
| `codeFrame`      | `boolean \| { linesAbove?: number; linesBelow?: number }`               | `{ linesAbove: 2, linesBelow: 2 }`                  | 顶层错误栈帧的代码片段上下文行数。                                       |
| `stack`          | `number \| false \| 'full' \| 'top'`                                    | `'top'`                                             | 输出的堆栈帧数量（`'full'` 最多保留 50 帧）。                            |
| `candidateFiles` | `boolean \| { max?: number }`                                           | `{ max: 5 }`                                        | 从堆栈中提取的疑似相关文件列表。                                         |
| `console`        | `boolean \| { maxLogsPerTestPath?: number; maxCharsPerEntry?: number }` | `{ maxLogsPerTestPath: 10, maxCharsPerEntry: 500 }` | 每个失败用例附带的 console 日志上限。                                    |
| `errors`         | `boolean \| { unhandled?: boolean }`                                    | `{ unhandled: true }`                               | 是否输出 `## Unhandled Errors` 章节。                                    |

#### 输出结构

报告以 YAML frontmatter 和 `# Rstest Test Execution Report` 开头，随后依次输出 `## Summary`、可选的 `## Tests`（聚焦运行全部通过或 `testLists: 'always'` 时）、`## Failures`，以及存在未捕获异常时的 `## Unhandled Errors`。

全量运行且全部通过时的摘录：

````md
## Summary

```json
{
  "status": "passed",
  "counts": {
    "testFiles": 2,
    "failedFiles": 0,
    "tests": 14,
    "failedTests": 0,
    "passedTests": 13,
    "skippedTests": 1,
    "todoTests": 0
  },
  "durationMs": {
    "total": 120,
    "build": 25,
    "tests": 95
  },
  "snapshot": {
    "added": 0,
    "updated": 0,
    "unmatched": 0,
    "removed": 0,
    "unchecked": 0
  }
}
```

## Failures

No test failures reported.

Note: all tests passed. Lists omitted for brevity.
````

````md
## Failures

repro:

```bash
pnpm exec rstest 'fixtures/agent-md/index.test.ts' --testNamePattern 'agent-md > fails with diff'
```

details:

```json
{
  "testPath": "fixtures/agent-md/index.test.ts",
  "project": "rstest",
  "fullName": "agent-md > fails with diff",
  "status": "failed",
  "duration": 12,
  "retryCount": 0,
  "errors": [
    {
      "type": "AssertionError",
      "message": "expected 2 to be 3",
      "topFrame": {
        "file": "fixtures/agent-md/index.test.ts",
        "line": 4,
        "column": 15,
        "method": null
      },
      "stackFrames": []
    }
  ]
}
```

diff:

```diff
- Expected
+ Received

- 3
+ 2
```
````

可通过覆盖 preset 字段进一步控制输出大小：

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: [
    [
      'md',
      {
        preset: 'compact',
        failures: { max: 20 },
        reproduction: 'file+name',
      },
    ],
  ],
});
```

### Blob 报告器

<ApiMeta addedVersion="0.9.3" />

将测试结果序列化为 JSON 文件，供 [`rstest merge-reports`](/guide/basic/cli#rstest-merge-reports) 后续合并。专用于 CI 环境中的[测试分片](/guide/basic/cli#sharding-tests)，不支持 watch 模式。

<Tabs defaultValue='CLI'>
  <Tab label="CLI">
```bash
npx rstest run --shard 1/3 --reporters=blob
```
  </Tab>
  <Tab label="rstest.config.ts">
```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: ['blob'],
});
```
  </Tab>
</Tabs>

**选项：**

- `outputDir`：`string` — blob 报告文件的输出目录（默认：`.rstest-reports`）。

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: [['blob', { outputDir: './custom-blob-output' }]],
});
```

启用覆盖率时，每个 blob 只保存当次运行采集到的覆盖率数据。对于支持延迟最终处理的 coverage provider，使用 blob 报告器的运行不会生成覆盖率报告、不会按 `coverage.include` 补齐未测试文件，也不会检查覆盖率阈值（不使用 blob 报告器的运行仍会正常完成最终处理，包括分片运行；旧版 provider 维持单次最终处理）。所有分片完成后，执行带覆盖率的 [`rstest merge-reports`](/guide/basic/cli#rstest-merge-reports) 对汇总结果统一执行这些步骤。仅通过命令行传给生成 blob 运行的覆盖率参数不会写入 blob；请将最终处理参数写入配置文件，或在执行 `merge-reports` 时再次传入。

完整 CI 工作流见[使用分片拆分测试](/guide/advanced/ci#split-tests-with-shards)。

## 自定义报告器

可通过模块路径（`'./custom-reporter.js'` 或 `['./custom-reporter.js', options]`，需默认导出 `Reporter` 类），或直接传入实现 `Reporter` 接口的实例对象来使用自定义报告器；不支持直接传入类构造函数。在启用类型擦除的 Node 22.18+ / 24 运行时下，可直接加载 `.ts` 和 `.mts` 模块。

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: [['./custom-reporter.js', { outputPath: './report.json' }]],
});
```

生命周期钩子和载荷类型定义见 [Reporter API 参考](/api/javascript-api/reporter)。
