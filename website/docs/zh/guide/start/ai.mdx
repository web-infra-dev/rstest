## Agent prompt

如果你正在使用 Coding Agent（如 Claude Code、Cursor、Copilot 等），请复制下面与你项目匹配的 prompt。Agent 会读取链接中的指令，并根据你的项目类型安装依赖、创建配置并编写测试。

### 设置 Rstest

如果当前项目还没有配置测试框架，使用这个 prompt：

<Prompt
  title="设置 Rstest"
  description="复制这个 prompt 并发送给你的 Coding Agent。"
  prompt={`Set up Rstest, the JavaScript testing framework, in this project by following the instructions here:
https://rstest.rs/guide/start/agent-install.md`}
/>

### 从 Jest、Vitest 或 Playwright 迁移

如果要将现有的 Jest、Vitest 或 Playwright Test 项目迁移到 Rstest，使用这个 prompt。Playwright Test 项目会迁移到 `@rstest/playwright`。为方便使用，链接中的指令内联了完整的 [migrate-to-rstest](https://github.com/rstackjs/agent-skills#migrate-to-rstest) skill，无需额外安装；你也可以[安装该 skill](#agent-skills) 后直接使用：

<Prompt
  title="迁移到 Rstest"
  description="复制这个 prompt 并发送给你的 Coding Agent。"
  prompt={`Migrate this project to Rstest, the JavaScript testing framework. Detect whether it uses Jest, Vitest, or Playwright Test; for Playwright Test, migrate to @rstest/playwright. Follow the instructions here:
https://rstest.rs/guide/start/agent-migrate.md`}
/>

## Agent Skills

Agent Skills 是可安装到 Agent 中的领域知识包，用于指导 Coding Agent 完成 Rstest 相关工作流。

[rstackjs/agent-skills](https://github.com/rstackjs/agent-skills) 仓库包含以下与 Rstest 相关的 Skills：

- [migrate-to-rstest](https://github.com/rstackjs/agent-skills#migrate-to-rstest)：将 Jest、Vitest 或 Playwright Test 项目迁移到 Rstest；Playwright E2E 测试使用 `@rstest/playwright`。
- [rstest-best-practices](https://github.com/rstackjs/agent-skills#rstest-best-practices)：Rstest 配置与测试编写的最佳实践。
- [rstest-debugging](https://github.com/rstackjs/agent-skills#rstest-debugging)：系统化排查 Rstest 问题，包括性能回归。适用于 Rstest 比预期慢、比 Jest 或 Vitest 慢，或需要在改动配置或代码前先定位瓶颈是在构建启动还是测试执行阶段的场景。

在支持 Skills 的 Coding Agent 中，可以通过 [skills](https://www.npmjs.com/package/skills) 安装指定 Skill：

<PackageManagerTabs
  command="skills add rstackjs/agent-skills --skill migrate-to-rstest"
  dlx
/>

安装完成后，用自然语言即可触发对应 Skill，例如：

```
帮我把这个 Playwright Test 项目迁移到 @rstest/playwright
```

## llms.txt

[llms.txt](https://llmstxt.org/) 是帮助 LLM 发现和读取项目文档的标准规范。Rstest 发布了以下两个文件：

- [llms.txt](https://rstest.rs/llms.txt)：结构化索引文件，包含所有文档页面的标题、链接和简要说明。

```
https://rstest.rs/llms.txt
```

- [llms-full.txt](https://rstest.rs/llms-full.txt)：完整内容文件，将所有文档页面合并为单个文件。

```
https://rstest.rs/llms-full.txt
```

可根据上下文窗口预算选择：

- `llms.txt` 体积小、消耗 token 少，适合让 Agent 按需获取具体页面。
- `llms-full.txt` 将全部文档合并在单个文件中，无需 Agent 逐一跳转链接，但 token 消耗更高。

## Markdown 文档

Rstest 文档的每个页面都提供对应的 `.md` 纯文本版本。在任意文档页面标题下方点击「复制 Markdown」或「复制 Markdown 链接」，即可将具体章节作为上下文提供给 AI：

```
https://rstest.rs/guide/start/index.md
```

## Markdown 报告器

需要让 AI 直接消费测试结果时，可以使用 `md` 报告器。它会将测试结果以单份 Markdown 文档输出到 stdout，相比带 ANSI 颜色的终端日志更简洁，也更容易被 LLM 解析。

在 Agent 环境中，如果在 `rstest.config.ts` 或 CLI 参数中均未显式配置 reporter，Rstest 会默认使用 `['md']`。设置 `RSTEST_NO_AGENT=1` 可以关闭 Agent 环境检测，保留默认的控制台报告器。

```bash
npx rstest --reporters=md
```

也可以在 `rstest.config.ts` 中配置并与其他报告器组合使用：

```ts
import { defineConfig } from '@rstest/core';

export default defineConfig({
  reporters: ['md'],
});
```

预设与配置项详情见 [Markdown 报告器](/guide/basic/reporters#markdown-报告器)。

## AGENTS.md

在项目根目录创建遵循 [AGENTS.md](https://agents.md/) 规范的 `AGENTS.md` 文件，向 Coding Agent 提供项目测试命令与文档链接：

```markdown wrapCode
# AGENTS.md

You are an expert in JavaScript, Rspack, Rsbuild, and Rstest. You write maintainable, performant, and accessible tests.

## Tools

### Rstest

- Run `npm run test` to run tests (`npx rstest`)
- Run `npm run test:watch` to run tests in watch mode (`npx rstest --watch`)

## Docs

- Rstest: https://rstest.rs/llms.txt
```

可以根据项目实际情况补充目录结构、约定和自定义脚本说明。
