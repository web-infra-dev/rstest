# Rslint

[Rslint](https://rslint.rs/) 是一个兼容 ESLint 的 JavaScript 和 TypeScript linter，内置的 `rstestPlugin` 用于检查 Rstest 测试定义、断言、mock 和 snapshot 中的常见问题。

先将 [@rslint/core](https://github.com/web-infra-dev/rslint) 安装为开发依赖：

import { PackageManagerTabs } from '@theme';

<PackageManagerTabs command="add @rslint/core -D" />

## 预设配置

`rstestPlugin.configs` 导出了四个预设配置：

| 预设          | 说明                                                                                        |
| ------------- | ------------------------------------------------------------------------------------------- |
| `recommended` | 包含 17 条规则，检查测试结构、断言、mock 和 snapshot 中的常见问题                           |
| `style`       | 包含 3 条代码风格规则（`prefer-to-be`、`prefer-to-contain`、`prefer-to-have-length`）       |
| `all`         | 启用全部 Rstest 规则（多数规则默认为警告级别）                                              |
| `env`         | 声明 Rstest 全局 API（`describe`、`test`、`it`、`expect`、`rs`、`rstest` 和生命周期钩子等） |

如果在 Rstest 中开启了 [`globals: true`](/config/test/globals)，可以同时引入 `rstestPlugin.configs.env`，让 Rslint 识别无需显式导入的全局测试 API：

```ts title="rslint.config.ts"
import { defineConfig, rstestPlugin } from '@rslint/core';

export default defineConfig([
  {
    ...rstestPlugin.configs.recommended,
    ...rstestPlugin.configs.env,
    files: ['**/*.{test,spec}.{js,jsx,ts,tsx,cjs,cts,mjs,mts}'],
  },
]);
```

## 独立的测试文件

如果测试代码位于独立的 `*.test.*` 或 `*.spec.*` 文件中，可以通过 `files` 将预设配置限定到测试文件：

```ts title="rslint.config.ts"
import { defineConfig, rstestPlugin } from '@rslint/core';

export default defineConfig([
  {
    ...rstestPlugin.configs.recommended,
    files: ['**/*.{test,spec}.{js,jsx,ts,tsx,cjs,cts,mjs,mts}'],
  },
]);
```

`rstestPlugin` 的预设配置默认不包含 `files` 匹配规则，加上 `files` 可以将 Rstest 规则限定在测试文件中，避免影响生产代码。

## In-source tests

使用 [in-source testing](/config/test/include-source) 时，测试代码与生产代码写在同一个文件中，并通过 `import.meta.rstest` 访问测试 API。此时不要限制 `files`，将预设应用到所有待检查文件：

```ts title="rslint.config.ts"
import { defineConfig, rstestPlugin } from '@rslint/core';

export default defineConfig([rstestPlugin.configs.recommended]);
```

使用 `import.meta.rstest` 不需要额外配置全局声明。

## 运行 Rslint

在项目根目录运行 Rslint：

<PackageManagerTabs command="exec rslint" />

检查通过时会输出如下汇总信息：

```text
start   Linting...
success Lint passed in 92ms (1 file, 17 rules, 14 threads)
```

如果发现问题，Rslint 会输出规则名称、源码位置、代码片段和失败汇总信息：

```text
start   Linting...

  rstest/no-identical-title  — [error] Test title is used multiple times in the same describe block
  ╭─┴──────────( invalid.test.ts:8:8 )─────
  │ 7 │
  │ 8 │  test('same title', () => {
  │ 9 │    expect(false).toBeFalsy();
  ╰────────────────────────────────

error   Lint failed with 1 error in 31ms (1 file, 17 rules, 14 threads)
```

也可以将 `rslint` 加入 `package.json` 的 `scripts` 中，通过包管理器的 lint 脚本运行。

## 查看 rules

有关预设配置的用法，请参考 [Rslint `rstestPlugin` 文档](https://rslint.rs/api/presets/rstest-plugin)；各条规则的说明与选项可查看 [Rstest 规则列表](https://rslint.rs/rules/?preset=rstestPlugin.configs.recommended)。
