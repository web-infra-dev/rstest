# Rspack 适配器配置参考

安装与注意事项请查看 [Rspack 集成概览](./)。本页包含完整的适配器 API、配置映射说明和调试方法。

## API

### `withRspackConfig(options)`

返回一个配置函数，用于加载 Rspack 配置文件并将其转换为 Rstest 配置。

#### `cwd`

- **类型：** `string`
- **默认值：** `process.cwd()`

用于解析 Rspack 配置文件和持久化缓存相对路径的工作目录。

当 Rspack 配置文件位于其他目录（例如 monorepo 中的某个子包）时，可通过 `cwd` 指定工作目录：

```ts title="rstest.config.ts"
export default defineConfig({
  extends: withRspackConfig({
    cwd: './packages/my-app',
  }),
});
```

#### `configPath`

- **类型：** `string`
- **默认值：** `undefined`

Rspack 配置文件路径。相对路径基于 `cwd` 解析。

未指定时，适配器会在 `cwd` 中按顺序查找 `rspack.config.{js,ts,mjs,mts,cjs,cts}`（优先 `.js`）。如果未找到配置文件或指定路径不存在，`withRspackConfig` 会静默返回 `{}`。

成功加载配置文件后，该文件路径会被加入 [`forceRerunTriggers`](/config/test/force-rerun-triggers)；若启用了持久化缓存，还会加入 `performance.buildCache.buildDependencies`。

#### `configName`

- **类型：** `string`
- **默认值：** `undefined`

当 Rspack 配置导出数组时，按 `name` 字段选择对应配置，并设置 Rstest 的 `name`（`configName ?? config.name`）。若未找到匹配项会抛出错误；未指定 `configName` 时默认使用数组的第一项。

假设你的 Rspack 配置导出了多个配置：

```ts title="rspack.config.ts"
export default [
  {
    name: 'client',
    target: 'web',
    entry: './src/client.ts',
    // ...
  },
  {
    name: 'server',
    target: 'node',
    entry: './src/server.ts',
    // ...
  },
];
```

通过 `configName` 选择其中一项：

```ts title="rstest.config.ts"
export default defineConfig({
  extends: withRspackConfig({
    configName: 'client',
  }),
});
```

如果需要用不同 Rspack 配置独立测试多个目标，可以定义多个 Rstest `projects`：

```ts title="rstest.config.ts"
export default defineConfig({
  projects: [
    {
      extends: withRspackConfig({ configName: 'server' }),
      include: ['tests/server/**/*.{test,spec}.?(c|m)[jt]s'],
    },
    {
      extends: withRspackConfig({ configName: 'client' }),
      include: ['tests/client/**/*.{test,spec}.?(c|m)[jt]s?(x)'],
    },
  ],
});
```

#### `env`

- **类型：** `Record<string, unknown> | string[]`
- **默认值：** `undefined`

当 Rspack 配置文件导出函数时，传递给该函数的 `env` 参数：

```ts title="rspack.config.ts"
export default (env) => {
  console.log(env); // 接收传入的 `env` 值
  return {/* ... */};
};
```

#### `nodeEnv`

- **类型：** `string`
- **默认值：** `undefined`

加载 Rspack 配置时使用的 `NODE_ENV` 值。

#### `modifyRspackConfig`

- **类型：** `(config: RspackOptions) => RspackOptions`
- **默认值：** `undefined`

在将选中的 Rspack 配置转换为 Rstest 配置之前对其进行修改。回调函数必须返回 `RspackOptions` 对象：

```ts title="rstest.config.ts"
export default defineConfig({
  extends: withRspackConfig({
    modifyRspackConfig: (rspackConfig) => {
      delete rspackConfig.resolve?.alias;
      return rspackConfig;
    },
  }),
});
```

### `toRstestConfig(options)`

将内存中的 `RspackOptions` 对象直接转换为 Rstest 配置，不从磁盘读取配置文件。

```ts title="rstest.config.ts"
import type { RspackOptions } from '@rspack/core';
import { defineConfig } from '@rstest/core';
import { toRstestConfig } from '@rstest/adapter-rspack';

const rspackConfig: RspackOptions = {
  target: 'web',
  resolve: {
    alias: {
      '@': './src',
    },
  },
};

export default defineConfig({
  extends: toRstestConfig({
    rspackConfig,
  }),
});
```

#### `rspackConfig`

- **类型：** `RspackOptions`

要转换的单个 Rspack 配置对象。

#### `configPath`

- **类型：** `string`
- **默认值：** `undefined`

与 `rspackConfig` 关联的源配置文件路径。适配器不会读取该路径，仅将其规范化后加入 [`forceRerunTriggers`](/config/test/force-rerun-triggers) 和持久化缓存的 `performance.buildCache.buildDependencies`。

同时支持 `cwd`（用于解析相对的 `rspackConfig.context`，或在未设置 `context` 时作为默认缓存根目录）、`configName`（覆盖 `name`）和 `modifyRspackConfig`，详见 [`withRspackConfig`](#withrspackconfigoptions)。

## 配置映射

适配器会根据选项所属的层级分别处理 Rspack 配置：有对应概念的选项转换为 Rstest 配置，兼容的编译器选项传给 Rspack，仅用于应用构建或与测试冲突的设置仍由 Rstest 控制。

### 转换为 Rstest 选项

这些选项会在创建编译器之前完成转换，供 Rstest 选择测试环境、解析模块及配置构建缓存：

| Rspack 选项                                                     | Rstest 等效项            | 说明                                                                                                                   |
| --------------------------------------------------------------- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| `name`                                                          | `name`                   | `configName` 优先级更高（`configName ?? config.name`）                                                                 |
| `resolve.alias`、`extensions`、`conditionNames` 和 `mainFields` | `resolve`                | 两端共用的模块解析选项；`resolve.alias: false` 不会写入此处，而是转发给 `tools.rspack`                                 |
| `resolve.tsConfig`                                              | `source.tsconfigPath`    | 支持字符串路径或 `{ configFile }`；完整的 `resolve.tsConfig` 也会转发给 `tools.rspack`                                 |
| `output.module`                                                 | `output.module`          | 输出模块格式                                                                                                           |
| `target`                                                        | `testEnvironment`        | 若为 `'async-node'` 或以 `'node'` 开头（字符串或数组）则映射为 `'node'`，其余及未设置时映射为 `'happy-dom'`            |
| `cache`                                                         | `performance.buildCache` | 复用持久化缓存的 `storage.directory`、`version` 和 `buildDependencies`；`false` 或 `{ type: 'memory' }` 映射为 `false` |
| `context`                                                       | 持久化缓存路径           | 用于解析 `cache.storage.directory`、`cache.storage.location` 和 `cache.buildDependencies` 中的相对路径                 |
| `mode`                                                          | 持久化缓存标识           | 参与生成默认缓存名称（`<name>-<mode>`，未设置时按 `'production'` 处理）；编译器 `mode` 由 Rstest 根据 `NODE_ENV` 控制  |

### 与 Rstest 编译器钩子合并

这些选项通过 `tools.rspack` 参与 Rspack 编译，同时 Rstest 会保留测试运行时所需的约束：

| Rspack 选项        | 行为                                                                                                                                                                                                          |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `module`           | 合并 `module` 选项，并在 Rstest 基础规则之后追加 `rules`                                                                                                                                                      |
| `plugins`          | 过滤掉 `HtmlRspackPlugin` 后追加 `plugins`；同时适配器会移除 Rsbuild 内置的 CSS 插件（`rsbuild:css`、`rsbuild:less`、`rsbuild:sass`）                                                                         |
| `output`           | 合并 `output` 选项，同时保留 Rstest 的 `output.path` 及内部运行时输出设置                                                                                                                                     |
| `resolve`          | 合并 `fallback`、`byDependency`、`extensionAlias`、`preferRelative`、`tsConfig` 等 Rspack 专属选项；`alias: false` 会在编译器层清除别名，Rstest 仍保留 `.cjs`、`extensionAlias` 和 Node/CommonJS 默认解析规则 |
| `experiments`      | 合并 `experiments`，但 Rstest 会保留运行时模式并禁用 `asyncWebAssembly`                                                                                                                                       |
| `optimization`     | 合并 `optimization`，但 Rstest 会保留共享的 `runtimeChunk` 和 `emitOnErrors: true`                                                                                                                            |
| `devtool`          | 保留 inline 类型的 source map；非 inline 或未设置时由 Rstest 归一化为 `'nosources-source-map'`                                                                                                                |
| `watchOptions`     | 合并 Rstest 在 watch 模式下使用的监听选项                                                                                                                                                                     |
| `externalsPresets` | 合并兼容的 presets，随后由 Rstest 固定 `node: false` 以便按请求分配 external 类型                                                                                                                             |
| `cache`            | 直接应用 `false` 或 `{ type: 'memory' }`；对于 `{ type: 'persistent' }`，Rstest 会重新生成持久化缓存配置并保留解析后的 `storage.location`                                                                     |

:::warning
由于适配器移除了 Rsbuild 内置的 CSS 插件（`rsbuild:css`、`rsbuild:less`、`rsbuild:sass`），使用此适配器时 `output.cssModules` 等 Rsbuild 专属 CSS 选项不可用，请在 Rspack 配置中处理 CSS 规则和 loader。
:::

### 通过 `mergeConfig` 透传

这些选项不与 Rstest 的测试构建结构冲突，适配器会通过 Rsbuild 的 `mergeConfig` 将它们合并到基础 Rspack 配置中：

| Rspack 选项             | 行为                                                                                |
| ----------------------- | ----------------------------------------------------------------------------------- |
| `externals`             | 将用户 externals 与 Rstest 生成的 externals 合并                                    |
| `externalsType`         | 为未声明类型的用户 externals 设置默认类型；Rstest 生成的 externals 会按请求指定类型 |
| `infrastructureLogging` | 合并编译器和插件的 infrastructure logging 选项                                      |
| `loader`                | 合并通过 loader context 暴露的自定义值                                              |
| `ignoreWarnings`        | 将用户的警告过滤规则追加到 Rstest 生成的规则中                                      |
| `resolveLoader`         | 合并 loader 解析选项                                                                |
| `amd`                   | 应用配置的 `require.amd` 和 `define.amd` 值                                         |
| `incremental`           | 应用配置的 Rspack 增量构建策略（Rspack 可能会将 `'safe'` 等预设展开为具体选项）     |

### 由 Rstest 控制或忽略

这些选项用于描述应用入口、多编译器编排、dev server 或由 Rstest 接管的编译与输出行为，因此不会被转发：

- **入口与多编译器：** `entry`、`dependencies`、`extends`
- **编译与输出控制：** `output.path`、`context`（仅用于解析缓存路径；编译器使用项目根目录）、`mode`（仅参与缓存名称生成；编译器根据 `NODE_ENV` 设置）、`node`、`stats`、`bail`、`performance`、`snapshot`
- **监听、dev server 与懒编译：** `watch`、`devServer`、`lazyCompilation`
- **持久化缓存调优：** `cache.snapshot`、`maxAge`、`portable`、`readonly`
