- **类型：**

```ts
type BrowserViewport =
  | {

      height: number;

  | 'iPhoneSE'
  | 'iPhoneXR'

  | 'iPhone14ProMax'
  | 'Pixel7'
  | 'SamsungGalaxyS8Plus'
  | 'SamsungGalaxyS20Ultra'
  | 'iPadMini'

  | 'iPadPro'

  | 'GalaxyZFold5'

  | 'SamsungGalaxyA51A71'
  | 'NestHub'

type BrowserModeConfig = {
  enabled?: boolean;
  provider: 'playwright';
  /** @deprecated 请改用 `instances`，将在 1.0 移除。 */
  browser?: 'chromium' | 'firefox' | 'webkit';
  headless?: boolean;
  screenshotFailures?: boolean;
  port?: number;
  viewport?: BrowserViewport;
  strictPort?: boolean;
  providerOptions?: Record<string, unknown>;
  /** @default 'chromium' */
  instances?: BrowserInstanceConfig[];
  expect?: BrowserExpectConfig;

type BrowserExpectConfig = {
  toMatchScreenshot?: BrowserScreenshotMatcherConfig;
};

  browserName: BrowserName;
  headless?: boolean;

  screenshotFailures?: boolean;

type BrowserScreenshotPathOptions = {

  screenshotAssertionOrdinal?: number;
};
```

- **默认值：**

```ts
const defaultBrowser = {
  enabled: false,
  provider: 'playwright',
  instances: [{ browserName: 'chromium' }],
  headless: true, // CI 环境；本地开发为 false
  screenshotFailures: true, // 默认与 headless 设置一致
  port: undefined, // 随机可用端口
  viewport: undefined, // Browser UI 填满预览面板
  strictPort: false,
  providerOptions: {},
};
```

浏览器模式配置。启用后，测试将在真实浏览器中运行，而非 Node.js 环境。

## 选项

### screenshotFailures

<ApiMeta addedVersion="0.12.4" />

每个失败的浏览器测试都会保存一张 PNG 截图，默认值与 `headless` 设置一致。截图位于项目根目录下的 `.rstest/screenshots/`，文件名包含测试文件和测试名称。设为 `false` 可关闭截图。

- **类型：** `boolean`
- **默认值：** `browser.headless`
- **CLI：** `--browser.screenshotFailures`

### enabled

- **类型：** `boolean`
- **默认值：** `false`
- **CLI：** `--browser`、`--browser.enabled`

启用浏览器模式。

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
  },
});
```

:::tip
启用浏览器模式需要安装 `@rstest/browser` 包和 Playwright 浏览器。

```bash
npm add @rstest/browser -D
npx playwright install chromium
```

:::

### provider

- **类型：** `'playwright'`
- **默认值：** `'playwright'`

浏览器驱动提供者。目前仅支持 [Playwright](https://playwright.dev/)。

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
  },
});
```

### browser（已废弃） \{#browser-deprecated}

<ApiMeta addedVersion="0.13.0" />

:::warning 已废弃
`browser.browser` 已废弃，将在 1.0 移除。请改用 [`instances`](#instances)，例如 `instances: [{ browserName: 'firefox' }]`。设置该字段时，每个 run 会输出一次废弃警告。`--browser.name` 是对应的已废弃 CLI 形式。
:::

- **类型：** `'chromium' | 'firefox' | 'webkit'`
- **默认值：** `'chromium'`
- **CLI：** `--browser.name <name>`（已废弃）

用于测试的单个浏览器类型。设置该字段后会被规范化为 `instances: [{ browserName: browser }]`。

在 browser 项目中同时设置 `browser` 和 `instances` 属于配置错误。

- `chromium` - Google Chrome、Microsoft Edge
- `firefox` - Mozilla Firefox
- `webkit` - Safari

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    browser: 'firefox', // 已废弃；推荐 instances: [{ browserName: 'firefox' }]
  },
});
```

使用前需要安装对应的浏览器：

```bash
# 安装 Chromium
npx playwright install chromium

# 安装 Firefox
npx playwright install firefox

# 安装 WebKit
npx playwright install webkit

# 安装所有浏览器
npx playwright install
```

### instances

<ApiMeta addedVersion="0.13.0" />

- **类型：** `BrowserInstanceConfig[]`
- **默认值：** `[{ browserName: 'chromium' }]`
- **CLI：** `--browser.instances <names>`（逗号分隔和/或可重复传入，用于过滤已配置的 instance）

项目运行的浏览器 instance 列表，每个 instance 对应一个浏览器。一个项目的所有 instance共用同一次构建和同一个 dev server —— multi-browser run 并不会成倍增加构建时间。

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    instances: [{ browserName: 'chromium' }, { browserName: 'firefox' }],
  },
});
```

每一项都是 `BrowserInstanceConfig` 对象：`browserName` 必填，其余字段按浏览器覆盖项目级的值。只写浏览器名（例如 `instances: ['chromium']`）属于配置错误，请写成 `{ browserName: 'chromium' }`：

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    providerOptions: {
      launch: { slowMo: 100 },
      context: { locale: 'en-US' },
    },
    instances: [
      { browserName: 'firefox' },
      {
        browserName: 'chromium',
        viewport: { width: 800, height: 600 },
        providerOptions: {
          launch: { channel: 'chrome' },
        },
      },
    ],
  },
});
```

`BrowserInstanceConfig` 只支持运行时生效的覆盖字段；构建作用域的选项（`enabled`、`provider`、`port`、`strictPort`）仍留在项目级 `browser` 配置上：

| 字段                 | 默认值                              |
| -------------------- | ----------------------------------- |
| `browserName`        | 必填                                |
| `headless`           | 项目级 `browser.headless`           |
| `viewport`           | 项目级 `browser.viewport`           |
| `screenshotFailures` | 项目级 `browser.screenshotFailures` |
| `expect`             | 项目级 `browser.expect`             |
| `providerOptions`    | 项目级 `browser.providerOptions`    |

每个 instance 的合并规则：instance 字段优先，其次是项目级 `browser.*` 字段，最后是内置默认值。`providerOptions` 按顶层键（`launch`、`context`）合并，而不是整字段合并：instance 的某个顶层键（如 `launch`）会整体替换项目级的同名键（Playwright 选项可能包含函数和类实例，因此不在其内部逐层合并），instance 未设置的键保留项目级值 —— 上例中的 chromium instance 仅以 `channel: 'chrome'` 启动，其 context 保留项目级的 `locale: 'en-US'`。

一个项目按 instance 各运行一份浏览器；同一个文件会得到多条结果，每条结果以各自的项目名上报 —— 见 [多浏览器的 reporter 表现](#多浏览器的-reporter-表现)。

校验规则：

- 同一个 `browserName` 在一个项目中最多配置一次（重复为配置错误）。
- `instances` 不能为空 —— 移除该选项即可运行默认的 Chromium。
- 每次 run 最多只有一对 `(project, browser)` 以 headed 模式（`headless: false`）运行，见 [启动规则](#启动规则)。
- [`coverage.provider: 'v8'`](/config/test/coverage) 要求所有选中的浏览器都是 Chromium，见 [启动规则](#启动规则)。

### viewport

<ApiMeta addedVersion="0.8.4" />

- **类型：** `BrowserViewport`
- **默认值：** `undefined`

设置 Browser Mode 测试的默认 runner iframe viewport。如果未指定，Browser UI 会填满预览面板。[`instances`](#instances) 的每一项可以按浏览器覆盖 viewport。

```ts
type BrowserViewport =
  | {
      width: number;
      height: number;
    }
  | DevicePreset;
```

如果你希望一个 browser 项目中的所有文件都使用同一个 viewport，可以显式指定尺寸：

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    viewport: { width: 390, height: 844 },

});
```

import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {

### port

- **类型：** `number`
- **默认值：** `undefined`（自动选择可用端口）
- **CLI：** `--browser.port <port>`

浏览器模式 Dev Server 的端口号。

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    port: 5173,
  },
});
```

如果指定了 `port` 且端口已被占用，是否报错由 `strictPort` 控制：当 `strictPort: true` 时会报错退出；当 `strictPort: false` 时会尝试使用其他可用端口。如果未指定 `port`，则始终会自动选择一个可用端口。

### strictPort

- **类型：** `boolean`
- **默认值：** `false`
- **CLI：** `--browser.strictPort`

当指定 `port` 时，是否要求端口必须可用：

- `true`：如果端口被占用则直接报错退出
- `false`：如果端口被占用则自动回退到其他可用端口

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    port: 5173,
    strictPort: true,
  },
});
```

### providerOptions

<ApiMeta addedVersion="0.9.3" />

- **类型：** `Record<string, unknown>`
- **默认值：** `{}`
- **CLI：** `--browser.providerOptions.*`

传递给 Playwright 浏览器启动和 context 创建过程的选项。Rstest 不会验证或解析该对象，而是将值原样转发给 Playwright。

[`instances`](#instances) 的每个 `BrowserInstanceConfig` 可以携带自己的 `providerOptions`：instance 设置的顶层键（`launch`、`context`）会替换项目级的同名键，instance 未设置的键保留项目级值。

支持的字段详见下方 [Playwright provider 选项](#provider-选项)。

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    providerOptions: {
      launch: {
        timeout: 60_000,
      },
    },
  },
});
```

也可以通过 CLI 传入嵌套的 Playwright 选项：

```bash
npx rstest --browser.providerOptions.launch.channel=chrome
```

### expect.toMatchScreenshot

<ApiMeta addedVersion="0.12.4" />

- **类型：** `BrowserScreenshotMatcherConfig`
- **默认值：**

```ts
{
  comparatorOptions: {
    threshold: 0.1,
    maxDiffPixels: 0,
  },
  stabilityTimeout: 2000,
  maskColor: '#FF00FF',
  caret: 'hide',
  scale: 'device',
  omitBackground: false,
}
```

`maxDiffPixelRatio` 的默认值同样为 `0`；如需按比例设置容差，请用它替代 `maxDiffPixels`。默认不注入额外的 `style`，也不遮罩任何元素；`mask` 仅支持在断言中配置。

为 Browser Mode 项目中的 [`toMatchScreenshot()`](/api/runtime-api/browser-mode/assertion#screenshot-matching) 配置全局默认值。像素比较容差配置在 `comparatorOptions` 下；截图和路径选项与它同级。单次断言传入的值会覆盖对应的全局值。`mask` 仍需在断言中单独传入，因为它需要浏览器中的 `Locator` 对象。

省略选项时会使用以下默认行为。`maskColor`、`caret`、`scale` 和 `omitBackground` 的截图默认值由 Playwright 提供。

| 选项                                  | 默认值            | 说明                                         |
| ------------------------------------- | ----------------- | -------------------------------------------- |
| `comparatorOptions.threshold`         | `0.1`             | 单像素颜色距离阈值，`0` 最严格，`1` 最宽松。 |
| `comparatorOptions.maxDiffPixels`     | `0`               | 允许差异的最大像素数。                       |
| `comparatorOptions.maxDiffPixelRatio` | `0`               | 允许差异像素所占的最大比例。                 |
| `stabilityTimeout`                    | `2000`            | 等待连续截图一致的最长时间，单位为毫秒。     |
| `maskColor`                           | `#FF00FF`         | 遮罩内容使用的颜色。                         |
| `style`                               | 未设置            | 不注入额外 CSS。                             |
| `caret`                               | `hide`            | 截图时隐藏文本光标。                         |
| `scale`                               | `device`          | 按设备像素比截图。                           |
| `omitBackground`                      | `false`           | 截图保留页面背景。                           |
| `screenshotDirectory`                 | `__screenshots__` | 测试文件旁存放基线的目录。                   |
| `resolveScreenshotPath`               | 内置默认          | 使用下文介绍的默认路径布局。                 |

`comparatorOptions.maxDiffPixels` 和 `comparatorOptions.maxDiffPixelRatio` 只能配置其中一个。相对路径的 `screenshotDirectory` 从各测试文件所在目录解析；未配置时默认为 `__screenshots__`。共用同一截图目录时，Rstest 会按项目名和测试文件隔离基线，切换 checkout 后路径仍保持稳定。如果所选目录就是测试文件所在目录，基线会存入其中的 `__screenshots__` 子目录。

默认路径如下：

```text
<测试文件目录>/__screenshots__/<测试文件名>/<基线名>-<浏览器>-<平台>.png
```

基线名来自显式传入的名称或测试名，并会转换为适合文件系统的路径；可能因清理规则产生冲突的名称会追加稳定后缀。每个未命名断言都会从 `1` 开始编号，即使测试中只有一张截图，例如 `<测试名>-1`。显式命名的断言不加序号。

默认路径不包含项目名，因此测试文件、截图名、浏览器和平台相同的项目会共用一份基线。如需按项目隔离基线，可通过 `resolveScreenshotPath` 自定义路径。Rstest 旧哈希布局中的基线不会自动迁移；请将其移动到新路径，或使用 `--update` 重新生成。

如需自定义路径布局，可使用 `resolveScreenshotPath`。回调会收到测试文件绝对路径、项目名、测试名、浏览器、平台，以及未命名断言使用的可选序号。第一个未命名断言不传序号，后续断言从 `2` 开始。返回绝对路径或相对于项目根目录的路径。配置此回调后，它的优先级高于 `screenshotDirectory`。

```ts title="rstest.config.ts"
import path from 'node:path';
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    expect: {
      toMatchScreenshot: {
        comparatorOptions: {
          threshold: 0.1,
          maxDiffPixels: 10,
        },
        resolveScreenshotPath: ({
          testFilePath,
          projectName,
          testName,
          browserName,
          platform,
        }) =>
          path.join(
            'visual-baselines',
            projectName,
            path.relative(process.cwd(), testFilePath),
            `${testName}-${browserName}-${platform}.png`,
          ),
      },
    },
  },
});
```

## 启动规则

每次 `rstest` run 会按 `(provider, browserName, headless, providerOptions.launch)` 组合为所有 Browser Mode 项目启动浏览器：两个项目若配置了相同且 launch key 一致的浏览器，会共用同一个浏览器实例；`providerOptions.launch` 或 `headless` 不同则各自启动。一个项目的所有浏览器共享同一次构建和同一个 dev server。

浏览器按需启动：某个 launch 在第一个测试文件需要它时才启动，因此无法启动的 launch（例如可执行文件不存在）会在运行到对应文件时让本次 run 失败，而不是在 run 开始前。同时打开的 headless 浏览器最多为 [`pool.maxWorkers`](/config/test/pool#poolmaxworkers) 个；有新的 launch 需要名额时，会关闭空闲的浏览器，优先关闭最久未使用的。watch 模式下，空闲浏览器会在两次运行之间保持打开，直到需要腾出名额。headed 浏览器不计入该数量，并在整个 run 期间保持打开。

以下规则在任何浏览器启动之前完成校验：

- **每次 run 只能有一个 headed 浏览器。** Browser Mode 只打开一个调试窗口，因此最多允许一对 `(project, browser)` 设置 `headless: false`，其余浏览器必须设置 `headless: true`。报错信息会给出具体修复方式：

  > Only one (project, browser) pair can run headed per run: "web" ("chromium"). Browser mode opens one debug window, so every other browser must set headless: true. Most often this comes from `--browser.headless=false` on a multi-browser run: select a single headless pair with `--browser.instances <name>` or narrow the projects with `--project`.

- **Watch 模式不支持混合 headed 与 headless 浏览器。** 当一个浏览器 headed、另一个 headless 时，watch 会话在校验阶段被拒绝：所有配置的浏览器必须设置 `headless: true`，或改用非 watch 方式运行。

- **Coverage provider `v8` 需要 Chromium。** 当设置 `coverage.enabled` 且 `coverage.provider: 'v8'` 时，browser 项目选中任何非 Chromium 浏览器都会校验失败。可切换到 `coverage.provider: 'istanbul'`，或只选择 Chromium（`--browser.instances chromium`）。

如需浏览器与运行环境一一对应的严格覆盖策略，仍可将测试拆成多次执行（例如在 CI matrix 中分别跑），并用 `--browser.instances` 过滤：

```bash
npx rstest --browser.instances chromium
npx rstest --browser.instances firefox
npx rstest --browser.instances webkit
```

## CLI 浏览器过滤

`--browser.instances <names>`（可重复和/或逗号分隔）与 `--project` 一样只做过滤：只运行 `browserName` 在列表中的已配置 instance，不会根据名字新建 instance。未配置任何 instance 时的默认 Chromium instance，以及已废弃的 `browser.browser` 对应的 instance，都算作已配置的 instance。

- 某个 browser 项目的 instance 一个都没匹配上时，该项目在本次 run 中被跳过；node 项目不受影响。
- 列出的名字如果没有任何被选中的 browser 项目配置，会报错，并给出该名字和各项目已配置的浏览器。
- 重复的名字，以及 `chromium`、`firefox`、`webkit` 之外的名字，都会报错。

`--browser.name <name>` 作为已废弃的选项保留，每个 run 输出一次废弃警告。项目只运行该浏览器：配置了同名 `browserName` 的 instance 时沿用它的覆盖项，否则使用继承项目级默认值的普通 instance。它不能与 `--browser.instances` 同时使用。

## 多浏览器的 reporter 表现

Reporter 不感知浏览器。当项目选择了多个浏览器时，每个 `(project, browser)` 组合会作为一个独立项目上报，名称为 `<project> (<browserName>)`，例如 `web (chromium)` 与 `web (firefox)`。只选择一个浏览器的项目保留原名。

- Reporter payload、`rstest list` 结果和 blob 报告都以该名称作为 `project`，因此同一文件在两个浏览器下运行会得到两条互不覆盖的结果。内置 reporter 像展示其他项目名一样展示它，例如 `✓ [web (chromium)] tests/basic.test.ts`。
- 这些组合只影响上报：同一项目的所有浏览器仍共用一次构建和一个 dev server，`--project` 仍按配置中的项目名过滤。
- 配置中的项目名不能与生成的 `<project> (<browserName>)` 名称冲突，冲突会作为配置错误报出。

## 多项目配置隔离

在 Browser Mode 下使用 `projects` 时，每个项目会按自己的构建配置独立编译和执行（如 `plugins`、`include`、框架设置），不会复用其他项目的构建配置。

Browser 构建作用域的选项按项目保留（`provider`、`port`、`strictPort`），而浏览器列表、默认值与按浏览器覆盖（`instances`、`headless`、`viewport`、`providerOptions`）由项目自持：两个 browser 项目可以在一次 run 中运行不同浏览器。若多个项目配置了相同的浏览器，会遵循[启动规则](#启动规则)共用浏览器实例。

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  projects: ['./project-b/rstest.config.ts', './project-a/rstest.config.ts'],
});
```

```ts title="project-a/rstest.config.ts"
import { pluginReact } from '@rsbuild/plugin-react';
import { defineConfig } from '@rstest/core';

export default defineConfig({
  name: 'project-a',
  plugins: [pluginReact()],
  include: ['tests/**/*.test.tsx'],
  browser: {
    enabled: true,
    provider: 'playwright',
  },
});
```

## 与 Node 测试混合

可以同时配置浏览器测试和 Node.js 测试：

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  projects: [
    {
      name: 'browser',
      include: ['src/**/*.browser.test.ts'],
      browser: {
        enabled: true,
        provider: 'playwright',
      },
    },
    {
      name: 'node',
      include: ['src/**/*.node.test.ts'],
      testEnvironment: 'node',
    },
    {
      name: 'jsdom',
      include: ['src/**/*.test.ts'],
      exclude: ['src/**/*.browser.test.ts', 'src/**/*.node.test.ts'],
      testEnvironment: 'jsdom',
    },
  ],
});
```

## Provider 选项

### Playwright

使用 `provider: 'playwright'` 时，Playwright provider 识别 `providerOptions` 中的以下字段：

1. **`launch`** — 传递给 Playwright [`browserType.launch()`](https://playwright.dev/docs/api/class-browsertype#browser-type-launch)，控制浏览器进程的启动方式。
2. **`context`** — 传递给 Playwright [`browser.newContext()`](https://playwright.dev/docs/api/class-browser#browser-new-context)，控制每个测试文件创建的 browser context。

由于 `providerOptions` 的类型是 `Record<string, unknown>`，默认不会提供 IntelliSense。如需类型检查和自动补全，可以直接从 `playwright` 包导入类型，并配合 TypeScript 的 `satisfies` 运算符使用：

```ts title="rstest.config.ts"
import type { LaunchOptions, BrowserContextOptions } from 'playwright';
import { defineConfig } from '@rstest/core';

type PlaywrightProviderOptions = {
  launch?: LaunchOptions;
  context?: BrowserContextOptions;
};

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    providerOptions: {
      launch: {
        timeout: 60_000,
      },
      context: {
        locale: 'en-US',
        colorScheme: 'dark',
      },
    } satisfies PlaywrightProviderOptions,
  },
});
```
