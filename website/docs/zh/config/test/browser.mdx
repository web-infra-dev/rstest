# browser

- **类型：**

```ts
type BrowserName = 'chromium' | 'firefox' | 'webkit';

type BrowserViewport =
  | {
      width: number;
      height: number;
    }
  | DevicePreset;

type DevicePreset =
  | 'iPhoneSE'
  | 'iPhoneXR'
  | 'iPhone12Pro'
  | 'iPhone14ProMax'
  | 'Pixel7'
  | 'SamsungGalaxyS8Plus'
  | 'SamsungGalaxyS20Ultra'
  | 'iPadMini'
  | 'iPadAir'
  | 'iPadPro'
  | 'SurfacePro7'
  | 'SurfaceDuo'
  | 'GalaxyZFold5'
  | 'AsusZenbookFold'
  | 'SamsungGalaxyA51A71'
  | 'NestHub'
  | 'NestHubMax';

type BrowserModeConfig = {
  enabled?: boolean;
  provider: 'playwright';
  /** @deprecated 请改用 `instances`，将在 1.0 移除。 */
  browser?: BrowserName;
  headless?: boolean;
  screenshotFailures?: boolean | { clean?: boolean };
  port?: number;
  viewport?: BrowserViewport;
  strictPort?: boolean;
  providerOptions?: Record<string, unknown>;
  /** @default [{ browserName: 'chromium' }] */
  instances?: BrowserInstanceConfig[];
  expect?: BrowserExpectConfig;
};

type BrowserExpectConfig = {
  toMatchScreenshot?: BrowserScreenshotMatcherConfig;
};

type BrowserInstanceConfig = {
  browserName: BrowserName;
  headless?: boolean;
  viewport?: BrowserViewport;
  screenshotFailures?: boolean | { clean?: boolean };
  expect?: BrowserExpectConfig;
  providerOptions?: Record<string, unknown>;
};

type BrowserScreenshotPathOptions = {
  testFilePath: string;
  projectName: string;
  testName: string;
  browserName: BrowserName;
  platform: string;
  screenshotAssertionOrdinal?: number;
};
```

- **默认值：**

```ts
const defaultBrowser = {
  enabled: false,
  provider: 'playwright',
  instances: [{ browserName: 'chromium' }],
  headless: true, // CI 环境；本地开发为 false
  screenshotFailures: true, // 默认与 browser.headless 一致（CI 为 true，本地为 false）
  port: undefined, // 随机可用端口
  viewport: undefined, // Browser UI 填满预览面板
  strictPort: false,
  providerOptions: {},
};
```

配置浏览器模式，使测试在真实浏览器而非 Node.js 环境中运行。

## 选项

### enabled

- **类型：** `boolean`
- **默认值：** `false`
- **CLI：** `--browser`、`--browser.enabled`

启用浏览器模式。

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
  },
});
```

:::tip
启用浏览器模式需要安装 [@rstest/browser](https://github.com/web-infra-dev/rstest/tree/main/packages/browser)、`playwright` 和 Playwright 浏览器：

```bash
npm add @rstest/browser playwright -D
npx playwright install chromium
```

:::

### provider

- **类型：** `'playwright'`
- **默认值：** `'playwright'`

浏览器驱动提供者。目前仅支持 [Playwright](https://playwright.dev/)。在 `BrowserModeConfig` TypeScript 类型中 `provider` 为必填字段；运行时默认值为 `'playwright'`。

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
  },
});
```

### instances

<ApiMeta addedVersion="0.13.0" />

- **类型：** `BrowserInstanceConfig[]`
- **默认值：** `[{ browserName: 'chromium' }]`
- **CLI：** `--browser.instances <names>`（逗号分隔和/或可重复传入，用于过滤已配置的 instance）

项目运行的浏览器 instance 列表，每个 instance 对应一个浏览器。同一个项目的所有 instance 共用同一次构建和同一个 dev server，因此多浏览器运行不会成倍增加构建时间。

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    instances: [{ browserName: 'chromium' }, { browserName: 'firefox' }],
  },
});
```

每一项都是 `BrowserInstanceConfig` 对象：`browserName` 必填，其余字段按浏览器覆盖项目级的值。只写浏览器名（如 `instances: ['chromium']`）属于配置错误，请写成 `{ browserName: 'chromium' }`：

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    providerOptions: {
      launch: { slowMo: 100 },
      context: { locale: 'en-US' },
    },
    instances: [
      { browserName: 'firefox' },
      {
        browserName: 'chromium',
        viewport: { width: 800, height: 600 },
        providerOptions: {
          launch: { channel: 'chrome' },
        },
      },
    ],
  },
});
```

`BrowserInstanceConfig` 只支持运行时覆盖字段；构建作用域的选项（`enabled`、`provider`、`port`、`strictPort`）仍留在项目级 `browser` 配置上：

| 字段                 | 默认值                              |
| -------------------- | ----------------------------------- |
| `browserName`        | 必填                                |
| `headless`           | 项目级 `browser.headless`           |
| `viewport`           | 项目级 `browser.viewport`           |
| `screenshotFailures` | 项目级 `browser.screenshotFailures` |
| `expect`             | 项目级 `browser.expect`             |
| `providerOptions`    | 项目级 `browser.providerOptions`    |

每个 instance 的合并优先级：instance 字段 > 项目级 `browser.*` > 内置默认值。`providerOptions` 按顶层键（`launch`、`context`）合并，不在内部逐层深合并：instance 上设置的 `launch` 会整体替换项目级的 `launch`（Playwright 选项可能包含函数或类实例），未设置的键保留项目级值。上例中的 `chromium` 仅以 `channel: 'chrome'` 启动，其 `context` 仍保留项目级的 `locale: 'en-US'`。

每个 instance 会独立执行项目的测试文件，并以各自的项目名称上报结果——见[多浏览器的 reporter 表现](#多浏览器的-reporter-表现)。

校验规则：

- 同一个 `browserName` 在单个项目中最多配置一次。
- `instances` 不能为空——移除该选项即可使用默认的 Chromium。
- [`coverage.provider: 'v8'`](/config/test/coverage) 要求选中的浏览器全部为 Chromium，见[启动规则](#launch-rules)。

### browser（已废弃） \{#browser-deprecated}

<ApiMeta addedVersion="0.13.0" />

:::warning 已废弃
`browser.browser` 已废弃，将在 1.0 移除。请改用 [`instances`](#instances)，例如 `instances: [{ browserName: 'firefox' }]`。设置该字段时，每次 run 会输出一次废弃警告。`--browser.name` 是对应的已废弃 CLI 形式。
:::

- **类型：** `'chromium' | 'firefox' | 'webkit'`
- **默认值：** `'chromium'`
- **CLI：** `--browser.name <name>`（已废弃）

用于测试的单个浏览器类型。设置该字段后会被规范化为 `instances: [{ browserName: browser }]`。

在同一个项目中同时设置 `browser` 和 `instances` 属于配置错误。

- `chromium`：Google Chrome、Microsoft Edge
- `firefox`：Mozilla Firefox
- `webkit`：Safari

运行前需先安装对应的 Playwright 浏览器（例如 `npx playwright install firefox`）。

### headless

- **类型：** `boolean`
- **默认值：** CI 环境为 `true`，本地开发为 `false`
- **CLI：** `--browser.headless`

以无头模式（无 UI 窗口）运行浏览器。[`instances`](#instances) 的每一项可按浏览器覆盖它，关于 headed 与 headless 协同运行的行为详见[启动规则](#launch-rules)。

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    headless: true,
  },
});
```

如果希望本地调试使用 headed 模式、CI 中使用 headless，可配置 `headless: process.env.CI === 'true'`。GitHub Actions 工作流示例见 [CI 集成](/guide/advanced/ci)。

### screenshotFailures

<ApiMeta addedVersion="0.12.4" />

- **类型：** `boolean | { clean?: boolean }`
- **默认值：** `browser.headless`
- **CLI：** `--browser.screenshotFailures`

浏览器测试每失败一次，Rstest 就会在项目根目录的 `.rstest/screenshots/` 下保存一张 PNG 截图。即使重试通过或跳过，仍可查看之前失败时的截图。设为 `false` 可关闭截图。

每个测试文件都有自己的截图子目录。同一文件在不同项目或浏览器下运行时，截图也会分开保存。文件名由用例名和 UTC 时间（`YYYYMMDD-HHmmss`）组成，例如 `login-failed-20261127-100245.png`。如果文件名已存在，Rstest 会在 `.png` 前依次加上 `-2`、`-3` 等后缀。命令行会输出每张截图的实际路径。

默认情况下，重新运行测试文件会清理该文件上次的截图，在 watch 模式中删除文件也会清理对应的截图。设置 `screenshotFailures: { clean: false }` <ApiMeta sup addedVersion="1.0.0" /> 可开启截图并保留历次运行的截图，包括在 watch 模式中重跑或删除文件时。可以手动删除 `.rstest/screenshots/` 中的截图。

### viewport

<ApiMeta addedVersion="0.8.4" />

- **类型：** `BrowserViewport`
- **默认值：** `undefined`

Browser Mode 测试的默认 runner iframe viewport。未指定时，Browser UI 会填满预览面板。[`instances`](#instances) 的每一项可按浏览器覆盖 viewport。

可传入显式尺寸或内置设备 preset：

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    viewport: { width: 390, height: 844 },
    // 或使用设备 preset：
    // viewport: 'iPhone12Pro',
  },
});
```

### port

- **类型：** `number`
- **默认值：** `undefined`（自动选择可用端口）
- **CLI：** `--browser.port <port>`

浏览器模式 dev server 的端口号。

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    port: 5173,
  },
});
```

如果指定的 `port` 已被占用，[`strictPort`](#strictport) 决定 Rstest 是报错退出还是回退到其他可用端口。

### strictPort

- **类型：** `boolean`
- **默认值：** `false`
- **CLI：** `--browser.strictPort`

指定 `port` 时，控制端口被占用时的行为：设为 `true` 时直接报错退出，设为 `false` 时自动回退到其他可用端口。

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    port: 5173,
    strictPort: true,
  },
});
```

### providerOptions

<ApiMeta addedVersion="0.9.3" />

- **类型：** `Record<string, unknown>`
- **默认值：** `{}`
- **CLI：** `--browser.providerOptions.*`

原样转发给浏览器 provider 用于启动浏览器和创建 context 的选项。Rstest 不会校验或解析其中的字段。

[`instances`](#instances) 的每个 `BrowserInstanceConfig` 都可以定义自己的 `providerOptions`：instance 设置的顶层键（`launch`、`context`）会替换项目级同名键，未设置的键保留项目级值。

支持的字段详见下方 [Playwright provider 选项](#provider-选项)。

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    providerOptions: {
      launch: {
        timeout: 60_000,
      },
    },
  },
});
```

也可以通过 CLI 传入嵌套的 Playwright 选项：

```bash
npx rstest --browser.providerOptions.launch.channel=chrome
```

### expect.toMatchScreenshot

<ApiMeta addedVersion="0.12.4" />

- **类型：** `BrowserScreenshotMatcherConfig`
- **默认值：**

```ts
{
  comparatorOptions: {
    threshold: 0.1,
  },
  stabilityTimeout: 5000,
  maskColor: '#FF00FF',
  caret: 'hide',
  scale: 'device',
  omitBackground: false,
}
```

为 Browser Mode 项目中的 [`toMatchScreenshot()`](/api/runtime-api/browser-mode/assertion#toMatchScreenshot) 配置全局默认值。像素比较容差（`threshold`、`maxDiffPixels`、`maxDiffPixelRatio`）位于 `comparatorOptions` 下，截图与路径选项（`stabilityTimeout`、`maskColor`、`style`、`caret`、`scale`、`omitBackground`、`screenshotDirectory`、`resolveScreenshotPath`）与其同级（`mask` 仅支持在单次断言中传入）。

单次断言传入的选项会覆盖这些默认值；各选项默认值及像素上限优先级详见 [`toMatchScreenshot()`](/api/runtime-api/browser-mode/assertion#toMatchScreenshot)。

相对路径的 `screenshotDirectory` 从各测试文件所在目录解析（默认为 `__screenshots__`）。共用同一目录时，Rstest 会按项目名和测试文件隔离基线；若所选目录就是测试文件所在目录，基线会存入其中的 `__screenshots__` 子目录。

默认路径布局：

```text
<测试文件目录>/__screenshots__/<测试文件名>/<基线名>-<浏览器>-<平台>.png
```

基线名取自显式传入的名称或清理后的测试名（若清理后可能冲突则会追加稳定后缀）。每个未命名断言都会从 `1` 开始编号，即使测试中只有一张截图（如 `<测试名>-1`）；显式命名的断言不加序号。

默认路径不包含项目名，因此测试文件、截图名、浏览器和平台相同的项目会共用同一份基线。如需按项目隔离基线，请使用 `resolveScreenshotPath`。Rstest 旧哈希布局的基线不会自动迁移——请手动移动或使用 `--update` 重新生成。

`resolveScreenshotPath` 接收测试文件绝对路径、项目名、测试名、浏览器、平台以及未命名断言的可选序号（首个未命名断言为 `undefined`，后续从 `2` 开始），返回绝对路径或相对于项目根目录的路径。配置此回调后，其优先级高于 `screenshotDirectory`。

```ts title="rstest.config.ts"
import path from 'node:path';
import { defineConfig } from '@rstest/core';

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    expect: {
      toMatchScreenshot: {
        comparatorOptions: {
          threshold: 0.1,
          maxDiffPixels: 10,
        },
        resolveScreenshotPath: ({
          testFilePath,
          projectName,
          testName,
          browserName,
          platform,
        }) =>
          path.join(
            'visual-baselines',
            projectName,
            path.relative(process.cwd(), testFilePath),
            `${testName}-${browserName}-${platform}.png`,
          ),
      },
    },
  },
});
```

## 启动规则 \{#launch-rules}

每次 `rstest` run 会按 `(provider, browserName, headless, providerOptions.launch)` 组合为所有 Browser Mode 项目启动浏览器：launch key 一致的项目共用同一个浏览器实例，`providerOptions.launch` 或 `headless` 不同则各自启动。同一个项目的所有浏览器共享同一次构建和同一个 dev server。

浏览器按需启动：某个 launch 在第一个测试文件需要它时才启动，因此无法启动的 launch（例如可执行文件不存在）会在运行到对应文件时失败。同时打开的 headless 浏览器最多为 [`pool.maxWorkers`](/config/test/pool#poolmaxworkers) 个；有新的 launch 需要名额时，会优先关闭最久未使用的空闲浏览器。watch 模式下，空闲浏览器在两次运行之间保持打开，直到需要腾出名额。headed 浏览器不计入该上限，并在整个 run 期间保持打开。

headed 与混合模式行为：

- **多个 headed 浏览器。** 每对 headed `(project, browser)` 都会打开独立的 Browser UI 窗口，并在各自窗口内串行执行测试文件；不同 headed 窗口之间并发运行（共用同一个 `pool.maxWorkers` 文件并发预算）。如果只想打开单个调试窗口，可通过 `--browser.instances <name>` 或 `--project` 缩小范围。
- **混用 headed 与 headless 浏览器。** `run` 与 `watch` 模式均支持跨项目或同项目混用 headed 与 headless instance。在 watch 模式下，文件变更和 CLI 快捷键会重跑所有受影响的 lane；点击某个 headed Browser UI 窗口内的重跑按钮则仅重跑该窗口对应的 instance。

以下规则在任何浏览器启动之前完成校验：

- **Coverage provider `v8` 需要 Chromium。** 启用 `coverage.enabled` 且 `coverage.provider: 'v8'` 时，选中任何非 Chromium 浏览器都会校验失败。可切换为 `coverage.provider: 'istanbul'`，或仅选择 Chromium（`--browser.instances chromium`）。

如需按浏览器分别运行测试或收集覆盖率（例如在 CI matrix 中），可使用 `--browser.instances` 过滤：

```bash
npx rstest --browser.instances chromium
npx rstest --browser.instances firefox
npx rstest --browser.instances webkit
```

## CLI 浏览器过滤

`--browser.instances <names>`（可重复和/或逗号分隔）与 `--project` 一样只做过滤，仅运行 `browserName` 在列表中的已配置 instance，不会根据名字新建 instance。未配置 `instances` 时的默认 Chromium，以及已废弃的 `browser.browser` 对应的 instance，均计入已配置的 instance。

- 某个 browser 项目没有匹配到任何 instance 时，该项目在本次 run 中被跳过；Node 项目不受影响。
- 若传入的名称未被任何选中的 browser 项目配置，会报错并列出该名称及各项目已配置的浏览器。
- 重复的名称以及 `chromium`、`firefox`、`webkit` 之外的名称都会报错。

`--browser.name <name>` 作为已废弃选项保留，每次 run 输出一次废弃警告。它仅运行指定的单个浏览器（若配置了同名 `instances` 项则沿用其覆盖项，否则继承项目级默认值），且不能与 `--browser.instances` 同时使用。

## 多浏览器的 reporter 表现

Reporter 不感知浏览器。当项目运行多个浏览器时，每个 `(project, browser)` 组合会作为一个独立项目上报，名称为 `<project> (<browserName>)`（例如 `web (chromium)` 和 `web (firefox)`）；仅运行单个浏览器的项目保留原名。

- Reporter payload、`rstest list` 结果和 blob 报告都以此名称作为 `project`，因此同一文件在两个浏览器下运行会得到两条独立结果（例如 `✓ [web (chromium)] tests/basic.test.ts`）。
- 这仅用于上报视图：同一项目的所有浏览器仍共用一次构建和一个 dev server，`--project` 仍按配置中的项目名过滤。
- 配置中的项目名不能与生成的 `<project> (<browserName>)` 名称冲突，冲突会报配置错误。

## 多项目配置隔离

在 Browser Mode 下使用 `projects` 时，每个项目按自己的构建配置独立编译和执行（如 `plugins`、`include` 和框架设置）。构建作用域选项（`provider`、`port`、`strictPort`）按项目保留，浏览器列表、默认值及按浏览器覆盖（`instances`、`headless`、`viewport`、`screenshotFailures`、`expect`、`providerOptions`）归各项目自持。多项目配置示例见 [Browser mode 中的 projects](/guide/basic/projects#browser-mode-中的-projects)。

## 与 Node 测试混合

可以在同一配置中同时运行浏览器测试和 Node.js 测试：

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  projects: [
    {
      name: 'browser',
      include: ['src/**/*.browser.test.ts'],
      browser: {
        enabled: true,
        provider: 'playwright',
      },
    },
    {
      name: 'node',
      include: ['src/**/*.node.test.ts'],
      testEnvironment: 'node',
    },
  ],
});
```

## Provider 选项

### Playwright

使用 `provider: 'playwright'` 时，`providerOptions` 支持以下字段：

1. **`launch`** — 传递给 Playwright [`browserType.launch()`](https://playwright.dev/docs/api/class-browsertype#browser-type-launch)，控制浏览器进程启动。
2. **`context`** — 传递给 Playwright [`browser.newContext()`](https://playwright.dev/docs/api/class-browser#browser-new-context)，控制每个测试文件创建的 browser context。

由于 `providerOptions` 的类型为 `Record<string, unknown>`，可从 `playwright` 导入类型并配合 `satisfies` 获取类型检查和自动补全：

```ts title="rstest.config.ts"
import type { LaunchOptions, BrowserContextOptions } from 'playwright';
import { defineConfig } from '@rstest/core';

type PlaywrightProviderOptions = {
  launch?: LaunchOptions;
  context?: BrowserContextOptions;
};

export default defineConfig({
  browser: {
    enabled: true,
    provider: 'playwright',
    providerOptions: {
      launch: {
        timeout: 60_000,
      },
      context: {
        locale: 'en-US',
        colorScheme: 'dark',
      },
    } satisfies PlaywrightProviderOptions,
  },
});
```
