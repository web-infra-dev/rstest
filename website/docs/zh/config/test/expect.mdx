# expect

<ApiMeta addedVersion="0.11.6" />

- **类型：** `ExpectConfig`
- **默认值：** `{ poll: { interval: 50, timeout: 1000 } }`（Browser Mode 下 `timeout` 为 `5000`）

配置 [`expect.poll()`](/api/runtime-api/test-api/expect#expectpoll) 的默认值，以及 Browser Mode [`expect.element()`](/api/runtime-api/browser-mode/assertion) 的默认超时时间。Browser Mode 默认轮询超时为 `5000ms`，Node Mode 为 `1000ms`。调用处未显式传入 timeout 时，配置的超时时间会受当前测试阶段剩余时间限制；直接传给 `expect.poll()` 的选项优先级更高，不受此限制。`expect.poll()` 只能在测试阶段调用：它可以使用单个测试的 Hook 和 fixture 的有效超时时间，但不能在 `beforeAll` 或 `afterAll` 中使用。

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  expect: {
    poll: {
      interval: 100,
      timeout: 5000,
    },
  },
});
```

## expect.poll

轮询断言的全局配置。

### expect.poll.interval

- **类型：** `number`
- **默认值：** `50`

`expect.poll()` 每次重试之间的间隔时间，单位为毫秒。此配置不控制 Browser Mode `expect.element()` 的重试间隔，后者由浏览器 Provider 控制。`@rstest/playwright` 的 Locator/Page 断言也保留固定的 `50ms` 重试间隔。

### expect.poll.timeout

- **类型：** `number`
- **默认值：** `1000`（Browser Mode 下为 `5000`）

断言失败前允许的最长轮询时间，单位为毫秒。调用处未显式传入 timeout 时，实际值还会受当前 test 阶段的剩余时间限制。

此超时时间的作用范围如下：

| API                                                                     | 是否使用 `expect.poll.timeout` | 单次调用的覆盖方式                 |
| ----------------------------------------------------------------------- | ------------------------------ | ---------------------------------- |
| Node 或 Browser Mode 中的 `expect.poll(fn).toBe(...)`                   | 是                             | `expect.poll(fn, { timeout })`     |
| Browser Mode 的 `expect.element(locator).toContainText(...)` 等元素断言 | 是                             | `toContainText(text, { timeout })` |
| `expect(value).toBe(...)` 等普通断言                                    | 否，普通断言不会重试           | —                                  |
| `@rstest/playwright` 的 `expect(locator).toContainText(...)`            | 是，自 0.12.0 起               | `toContainText(text, { timeout })` |

单次调用显式传入的 timeout 优先于此配置（`expect.poll()` 仍可能因外层测试或 Hook 超时而提前结束；Browser Mode 的 `expect.element()` 和 `@rstest/playwright` 的 Locator/Page 断言仍受当前测试或 Hook 剩余时间限制）。未显式传入 timeout 时，Rstest 会取配置值与当前剩余时间中较小的值。

- **Browser Mode：** 默认为 `5000ms`；在并发测试中，请使用测试作用域内的 `expect` fixture 来按该测试的剩余时间计算（详见[浏览器断言超时](/api/runtime-api/browser-mode/assertion)）。
- **`@rstest/playwright`：** [`definePlaywrightConfig`](/guide/basic/e2e-testing#e2e-defaults) 将 `expect.poll.timeout` 默认设为 `5000ms`（不使用时 Node Mode 默认为 `1000ms`），显式配置会同时覆盖轮询和 Playwright Locator/Page 断言的超时。
- **并行 Hook：** 设置 [`sequence.hooks: 'parallel'`](/config/test/sequence#sequencehooks) 后，生命周期 Hook 内的断言使用配置的超时时间，不继承其他 Hook 的剩余时间。
