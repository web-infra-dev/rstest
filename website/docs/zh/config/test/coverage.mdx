# coverage

<ApiMeta addedVersion="0.4.0" />

- **类型：**

```ts
type CoverageOptions = {
  enabled?: boolean;
  provider?: 'istanbul' | 'v8';
  include?: string[];
  changed?: boolean | string;
  exclude?: string[];
  reporters?: CoverageReporter[];
  reportsDirectory?: string;
  reportOnFailure?: boolean;
  clean?: boolean;
  allowExternal?: boolean;
  thresholds?: CoverageThresholds;
};

type ReportWithOptions<Name extends keyof ReportOptions = keyof ReportOptions> =
  Name extends keyof ReportOptions
    ? [Name, Partial<ReportOptions[Name]>]
    : [Name, Record<string, unknown>];

type CoverageReporter =
  | keyof ReportOptions
  | ReportWithOptions
  | ReportBase
  | string
  | [string, Record<string, unknown>];
```

- **默认值：**

```ts
{
  enabled: false,
  provider: 'istanbul',
  reporters: ['text', 'html', 'clover', 'json'],
  reportsDirectory: './coverage',
  clean: true,
  reportOnFailure: false,
  allowExternal: false,
  exclude: [
    '**/node_modules/**',
    '**/__tests__/**',
    '**/__mocks__/**',
    '**/*.d.ts',
    '**/*.{test,spec}.[jt]s',
    '**/*.{test,spec}.[cm][jt]s',
    '**/*.{test,spec}.[jt]sx',
    '**/*.{test,spec}.[cm][jt]sx',
  ],
}
```

收集代码覆盖率并生成覆盖率报告。

```bash
$ npx rstest --coverage

----------|---------|----------|---------|---------|-------------------
File      | % Stmts | % Branch | % Funcs | % Lines | Uncovered Line #s
----------|---------|----------|---------|---------|-------------------
All files |     100 |      100 |     100 |     100 |
 index.ts |     100 |      100 |     100 |     100 |
----------|---------|----------|---------|---------|-------------------
```

### provider

- **类型：** `'istanbul' | 'v8'`
- **默认值：** `'istanbul'`
- **CLI：** `--coverage.provider <provider>`

选择覆盖率收集方式：

- `'istanbul'`：在 transform 阶段通过 SWC 插桩收集覆盖率，Istanbul 语义稳定；但已执行模块会保留覆盖率计数器，运行时内存占用相对较高。
- `'v8'`：通过 Node.js inspector 或 Chromium 原生 coverage API 收集数据并重映射为 Istanbul 格式；运行时内存占用更低，适合受内存压力影响的大型测试套件。

```ts title='rstest.config.ts'
import { defineConfig } from '@rstest/core';

export default defineConfig({
  coverage: {
    enabled: true,
    provider: 'v8',
  },
});
```

#### Istanbul provider

安装 [@rstest/coverage-istanbul](https://github.com/web-infra-dev/rstest/tree/main/packages/coverage-istanbul) 以使用 [Istanbul](https://istanbul.js.org/) 插桩收集覆盖率：

<PackageManagerTabs command="add @rstest/coverage-istanbul -D" />

`@rstest/coverage-istanbul` 在 SWC 转译阶段使用 [swc-plugin-coverage-instrument](https://github.com/kwonoj/swc-plugin-coverage-instrument) 对源文件插桩。

##### 排除代码

如需跳过整个文件、一组生成文件或注入脚本，请使用 `coverage.exclude`（或在 CLI 中重复传入 `--coverage.exclude`）：

```ts title='rstest.config.ts'
import { defineConfig } from '@rstest/core';

export default defineConfig({
  coverage: {
    enabled: true,
    provider: 'istanbul',
    exclude: ['**/src/injected-script.ts', '**/src/**/*.{worker,evaluate}.ts'],
  },
});
```

对于仍需统计覆盖率的文件中的少量代码片段，可使用 Istanbul ignore 注释（`/* istanbul ignore file */`、`/* istanbul ignore next */`、`/* istanbul ignore if */`、`/* istanbul ignore else */`）：

```ts
/* istanbul ignore next */
function browserEvaluateFn() {
  return window.location.href;
}

/* istanbul ignore if */
if (process.env.NODE_ENV === 'test') {
  setupTestOnlyState();
}

/* istanbul ignore else */
if (hasNativeFeature()) {
  useNativeFeature();
} else {
  useFallback();
}
```

如果被忽略的片段里仍然出现了注入的 `cov_*` 调用，请改用 `coverage.exclude` 排除对应源文件。

##### 已知限制 \{#known-limitations}

以下场景可能导致覆盖率不准确或插桩代码执行失败：

- **Legacy decorators 和 metadata**：生成的语句和分支可能被计入源码覆盖率，即使所有源码分支都已测试，报告中的覆盖率仍可能偏低。参见 [SWC #5535](https://github.com/swc-project/swc/issues/5535)。
- **TypeScript 运行时代码**：`enum`、`namespace` 和构造器参数属性可能引入生成代码的计数，包括位于第 `0` 行的记录。参见 [swc-plugin-coverage-instrument #300](https://github.com/kwonoj/swc-plugin-coverage-instrument/issues/300)。
- **模块重载**：在 `rs.resetModules()` 后重新导入模块，可能重置其覆盖率计数器并丢失此前记录的执行情况。参见 [swc-plugin-coverage-instrument #295](https://github.com/kwonoj/swc-plugin-coverage-instrument/issues/295)。
- **序列化函数**：将插桩后的函数序列化到其他作用域或执行环境（如 `page.evaluate` 或 `Worker`）运行，可能因缺少覆盖率辅助函数而报错 `ReferenceError: cov_... is not defined`。

#### V8 provider

<ApiMeta addedVersion="0.10.2" />

安装 [@rstest/coverage-v8](https://github.com/web-infra-dev/rstest/tree/main/packages/coverage-v8) 以收集原生 V8 覆盖率：

<PackageManagerTabs command="add @rstest/coverage-v8 -D" />

由于底层覆盖率数据直接来自 Node.js / Chromium V8，重映射后的分支覆盖率和未覆盖行细节在不同引擎版本间可能略有差异。

你可以用 V8 覆盖率数据评估 Node.js 测试构建产物的利用率。具体用法见[查看构建产物的覆盖率](/guide/debug/debugging#inspect-bundle-coverage)。

##### Ignore hints

`v8` provider 支持 `istanbul`、`c8`、`v8` 和 `node:coverage` 前缀的忽略注释（`next`、`if`、`else`、`start`/`stop`、`file`）。建议在项目中统一使用同一种前缀：

```ts
/* v8 ignore next */
const value = optionalExpensivePath();

/* v8 ignore if */
if (process.env.NODE_ENV === 'test') {
  setupTestOnlyState();
}

/* v8 ignore else */
if (hasNativeFeature()) {
  useNativeFeature();
} else {
  useFallback();
}

/* v8 ignore start */
const generatedLookup = createGeneratedLookup();
/* v8 ignore stop */
```

`ignore file` 会在 source map 重映射前作用于生成后的 coverage entry；由于单个生成 chunk 可能包含多个源文件，跳过整个源文件请优先使用 `coverage.exclude`。

`v8` provider 适用于 `node`、`jsdom` 和 `happy-dom` 环境。Browser Mode 的稳定支持仅限使用 Playwright provider 的 headless、非 watch Chromium 运行：Chromium 从 HTTP(S) 脚本（支持 classic、module 脚本及带 query 的 URL）收集覆盖率，并通过 source map 重映射，无需对应用代码插桩。

headed 和 watch 模式下的 Browser Mode V8 覆盖率为实验性能力：报告可能包含容器或非活跃 runner frame 的执行数据，watch 重建也可能使脚本与 source map 配对不准确。Firefox 和 WebKit 未暴露原生覆盖率 API。浏览器原生 V8 覆盖率也不会收集 `blob:`、`data:`、其他非 HTTP 或匿名脚本（如 `eval`、`new Function`），以及仅在独立 `Worker` 或 `SharedWorker` 中运行的代码。上述场景请改用 `istanbul`。

### include

- **类型：** `string[]`
- **默认值：** `undefined`
- **CLI：** `--coverage.include <pattern>`

指定要纳入覆盖率收集的 glob 模式列表。可重复传入 CLI 参数以指定多个模式。

默认情况下，Rstest 只收集已测试文件的覆盖率；设置 `include` 后可将未测试的源文件纳入报告。

请使用标准 glob 语法，匹配单个扩展名时写 `src/**/*.ts`，不要写 `src/**/*.{ts}`（底层 glob 库会把单元素花括号按字面量处理）。

```ts title='rstest.config.ts'
import { defineConfig } from '@rstest/core';

export default defineConfig({
  coverage: {
    enabled: true,
    include: ['src/**/*.{js,jsx,ts,tsx}'],
  },
});
```

### changed

<ApiMeta addedVersion="0.10.0" />

- **类型：** `boolean | string`
- **默认值：** `undefined`
- **CLI：** `--coverage.changed`、`--coverage.changed=<commit>`

只收集当前 Git 仓库中变更文件的覆盖率，或仅收集自指定 commit / branch ref 以来变更文件的覆盖率。

`coverage.changed` 只过滤覆盖率报告范围，不改变执行的测试范围：

- `--changed` 仅运行与变更文件相关的测试。
- `--coverage.changed` 运行正常的测试集，但覆盖率报告仅包含变更的源文件。

```ts title='rstest.config.ts'
import { defineConfig } from '@rstest/core';

export default defineConfig({
  coverage: {
    enabled: true,
    changed: 'origin/main',
  },
});
```

```bash
# 同时将测试和覆盖率限制在变更文件范围
npx rstest run --changed --coverage

# 运行全部测试，仅报告未提交变更或相对某 ref 变更文件的覆盖率
npx rstest run --coverage.changed
npx rstest run --coverage.changed=HEAD~1
```

#### 与 `--changed` 的关系

- 使用 [`--changed`](/guide/basic/cli#运行变更相关测试) 且未配置 `coverage.changed` 时，覆盖率报告会继承 `--changed` 收集到的变更文件。
- 如果 `--changed` 命中 [`forceRerunTriggers`](/config/test/force-rerun-triggers)，Rstest 会运行完整测试套件，此时覆盖率默认也保持完整范围，除非显式启用了 `coverage.changed`。
- 若希望用 `--changed` 缩小测试范围但保留完整覆盖率报告，可在配置中设置 `coverage.changed: false`。

### exclude

- **类型：** `string[]`
- **CLI：** `--coverage.exclude <pattern>`
- **默认值：**

```ts
[
  '**/node_modules/**',
  '**/__tests__/**',
  '**/__mocks__/**',
  '**/*.d.ts',
  '**/*.{test,spec}.[jt]s',
  '**/*.{test,spec}.[cm][jt]s',
  '**/*.{test,spec}.[jt]sx',
  '**/*.{test,spec}.[cm][jt]sx',
];
```

从覆盖率收集中排除的 glob 模式列表，自定义配置会与默认值合并。可重复传入 CLI 参数以指定多个模式。

Rstest 默认不排除名为 `test` 的目录，以免误排除路径中含 `test` 片段的包或工作区源码（例如 `packages/test/src/index.ts`）。如需排除这类目录，请显式添加 `test/**` 或 `**/test/**`。

```ts title='rstest.config.ts'
import { defineConfig } from '@rstest/core';

export default defineConfig({
  coverage: {
    enabled: true,
    exclude: ['**/node_modules/**', '**/dist/**'],
  },
});
```

### reporters

- **类型：** `CoverageReporter[]`
- **默认值：** `['text', 'html', 'clover', 'json']`
- **CLI：** `--coverage.reporters <reporter>`

用于生成覆盖率报告的 reporter。Rstest 使用标准的 [Istanbul reporter API](https://istanbul.js.org/docs/advanced/alternative-reporters/)。

每一项可以是 reporter 名称、`[name, options]` 元组，或带有 `execute(context)` 方法且兼容 Istanbul 的 reporter 对象。在 CLI 中可通过重复参数传入多个 reporter 名称：

```bash
npx rstest run --coverage.reporters text --coverage.reporters=json
```

可用的内置 reporter 名称详见 [Istanbul Reporters](https://istanbul.js.org/docs/advanced/alternative-reporters/)，各 reporter 的选项详见 [@types/istanbul-reports](https://github.com/DefinitelyTyped/DefinitelyTyped/blob/master/types/istanbul-reports/index.d.ts)。

```ts title='rstest.config.ts'
import { defineConfig } from '@rstest/core';

export default defineConfig({
  coverage: {
    enabled: true,
    reporters: ['html', 'text', ['json', { file: 'coverage-final.json' }]],
  },
});
```

#### 自定义 coverage reporter

自定义 coverage reporter 遵循 Istanbul reporter 约定：coverage provider 会加载对应的包或文件路径，用元组中的选项实例化，并传入 `istanbul-lib-report` 的 `Context` 调用：

```js title='custom-coverage-reporter.mjs'
export default class CustomCoverageReporter {
  constructor(options = {}) {
    this.options = options;
  }

  /** @param {import('istanbul-lib-report').Context} context */
  execute(context) {
    const summary = context.getTree('flat').getRoot().getCoverageSummary();
    console.log('Coverage summary:', summary.toJSON());
  }
}
```

可以在 `rstest.config.ts` 中通过包名或文件路径引用，也可以直接传入内联的 reporter 对象：

```ts title='rstest.config.ts'
import { defineConfig } from '@rstest/core';

export default defineConfig({
  coverage: {
    enabled: true,
    reporters: [
      'text',
      ['./custom-coverage-reporter.mjs', { outputFile: 'summary.json' }],
      {
        execute(context) {
          const summary = context
            .getTree('flat')
            .getRoot()
            .getCoverageSummary();
          console.log(summary.toJSON());
        },
      },
    ],
  },
});
```

### allowExternal

<ApiMeta addedVersion="0.9.3" />

- **类型：** `boolean`

### thresholds

- **类型：**

```ts
type CoverageThreshold = {
  statements?: number;
  functions?: number;
  branches?: number;
  lines?: number;
};

type CoverageThresholds =
  | CoverageThreshold
  | (CoverageThreshold &
      Record<
        string,
        CoverageThreshold & {
          /** 按单文件检查覆盖率阈值 */
          perFile?: boolean;
        }
      >);
```

- **默认值：** `undefined`

设置语句、函数、分支和行覆盖率的最低要求：

- **正数**：所需的最低覆盖率百分比。
- **负数**：允许未覆盖项的最大数量。

```ts title='rstest.config.ts'
import { defineConfig } from '@rstest/core';

export default defineConfig({
  coverage: {
    enabled: true,
    thresholds: {
      statements: 80,
      functions: 80,
      branches: 80,
      lines: -10,
    },
  },
});
```

覆盖率未达到阈值时，测试会失败并输出未满足的项：

```bash
Error: Coverage for statements 75% does not meet global threshold 80%
Error: Coverage for functions 75% does not meet global threshold 80%
Error: Coverage for branches 75% does not meet global threshold 80%
Error: Uncovered lines 20 exceeds maximum global threshold allowed 10
```

#### glob 模式

在全局阈值之外按 glob 模式设置阈值。如果指定的路径不存在，则会返回错误。

```ts title='rstest.config.ts'
import { defineConfig } from '@rstest/core';

export default defineConfig({
  coverage: {
    enabled: true,
    thresholds: {
      'src/**': {
        statements: 100,
      },
      'node/**/*.js': {
        statements: 90,
      },
      statements: 80,
    },
  },
});
```

按上述配置，若 `src/**` 的总语句覆盖率低于 100%、`node/**/*.js` 低于 90%，或全局低于 80%，Rstest 均会判定失败。

#### 单文件检查

在 glob 条目中设置 `perFile: true`，对每个匹配文件单独检查阈值：

```ts title='rstest.config.ts'
import { defineConfig } from '@rstest/core';

export default defineConfig({
  coverage: {
    enabled: true,
    thresholds: {
      'src/**': {
        statements: 90,
        perFile: true,
      },
    },
  },
});
```
