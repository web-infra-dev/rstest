# extends

- **类型：** `ExtendConfig | ExtendConfigFn | (ExtendConfig | ExtendConfigFn)[]`
- **默认值：** `undefined`

从共享预设、异步工厂函数或构建工具适配器（如 `@rstest/adapter-rslib`）扩展 Rstest 配置。

## 基本用法（对象）

```ts
type LooseRstestConfig = Omit<RstestConfig, 'reporters'> & {
  reporters?: any;
};

type ExtendConfig = Omit<LooseRstestConfig, 'projects'>;
```

`ExtendConfig` 是不包含 `projects` 的 `RstestConfig` 子集，同时将 `reporters` 放宽为 `any`，以兼容不同 `@rstest/core` 版本下的适配器。Rstest 会按照[合并规则](#配置合并)将扩展配置与本地配置合并。

```ts
import { defineConfig } from '@rstest/core';
import { sharedConfig } from './shared.config';

export default defineConfig({
  extends: sharedConfig,
  // 本地配置
  testTimeout: 10000,
  retry: 2,
});
```

## 函数用法

```ts
type ExtendConfigFn = (
  userConfig: Readonly<LooseRstestConfig>,
) => ExtendConfig | Promise<ExtendConfig>;
```

`ExtendConfigFn` 接收用户配置（只读），同步或异步返回扩展配置，适用于加载外部配置文件、获取远程配置或基于用户设置动态生成配置：

```ts
import { defineConfig } from '@rstest/core';

export default defineConfig({
  extends: async (user) => {
    const useJsdom = user.testEnvironment === 'jsdom';
    return {
      setupFiles: useJsdom ? ['<rootDir>/setupDomTests.ts'] : undefined,
      source: {
        define: {
          BUILD_TARGET: '"test"',
        },
      },
    };
  },
  testTimeout: 10_000,
});
```

## 多个 extends

传入数组即可组合多个预设。Rstest 按从左到右的顺序合并，后项覆盖前项，本地配置保持最高优先级。

数组中的函数会各自独立接收原始用户配置；数组顺序只影响合并优先级，不影响传入每个函数的参数。

```ts
import { defineConfig } from '@rstest/core';
import { withRslibConfig } from '@rstest/adapter-rslib';
import { sharedConfig } from './shared.config';

export default defineConfig({
  extends: [
    sharedConfig,
    withRslibConfig({}),
    (userConfig) => ({
      globals: userConfig.retry !== undefined,
    }),
  ],
  testTimeout: 10_000,
});
```

## 配置合并

Rstest 对对象字段执行深度合并，对基本类型字段执行覆盖，本地配置优先于扩展配置。当 `extends` 为数组时，优先级顺序如下：

```ts
extends[0] < extends[1] < ... < extends[n] < local config
```

合并规则如下：

- `testTimeout`、`retry`、`globals` 等基本类型字段由后者直接覆盖前者。
- `setupFiles`、`globalSetup` 和 `plugins` 会依次拼接，便于多个预设追加配置。
- `include`、`reporters` 和 `coverage.reporters` 会被后者整体替换。
- `source`、`resolve`、`output`、`tools`、`env` 和 `coverage` 等对象字段会执行深度合并。
- `browser` 中的普通对象会执行深度合并（包括嵌套的 `providerOptions`）；数组、函数和类实例由后者整体替换（例如覆盖 `providerOptions.launch.args` 会替换整个参数数组，同时保留之前的 `launch.timeout` 和 `context.locale`）。
- 每个扩展配置中的 `projects` 都会被忽略。

示例：

```ts
import { defineConfig } from '@rstest/core';

export default defineConfig({
  extends: [
    {
      testEnvironment: 'jsdom',
      setupFiles: ['./setup-a.ts'],
      testTimeout: 5000,
      source: {
        define: {
          BASE_URL: '"https://example.com"',
        },
      },
    },
    {
      globals: true,
      setupFiles: ['./setup-b.ts'],
      source: {
        define: {
          API_URL: '"https://api.example.com"',
        },
      },
    },
  ],
  // 本地配置
  testTimeout: 10000,
  retry: 2,
});

// 结果：
// {
//   testEnvironment: 'jsdom',
//   globals: true,
//   testTimeout: 10000,
//   retry: 2,
//   setupFiles: ['./setup-a.ts', './setup-b.ts'],
//   source: {
//     define: {
//       BASE_URL: '"https://example.com"',
//       API_URL: '"https://api.example.com"',
//     },
//   },
// }
```

## 使用适配器

`@rstest/adapter-rslib` 等适配器会自动将已有构建配置中的兼容选项（如 `source.define`、`source.include`、`source.exclude`、`source.transformImport`）映射到 Rstest：

```ts
import { defineConfig } from '@rstest/core';
import { withRslibConfig } from '@rstest/adapter-rslib';

export default defineConfig({
  extends: withRslibConfig({}),
  // 额外的 Rstest 特定配置
  coverage: {
    enabled: true,
    reporters: ['text', 'html'],
  },
});
```

## 限制

`extends` 配置不支持 `projects` 字段。需要配置多个项目时，在各个项目配置中单独使用 `extends`：

```ts
export default defineConfig({
  projects: [
    {
      name: 'node',
      extends: withRslibConfig({ libId: 'node' }),
      include: ['tests/node/**/*.{test,spec}.?(c|m)[jt]s'],
    },
    {
      name: 'react',
      extends: withRslibConfig({ libId: 'react' }),
      include: ['tests/react/**/*.{test,spec}.?(c|m)[jt]s?(x)'],
    },
  ],
});
```
