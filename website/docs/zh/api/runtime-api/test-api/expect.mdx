# Expect

`expect` 用于在测试中创建断言，支持内置匹配器、取反、软断言、轮询、快照以及自定义匹配器。

可以从 `@rstest/core` 导入 `expect`，或在并发测试中从 [`TestContext`](/api/runtime-api/test-api/test#testcontext) 解构，以将断言准确绑定到当前测试：

```ts
import { expect, test } from '@rstest/core';

test('adds two numbers', () => {
  expect(1 + 1).toBe(2);
});

test('concurrent-safe expect', ({ expect }) => {
  expect(1 + 2).toBe(3);
});
```

## expect

- **类型：** `<T>(actual: T, message?: string) => Assertion<T>`

为 `actual` 创建断言对象，可选传入失败时显示的自定义提示信息 `message`。

```ts
import { expect } from '@rstest/core';

expect(1 + 1).toBe(2);
expect('hello').toBeDefined();
expect([1, 2, 3]).toContain(2);
```

## expect.element（Browser mode）

- **类型：** `(locator: Locator | Element) => BrowserElementExpect`

在 Browser Mode 中，`expect.element` 用于对 `Locator` 或 DOM `Element` 创建断言（如 `toBeVisible`、`toHaveText`、`toHaveValue`）。

```ts
import { page } from '@rstest/browser';
import { expect, test } from '@rstest/core';

test('asserts by locator', async () => {
  document.body.innerHTML = '<button>Save</button>';
  await expect
    .element(page.getByRole('button', { name: 'Save' }))
    .toBeVisible();
});
```

`expect.element` 仅在 Browser Mode 中引入 `@rstest/browser` 后可用。完整匹配器与超时规则见 [Assertion（Browser Mode）](/api/runtime-api/browser-mode/assertion)。

## expect.not

通过 `expect(actual).not` 对后续匹配器取反：

```ts
expect(1 + 1).not.toBe(3);
expect('foo').not.toBeUndefined();
```

## expect.soft

- **类型：** `<T>(actual: T, message?: string) => Assertion<T>`

软断言。断言失败时不会中断测试，所有失败会在测试结束时统一报告。

```ts
expect.soft(1 + 1).toBe(3); // 不会中断测试
expect.soft(1 + 2).toBe(4);
```

## expect.poll

- **类型：**

```ts
<T>(
  actual: () => T,
  options?: { interval?: number; timeout?: number; message?: string },
) =>
  Omit<
    PromisifyAssertion<Awaited<T>>,
    | 'rejects'
    | 'resolves'
    | 'toThrow'
    | 'toThrowError'
    | 'throw'
    | 'throws'
    | 'matchSnapshot'
    | 'toMatchSnapshot'
    | 'toMatchInlineSnapshot'
    | 'toThrowErrorMatchingSnapshot'
    | 'toThrowErrorMatchingInlineSnapshot'
  >;
```

持续调用 `actual` 并重试后续匹配器，直到通过或超时。每个匹配器返回 `Promise<void>`，**必须**使用 `await` 等待（`Awaited<T>` 会自动解包异步 `actual` 的返回值）。

- **默认 `interval`：** `50` 毫秒
- **默认 `timeout`：** `1000` 毫秒（Browser Mode 下为 `5000` 毫秒）

可通过 [`expect.poll` 配置](/config/test/expect#expectpoll)修改默认值；单次调用传入的 `options` 优先级更高：

- `interval`：每次重试之间的间隔时间（毫秒）。
- `timeout`：超时失败前的最大轮询时间（毫秒）。
- `message`：超时失败时显示的自定义提示信息。

`expect.poll` 不支持 `.resolves`、`.rejects`、`.toThrow*` 及快照匹配器，遇到这类场景请改用 [`rs.waitFor`](/api/runtime-api/rstest/utilities#rswaitfor)。

```ts
await expect.poll(() => getStatus()).toBe('ready');

await expect
  .poll(
    async () => {
      const response = await fetch('/api/health');
      const data = await response.json();
      return data.status;
    },
    {
      interval: 100,
      timeout: 5000,
      message: '服务应在 5 秒内恢复健康',
    },
  )
  .toBe('healthy');
```

## expect.unreachable

- **类型：** `(message?: string) => never`

执行到该调用时立即抛出异常。

```ts
if (shouldNotHappen) {
  expect.unreachable('这里不应该被执行');
}
```

## expect.assertions

- **类型：** `(expected: number) => void`

校验当前测试期间精确执行了 `expected` 次断言，常用于确保异步分支或 `catch` 块确实被执行。

```ts
expect.assertions(1);

try {
  await someAsyncFunction();
} catch (e) {
  expect(e).toBeInstanceOf(Error);
}
```

## expect.hasAssertions

- **类型：** `() => void`

校验当前测试期间至少执行了一次断言。

```ts
expect.hasAssertions();
expect(1 + 1).toBe(2);
```

## expect.addEqualityTesters

- **类型：** `(testers: Tester[]) => void`

为深度相等匹配器注册自定义相等性测试器。每个 tester 返回 `true`（相等）、`false`（不等），或 `undefined`（交由下一个 tester 或默认逻辑处理）。

遵循与 snapshot serializer 相同的[文件隔离规则](#expectaddsnapshotserializer)。

```ts
expect.addEqualityTesters([
  (a, b) => {
    if (typeof a === 'number' && typeof b === 'number') {
      return Math.abs(a - b) < 0.01;
    }
  },
]);
expect(0.1 + 0.2).toEqual(0.3);
```

## expect.addSnapshotSerializer

- **类型：** `(plugin: Parameters<ExpectStatic['addSnapshotSerializer']>[0]) => void`

添加自定义的快照序列化插件（`pretty-format` 插件）。对当前测试文件及其 Hook 生效，后添加的优先匹配。如需对项目内所有文件生效，请在 `setupFiles` 中注册。

在 `vmThreads` 和 `vmForks` pool 中，每个文件结束或失败后都会还原序列化器列表（即使 `isolate` 为 `false`）。使用 `forks` 或 `threads` 且设置 `isolate: false` 时，同一 worker 内的文件（包括不同项目）会共享序列化器。

```ts
expect.addSnapshotSerializer({
  test: (val) => typeof val === 'string' && val.startsWith('secret:'),
  print: () => '***MASKED***',
});
expect('secret:123').toMatchSnapshot();
```

## expect.getState / expect.setState

- **类型：**
  - `getState: () => MatcherState`
  - `setState: (state: Partial<MatcherState>) => void`

读取或更新内部匹配器状态（`MatcherState` 为内部匹配器状态类型，未从 `@rstest/core` 直接重新导出）。

```ts
const state = expect.getState();
console.log(state.currentTestName);
expect.setState({ currentTestName: '自定义名称' });
```

## 匹配器（Matchers）

### 常用匹配器

相等性与同一性：

- `toBe(value)`：基于 `Object.is` 的严格相等。
- `toEqual(value)`：对象与数组的深度相等。
- `toStrictEqual(value)`：更严格的深度相等（校验 `undefined` 属性与稀疏数组差异）。
- `toBeOneOf(array)`：值匹配 `array` 中的任意一项。

类型与存在性：

- `toBeTruthy()` / `toBeFalsy()`：真值 / 假值判断。
- `toBeNull()` / `toBeUndefined()` / `toBeDefined()`：空值与已定义判断。
- `toBeNaN()`：是否为 `NaN`。
- `toBeInstanceOf(class)`：原型链实例判断。
- `toBeTypeOf(type)`：运行时 `typeof` 类型判断（如 `'string'`）。

数值比较：

- `toBeGreaterThan(number)` / `toBeGreaterThanOrEqual(number)`
- `toBeLessThan(number)` / `toBeLessThanOrEqual(number)`
- `toBeCloseTo(number, numDigits?)`：按指定精度比较浮点数。

集合与字符串：

- `toContain(item)`：数组或字符串包含 `item`。
- `toContainEqual(item)`：数组包含与 `item` 深度相等的元素。
- `toMatch(stringOrRegExp)`：字符串匹配子串或正则。
- `toMatchObject(object)`：对象包含 `object` 的属性子集。
- `toHaveLength(length)`：校验 `.length`。
- `toHaveProperty(path, value?)`：校验属性路径存在及可选的目标值。

自定义谓词与异常：

- `toSatisfy(fn)`：满足自定义谓词函数 `fn`。
- `toThrowError(expected?)`：断言包裹的函数抛出匹配的错误（支持字符串、正则、错误实例或构造函数）。

```ts
expect(1 + 1).toBe(2);
expect({ id: 1, name: 'a' }).toEqual({ id: 1, name: 'a' });
expect({ a: undefined, b: 1 }).toStrictEqual({ a: undefined, b: 1 });

expect(0.1 + 0.2).toBeCloseTo(0.3, 5);
expect(10).toBeGreaterThan(5);

expect([1, 2, 3]).toContain(2);
expect([{ id: 1 }]).toContainEqual({ id: 1 });
expect({ user: { role: 'admin' } }).toHaveProperty('user.role', 'admin');
expect({ id: 1, role: 'admin', active: true }).toMatchObject({
  id: 1,
  role: 'admin',
});

expect('request id: 42').toMatch(/id:\s\d+/);
expect(21).toSatisfy((n) => n % 3 === 0);

expect(() => {
  throw new TypeError('invalid input');
}).toThrowError(TypeError);
```

### Mock 匹配器

校验 `rs.fn` / `rs.spyOn` mock 的调用次数、参数、调用顺序、返回值和 Promise 结果（`Nth` 系列从 `1` 开始计数）：

调用断言：

- `toHaveBeenCalled()`
- `toHaveBeenCalledTimes(times)`
- `toHaveBeenCalledWith(...args)`
- `toHaveBeenLastCalledWith(...args)`
- `toHaveBeenNthCalledWith(n, ...args)`
- `toHaveBeenCalledExactlyOnceWith(...args)`
- `toHaveBeenCalledBefore(mock, failIfNoFirstInvocation?)` / `toHaveBeenCalledAfter(mock, failIfNoFirstInvocation?)`

返回值断言：

- `toHaveReturned()`
- `toHaveReturnedTimes(times)`
- `toHaveReturnedWith(value)`
- `toHaveLastReturnedWith(value)`
- `toHaveNthReturnedWith(n, value)`

Promise resolve 断言：

- `toHaveResolved()`
- `toHaveResolvedTimes(times)`
- `toHaveResolvedWith(value)`
- `toHaveLastResolvedWith(value)`
- `toHaveNthResolvedWith(n, value)`

```ts
const sum = rs.fn((a: number, b: number) => a + b);
sum(1, 2);
sum(2, 3);

expect(sum).toHaveBeenCalledTimes(2);
expect(sum).toHaveBeenNthCalledWith(1, 1, 2);
expect(sum).toHaveBeenLastCalledWith(2, 3);
expect(sum).toHaveReturnedWith(3);
expect(sum).toHaveLastReturnedWith(5);

const fetchUser = rs.fn(async (id: number) => ({ id, name: 'alice' }));
await fetchUser(1);
await fetchUser(2);

expect(fetchUser).toHaveResolvedTimes(2);
expect(fetchUser).toHaveNthResolvedWith(1, { id: 1, name: 'alice' });

const before = rs.fn();
const after = rs.fn();
before();
after();
expect(before).toHaveBeenCalledBefore(after);
```

### 快照匹配器

关于快照配置、更新流程与序列化规则，详见[快照测试](/guide/basic/snapshot)。

- `toMatchSnapshot(propertiesOrMessage?, message?)`：与已保存的 `.snap` 快照对比。
- `toMatchInlineSnapshot(propertiesOrSnapshot?, snapshotOrMessage?, message?)`：与测试文件中的内联快照对比。
- `toThrowErrorMatchingSnapshot(message?)`：校验抛出的错误与已保存快照匹配。
- `toThrowErrorMatchingInlineSnapshot(snapshot?, message?)`：校验抛出的错误与内联快照匹配。
- `toMatchFileSnapshot(filepath, message?)`：异步匹配器，与指定独立文件对比。

```ts
expect('hello world').toMatchSnapshot();

expect(() => {
  throw new Error('fail');
}).toThrowErrorMatchingSnapshot();

await expect('hello world').toMatchFileSnapshot(
  '__snapshots__/file.output.txt',
);
```

### Promise 匹配器

- `resolves`：解包已兑现的 Promise，并对结果继续链式断言。
- `rejects`：解包已拒绝的 Promise，并对错误继续链式断言。

```ts
await expect(Promise.resolve('ok')).resolves.toBe('ok');
await expect(Promise.reject(new Error('fail'))).rejects.toThrow('fail');
```

### 不对称匹配器

用于在相等性断言中进行部分匹配、类型匹配或模式匹配：

- `expect.anything()`：匹配除 `null` 和 `undefined` 之外的任意值。
- `expect.any(constructor)`：匹配指定构造函数的任意值。
- `expect.closeTo(number, precision?)`：匹配在浮点精度范围内的数值。
- `expect.arrayContaining(array)`：匹配包含 `array` 中所有元素的数组。
- `expect.objectContaining(object)`：匹配包含 `object` 中所有属性的对象。
- `expect.stringContaining(string)`：匹配包含子串 `string` 的字符串。
- `expect.stringMatching(stringOrRegExp)`：匹配符合 `stringOrRegExp` 的字符串。

```ts
expect({ a: 1 }).toEqual({ a: expect.anything() });
expect(1).toEqual(expect.any(Number));
expect(0.1 + 0.2).toEqual(expect.closeTo(0.3, 5));
expect([1, 2, 3]).toEqual(expect.arrayContaining([2, 1]));
expect({ a: 1, b: 2 }).toEqual(expect.objectContaining({ a: 1 }));
expect('hello world').toEqual(expect.stringContaining('world'));
expect('hello world').toEqual(expect.stringMatching(/^hello/));
```

### 自定义匹配器

通过 `expect.extend` 注册自定义匹配器。在 VM pool 中，自定义匹配器（包括对内置匹配器的覆盖以及不对称匹配器 `expect.<matcher>` / `expect.not.<matcher>`）遵循与 snapshot serializer 相同的[文件隔离规则](#expectaddsnapshotserializer)。

```ts
expect.extend({
  toBeDivisibleBy(received, argument) {
    const pass = received % argument === 0;
    return {
      pass,
      message: () =>
        pass
          ? `期望 ${received} 不能被 ${argument} 整除`
          : `期望 ${received} 能被 ${argument} 整除`,
    };
  },
});

expect(10).toBeDivisibleBy(2);
```

如需为自定义匹配器补充 TypeScript 类型，可扩展 `@rstest/core` 中的 `Assertion` 接口：

```ts
declare module '@rstest/core' {
  interface Assertion<T> {
    toBeDivisibleBy(argument: number): void;
  }
}
```
