# Hooks

为测试套件或单个测试注册初始化与清理回调。

## beforeAll

- **类型：**

```ts
interface SuiteContext {
  filepath: string;
  meta: TaskMeta;
}

type BeforeAll = (
  fn: (
    ctx: SuiteContext,
  ) =>
    | void
    | ((ctx: SuiteContext) => void | Promise<void>)
    | Promise<void | ((ctx: SuiteContext) => void | Promise<void>)>,
  timeout?: number,
) => void;
```

在当前套件的所有测试执行前运行一次（位于文件顶层时则在文件内所有测试前运行一次）。

当套件中没有可运行的测试时（例如所有测试被跳过、被测试名称筛选排除，或未被 `test.only` 选中），Rstest 会跳过 `beforeAll`。

```ts
import { beforeAll } from '@rstest/core';

beforeAll(async (ctx) => {
  // ctx.filepath 为当前测试文件路径
  ctx.meta.startedAt = Date.now();
});
```

`beforeAll` 返回的函数会注册为套件级清理回调，在所属套件的 `afterAll` 之后执行，执行顺序由 [`sequence.hooks`](/config/test/sequence#sequencehooks) 控制：

```ts
import { beforeAll } from '@rstest/core';

beforeAll(async () => {
  const resource = await acquireResource();

  return async () => {
    await resource.close();
  };
});
```

## afterAll

- **类型：** `(fn: (ctx: SuiteContext) => void | Promise<void>, timeout?: number) => void`

在当前套件的所有测试结束后运行一次。套件中没有可运行的测试时会跳过。

```ts
import { afterAll } from '@rstest/core';

afterAll(async (ctx) => {
  ctx.meta.finished = true;
});
```

<ApiMeta addedVersion="0.11.1" />

`ctx.meta` 是当前套件的可变元数据对象。若套件通过 `describe(name, { meta }, fn)` 声明，`ctx.meta` 会以继承后的元数据作为初始值。文件级 Hook 写入的元数据出现在 `TestFileResult.meta` 中；`describe` 内的 Hook 写入的元数据出现在自定义 Reporter 收到的对应套件 `TestResult.meta` 中。

## beforeEach

- **类型：** `<ExtraContext = object>(fn: (ctx: TestContext & ExtraContext) => void | ((ctx: TestContext & ExtraContext) => void | Promise<void>) | Promise<void | ((ctx: TestContext & ExtraContext) => void | Promise<void>)>, timeout?: number) => void`

在当前套件的每个测试执行前运行。`ctx` 上的字段见 [`TestContext`](/api/runtime-api/test-api/test#testcontext)（`afterEach`、`onTestFinished` 与 `onTestFailed` 同理）。

```ts
import { beforeEach } from '@rstest/core';

beforeEach(async () => {
  // 每个测试前的初始化逻辑
});
```

`beforeEach` 返回的函数会注册为单测清理回调，在该测试的所有 `afterEach` 之后执行，执行顺序由 [`sequence.hooks`](/config/test/sequence#sequencehooks) 控制：

```ts
import { beforeEach } from '@rstest/core';

beforeEach(async () => {
  const handle = await openHandle();

  return async () => {
    await handle.close();
  };
});
```

<ApiMeta addedVersion="0.11.4" />

`beforeEach`、`afterEach` 以及 `beforeEach` 返回的清理函数都可以使用 `test.extend` 创建的 fixture。将 fixture 接口作为 `ExtraContext` 传入，并在回调参数中通过直接对象解构声明所需的 fixture。Rstest 不会从函数体内推断 fixture 依赖，且不支持对象 rest 属性和默认值。详见[在 hook 中使用 fixture](/api/runtime-api/test-api/test#在-hook-中使用-fixture)。

## afterEach

- **类型：** `<ExtraContext = object>(fn: (ctx: TestContext & ExtraContext) => void | Promise<void>, timeout?: number) => void`

在当前套件的每个测试结束后运行。

```ts
import { afterEach } from '@rstest/core';

afterEach(async () => {
  // 每个测试后的清理逻辑
});
```

## onTestFinished

- **类型：** `(fn: (ctx: TestContext) => void | Promise<void>, timeout?: number) => void`

注册在当前测试结束后运行的回调，无论测试通过还是失败都会执行。执行时机在 `afterEach` 之后，且必须在测试函数内部调用。

```ts
import { onTestFinished, test } from '@rstest/core';

test('closes server after test', () => {
  const server = startServer();
  // 注册测试结束后的清理回调
  onTestFinished(() => server.close());

  server.listen(3000);
});
```

在并发测试中，请从测试上下文参数解构 `onTestFinished`，不要使用顶层导入的函数，以便 Rstest 将回调准确绑定到对应测试：

```ts
import { describe, test } from '@rstest/core';

describe.concurrent('并发套件', () => {
  test('test 1', async ({ onTestFinished }) => {
    /* ... */
  });
  test('test 2', async ({ onTestFinished }) => {
    /* ... */
  });
});
```

## onTestFailed

- **类型：** `(fn: (ctx: TestContext) => void | Promise<void>, timeout?: number) => void`

注册仅在当前测试失败时运行的回调。必须在测试函数内部调用。

```ts
import { onTestFailed, test } from '@rstest/core';

test('logs errors on failure', () => {
  onTestFailed(({ task }) => {
    console.log(task.result?.errors);
  });
});
```

在并发测试中，同样请从测试上下文参数解构 `onTestFailed`，不要使用顶层导入的函数，以确保回调准确绑定到当前测试。
