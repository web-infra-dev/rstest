# Test

`test`（别名：`it`）用于定义测试用例，支持单测选项、参数化测试、链式修饰符以及通过 `test.extend` 扩展自定义 fixture。

## test

- **类型：**

```ts
(name: string | Function, fn?: (testContext: TestContext) => void | Promise<void>, timeout?: number): void;
(name: string | Function, options: TestOptions, fn?: (testContext: TestContext) => void | Promise<void>): void;
```

定义一个测试用例。

```ts
import { expect, test } from '@rstest/core';

test('adds two numbers', () => {
  expect(1 + 1).toBe(2);
  expect(1 + 2).toBe(3);
});
```

<ApiMeta addedVersion="0.12.3" />

`name` 可以是字符串或具名函数。Rstest 会读取函数的 `name` 属性作为测试名称，不会调用该函数（匿名函数显示为 `<anonymous>`）。`test.each` 和 `test.for` 也支持此写法。

### TestOptions

<ApiMeta addedVersion="0.11.1" />

将 `TestOptions` 对象作为**第二个参数**（位于测试函数之前）传入，用于配置单个测试的运行行为：

```ts
test('flaky network call', { retry: 3 }, async () => {
  /* ... */
});
```

将数字作为**最后一个参数**传入等价于 `{ timeout: n }`：

```ts
test('runs within 3s', async () => {
  /* ... */
}, 3000);
```

`TestOptions` 支持的字段：

- `timeout?: number`：单测超时时间（毫秒），覆盖 [`test.testTimeout`](/config/test/test-timeout)。
- `retry?: number`：测试失败时的重试次数，首次通过即停止，覆盖 [`test.retry`](/config/test/retry)。
- `repeats?: number`：在首次执行之外的额外运行次数，覆盖 [`test.repeats`](/config/test/repeats)；生命周期与重试交互规则见该配置页。
- `meta?: TaskMeta`：`0.11.1` 新增。测试结果的初始可 JSON 序列化元数据。位于带有 `meta` 的 `describe` 中时，会继承一份套件元数据副本，测试级别的同名字段覆盖继承值。

`TaskMeta` 和 `TaskMetaValue` 均从 `@rstest/core` 导出：

```ts
type TaskMeta = Record<string, TaskMetaValue>;

type TaskMetaValue =
  | string
  | number
  | boolean
  | null
  | TaskMetaValue[]
  | { [key: string]: TaskMetaValue };
```

```ts
// 共执行 10 次；任一次失败即短路后续重跑
test('stays green across runs', { repeats: 9 }, async () => {
  /* ... */
});

test('records metadata', { meta: { owner: 'team-a' } }, (context) => {
  context.task.meta.startedBy = 'runtime';
});
```

测试执行期间修改 `context.task.meta` 会更新传给 Reporter 和编程 API 的 `TestResult.meta`。

`test.each` 和 `test.for` 同样在第二个参数位置接受 `TestOptions`，并作用于生成的每个测试用例。

## test.only

只运行当前文件中标记了 `only` 的测试。

```ts
test.only('run only this test', () => {
  // ...
});
```

## test.skip

在定义阶段跳过测试。

```ts
test.skip('skip this test', () => {
  // ...
});
```

若需要在测试运行过程中动态跳过，可调用 `context.skip()`。它会立即终止当前测试，后续代码不会执行，并将测试报告为 skipped：

```ts
test('skip at runtime', (context) => {
  context.skip();

  // 不会执行
  expect(1 + 1).toBe(3);
});
```

## test.todo

将测试标记为待办，不执行测试体。

```ts
test.todo('should implement this test');
```

## test.each

- **类型：**

```ts
type TestCall<Fn> = {
  (name: string | Function, fn?: Fn, timeout?: number): void;
  (name: string | Function, options: TestOptions, fn?: Fn): void;
};

// 对象行：整行作为单个参数传入
test.each<T extends Record<string, unknown>>(
  cases: readonly T[],
): TestCall<(param: T) => void | Promise<void>>;
// 元组或数组行：每一行都是数组时，展开为多个参数
test.each<T extends readonly [unknown, ...unknown[]]>(
  cases: readonly T[],
): TestCall<(...args: [...T]) => void | Promise<void>>;
test.each<T extends readonly unknown[]>(
  cases: readonly T[],
): TestCall<(...args: [...T]) => void | Promise<void>>;
// 混合或基本类型行：整行作为单个参数传入
test.each<T>(
  cases: readonly T[],
): TestCall<(param: T) => void | Promise<void>>;
// 标签模板字面量表格
test.each<T extends Record<string, unknown>>(
  strings: TemplateStringsArray,
  ...expressions: unknown[]
): TestCall<(param: T) => void | Promise<void>>;
```

为 `cases` 或标签模板表格中的每一项执行相同的测试逻辑。

只有当每一行都是数组时，行元素才会展开为 `fn` 的多个参数；只要存在非数组行，每一行都会整体作为单个参数传入：

```ts
test.each([null, 42, ['a']])('rejects %o', (value) => {
  // 第三项收到的是 ['a']，而不是 'a'
  expect(isValid(value)).toBe(false);
});
```

测试名称支持 [printf 占位符](https://nodejs.org/api/util.html#utilformatformat-args)（`%s`、`%d`、`%i`、`%f`、`%j`、`%o`、`%O`、`%c`、`%#` 表示从 0 开始的索引、`%$` 表示从 1 开始的索引、`%%` 表示 `%`），对象行还支持 `$属性名` 占位符：

```ts
test.each([
  [1, 2, 3],
  [2, 2, 4],
])('adds %i + %i to equal %i', (a, b, sum) => {
  expect(a + b).toBe(sum);
});

test.each([
  { a: 1, b: 1, sum: 2 },
  { a: 1, b: 2, sum: 3 },
])('adds $a + $b to equal $sum', ({ a, b, sum }) => {
  expect(a + b).toBe(sum);
});
```

使用标签模板字面量时，第一行用 `|` 分隔列标题作为参数名，后续每行通过 `${...}` 提供值。传入显式泛型参数可为行对象提供类型推导：

```ts
test.each<{ a: number; b: number; expected: number }>`
  a    | b    | expected
  ${1} | ${2} | ${3}
  ${2} | ${3} | ${5}
`('$a + $b = $expected', ({ a, b, expected }) => {
  expect(a + b).toBe(expected);
});
```

## test.for

- **类型：**

```ts
type TestCall<Fn> = {
  (name: string | Function, fn?: Fn, timeout?: number): void;
  (name: string | Function, options: TestOptions, fn?: Fn): void;
};

test.for<T>(
  cases: readonly T[],
): TestCall<(param: T, context: TestContext) => void | Promise<void>>;
test.for<T extends Record<string, unknown>>(
  strings: TemplateStringsArray,
  ...expressions: unknown[]
): TestCall<(param: T, context: TestContext) => void | Promise<void>>;
```

`test.each` 的替代方法：始终将每条用例整体作为单个 `param` 参数传入（不展开数组行），并将 [`TestContext`](#testcontext)（以及扩展的 fixture）作为第二个参数传入。

```ts
test.for([
  { a: 1, b: 2 },
  { a: 2, b: 2 },
])('adds $a + $b', ({ a, b }, { expect }) => {
  expect(a + b).matchSnapshot();
});
```

同样支持标签模板字面量以及可选的显式泛型参数：

```ts
test.for<{ a: number; b: number; expected: number }>`
  a    | b    | expected
  ${1} | ${2} | ${3}
  ${2} | ${3} | ${5}
`('$a + $b = $expected', ({ a, b, expected }, { expect }) => {
  expect(a + b).toBe(expected);
});
```

## test.fails

将测试标记为预期失败。测试抛出异常或断言失败时记为通过，正常完成时反而记为失败。

```ts
test.fails('should fail', () => {
  throw new Error('This test is expected to fail');
});
```

## test.concurrent

并发运行同一套件中连续带有 `concurrent` 标记的测试。

```ts
describe('suite', () => {
  test('serial test', async () => {
    /* ... */
  });
  test.concurrent('concurrent test 1', async () => {
    /* ... */
  });
  test.concurrent('concurrent test 2', async () => {
    /* ... */
  });
  test('serial test 2', async () => {
    /* ... */
  });
});
```

## test.sequential

顺序运行测试（默认行为，可用于在 `describe.concurrent` 内将特定测试改回顺序执行）。

```ts
describe.concurrent('suite', () => {
  test.sequential('runs sequentially', async () => {
    /* ... */
  });
});
```

## test.runIf

仅当 `condition` 为真值时运行该测试。

```ts
test.runIf(process.env.RUN_EXTRA === '1')('conditionally run', () => {
  // ...
});
```

## test.skipIf

当 `condition` 为真值时跳过该测试。

```ts
test.skipIf(process.platform === 'win32')('skip on Windows', () => {
  // ...
});
```

## test.extend

- **类型：**

```ts
// fixtures 对象写法（test scope）
test.extend<T extends Record<string, any>>(
  fixtures: Fixtures<T>,
): TestAPIs<T>;
// 具名 fixture 写法（test scope）
test.extend<Name extends string, Value>(
  name: Name,
  fixture: Value | ((context: TestContext, lifecycle: FixtureLifecycle) => MaybePromise<Value>),
): TestAPIs<Record<Name, Value>>;
// 具名 fixture 写法（worker scope）
test.extend<Name extends string, Value>(
  name: Name,
  options: WorkerFixtureOptions,
  fixture: Value | ((context: object, lifecycle: FixtureLifecycle) => MaybePromise<Value>),
): TestAPIs<object, object, Record<Name, Value>>;
// 具名 fixture 写法（file scope）
test.extend<Name extends string, Value>(
  name: Name,
  options: FileFixtureOptions,
  fixture: Value | ((context: object, lifecycle: FixtureLifecycle) => MaybePromise<Value>),
): TestAPIs<object, Record<Name, Value>>;
```

基于自定义 fixture 创建一个**新的** `test` API。原始 `test` 保持不变，返回的新 API 拥有相同的修饰符，并支持继续链式调用 `.extend()`。

```ts
import { test } from '@rstest/core';

const myTest = test.extend<{ user: { name: string } }>({
  user: async ({}, use) => {
    await use({ name: 'Alice' });
  },
});

myTest('has user in context', ({ user, expect }) => {
  expect(user.name).toBe('Alice');
});
```

使用 fixture 的回调（测试回调、fixture 函数和单测 Hook）必须在参数中通过直接对象解构声明依赖（`({ db }) => ...`）。Rstest 不会从函数体内的解构语句推断依赖，也不支持对象 rest 属性（`{ db, ...rest }`）或解构默认值（`{ db = fallback }`）。

### fixtures 对象写法

fixtures 对象中的每一项可以是普通值、fixture 函数 `(context, use) => Promise<void>`，或 `[fixture, { auto?: boolean }]` 元组。

- **普通值 fixture**：不需要 setup 或 teardown 逻辑时，可直接提供非函数值（例如 `baseURL: 'https://api.example.com'`）。
- **访问 `TestContext`**：fixture 函数会在第一个参数 `context` 中收到已声明的其他 fixture 以及 [`TestContext`](#testcontext) 字段（例如 `{ task }`）。
- **setup 与 teardown**：调用 `await use(value)` 向测试传入 fixture 值；`use` 之前为 setup，之后为 teardown。

```ts
import { test } from '@rstest/core';

const testWithDb = test.extend({
  db: async ({}, use) => {
    const db = await connectTestDb();
    await use(db);
    await db.close();
  },
});
```

### 具名 fixture 写法

<ApiMeta addedVersion="0.11.7" />

具名 fixture 写法接收 `(name, fixture)`，直接返回 fixture 值而无需调用 `use`。第二个参数提供 `onCleanup` 用于注册清理回调（两个函数均支持异步）：

```ts
import { test } from '@rstest/core';

const apiTest = test
  .extend('baseURL', 'https://api.example.com')
  .extend('client', async ({ baseURL }, { onCleanup }) => {
    const client = await createClient(baseURL);
    onCleanup(() => client.close());
    return client;
  });
```

具名 fixture 的约束如下：

- 双参数写法属于 test scope：fixture 函数会在每次测试尝试时运行，并在测试及其单测 Hook 结束后执行清理；普通值会在多次尝试之间复用。
- `name` 必须是静态可知的 ASCII JavaScript 标识符（不接受 `string`、`` `slot${string}` `` 等模板字面量模式、`'base-url'` 等非标识符名称以及 `TestContext` 保留字段；允许使用 `'name'` 和 `'length'` 等与 Function 属性重名的名称）。
- 直接作为第二个参数传入的函数和 class 会被当作 fixture 工厂执行。如需将函数或 class 本身作为 fixture 值暴露，请用工厂函数返回，例如 `.extend('predicate', () => predicate)`。

### File scope 具名 fixtures

<ApiMeta addedVersion="0.11.7" />

传入 `{ scope: 'file' }` 为当前测试文件惰性创建单个 fixture 实例，在文件内所有测试、重试、重复运行及并发测试间共享，并在所有测试和 `afterAll` 结束后按初始化的反序执行清理。

```ts
import { test } from '@rstest/core';

const apiTest = test
  .extend('server', { scope: 'file' }, async (_context, { onCleanup }) => {
    const server = await startServer();
    onCleanup(() => server.close());
    return server;
  })
  .extend('client', { scope: 'file' }, ({ server }) => {
    return createClient(server.url);
  });
```

- 必须在测试文件顶层声明，且不可被后续 `.extend()` 覆盖。
- 可依赖链中更早声明的 worker scope 或 file scope fixture，不可访问 test scope fixture 或 `TestContext`（test scope fixture 可依赖 file scope fixture）。
- setup 受首次请求它的测试或 Hook 的超时限制；文件清理受 Node 或浏览器宿主超时保护。

### Worker scope 具名 fixtures

<ApiMeta addedVersion="0.11.9" />

传入 `{ scope: 'worker' }` 为当前测试 worker 惰性创建单个 fixture 实例。当同一 worker 执行的多个文件复用同一个扩展 test API/fixture 定义时，它们共享该实例；worker 退出或回收时执行清理。

```ts
import { test } from '@rstest/core';

const apiTest = test.extend(
  'server',
  { scope: 'worker' },
  async (_context, { onCleanup }) => {
    const server = await startServer();
    onCleanup(() => server.close());
    return server;
  },
);
```

- 必须在测试文件顶层声明，且不可被后续 `.extend()` 覆盖。
- 只能依赖链中更早声明的 worker scope fixture，不可访问 `TestContext` 或 file scope fixture（file scope fixture 可依赖 worker scope fixture）。
- setup 受首次请求它的测试超时限制；清理受 worker 宿主超时保护（worker 被强制终止时无法执行用户清理回调）。
- 在 Browser Mode 中，`isolate: false` 会让分配到同一浏览器 worker 的文件共享该 fixture；若项目配置了 `setupFiles`，文件仍保持隔离。默认隔离模式下其生命周期等同于单文件。

### Fixture 之间的依赖

在第一个参数中解构其他 fixture 即可声明依赖。Rstest 按拓扑顺序初始化依赖，并按反序执行清理：

```ts
import { test } from '@rstest/core';

const testWithApi = test.extend({
  baseURL: 'https://api.example.com',
  token: async ({ baseURL }, use) => {
    const token = await createTestToken(baseURL);
    await use(token);
    await revokeTestToken(token);
  },
});

testWithApi('fetch profile', async ({ baseURL, token, expect }) => {
  const res = await fetch(`${baseURL}/profile`, {
    headers: { Authorization: `Bearer ${token}` },
  });
  expect(res.ok).toBe(true);
});
```

### 在 hook 中使用 fixture

<ApiMeta addedVersion="0.11.4" />

`beforeEach`、`afterEach` 及 `beforeEach` 返回的清理函数均可通过直接参数解构请求 fixture（例如 `beforeEach(({ db }) => {})`）。

- 测试回调请求的 fixture 在 `beforeEach` 之前初始化；仅由 Hook 请求的 fixture 在该 Hook 运行前初始化。
- 为 `beforeEach<Fixtures>` / `afterEach<Fixtures>` 显式传入 fixture 类型，并在使用对应扩展 test API 的套件中注册 Hook（若测试未提供请求的 fixture，Rstest 会在调用 Hook 前报错失败）。

```ts
import { beforeEach, describe, test } from '@rstest/core';

interface DbFixtures {
  db: Database;
}

describe('database tests', () => {
  const dbTest = test.extend<DbFixtures>({
    db: async ({}, use) => {
      const db = await connectTestDb();
      await use(db);
      await db.close();
    },
  });

  beforeEach<DbFixtures>(({ db }) => {
    return async ({ db }) => {
      await db.rollback();
    };
  });

  dbTest('creates a user', async () => {
    // 即使测试本身未解构 db，也会为 beforeEach 初始化它
  });
});
```

### 自动 fixture（`auto`）

Fixture 默认是惰性的，只有在测试、Hook 或其他 fixture 中解构时才会执行。使用元组语法并配置 `{ auto: true }` 可让 fixture 对每个测试自动生效：

```ts
import { test } from '@rstest/core';

const events: string[] = [];

const myTest = test.extend({
  logger: [
    async ({ task }, use) => {
      events.push(`start:${task.name}`);
      await use(undefined);
      events.push(`end:${task.name}`);
    },
    { auto: true },
  ],
});

myTest('runs logger automatically', ({ expect }) => {
  expect(events).toContain('start:runs logger automatically');
});
```

### 类型推断与显式泛型

当自动推断的类型过宽时，可为 `test.extend<MyFixtures>(...)` 传入显式泛型。新类型仅作用于返回的新 API，不会改变原始 `test`：

```ts
import { test } from '@rstest/core';

interface MyFixtures {
  user: { name: string; role: 'admin' | 'guest' };
}

const myTest = test.extend<MyFixtures>({
  user: async ({}, use) => {
    await use({ name: 'Alice', role: 'admin' });
  },
});
```

## 链式修饰符

`test` 的修饰符支持按任意顺序链式组合：

- `test.only.runIf(condition)` / `test.runIf(condition).only`
- `test.skipIf(condition).concurrent` / `test.concurrent.skipIf(condition)`
- `test.runIf(condition).concurrent` / `test.concurrent.runIf(condition)`
- `test.only.concurrent` / `test.concurrent.only`
- `test.for(cases).concurrent` / `test.concurrent.for(cases)`

## 类型

### TestContext

`TestContext` 会传递给测试回调、test scope fixture 和单测 Hook。

```ts
export interface TestContext {
  /** 当前测试的元数据 */
  task: {
    /** 唯一标识符，例如 `419cefd87e_0_0`。 */
    id: string;
    /** 用户提供的测试名称。 */
    name: string;
    /** 当前测试文件的绝对路径（由 runner 提供）。0.11.1 新增。 */
    filepath?: string;
    /** 当前项目根目录的绝对路径（由 runner 提供）。0.11.1 新增。 */
    projectRoot?: string;
    /** 当前重试次数索引，首次执行为 0。0.11.6 新增。 */
    retryCount: number;
    /** 当前测试结果，测试未完成时为 undefined（结构同 TestResult，不含 fullName 和 relativeTestPath）。 */
    result?: RawTestResult;
    /** 会复制到当前测试结果中的可变元数据。0.11.1 新增。 */
    meta: TaskMeta;
  };
  /** 当前测试尝试超时时触发中止的 AbortSignal，reason 为对应的超时错误。0.11.9 新增。 */
  readonly signal: AbortSignal;
  /** 绑定到当前测试的 `expect` API。 */
  expect: Expect;
  /** 在运行期间跳过当前测试。 */
  skip: () => never;
  /** 绑定到当前测试的 `onTestFinished` Hook。 */
  onTestFinished: (
    fn: (ctx: TestContext) => void | Promise<void>,
    timeout?: number,
  ) => void;
  /** 绑定到当前测试的 `onTestFailed` Hook。 */
  onTestFailed: (
    fn: (ctx: TestContext) => void | Promise<void>,
    timeout?: number,
  ) => void;
}
```

<ApiMeta addedVersion="0.11.6" />

`context.task.retryCount` 在首次尝试时为 `0`，每次重试递增，在 `repeats` 的每次重复执行中重新从 `0` 开始计数。

#### signal

<ApiMeta addedVersion="0.11.9" />

当前测试尝试超时时（包括测试回调、单测 Hook 与 fixture 超时），`context.signal` 会以超时错误作为 reason 中止。每次重试和重复执行都会收到一个新的 `AbortSignal`。

将 `signal` 传给支持取消的 API（如 `fetch`、`fs.readFile`），可在超时后及时终止尚未完成的操作：

```ts
import { readFile } from 'node:fs/promises';
import { test } from '@rstest/core';

test('loads a user', { timeout: 1_000 }, async ({ signal }) => {
  await fetch('/api/user', { signal });
});

test('loads a large fixture', { timeout: 1_000 }, async ({ signal }) => {
  const contents = await readFile('./fixtures/large-data.json', {
    encoding: 'utf8',
    signal,
  });

  JSON.parse(contents);
});
```

在 1000 ms 超时后，`signal.reason` 即为 Rstest 报告的超时错误（例如 `Error: test timed out in 1000ms (no expect assertions completed)`）。`fs.readFile` 等 Node API 会抛出 `AbortError`，其 `cause` 指向 `signal.reason`。
