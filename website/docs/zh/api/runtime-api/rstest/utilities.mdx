# Utilities

`rs`（别名 `rstest`）上提供的运行时工具函数，用于模拟环境变量与全局变量、修改运行时配置以及异步轮询等待条件满足。

## rs.stubEnv

- **别名：** `rstest.stubEnv`

- **类型：** `(name: string, value: string | undefined) => RstestUtilities & Disposable`

临时设置 `process.env` 和 `import.meta.env` 中的环境变量。

- 传入 `undefined` 会从 `process.env` 和 `import.meta.env` 中移除该变量。
- 多次调用会按栈叠加；调用 [`rs.unstubAllEnvs()`](#rsunstuballenvs) 可恢复所有被修改的环境变量。

```ts
rs.stubEnv('NODE_ENV', 'test');
expect(process.env.NODE_ENV).toBe('test');
expect(import.meta.env.NODE_ENV).toBe('test');

rs.stubEnv('MY_VAR', undefined);
expect(process.env.MY_VAR).toBeUndefined();
expect(import.meta.env.MY_VAR).toBeUndefined();
```

- **`using` 语法**

<ApiMeta addedVersion="0.10.3" />

`rs.stubEnv()` 返回一个 `Disposable`，在 `using` 代码块退出时自动恢复该变量的原始值（`using` 语法要求声明变量，例如 `_env`）：

```ts
{
  using _env = rs.stubEnv('NODE_ENV', 'test');
  expect(process.env.NODE_ENV).toBe('test');
}

// NODE_ENV 已恢复为原始值。
```

## rs.unstubAllEnvs

- **别名：** `rstest.unstubAllEnvs`

- **类型：** `() => RstestUtilities`

将所有通过 [`rs.stubEnv`](#rsstubenv) 修改的环境变量恢复为原始值。启用 [`unstubEnvs`](/config/test/unstub-envs) 时会在每个测试前自动执行。

```ts
const originalNodeEnv = process.env.NODE_ENV;
rs.stubEnv('NODE_ENV', 'production');
// ... 在模拟环境变量下运行代码
rs.unstubAllEnvs();
expect(process.env.NODE_ENV).toBe(originalNodeEnv);
```

如果不启用 [`unstubEnvs`](/config/test/unstub-envs)，也可以在 [`afterEach`](/api/runtime-api/test-api/hooks#aftereach) 中调用 `rs.unstubAllEnvs()` 以便每个测试后恢复。

## rs.stubGlobal

- **别名：** `rstest.stubGlobal`

- **类型：** `(name: string | number | symbol, value: unknown) => RstestUtilities & Disposable`

临时将 `globalThis` 上的指定属性设置为 `value`。多次调用会按栈叠加；调用 [`rs.unstubAllGlobals()`](#rsunstuballglobals) 可恢复所有被修改的全局变量。

```ts
rs.stubGlobal('myGlobal', 123);
expect(globalThis.myGlobal).toBe(123);

rs.stubGlobal(Symbol.for('foo'), 'bar');
expect(globalThis[Symbol.for('foo')]).toBe('bar');
```

- **`using` 语法**

<ApiMeta addedVersion="0.10.3" />

`rs.stubGlobal()` 返回一个 `Disposable`，在 `using` 代码块退出时自动恢复该全局变量的原始值：

```ts
{
  using _global = rs.stubGlobal('myGlobal', 123);
  expect(globalThis.myGlobal).toBe(123);
}

// myGlobal 已恢复为原始值。
```

## rs.unstubAllGlobals

- **别名：** `rstest.unstubAllGlobals`

- **类型：** `() => RstestUtilities`

将所有通过 [`rs.stubGlobal`](#rsstubglobal) 修改的全局变量恢复为原始属性描述符（原本不存在的属性会被删除）。启用 [`unstubGlobals`](/config/test/unstub-globals) 时会在每个测试前自动执行。

```ts
rs.stubGlobal('myGlobal', 123);
// ... 在模拟全局变量下运行代码
rs.unstubAllGlobals();
expect(globalThis.myGlobal).toBeUndefined();
```

如果不启用 [`unstubGlobals`](/config/test/unstub-globals)，也可以在 [`afterEach`](/api/runtime-api/test-api/hooks#aftereach) 中调用 `rs.unstubAllGlobals()` 以便每个测试后恢复。

## rs.setConfig

- **别名：** `rstest.setConfig`

- **类型：**

```ts
type RuntimeOptions = {
  testTimeout?: number;
  hookTimeout?: number;
  clearMocks?: boolean;
  resetMocks?: boolean;
  restoreMocks?: boolean;
  maxConcurrency?: number;
  retry?: number;
};

type SetConfig = (config: RuntimeOptions) => void;
```

动态更新当前测试文件的运行时配置。

```ts
rs.setConfig({ testTimeout: 1000, retry: 2 });
// ... 使用更新后的配置运行测试
rs.resetConfig();
```

## rs.resetConfig

- **别名：** `rstest.resetConfig`

- **类型：** `() => void`

将通过 [`rs.setConfig`](#rssetconfig) 修改的运行时配置恢复为当前测试文件的初始值。

## rs.getConfig

- **别名：** `rstest.getConfig`

- **类型：**

```ts
type GetConfig = () => RuntimeOptions & {
  expect: {
    poll: {
      interval: number;
      timeout: number;
    };
  };
};
```

获取当前测试文件的运行时配置。

<ApiMeta addedVersion="0.12.0" />

返回值还包含合并后的 `expect.poll` 配置副本；修改该副本不会影响运行时配置。

```ts
const config = rs.getConfig();
console.log(config);
```

## rs.waitFor

- **别名：** `rstest.waitFor`

- **类型：**

```ts
type WaitForOptions = {
  timeout?: number; // 默认: 1000
  interval?: number; // 默认: 50
};

type WaitFor = <T>(
  callback: () => T | Promise<T>,
  options?: number | WaitForOptions,
) => Promise<T>;
```

不断重试 `callback`，直到执行成功（不抛错）或达到 `timeout` 超时。

- `options` 为数字时，作为 `timeout` 使用。
- 超时时会抛出 `callback` 最后一次抛出的错误（若超时前尚未抛出过错误，则抛出超时错误）。

```ts
await rs.waitFor(
  async () => {
    const res = await fetch(url);
    expect(res.ok).toBe(true);
  },
  { timeout: 30_000, interval: 1_000 },
);
```

启用 [fake timers](/api/runtime-api/rstest/fake-timers) 时，`rs.waitFor` 会在每次检查前将其推进 `interval` 毫秒，异步 `callback` 仍在执行时也会每隔 `interval` 毫秒推进一次，使 `callback` 等待的定时器能够触发。

## rs.waitUntil

- **别名：** `rstest.waitUntil`

- **类型：**

```ts
type Falsy = false | 0 | 0n | '' | null | undefined;
type Truthy<T> = Exclude<T, Falsy>;

type WaitUntilOptions = {
  timeout?: number; // 默认: 1000
  interval?: number; // 默认: 50
};

type WaitUntil = <T>(
  callback: () => T | Promise<T>,
  options?: number | WaitUntilOptions,
) => Promise<Truthy<Awaited<T>>>;
```

在 `callback` 返回 falsy 值期间持续重试，并在返回首个 truthy 值时 resolve。

- `options` 为数字时，作为 `timeout` 使用。
- 若 `callback` 抛错，会立即中断并重新抛出该错误。
- 超时时会抛出超时错误。

```ts
const serverReady = await rs.waitUntil(
  async () => {
    const status = await getServerStatus();
    return status.ready ? status : null;
  },
  { timeout: 10_000, interval: 200 },
);
```

启用 [fake timers](/api/runtime-api/rstest/fake-timers) 时，`rs.waitUntil` 会在每次检查前将其推进 `interval` 毫秒，异步 `callback` 仍在执行时也会每隔 `interval` 毫秒推进一次，使 `callback` 等待的定时器能够触发。
