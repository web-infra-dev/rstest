# Mock modules

Rstest 在 `rs`（别名 `rstest`）上提供了用于 mock ESM 和 CommonJS 模块的 API。

## rs.mock

- **类型：** `<T = unknown>(moduleName: string | Promise<T>, factoryOrOptions?: (() => Partial<T>) | { spy: true } | { mock: true }) => void`

将 `moduleName` 指定的模块替换为 mock 实现，作用于 `import`（以及解析到同一打包模块的 `require()`）。

:::tip 提升（Hoisting）
`rs.mock` 会被提升到当前模块顶部，因此同一文件中的静态 `import` 也会拿到 mock 后的模块。
:::

### 使用工厂函数

传入工厂函数作为第二个参数时，模块会替换为该工厂函数的返回值。工厂函数必须是同步函数；如需保留部分原始导出，请参见 [使用 `importActual` 部分 mock](#使用-importactual-部分-mock)。

#### 基础示例

<div style={{ display: 'flex', gap: '1rem' }}>
  <div>
    ```ts title="src/sum.test.ts"
    import { expect, rs } from '@rstest/core';
    import { sum } from './sum';

    rs.mock('./sum', () => ({
      sum: (a: number, b: number) => a + b + 100,
    }));

    expect(sum(1, 2)).toBe(103);
    ```

  </div>
  <div>
    ```ts title="src/sum.ts"
    export const sum = (a: number, b: number) => a + b;
    ```
  </div>
</div>

#### Mock 虚拟模块

Rstest 可以 mock 磁盘上不存在的模块（如生成模块、原生模块），在 Node 模式和浏览器模式下配置方式相同：

1. 为 TypeScript 声明模块类型：

```ts title="src/types/native-runtime.d.ts"
declare module 'native-runtime' {
  export const platform: string;
}
```

2. 将该 specifier 映射为 `false`，使打包工具跳过磁盘解析：

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  resolve: {
    alias: {
      'native-runtime': false,
    },
  },
});
```

3. 使用工厂函数（或匹配的 `__mocks__` 文件）提供运行时导出：

```ts title="src/native-runtime.test.ts"
import { expect, rs, test } from '@rstest/core';
import { platform } from 'native-runtime';

rs.mock('native-runtime', () => ({
  platform: 'test',
}));

test('使用虚拟模块', () => {
  expect(platform).toBe('test');
});
```

Rstest 不使用 Jest 的第三个 `{ virtual: true }` 参数。请在类型声明、alias、mock 调用和 import 中使用相同的 specifier；被测源码间接导入该虚拟模块时同样会被 mock。

`rs.mock` 会被提升，覆盖静态 `import`；动态 `import()` 需在导入前调用 `rs.doMock`，而解析到独立 CommonJS 入口的 `require()` 请使用 `rs.mockRequire` 或 `rs.doMockRequire`。由于映射为 `false` 的 alias 没有真实实现，请使用工厂函数或手写 mock，不要使用 `{ mock: true }`、`{ spy: true }` 或 `rs.importActual`。

#### 使用 `rs.fn()` 追踪调用

在工厂函数中返回 `rs.fn()`，以追踪调用并配置返回值：

```ts title="src/api.test.ts"
import { expect, rs, test } from '@rstest/core';
import { fetchUser, fetchPosts } from './api';

rs.mock('./api', () => ({
  fetchUser: rs.fn().mockResolvedValue({ id: 1, name: 'John' }),
  fetchPosts: rs.fn().mockResolvedValue([{ id: 1, title: 'Hello' }]),
}));

test('获取用户数据', async () => {
  const user = await fetchUser(1);
  expect(user).toEqual({ id: 1, name: 'John' });
  expect(fetchUser).toHaveBeenCalledWith(1);
});
```

#### 使用 `rs.mockObject()` 自动 mock

```ts title="src/service.test.ts"
import { expect, rs, test } from '@rstest/core';
import { userService } from './userService';

rs.mock('./userService', () => ({
  userService: rs.mockObject({
    getUser: () => {},
    updateUser: () => {},
    deleteUser: () => {},
  }),
}));

test('服务方法被 mock', () => {
  userService.getUser(1);
  expect(userService.getUser).toHaveBeenCalledWith(1);
});
```

#### 使用 `importActual` 部分 mock

通过 [import attribute](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/import/with) `with { rstest: 'importActual' }` 加载未 mock 的原始模块，并将其导出展开到工厂函数返回值中：

```ts title="src/utils.test.ts"
import { expect, rs, test } from '@rstest/core';
import * as dateUtils from './dateUtils' with { rstest: 'importActual' };
import { formatDate, parseDate } from './dateUtils';

rs.mock('./dateUtils', () => ({
  ...dateUtils,
  formatDate: rs.fn().mockReturnValue('2024-01-01'),
}));

test('formatDate 被 mock，parseDate 保持原实现', () => {
  expect(formatDate(new Date())).toBe('2024-01-01');
  expect(parseDate('2024-01-01')).toBeInstanceOf(Date);
});
```

如果真实模块或其依赖使用了 top-level `await`，请不要在同一测试文件中静态导入被 mock 的模块——否则工厂函数可能在真实模块求值完成前执行。请保留 `importActual` 导入，并在异步测试中通过 `await import()` 动态导入被 mock 的模块：

```ts title="src/api.test.ts"
import { expect, it, rs } from '@rstest/core';
import * as apiActual from './api' with { rstest: 'importActual' };

rs.mock('./api', () => ({ ...apiActual, extra: true }));

it('使用真实导出', async () => {
  const api = await import('./api');
  expect(api.answer()).toBe(42);
});
```

### 使用 `__mocks__` 目录

调用 `rs.mock` 且不传第二个参数时，Rstest 会先在 `__mocks__` 目录中查找同名手写 mock；若未找到，则回退为自动 mock（等价于传入 `{ mock: true }`）。

**解析规则：**

1. **本地模块**：目标文件同级 `__mocks__` 目录下的同名文件。
2. **npm 依赖**：项目根目录 `__mocks__` 目录下与包名同名的文件。
3. **Node.js 内置模块**：项目根目录 `__mocks__` 目录下与内置模块同名的文件（如 `__mocks__/fs.mjs`、`__mocks__/path.ts`），会自动忽略 `node:` 前缀。

**示例：**

```txt
├── __mocks__
│   └── lodash.js
├── src
│   ├── multiple.ts
│   └── __mocks__
│       └── multiple.ts
└── __test__
    └── multiple.test.ts
```

```ts title="src/multiple.test.ts"
import { rs } from '@rstest/core';
import lodash from 'lodash';
import { multiple } from '../src/multiple';

rs.mock('lodash');
rs.mock('../src/multiple');

lodash.random(multiple(1, 2), multiple(3, 4));
```

未找到手写 mock 时，Rstest 会自动 mock 该模块：

```ts title="src/math.test.ts"
import { expect, rs, test } from '@rstest/core';
import { add } from './math';

rs.mock('./math');

test('回退为自动 mock', () => {
  expect(rs.isMockFunction(add)).toBe(true);
  expect(add(1, 2)).toBeUndefined();
});
```

### 使用 `{ spy: true }` 选项 \{#with-spy-true-option}

将模块的所有导出包装为 spy 函数，同时保留原始实现。

```ts title="src/calculator.test.ts"
import { expect, rs, test } from '@rstest/core';
import { calculate } from './calculator';

rs.mock('./calculator', { spy: true });

test('保留真实实现并追踪调用', () => {
  const result = calculate(1, 2);
  expect(result).toBe(3);

  expect(calculate).toHaveBeenCalledWith(1, 2);
  expect(calculate).toHaveReturnedWith(3);
});
```

:::note 模块内部调用不会被追踪

spy 包装的是模块的**导出**。同一模块内某个导出直接调用另一个函数时，走的是模块内部绑定而非包装后的导出，因此不会被追踪。

:::

:::note ESM 和 CommonJS 模块

- **ESM 模块**：所有命名导出都会被包装为 spy 函数。
- **CommonJS 模块**：除包装导出外，若不存在 `default` 导出，会自动添加指向模块对象的 `default` 导出，以保持 `import x from 'cjs-module'` 的行为。

:::

### 使用 `{ mock: true }` 选项

跳过 `__mocks__` 查找，直接自动 mock 模块，将所有导出的函数替换为默认返回 `undefined` 的 mock 函数。

```ts title="src/math.test.ts"
import { expect, rs, test } from '@rstest/core';
import { add, multiply } from './math';

rs.mock('./math', { mock: true });

test('mock 函数默认返回 undefined', () => {
  expect(add(1, 2)).toBeUndefined();
  expect(multiply(3, 4)).toBeUndefined();
  expect(rs.isMockFunction(add)).toBe(true);
});

test('配置 mock 实现', () => {
  rs.mocked(add).mockReturnValue(100);
  expect(add(1, 2)).toBe(100);

  rs.mocked(multiply).mockImplementation((a, b) => a * b * 2);
  expect(multiply(3, 4)).toBe(24);
});
```

### 使用 `Promise<T>` 增强类型

第一个参数传入动态 `import()` 表达式（`Promise<T>`），可为工厂函数返回值提供 IDE 类型推导，不影响运行时行为：

```ts
rs.mock(import('../src/b'), () => ({
  b: 222,
}));
```

## rs.doMock

- **类型：** `<T = unknown>(moduleName: string | Promise<T>, factoryOrOptions?: (() => Partial<T>) | { spy: true } | { mock: true }) => void`

`rs.mock` 的非提升版本。仅在执行时生效，因此在此之前求值的导入保持原始模块，之后的动态 `import()` 会获得 mock 模块。

第二个参数支持与 `rs.mock` 相同的选项（工厂函数、`__mocks__` 回退、`{ spy: true }` 或 `{ mock: true }`）。

```ts title="src/sum.test.ts"
import { expect, it, rs } from '@rstest/core';
import { sum } from './sum';

it('仅 mock 后续导入', async () => {
  expect(sum(1, 2)).toBe(3);

  rs.doMock('./sum');
  const { sum: mockedSum } = await import('./sum');

  expect(mockedSum(1, 2)).toBeUndefined();
});
```

## rs.mockRequire

- **类型：** `<T = unknown>(moduleName: string, factoryOrOptions?: (() => T) | { spy: true } | { mock: true }) => void`

mock 通过 CommonJS `require()` 加载的模块。与 `rs.mock` 一样，调用会被提升到当前模块顶部。

:::tip 双入口包（ESM + CJS）
当依赖同时提供 ESM 和 CommonJS 入口时：

- `rs.mock()` 作用于 **ESM 入口**（`import` 使用）。
- `rs.mockRequire()` 作用于 **CJS 入口**（`require()` 使用）。
  :::

```ts title="src/math.test.cjs"
const { sum } = require('./math.cjs');

rs.mockRequire('./math.cjs', () => ({
  sum: (a, b) => a + b + 100,
}));

test('使用 require mock cjs 模块', () => {
  expect(sum(1, 2)).toBe(103);
});
```

## rs.doMockRequire

- **类型：** `<T = unknown>(moduleName: string, factoryOrOptions?: (() => T) | { spy: true } | { mock: true }) => void`

`rs.mockRequire` 的非提升版本，仅对执行后的 `require()` 调用生效。

```ts title="src/math.test.cjs"
test('doMockRequire 只影响后续 require 调用', () => {
  const { sum } = require('./math.cjs');
  expect(sum(1, 2)).toBe(3);

  rs.doMockRequire('./math.cjs', () => ({
    sum: (a, b) => a + b + 100,
  }));

  const { sum: mockedSum } = require('./math.cjs');
  expect(mockedSum(1, 2)).toBe(103);
});
```

## rs.unmockRequire

- **类型：** `(path: string) => void`

移除通过 `require()` 加载模块的 mock。与 `rs.mockRequire` 一样，调用会被提升到文件顶部，使后续 `require()` 加载原始 CommonJS 模块。

```ts title="src/math.test.cjs"
const { sum } = require('./math.cjs');

rs.mockRequire('./math.cjs', () => ({
  sum: (a, b) => a + b + 100,
}));

rs.unmockRequire('./math.cjs');

test('unmockRequire 恢复原始 CommonJS 模块', () => {
  expect(sum(1, 2)).toBe(3);
});
```

## rs.doUnmockRequire

- **类型：** `(path: string) => void`

`rs.unmockRequire` 的非提升版本，仅影响执行后的 `require()` 调用。

```ts title="src/math.test.cjs"
test('doUnmockRequire 只影响后续 require 调用', () => {
  rs.doMockRequire('./math.cjs', () => ({
    sum: (a, b) => a + b + 100,
  }));

  const { sum: mockedSum } = require('./math.cjs');
  expect(mockedSum(1, 2)).toBe(103);

  rs.doUnmockRequire('./math.cjs');

  const { sum } = require('./math.cjs');
  expect(sum(1, 2)).toBe(3);
});
```

## rs.hoisted

- **类型：** `<T = unknown>(fn: () => T) => T`

将 `fn` 提升到模块顶部执行（作用域内可访问 `rs`）并返回其结果。用于在被提升的 `rs.mock` 工厂函数与测试断言之间共享 mock 函数或变量。

```ts title="src/sum.test.ts"
import { expect, it, rs } from '@rstest/core';
import { foo } from './sum';

const mocks = rs.hoisted(() => ({
  hoistedFn: rs.fn(),
}));

rs.mock('./sum', () => ({
  foo: mocks.hoistedFn,
}));

it('hoisted', () => {
  mocks.hoistedFn(42);
  expect(mocks.hoistedFn).toHaveBeenCalledOnce();
  expect(mocks.hoistedFn).toHaveBeenCalledWith(42);
  expect(foo).toBe(mocks.hoistedFn);
});
```

## rs.importActual

- **类型：** `<T = Record<string, unknown>>(path: string) => Promise<T>`

异步加载 ESM 模块的原始实现，绕过已注册的 mock。对于通过 `require()` 加载的 CommonJS 模块，请使用 [`rs.requireActual`](#rsrequireactual)；在同步 `rs.mock` 工厂函数中进行部分 mock 时，请使用 `with { rstest: 'importActual' }`（参见 [使用 `importActual` 部分 mock](#使用-importactual-部分-mock)）。

```ts title="src/sum.test.ts"
import { expect, it, rs } from '@rstest/core';

rs.mock('./sum');

it('加载原始模块', async () => {
  const actualModule = await rs.importActual<typeof import('./sum')>('./sum');
  expect(actualModule.sum(1, 2)).toBe(3);
});
```

## rs.requireActual

- **类型：** `<T = Record<string, unknown>>(path: string) => T`

同步加载 CommonJS 模块的原始实现，绕过已注册的 mock。若模块的依赖图使用了 top-level `await`，该方法会抛出错误，请改用异步的 [`rs.importActual`](#rsimportactual)。

```js title="src/math.test.cjs"
const { expect, rs, test } = require('@rstest/core');

rs.mockRequire('./math.cjs', () => ({
  sum: () => 100,
}));

test('加载原始 CommonJS 模块', () => {
  const actualMath = rs.requireActual('./math.cjs');

  expect(rs.isMockFunction(actualMath.sum)).toBe(false);
  expect(actualMath.sum(1, 2)).toBe(3);
});
```

## rs.importMock

- **类型：** `<T = Record<string, unknown>>(path: string) => Promise<T>`

异步加载 ESM 模块的 mock 导出。如需同步加载 CommonJS 模块的 mock，请使用 [`rs.requireMock`](#rsrequiremock)。

解析顺序如下：

- 若已通过 `rs.mock` 或 `rs.doMock` 注册 mock，则返回该已注册的 mock（已注册的工厂函数优先于 `__mocks__`，且其导出函数保持原样，不会自动包装为 `rs.fn()`）。
- 若未注册 mock 且 `path` 为字符串字面量，则加载匹配的 `__mocks__` 文件（若存在）。
- 若两者均不存在，返回的 Promise 会以模块未找到错误 reject。

如需自动 mock 模块，请先调用 `rs.mock('./sum', { mock: true })` 注册。

```ts title="src/sum.test.ts"
import { expect, rs, test } from '@rstest/core';

rs.mock('./sum', () => ({
  sum: () => 100,
}));

test('加载已注册的 mock', async () => {
  const mocked = await rs.importMock<typeof import('./sum')>('./sum');

  expect(mocked.sum(1, 2)).toBe(100);
});
```

### 变量路径

当 `path` 为变量时，`rs.importMock` 只会查找此前通过字面量路径注册的 mock（`rs.mock` 会被提升；`rs.doMock` 需在 `rs.importMock` 之前执行）。相对路径以调用所在文件为基准解析。变量路径不会在运行时查找未 mock 的模块或 `__mocks__` 文件。

```ts title="src/sum.test.ts"
import { expect, rs, test } from '@rstest/core';

test('通过变量加载自动 mock 的模块', async () => {
  rs.doMock('./sum', { mock: true });

  const path = './sum';
  const mocked = await rs.importMock<typeof import('./sum')>(path);

  expect(rs.isMockFunction(mocked.sum)).toBe(true);
  expect(mocked.sum(1, 2)).toBeUndefined();
});
```

## rs.requireMock

- **类型：** `<T = Record<string, unknown>>(path: string) => T`

同步加载通过 `rs.mockRequire` 或 `rs.doMockRequire` 注册的 CommonJS 模块 mock（当 `path` 为字符串字面量时，也可直接加载匹配的 `__mocks__` 文件）。找不到对应 mock 时同步抛出错误。

传入变量路径时，`rs.requireMock` 仅查找已注册的 mock（相对路径以调用文件为基准解析），不会在运行时查找 `__mocks__` 文件。

```js title="src/math.test.cjs"
const { expect, rs, test } = require('@rstest/core');

rs.mockRequire('./math.cjs', () => ({
  sum: () => 100,
}));

test('加载已注册的 CommonJS mock', () => {
  const path = './math.cjs';
  const mockedMath = rs.requireMock(path);

  expect(mockedMath.sum(1, 2)).toBe(100);
});
```

## rs.unmock

- **类型：** `(path: string) => void`

取消指定模块的 mock，使后续 `import` 加载原始模块。与 `rs.mock` 一样，调用会被提升到文件顶部，可用于取消 `setupFiles` 或同文件更早提升的 `rs.mock` 注册的 mock。

<div style={{ display: 'flex', gap: '1rem' }}>
  <div>
    ```ts title="sum.test.ts"
    import { expect, rs } from '@rstest/core';
    import { sum } from './src/sum';

    rs.unmock('./src/sum');

    expect(sum(1, 2)).toBe(3);
    ```

  </div>
  <div>
    ```ts title="rstest.setup.ts"
    import { rs } from '@rstest/core';

    rs.mock('./src/sum', () => ({
      sum: (a: number, b: number) => a + b + 100,
    }));
    ```

  </div>
</div>

## rs.doUnmock

- **类型：** `(path: string) => void`

`rs.unmock` 的非提升版本，仅影响后续导入，不会撤销此前已导入的模块绑定。

## rs.resetModules

- **类型：** `() => RstestUtilities`

清空模块缓存，使模块在下次 `import` 或 `require()` 时重新执行，用于隔离不同测试之间共享的模块状态。

:::warning
不会清除已注册的模块 mock。如需恢复原始模块，请使用 [`rs.unmock`](#rsunmock)、[`rs.doUnmock`](#rsdounmock)、[`rs.unmockRequire`](#rsunmockrequire) 或 [`rs.doUnmockRequire`](#rsdounmockrequire)。
:::
