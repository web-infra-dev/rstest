# Locator

`Locator` 是 Browser Mode 中用于元素查询与交互的核心 API。通过 `page.getBy*` 或 `page.locator()` 构建查询链后，可调用交互方法或将其传给 [`expect.element`](/api/runtime-api/browser-mode/assertion) 执行断言。具体执行语义由配置的 browser `provider` 决定。

:::tip 自动等待
使用 Playwright provider 时，`Locator` 交互方法（如 `click`、`fill`、`check`）会在执行前自动等待元素进入可操作状态（可见、启用、稳定）。这与 `expect.element` 断言的[自动重试](/api/runtime-api/browser-mode/assertion#自动重试与超时)机制不同。
:::

```ts title="src/locator.test.ts"
import { page } from '@rstest/browser';
import { expect, test } from '@rstest/core';

test('interacts with a form using locator', async () => {
  await page.getByLabel('Username').fill('alice');
  await page.getByLabel('Password').fill('secret123');
  await page.getByRole('button', { name: 'Login' }).click();

  await expect.element(page.getByLabel('Username')).toHaveValue('alice');
});
```

## page

- **类型：** `BrowserPage`

测试中定位元素的起点。调用 `page` 上的查询方法创建 `Locator`，然后链式调用交互方法或传给 `expect.element(...)`。需要基于当前焦点发送键盘输入时，请使用 [`page.keyboard`](/api/runtime-api/browser-mode/keyboard)。

```ts
const submitButton = page.getByRole('button', { name: 'Submit' });
await submitButton.click();
```

## BrowserPage

- **类型：**

```ts
type BrowserPage = Pick<
  Locator,
  | 'locator'
  | 'getByRole'
  | 'getByText'
  | 'getByLabel'
  | 'getByPlaceholder'
  | 'getByAltText'
  | 'getByTitle'
  | 'getByTestId'
> & {
  elementLocator: (element: Element) => Locator;
  keyboard: BrowserKeyboard;
  viewport: (width: number, height: number) => Promise<void>;
};
```

`page` 的类型，提供元素查询、DOM 到 Locator 的转换、[`keyboard`](/api/runtime-api/browser-mode/keyboard) 键盘输入和 `viewport` 视口调整。`click`、`fill` 等元素操作由 `Locator` 提供。

## page.viewport

<ApiMeta addedVersion="0.13.0" />

- **类型：** `(width: number, height: number) => Promise<void>`

调整当前测试的布局视口，用于验证不同尺寸下的响应式布局。宽高以 CSS 像素为单位，必须是正整数。`await page.viewport(width, height)` 完成后，媒体查询和布局读取都会使用新尺寸。

```ts
import { page } from '@rstest/browser';
import { expect, test } from '@rstest/core';

test('uses the tablet layout', async () => {
  await page.viewport(768, 1024);
  expect(window.matchMedia('(min-width: 768px)').matches).toBe(true);
});
```

Rstest 会在每次测试执行结束后恢复初始视口，包括重试（`retry`）和重复执行（`repeats`）。恢复会等到失败截图、`afterEach`、fixture 清理、`onTestFinished` 和 `onTestFailed` 回调完成后再执行。没有修改视口的测试会跳过恢复。

headless 模式会恢复当前浏览器实例的初始视口尺寸，headed 模式会恢复 UI 原先选择的视口模式。在 `afterAll` 或 `beforeAll` 返回的清理函数中修改视口，也会在这组测试结束后恢复。

要让一组测试使用相同尺寸，可以配置 [`browser.viewport`](/config/test/browser#viewport)，或在 `beforeEach` 中调用 `page.viewport()`。在 `beforeAll` 中设置的尺寸会在第一次测试执行结束后恢复，之后的重试、重复执行和其他测试不会自动沿用这个尺寸。

并发测试共享视口，因此不能调用 `page.viewport()`。如果测试组内有会执行的并发测试，组内的 `beforeAll`、`afterAll` 及清理函数同样不能调用该 API，否则会抛出错误。

在 headless 模式下，Playwright 调整视口时还会更新 `window.screen`。恢复视口时，通过 `browser.providerOptions.context.screen` 配置的屏幕尺寸不会还原。

## 查询 API

以下查询方法均返回 `Locator`，可继续链式调用。

### locator

- **类型：** `(selector: string, options?: LocatorOptions) => Locator`

按 CSS selector 查询元素，可选按子 `Locator` 或文本条件（`has`、`hasNot`、`hasText`、`hasNotText`）过滤。

```ts
const item = page.locator('.todo-item');
const activeItem = page.locator('.todo-item', { hasText: 'Active' });
```

### getByRole

- **类型：** `(role: LocatorAriaRole | (string & {}), options?: LocatorGetByRoleOptions) => Locator`

按 ARIA 语义角色查询元素。当语义角色可用时，优先使用此方法，而不是 CSS selector 或 test ID。

```ts
const saveBtn = page.getByRole('button', { name: 'Save' });
```

### getByText

- **类型：** `(text: string | RegExp, options?: LocatorTextOptions) => Locator`

按可见文本查询元素。

```ts
const successMessage = page.getByText('Saved successfully');
```

### getByLabel

- **类型：** `(text: string | RegExp, options?: LocatorTextOptions) => Locator`

按表单 label 文本查询控件。

```ts
const emailInput = page.getByLabel('Email');
```

### getByPlaceholder

- **类型：** `(text: string | RegExp, options?: LocatorTextOptions) => Locator`

按 placeholder 文本查询输入框。

```ts
const searchInput = page.getByPlaceholder('Search');
```

### getByAltText

- **类型：** `(text: string | RegExp, options?: LocatorTextOptions) => Locator`

按 `alt` 文本查询元素。

```ts
const avatarImage = page.getByAltText('User avatar');
```

### getByTitle

- **类型：** `(text: string | RegExp, options?: LocatorTextOptions) => Locator`

按 `title` 属性查询元素。

```ts
const helpIcon = page.getByTitle('Help');
```

### getByTestId

- **类型：** `(text: string | RegExp) => Locator`

按 test ID 属性查询元素（默认为 `data-testid`，可通过 [`setTestIdAttribute`](#settestidattribute) 自定义）。

```ts
const settingsPanel = page.getByTestId('settings-panel');
```

### elementLocator

<ApiMeta addedVersion="0.12.5" />

- **类型：** `(element: Element) => Locator`

将当前测试文档中的 DOM `Element` 同步转换为 `Locator`，用于对 Testing Library 或原生 DOM 查询返回的元素执行浏览器操作和断言。支持 HTML、SVG 以及 shadow DOM 中的元素。

```ts
import { getByRole } from '@testing-library/dom';

const button = getByRole(document.body, 'button', { name: 'Save' });
await page.elementLocator(button).click();
await expect.element(button).toBeEnabled();
```

`Locator` 始终指向原始 DOM 节点，不会修改 DOM 属性。如果重渲染替换了节点，该 `Locator` 仍指向旧节点：已卸载断言会通过，交互操作会等待原节点重新挂载或超时。需要在重渲染后重新查找元素时，请改用 `page.getByRole()` 等查询 Locator。

传入其他文档或 iframe 中的元素会抛出错误。当前文档中尚未挂载的元素可以提前转换。

## 配置 API

### setTestIdAttribute

- **类型：** `(attribute: string) => Promise<void>`

设置 `getByTestId()` 使用的属性名，默认为 `'data-testid'`。该设置会转发给浏览器 provider（例如 Playwright 的 `selectors.setTestIdAttribute()`）。

由于这是全局配置，建议在 [setup 文件](/config/test/setup-files)中统一设置一次，避免在测试执行中途修改：

```ts title="rstest.setup.ts"
import { setTestIdAttribute } from '@rstest/browser';

await setTestIdAttribute('data-qa');
```

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';

export default defineConfig({
  setupFiles: ['./rstest.setup.ts'],
});
```

## 组合 API

### filter

- **类型：** `(options: LocatorFilterOptions) => Locator`

基于文本、子 `Locator` 或可见性（`visible`）条件对已有 `Locator` 做二次过滤。

```ts
const profileSave = page
  .locator('section')
  .filter({ has: page.getByRole('heading', { name: 'Profile' }) })
  .getByRole('button', { name: 'Save' });

const visibleItems = page.locator('li').filter({
  visible: true,
  hasNotText: /archived/i,
  hasNot: page.getByRole('img', { name: 'Locked' }),
});
```

### and / or

- **类型：** `(other: Locator) => Locator`

组合两个 `Locator` 条件（`and` 匹配同时满足两者的元素；`or` 匹配满足任一条件的元素）。

```ts
const byRole = page.getByRole('button', { name: 'Submit' });
const byId = page.locator('#submit');

const exactOne = byRole.and(byId);
```

### nth / first / last

- **类型：**
  - `nth(index: number): Locator`
  - `first(): Locator`
  - `last(): Locator`

当 `Locator` 匹配多个元素时，按从 `0` 开始的下标、首个匹配或最后一个匹配选择单个元素。

### count

<ApiMeta addedVersion="1.0.0" />

- **类型：** `() => Promise<number>`

返回当前匹配该 `Locator` 的元素数量。该方法不会自动重试；断言数量请使用 [`toHaveCount`](/api/runtime-api/browser-mode/assertion#tohavecount)。

```ts
const total = await page.getByRole('listitem').count();
```

### all

<ApiMeta addedVersion="1.0.0" />

- **类型：** `() => Promise<Locator[]>`

解析当前匹配到的元素数量，并返回由 `nth(index)` 组成的 `Locator` 数组。该方法不会自动等待元素出现。

```ts
for (const item of await page.getByRole('listitem').all()) {
  await expect.element(item).toBeVisible();
}
```

## 交互 API

交互方法会执行浏览器操作并返回 `Promise<void>`（[`selectOption`](#selectoption) 除外，它会返回选中选项的值数组）。

:::warning 严格模式
Locator 默认处于严格模式。如果交互操作（如 `click`、`fill`）匹配到多个元素，会抛出错误。请使用 [`first()`](#nth--first--last)、[`last()`](#nth--first--last) 或 [`nth()`](#nth--first--last) 显式选择单个元素。
:::

### click

- **类型：** `(options?: LocatorClickOptions) => Promise<void>`

点击匹配到的元素。

```ts
await page.getByRole('button', { name: 'Submit' }).click();
```

### dblclick

- **类型：** `(options?: LocatorDblclickOptions) => Promise<void>`

双击匹配到的元素。

```ts
await page.getByText('Open details').dblclick();
```

### dragTo

<ApiMeta addedVersion="0.12.5" />

- **类型：** `(target: Locator, options?: LocatorDragToOptions) => Promise<void>`

将当前元素拖到目标 `Locator`。`sourcePosition` 和 `targetPosition` 分别相对于源元素和目标元素左上角内边距边界计算。

```ts
await page.getByTestId('card').dragTo(page.getByTestId('column'));
```

### hover

- **类型：** `(options?: LocatorHoverOptions) => Promise<void>`

将指针悬停到匹配到的元素上。

```ts
await page.getByRole('button', { name: 'More' }).hover();
```

### press

- **类型：** `(key: string, options?: LocatorPressOptions) => Promise<void>`

聚焦匹配到的元素并按下指定按键或组合键（例如 `'Enter'` 或 `'ControlOrMeta+A'`）。

```ts
await page.getByLabel('Search').press('Enter');
```

### pressSequentially

- **类型：** `(text: string, options?: LocatorPressOptions) => Promise<void>`

逐个字符输入 `text`，为每个字符触发按键事件。适用于需要响应单个按键事件的控件（如自动补全输入框或快捷键）；其他场景优先使用 [`fill`](#fill)。`delay` 用于设置按键之间的等待时间（毫秒）。

```ts
await page.getByLabel('Search').pressSequentially('rstest');
```

### fill

- **类型：** `(value: string, options?: LocatorFillOptions) => Promise<void>`

设置 `input`、`textarea` 或 `contenteditable` 元素的值。

```ts
await page.getByPlaceholder('Email').fill('dev@rstest.rs');
```

### clear

- **类型：** `(options?: LocatorClearOptions) => Promise<void>`

清空输入元素的值。

```ts
await page.getByPlaceholder('Email').clear();
```

### focus

- **类型：** `(options?: LocatorFocusOptions) => Promise<void>`

使匹配到的元素获得焦点。

```ts
await page.getByLabel('Username').focus();
```

### blur

- **类型：** `(options?: LocatorBlurOptions) => Promise<void>`

使匹配到的元素失去焦点。

```ts
await page.getByLabel('Username').blur();
```

### check

- **类型：** `(options?: LocatorCheckOptions) => Promise<void>`

勾选 checkbox 或 radio。

```ts
await page.getByLabel('Agree').check();
```

### uncheck

- **类型：** `(options?: LocatorCheckOptions) => Promise<void>`

取消勾选 checkbox。

```ts
await page.getByLabel('Agree').uncheck();
```

### scrollIntoViewIfNeeded

- **类型：** `(options?: LocatorScrollIntoViewIfNeededOptions) => Promise<void>`

必要时滚动页面，使匹配到的元素进入可视区域。

```ts
await page.getByRole('button', { name: 'Load more' }).scrollIntoViewIfNeeded();
```

### waitFor

- **类型：** `(options?: LocatorWaitForOptions) => Promise<void>`

等待匹配到的元素满足指定 `state`（`'attached'`、`'detached'`、`'visible'` 或 `'hidden'`）。

```ts
await page.getByText('Ready').waitFor();
```

### dispatchEvent

- **类型：** `(type: string, eventInit?: LocatorDispatchEventInit, options?: LocatorDispatchEventOptions) => Promise<void>`

在匹配到的元素上派发 DOM 事件。`type` 必须是非空字符串，`eventInit` 必须可被 JSON 序列化（`BrowserSerializable`）。

```ts
await page.getByRole('button', { name: 'Event' }).dispatchEvent('custom');
```

### selectOption

- **类型：** `(values: LocatorSelectOptionValue, options?: LocatorSelectOptionOptions) => Promise<string[]>`

按值字符串、`{ value?, label?, index? }`、它们的数组或 `null`（取消全部选中）选择 `<select>` 元素的选项，并返回已选中选项的 `value` 数组。

```ts
await page.getByLabel('Choice').selectOption('b');
await page.getByLabel('Choice').selectOption({ label: 'Option B' });
```

### setInputFiles

- **类型：** `(files: string | string[], options?: LocatorSetInputFilesOptions) => Promise<void>`

为 `<input type="file">` 元素设置文件。当前仅支持 `string` 或 `string[]` 形式的文件路径。

```ts
await page.locator('#upload').setInputFiles('/tmp/demo.txt');
```

## 使用约束

- 当前仅支持本页列出的 Playwright `Locator` API 子集。
- `and()`、`or()`、`dragTo()`、`locator(_, { has | hasNot })` 以及 `filter({ has | hasNot })` 的参数必须是 `@rstest/browser` 返回的 `Locator`。
- `dispatchEvent(type, eventInit?, options?)` 的 `type` 必须是非空字符串，`eventInit` 必须可被 JSON 序列化。
- `selectOption()` 仅接受 `null`、`string`、`{ value?, label?, index? }` 或它们的数组（不支持 DOM 元素）；`setInputFiles()` 仅接受 `string` 或 `string[]` 形式的文件路径。

## 与 expect.element 配合

将任意 `Locator` 传给 `expect.element(locator)` 即可执行自动重试断言，详见 [Assertion](/api/runtime-api/browser-mode/assertion)。
