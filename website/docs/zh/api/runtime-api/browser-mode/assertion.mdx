# Assertion

`expect.element` 用于在 Browser Mode 中对 [Locator](/api/runtime-api/browser-mode/locator) 或 DOM `Element` 创建自动重试的 DOM 断言。在 Browser Mode 测试中导入 `@rstest/browser` 后，`@rstest/core` 的 `expect` 会自动扩展 `expect.element()` 和 `expect(target).toMatchScreenshot()`。

```ts title="src/assertion.test.ts"
import { page } from '@rstest/browser';
import { expect, test } from '@rstest/core';

test('asserts element states in browser mode', async () => {
  await expect
    .element(page.getByRole('button', { name: 'Save' }))
    .toBeVisible();

  await expect.element(page.getByLabel('Agree')).toBeUnchecked();
  await page.getByLabel('Agree').check();
  await expect.element(page.getByLabel('Agree')).toBeChecked();

  await expect
    .element(page.getByRole('button', { name: 'Save' }))
    .toHaveAttribute('id', 'save-btn');
});
```

## expect.element

- **类型：** `(target: Locator | Element) => BrowserElementExpect`

`BrowserElementExpect` 提供 `.not` 以及下方列出的所有元素 matcher。

## 自动重试与超时

使用 Playwright provider 时，`expect.element` 的 matcher 是 **web-first assertion**：它们会持续重试直到条件成立或超时，无需手写 `waitFor` 或轮询逻辑。

```ts
// 使用 Browser Mode 的 expect.poll.timeout 默认值（5000ms），
// 同时受当前测试剩余时间限制
await expect.element(page.getByText('Done')).toBeVisible();

// 覆盖为更长的超时
await expect.element(page.getByText('Done')).toBeVisible({ timeout: 10000 });
```

### 超时优先级

1. **单次断言超时**：直接传给 matcher 的 `options.timeout` 优先级最高，包括 `0`。使用 Playwright 时，如果当前没有有限的 active test 或 hook deadline，显式传入 `0` 表示不设置 matcher 超时；在有限的非并发 test 或 hook 中，仍受当前作用域剩余时间限制。
2. **配置的轮询超时**：未传 matcher timeout 时，断言使用 `expect.poll.timeout`（Node Mode 默认为 `1000ms`，Browser Mode 默认为 `5000ms`）。
3. **当前测试或 hook 的剩余时间**：在非并发流程中，实际超时受当前 test 或 hook 的 deadline 限制（Browser Mode 测试默认 `testTimeout` 为 `15000ms`）。未传单次断言超时时取 `min(expect.poll.timeout, 剩余时间)`；显式传入时取 `min(timeout, 剩余时间)`。

对于 `test.concurrent`，请使用测试作用域内的 `expect` fixture（`async ({ expect }) => ...`），这样断言才会遵循该测试的剩余时间。由于浏览器无法可靠跟踪并发异步流程，共享的文件级 `expect` 会使用 `expect.poll.timeout`。`describe.concurrent` 内的 hook 遵循相同规则，但外层 hook timeout 仍会提前结束断言。

### 失败输出

断言超时后，错误信息会输出期望状态、实际状态与超时时间：

```
Error: Expected element to be visible
  Locator: getByText('Loading complete')
  Timeout: 5000ms
```

## 输入约束

- `target` 必须是 Rstest `Locator` 或当前测试文档中的 DOM `Element`，传入手写对象或其他库的 locator 会抛出错误。
- `expect.element` 仅在 Browser Mode 中可用；纯 Node 测试请使用常规的 `expect(value)` 断言。

## DOM 元素 \{#dom-elements}

<ApiMeta addedVersion="0.12.5" />

`expect.element()` 也接受 Testing Library 或原生 DOM 查询返回的元素。它会通过 [`page.elementLocator()`](/api/runtime-api/browser-mode/locator#elementlocator) 转换元素，并沿用 `Locator` 断言的重试和超时规则。

```ts
import { getByRole } from '@testing-library/dom';

const button = getByRole(document.body, 'button', { name: 'Save' });
await expect.element(button).toBeEnabled();
await expect.element(button).not.toBeDisabled();
```

每次重试都会检查同一 DOM 节点。如果重渲染替换了节点，请使用查询 `Locator` 查找新节点。来自其他文档或 iframe 的元素会被拒绝。

## 截图匹配 \{#screenshot-matching}

### toMatchScreenshot \{#toMatchScreenshot}

<ApiMeta addedVersion="0.12.4" />

- **类型：**

```ts
function toMatchScreenshot(options?: ToMatchScreenshotOptions): Promise<void>;
function toMatchScreenshot(
  name?: string,
  options?: ToMatchScreenshotOptions,
): Promise<void>;
```

使用 Playwright provider 时，截取 `Locator` 或 `page` 并与存储的 PNG 基线对比。若当前 snapshot 更新模式允许新增基线，首次运行会保存基线；后续运行会与基线比较，使用 `--update` 可替换不匹配的基线。不支持 `.not`。

默认使用当前测试名称作为基线名称。传入 `name` 可以让多个断言共用一份基线，或为同一测试中的多张截图分别命名；只传入选项对象时则继续使用默认基线名称。同一测试中的未命名断言会从 `1` 开始自动编号。在 `test.concurrent` 中，使用测试作用域内的 `expect` fixture（`async ({ expect }) => ...`）可继续使用测试名称，使用共享的文件级 `expect` 时需显式传入 `name`。

```ts
await expect(page.getByRole('button', { name: 'Save' })).toMatchScreenshot(
  'primary-save-button',
);

await expect(page.locator('#profile-card')).toMatchScreenshot({
  maxDiffPixels: 20,
  stabilityTimeout: 1000,
  mask: [page.locator('[data-testid="updated-at"]')],
});
```

已有基线时，只要首张截图在配置的容差范围内匹配基线，普通断言就会立即通过。若首张截图不匹配，Rstest 会等待连续两张截图尺寸相同且差异在容差范围内，再重新与基线比较。创建或更新基线时同样会执行稳定性检查。

`ToMatchScreenshotOptions` 选项（内部类型，未从 `@rstest/browser` 重新导出）：

| 选项                | 默认值      | 行为                                                                                    |
| ------------------- | ----------- | --------------------------------------------------------------------------------------- |
| `threshold`         | `0.1`       | 单像素颜色距离阈值，范围为 `0`（严格）到 `1`（宽松）。                                  |
| `maxDiffPixels`     | `undefined` | 允许差异的最大像素数。可与 `maxDiffPixelRatio` 同时设置（取更严格的一项）。             |
| `maxDiffPixelRatio` | `undefined` | 允许差异的最大像素比例（`0` 到 `1`）。可与 `maxDiffPixels` 同时设置（取更严格的一项）。 |
| `stabilityTimeout`  | `5000`      | 等待连续截图一致的最长时间（毫秒）。设为 `0` 关闭稳定性检查；正数必须至少为 `100`。     |
| `mask`              | `undefined` | 截图时用于遮罩动态区域的 `Locator[]`。                                                  |
| `maskColor`         | `'#FF00FF'` | 遮罩区域的填充颜色。                                                                    |
| `fullPage`          | `false`     | 截取完整可滚动页面而非仅当前视口。仅支持 `page` 断言。                                  |
| `style`             | `undefined` | 截图前注入的额外 CSS 字符串。                                                           |
| `caret`             | `'hide'`    | 截图时隐藏（`'hide'`）或保留（`'initial'`）文本光标。                                   |
| `scale`             | `'device'`  | 截图缩放模式（`'css'` 或 `'device'`）。                                                 |
| `omitBackground`    | `false`     | 省略默认的白色页面背景，保留透明区域。                                                  |

`maxDiffPixels` 与 `maxDiffPixelRatio` 均未设置时，应用 `threshold` 后不允许有像素差异。Rstest 在截图时会禁用 CSS 动画。基线 PNG 保存在 `__screenshots__` 目录下并按测试文件分组，文件名包含经过路径清理的基线名、浏览器和操作系统（清理后可能冲突的名称会追加稳定哈希后缀）。断言不匹配时，Rstest 会将实际截图和差异图写入同级的 `__failures__` 目录。截图捕获受当前测试剩余超时时间限制；设置 `testTimeout: 0` 时不受测试超时限制，但 `stabilityTimeout` 仍生效。

可通过 [`browser.expect.toMatchScreenshot`](/config/test/browser#expecttomatchscreenshot) 设置项目级 matcher 默认值和基线路径。

#### 元素截图 \{#element-screenshots}

传入 `Locator`，仅截取匹配到的元素：

```ts
await expect(page.getByRole('button', { name: 'Save' })).toMatchScreenshot();
```

#### 页面截图 \{#page-screenshots}

传入 `@rstest/browser` 的 `page` 对象截取当前视口，或设置 `fullPage: true` 截取完整页面：

```ts
await expect(page).toMatchScreenshot();
await expect(page).toMatchScreenshot('full-page', { fullPage: true });
```

## 元素断言

当前仅支持以下列出的 matcher。除非类型签名中另有说明，所有 matcher 均接受可选的 `options?: { timeout?: number }` 参数。

### not

- **类型：** `BrowserElementExpect`

对链式调用的 matcher 取反。

```ts
await expect
  .element(page.getByRole('button', { name: 'Submit' }))
  .not.toBeDisabled();
```

### toBeVisible

- **类型：** `(options?: { timeout?: number; visible?: boolean }) => Promise<void>`

断言元素已挂载且可见（bounding box 非空且 `visibility !== 'hidden'`）。`display: none` 和零尺寸元素会失败；`opacity: 0` 仍视为可见。传入 `{ visible: false }` 可断言元素不可见。

```ts
await expect.element(page.getByRole('button', { name: 'Save' })).toBeVisible();
```

### toBeHidden

- **类型：** `(options?: { timeout?: number }) => Promise<void>`

断言 `Locator` 不匹配任何 DOM 节点或匹配到不可见节点（与 `toBeVisible` 相反）。

```ts
await expect.element(page.getByTestId('loading')).toBeHidden();
```

### toBeEnabled

- **类型：** `(options?: { timeout?: number; enabled?: boolean }) => Promise<void>`

断言元素未被禁用（非 `disabled`、不在禁用的 `fieldset` 内且非 `aria-disabled="true"`）。传入 `{ enabled: false }` 可断言元素处于禁用状态。

```ts
await expect
  .element(page.getByRole('button', { name: 'Submit' }))
  .toBeEnabled();
```

### toBeDisabled

- **类型：** `(options?: { timeout?: number }) => Promise<void>`

断言元素处于禁用状态（与 `toBeEnabled` 相反）。

```ts
await expect
  .element(page.getByRole('button', { name: 'Submit' }))
  .toBeDisabled();
```

### toBeChecked

- **类型：** `(options?: { timeout?: number; checked?: boolean; indeterminate?: boolean }) => Promise<void>`

断言 checkbox 或 radio 控件的 `checked` 状态为 `true`。传入 `{ checked: false }` 可断言未勾选，传入 `{ indeterminate: true }` 可断言 checkbox 处于半选状态。

```ts
await expect.element(page.getByLabel('Agree')).toBeChecked();
await expect
  .element(page.getByLabel('Select all'))
  .toBeChecked({ indeterminate: true });
```

### toBeUnchecked

- **类型：** `(options?: { timeout?: number }) => Promise<void>`

断言 checkbox 或 radio 控件的 `checked` 状态为 `false`。

```ts
await expect.element(page.getByLabel('Agree')).toBeUnchecked();
```

### toBeAttached

- **类型：** `(options?: { timeout?: number; attached?: boolean }) => Promise<void>`

断言节点已连接到 `Document` 或 `ShadowRoot`（`Node.isConnected === true`），不要求元素可见。传入 `{ attached: false }` 可断言节点未连接。

```ts
await expect.element(page.locator('#toast')).toBeAttached();
```

### toBeDetached

- **类型：** `(options?: { timeout?: number }) => Promise<void>`

断言 `Locator` 不再指向已连接的 DOM 节点。

```ts
await expect.element(page.locator('#toast')).toBeDetached();
```

### toBeEditable

- **类型：** `(options?: { timeout?: number; editable?: boolean }) => Promise<void>`

断言元素同时满足已启用且非只读（`readonly` 或 `aria-readonly="true"`）。传入 `{ editable: false }` 可断言元素为只读状态。

```ts
await expect.element(page.getByLabel('Bio')).toBeEditable();
```

### toBeFocused

- **类型：** `(options?: { timeout?: number }) => Promise<void>`

断言元素是当前文档的焦点目标。

```ts
await expect.element(page.getByLabel('Username')).toBeFocused();
```

### toBeEmpty

- **类型：** `(options?: { timeout?: number }) => Promise<void>`

断言可编辑元素的值为空，或普通元素没有文本内容。

```ts
await expect.element(page.locator('#empty-state')).toBeEmpty();
```

### toBeInViewport

- **类型：** `(options?: { timeout?: number; ratio?: number }) => Promise<void>`

断言元素基于 Intersection Observer 语义与视口相交。`ratio` 指定最小相交比例（例如 `0.5` 表示至少一半区域在视口内）。

```ts
await expect.element(page.locator('#hero')).toBeInViewport({ ratio: 0.5 });
```

### toHaveRole

<ApiMeta addedVersion="0.12.5" />

- **类型：** `(role: LocatorAriaRole | (string & {}), options?: { timeout?: number }) => Promise<void>`

断言元素的精确 ARIA role（不按 role 层级匹配）。

```ts
await expect.element(page.getByTestId('save')).toHaveRole('button');
```

### toHaveAccessibleName

<ApiMeta addedVersion="0.12.5" />

- **类型：** `(name: string | RegExp, options?: { timeout?: number; ignoreCase?: boolean }) => Promise<void>`

断言元素的可访问名称。字符串与归一化后的完整名称匹配。设置 `ignoreCase: true` 可忽略大小写。

```ts
await expect.element(page.getByTestId('save')).toHaveAccessibleName('Save');
```

### toHaveAccessibleDescription

<ApiMeta addedVersion="0.12.5" />

- **类型：** `(description: string | RegExp, options?: { timeout?: number; ignoreCase?: boolean }) => Promise<void>`

断言元素的可访问描述。字符串与归一化后的完整描述匹配。设置 `ignoreCase: true` 可忽略大小写。

```ts
await expect
  .element(page.getByTestId('save'))
  .toHaveAccessibleDescription('Saves your changes');
```

### toHaveText

- **类型：** `(text: string | RegExp | readonly (string | RegExp)[], options?: { timeout?: number; ignoreCase?: boolean; useInnerText?: boolean }) => Promise<void>`

断言元素文本内容（包含后代节点，且空白字符会归一化）完整匹配 `text`。传入数组时按顺序断言所有匹配元素的文本列表。设置 `useInnerText: true` 可按 `element.innerText` 比较，`ignoreCase: true` 可忽略大小写。

```ts
await expect.element(page.getByRole('status')).toHaveText('Saved');
await expect
  .element(page.getByRole('listitem'))
  .toHaveText(['First', 'Second']);
```

### toContainText

- **类型：** `(text: string | RegExp | readonly (string | RegExp)[], options?: { timeout?: number; ignoreCase?: boolean; useInnerText?: boolean }) => Promise<void>`

断言元素文本内容（空白字符会归一化）包含 `string` 子串或匹配 `RegExp`。传入数组时按顺序断言每个匹配元素包含对应文本。支持 `ignoreCase` 和 `useInnerText`。

```ts
await expect.element(page.getByRole('status')).toContainText('Save');
```

### toHaveValue

- **类型：** `(value: string | RegExp, options?: { timeout?: number }) => Promise<void>`

断言表单控件（`input`、`textarea`、`select`）的当前 `value` 匹配 `value`。

```ts
await expect.element(page.getByLabel('Email')).toHaveValue('dev@rstest.rs');
```

### toHaveValues

<ApiMeta addedVersion="0.12.5" />

- **类型：** `(values: (string | RegExp)[], options?: { timeout?: number }) => Promise<void>`

断言 `<select multiple>` 元素所有已选中选项的值（按 DOM 顺序）。传入 `[]` 表示未选中任何选项。

```ts
const languages = page.getByLabel('Languages');
await languages.selectOption(['typescript', 'rust']);
await expect.element(languages).toHaveValues(['typescript', /^rust$/]);
```

### toHaveId

- **类型：** `(value: string | RegExp, options?: { timeout?: number }) => Promise<void>`

断言元素的 `id` 匹配 `value`。

```ts
await expect
  .element(page.getByRole('button', { name: 'Save' }))
  .toHaveId('save-btn');
```

### toHaveClass

- **类型：** `(value: string | RegExp | readonly (string | RegExp)[], options?: { timeout?: number }) => Promise<void>`

断言元素的 `class` 属性匹配 `value`。传入字符串时会匹配整个 `class` 字符串；传入数组可断言多个元素；匹配单个或多个类名请使用 [`toContainClass`](#tocontainclass)。

```ts
await expect.element(page.getByRole('alert')).toHaveClass(/error/);
```

### toContainClass

<ApiMeta addedVersion="1.0.0" />

- **类型：** `(value: string | readonly string[], options?: { timeout?: number }) => Promise<void>`

断言元素的 `classList` 包含期望的类名（空格分隔的字符串会要求同时包含所有类名）。传入字符串数组可按顺序断言多个匹配元素。不支持正则表达式。

```ts
await expect.element(page.getByRole('alert')).toContainClass('error');
await expect
  .element(page.getByRole('listitem'))
  .toContainClass(['item', 'item active']);
```

### toHaveAttribute

- **类型：**

```ts
function toHaveAttribute(
  name: string,
  options?: { timeout?: number },
): Promise<void>;
function toHaveAttribute(
  name: string,
  value?: string | RegExp,
  options?: { timeout?: number; ignoreCase?: boolean },
): Promise<void>;
```

省略 `value`（或传入 `undefined`）时断言属性 `name` 存在；传入 `value` 时断言属性值匹配。设置 `ignoreCase: true` 可忽略属性值大小写。

```ts
await expect
  .element(page.getByRole('button', { name: 'Save' }))
  .toHaveAttribute('type', { timeout: 1000 });
await expect
  .element(page.getByRole('button', { name: 'Save' }))
  .toHaveAttribute('type', 'submit', { ignoreCase: true });
```

### toHaveCount

- **类型：** `(count: number, options?: { timeout?: number }) => Promise<void>`

断言 `Locator` 精确匹配 `count` 个元素。

```ts
await expect.element(page.getByRole('listitem')).toHaveCount(3);
```

### toHaveCSS

- **类型：** `(name: string, value: string | RegExp, options?: { timeout?: number }) => Promise<void>`

断言元素 computed style 中 `name`（非空字符串）对应的 CSS 属性值匹配 `value`。

```ts
await expect.element(page.getByRole('alert')).toHaveCSS('display', 'block');
```

### toHaveJSProperty

- **类型：** `(name: string, value: unknown, options?: { timeout?: number }) => Promise<void>`

断言 DOM 元素的 JavaScript 属性 `name`（非空字符串）等于 `value`（`value` 必须可被 JSON 序列化）。

```ts
await expect
  .element(page.getByLabel('Agree'))
  .toHaveJSProperty('checked', true);
```
