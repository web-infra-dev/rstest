# Reporter API

通过实现 `Reporter` 接口来创建自定义测试结果处理器和输出格式器。内置 Reporter 和配置说明见[报告器指南](/guide/basic/reporters)。

## 使用自定义报告器

将实现 `Reporter` 接口的对象传入 [`reporters`](/config/test/reporters)：

```ts
import type { Reporter } from '@rstest/core';

export const customReporter: Reporter = {
  onTestFileStart(test) {
    console.log(`Starting: ${test.testPath}`);
  },

  onTestFileResult(result) {
    console.log(`Finished: ${result.testPath}`);
  },

  onTestRunEnd({ duration }) {
    console.log(`All tests completed in ${duration.totalTime}ms`);
  },
};
```

```ts title="rstest.config.ts"
import { defineConfig } from '@rstest/core';
import { customReporter } from './path/to/custom-reporter';

export default defineConfig({
  reporters: [customReporter],
});
```

通过模块路径配置 Reporter（如 `reporters: [['./custom-reporter.js', options]]`）时，模块需要默认导出一个 `Reporter` 类。Rstest 实例化该类时会传入 `(options, context)`，其中 `context` 为 [`ReporterContext`](#reportercontext)。

## 接口概览

`Reporter` 提供测试执行各阶段的生命周期钩子：

- **文件级钩子**：`onTestFileStart`、`onTestFileReady`、`onTestFileResult`
- **套件级钩子**：`onTestSuiteStart`、`onTestSuiteResult`
- **用例级钩子**：`onTestCaseStart`、`onTestCaseResult`
- **运行级钩子**：`onTestRunStart`、`onTestRunEnd`、`onUserConsoleLog`、`onExit`

```ts
interface Reporter {
  onTestRunStart?(payload: TestRunStartPayload): MaybePromise<void>;
  onTestFileStart?(test: TestFileInfo): MaybePromise<void>;
  onTestFileReady?(test: TestFileInfo): MaybePromise<void>;
  onTestFileResult?(test: TestFileResult): MaybePromise<void>;
  onTestSuiteStart?(test: TestSuiteInfo): MaybePromise<void>;
  onTestSuiteResult?(result: TestResult): MaybePromise<void>;
  onTestCaseStart?(test: TestCaseInfo): MaybePromise<void>;
  onTestCaseResult?(result: TestResult): MaybePromise<void>;
  onTestRunEnd?(payload: TestRunEndPayload): MaybePromise<void>;
  onUserConsoleLog?(log: UserConsoleLog): MaybePromise<void>;
  onExit?(): MaybePromise<void>;
}
```

- `onTestSuiteResult`：`result.errors` 仅包含套件级错误——即套件钩子（`beforeAll` 和 `afterAll`）错误以及运行器生成的套件错误（例如 `passWithNoTests` 为 `false` 时空套件产生的 `No tests` 错误），不包含子测试用例的失败错误。
- **元数据（Metadata）** <ApiMeta sup addedVersion="0.11.1" />：通过 `context.task.meta` 写入的运行时元数据可在 `onTestCaseResult` 收到的 `TestResult.meta` 中读取；通过钩子 `ctx.meta` 写入的元数据分别在 `onTestSuiteResult` 的 `TestResult.meta` 和 `onTestFileResult` 的 `TestFileResult.meta` 中读取。
- **`onExit`** <ApiMeta sup addedVersion="0.12.0" />：Reporter 所属的上下文释放时调用，涵盖正常 run/merge 结束、watch 关闭、启动失败以及 CLI 异常退出。适合用来释放流或渲染器等资源。`onExit` 抛出的错误不会覆盖操作本身的结果或错误。（list 上下文不挂载 Reporter，因此 `listTests` 不会触发 `onExit`。）

### onTestRunStart

<ApiMeta addedVersion="0.13.0" />

在测试开始执行前调用。watch 模式下，`files` 仅包含本轮重跑选中的文件，不是整个会话的累计结果。`TestRunStartPayload` 可从 `@rstest/core` 导入。

- **类型：**

```ts
interface TestRunStartPayload {
  files: {
    testPath: string;
    project: string;
    testId: string;
  }[];
}
```

### onTestRunEnd

<ApiMeta addedVersion="0.12.0" /> <ApiMeta addedVersion="0.13.0" />

每轮测试运行结束时调用，携带本轮的结果、汇总、耗时和运行状态。`status` 各取值的含义见 [`rstest.run`](/api/javascript-api/instance#rstestrun)。

- **类型：**

```ts
type TestRunStatus = 'passed' | 'failed' | 'error';

interface TestRunEndPayload {
  status: TestRunStatus;
  results: TestFileResult[]; // 测试文件结果；watch 模式下为整个会话的累计结果。
  testResults: TestResult[]; // 所有测试用例结果，不按文件分组。
  summary: {
    tests: {
      total: number;
      passed: number;
      failed: number;
      skipped: number;
      todo: number;
      flaky: number; // 重试后通过的测试数量。
    };
    files: {
      total: number;
      failed: number;
    };
  };
  duration: {
    totalTime: number; // 总耗时（毫秒）。
    buildTime: number; // 编译及环境准备耗时（毫秒）。
    prebundleTime?: Record<string, number>; // 各环境包的预打包耗时（毫秒），已计入 buildTime。
    testTime: number; // 测试执行耗时（毫秒）。
  };
  snapshotSummary: SnapshotSummary;
  unhandledErrors: SerializedError[];
  coverage?: CoverageMapData; // 启用覆盖率时提供。
  rerunTestPaths?: string[]; // 仅 watch 模式：本轮实际执行的文件。
  getSourcemap: (sourcePath: string) => Promise<SourceMapInput | null>; // 获取构建产物的 source map。
}
```

watch 模式下，`results`、`testResults` 和 `summary` 会累计整个会话的结果：每个文件保留最新一次的结果，已删除的文件会被移除。`rerunTestPaths` 列出本轮执行的文件，一次性运行中不存在该字段。`unhandledErrors` 中的每一项都是可 JSON 序列化的普通对象。

`duration.prebundleTime` <ApiMeta sup addedVersion="0.12.7" /> 按环境包记录预打包耗时（毫秒），已计入 `duration.buildTime`。

当测试组按构建产物就绪顺序派发时，`buildTime` 从整轮开始计到最后一组产物就绪（包含环境准备）。`testTime` 包含最后一组就绪之后的时间（含 worker 清理），以及此前至少有一组测试处于执行状态的时间（含 worker 准备）。并发执行的测试组只统计一次，仅存在构建活动的空档计入 `buildTime`。由于两个阶段可能重叠，两者之和大于等于 `totalTime`；整轮实际耗时请以 `totalTime` 为准。

### ReporterContext

通过模块路径加载自定义 Reporter 类时，作为构造函数的第二个参数传入。由 `@rstest/core` 导出。

- **类型：**

```ts
interface ReporterContext {
  rootPath: string;
  config: NormalizedConfig;
}
```

### TestFileInfo

传给 `onTestFileStart` 和 `onTestFileReady`。由 `@rstest/core` 导出。

- **类型：**

```ts
type TestRunMode = 'run' | 'skip' | 'todo' | 'only';

type TestInfo = TestCaseInfo | (TestSuiteInfo & { tests: TestInfo[] });

interface TestFileInfo {
  testId: string;
  testPath: string;
  relativeTestPath: string;
  project: string;
  tests: TestInfo[];
}
```

### TestSuiteInfo

传给 `onTestSuiteStart`。由 `@rstest/core` 导出。

- **类型：**

```ts
interface TestSuiteInfo {
  testId: string;
  testPath: string;
  relativeTestPath: string;
  name: string;
  fullName: string;
  parentNames?: string[];
  project: string;
  type: 'suite';
  runMode: TestRunMode;
  location?: { line: number; column: number }; // 启用 includeTaskLocation 时提供。

```

### TestCaseInfo

传给 `onTestCaseStart`。由 `@rstest/core` 导出。

- **类型：**

```ts
interface TestCaseInfo {
  testId: string;
  testPath: string;
  relativeTestPath: string;
  name: string;
  fullName: string;

  project: string;
  type: 'case';
  runMode: TestRunMode;

  startTime?: number;

  meta?: TaskMeta;
}
```

### TestResult

传给 `onTestSuiteResult` 和 `onTestCaseResult`。由 `@rstest/core` 导出。

- **类型：**

```ts
type TestResultStatus = 'skipped' | 'passed' | 'failed' | 'todo';

interface SerializedError {
  name?: string;
  message: string;
  stack?: string;
  diff?: string;
  expected?: string;
  actual?: string;
  retryCount?: number;
  fullStack?: boolean;
  cause?: SerializedError;
}

interface TestResult {
  testId: string;
  status: TestResultStatus;
  name: string;
  fullName: string; // 外层 suite 名称与 name，以 ` > ` 连接。
  testPath: string; // 所属测试文件的绝对路径。
  relativeTestPath: string; // 相对于 rootPath 的 POSIX 路径。
  parentNames?: string[];
  duration?: number; // 执行耗时（毫秒）。
  errors?: SerializedError[]; // 最后一次执行产生的错误（套件结果中为套件钩子错误）。
  retryErrors?: SerializedError[]; // 之前重试产生的错误。
  retryCount?: number;
  project: string;
  meta?: TaskMeta;
  heap?: number; // 启用 logHeapUsage 时采样的堆内存用量（字节）。
}
```

### TestFileResult

传给 `onTestFileResult` 并包含在 `onTestRunEnd` 中。在 `TestResult` 基础上增加文件级测试结果与汇总信息。由 `@rstest/core` 导出。

- **类型：**

```ts
interface TestFileResult extends TestResult {
  loadDuration?: number;
  results: TestResult[];
  summary: {
    total: number;
    passed: number;
    failed: number;
    skipped: number;
    todo: number;
    flaky: number;
  };
  snapshotResult?: SnapshotResult; // 来自 @vitest/snapshot。
  coverage?: Record<string, FileCoverageData>; // 启用覆盖率时提供，来自 istanbul-lib-coverage。
}
```

#### 文件耗时 \{#file-timing}

<ApiMeta addedVersion="0.12.6" />

在 Node pool 中，`loadDuration` 以毫秒记录 worker 内的产物加载、setup 文件执行以及测试模块求值与收集耗时。即使加载失败也会记录；尚未开始加载或使用 Browser Mode 时该字段缺省。`duration` 记录测试执行耗时，包含 hooks 和快照收尾。两者之和用于 Node 测试文件调度，不包含 worker 启动、环境初始化、排队和 worker 销毁耗时。

### UserConsoleLog

传给 `onUserConsoleLog`。由 `@rstest/core` 导出。

- **类型：**

```ts
interface UserConsoleLog {
  content: string;
  name: string;
  taskId?: string;
  taskName?: string;
  taskParentNames?: string[];
  taskType?: 'file' | 'suite' | 'case';
  trace?: string;
  testPath: string;
  relativeTestPath: string;
  project: string;
  type: 'stdout' | 'stderr';
}
```

## 示例

### 简单自定义报告器

```ts
import type { Reporter } from '@rstest/core';

const simpleReporter: Reporter = {
  onTestFileStart(test) {
    console.log(`Starting: ${test.testPath}`);
  },

  onTestCaseResult(result) {
    const status = result.status === 'passed' ? 'PASS' : 'FAIL';
    console.log(`${status} ${result.name}`);
  },

  onTestRunEnd({ results }) {
    const passed = results.filter((r) => r.status === 'passed').length;
    const failed = results.filter((r) => r.status === 'failed').length;
    console.log(`\n${passed} passed, ${failed} failed`);
  },
};
```

### 文件输出报告器

```ts
import { writeFileSync } from 'node:fs';
import type { Reporter } from '@rstest/core';

const jsonReporter: Reporter = {
  onTestRunEnd({ results }) {
    const report = {
      timestamp: new Date().toISOString(),
      results: results.map((r) => ({
        path: r.testPath,
        status: r.status,
        duration: r.duration,
        errors: r.errors,
      })),
    };

    writeFileSync('test-report.json', JSON.stringify(report, null, 2));
  },
};
```

### 读取运行时 metadata

```ts
import type { Reporter } from '@rstest/core';

const metadataReporter: Reporter = {
  onTestCaseResult(result) {
    console.log(result.name, result.meta);
  },

  onTestSuiteResult(result) {
    console.log(result.name, result.meta);
  },

  onTestFileResult(result) {
    console.log(result.testPath, result.meta);
  },
};
```
