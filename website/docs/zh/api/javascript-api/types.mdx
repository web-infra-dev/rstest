# Rstest types

Rstest 从 `@rstest/core` 导出公开的 TypeScript 类型。请使用 `import type` 导入，以便在构建产物中擦除类型引用。

```ts
import type { Mock, Mocked, RstestConfig } from '@rstest/core';
```

## 配置类型

在 [`defineConfig`](/api/javascript-api/rstest-core#defineconfig)、[`defineProject`](/api/javascript-api/rstest-core#defineproject) 和 [`defineInlineProject`](/api/javascript-api/rstest-core#defineinlineproject) 之外为配置对象、配置工厂或适配器标注类型时，可以使用以下类型：

```ts
import type {
  BrowserExpectConfig,
  BrowserInstanceConfig,
  BrowserName,
  BrowserViewport,
  CoverageOptions,
  ExpectConfig,
  ExpectPollConfig,
  ExtendConfig,
  ExtendConfigFn,
  InlineProjectConfig,
  ProjectConfig,
  RstestCommand,
  RstestConfig,
  RstestConfigAsyncFn,
  RstestConfigExport,
  RstestConfigSyncFn,
} from '@rstest/core';
```

- `RstestConfig`：顶层 Rstest 配置对象类型。
- `RstestConfigSyncFn` / `RstestConfigAsyncFn`：返回 `RstestConfig` 的同步与异步配置工厂函数。
- `RstestConfigExport`：`RstestConfig`、`RstestConfigSyncFn` 与 `RstestConfigAsyncFn` 的联合类型。
- `ProjectConfig`：独立 [Rstest Project](/guide/basic/projects) 配置文件的类型。
- `InlineProjectConfig`：`projects` 数组中内联项目配置的类型（`ProjectConfig & { name: string }`）。
- `ExtendConfig` / `ExtendConfigFn`：[`extends`](/config/test/extends) 与配置适配器使用的返回值和回调函数类型。
- `RstestCommand`：当前执行的 CLI 命令（`'watch' | 'run' | 'list' | 'merge-reports'`）。
- `ExpectConfig` / `ExpectPollConfig`：[`expect`](/config/test/expect) 与 `expect.poll` 的配置类型。
- `CoverageOptions`：[`coverage`](/config/test/coverage) 的配置类型。
- `BrowserInstanceConfig` / `BrowserExpectConfig` / `BrowserName` / `BrowserViewport`：Browser Mode 实例、断言、浏览器名称与视口配置类型。

## Test API 类型

扩展 Test API、编写可复用辅助函数或为自定义 fixture 标注类型时，可以使用以下类型：

```ts
import type {
  Describe,
  Expect,
  ExpectStatic,
  FakeTimerInstallOpts,
  FileFixtureOptions,
  FixtureCleanup,
  FixtureLifecycle,
  Fixtures,
  MaybePromise,
  Rstest,
  RstestUtilities,
  SuiteContext,
  TaskMeta,
  TaskMetaValue,
  TestAPIs,
  TestContext,
  TestForFn,
  TestOptions,
  Use,
  WorkerFixtureOptions,
} from '@rstest/core';
```

<ApiMeta addedVersion="0.10.1" /> <ApiMeta addedVersion="0.11.7" />

- `Rstest`：完整的运行时 API 类型（包含 `test`、`it`、`describe`、`expect`、`assert`、hooks、`rs` 和 `rstest`）。
- `RstestUtilities`：`rs` 与 `rstest` 工具对象的类型。
- `FakeTimerInstallOpts`：[`rs.useFakeTimers`](/api/runtime-api/rstest/fake-timers#rsusefaketimers) 接受的配置对象类型。
- `TestContext`：传给测试回调和单测 Hook 的上下文对象（自 `0.10.1` 起作为公开类型导出）。
- `SuiteContext`：传给 `beforeAll` 和 `afterAll` 套件级 Hook 的上下文对象（`{ filepath, meta }`）。
- `TestOptions`：单测与套件级选项（`timeout`、`retry`、`repeats`、`meta`）。
- `TestAPIs`：`test.extend(...)` 的返回值类型，包含 `test` 修饰符和链式 `.extend()`。
- `TestForFn`：`test.for` 的调用签名类型。
- `Describe`：`describe` API 的类型。
- `Expect` / `ExpectStatic`：可调用的 `expect` API 类型（`Expect` 是 `ExpectStatic` 的别名）。
- `TaskMeta` / `TaskMetaValue`：可 JSON 序列化的元数据对象与值类型。详见 [Metadata](/guide/advanced/metadata)。
- `Fixtures` / `Use`：`test.extend` 使用的 fixtures 对象映射及 `use(value)` 回调类型。
- `FileFixtureOptions` / `WorkerFixtureOptions`：具名 fixture 的作用域选项（`{ scope: 'file' }` 与 `{ scope: 'worker' }`）。
- `FixtureCleanup` / `FixtureLifecycle`：具名 fixture 的清理回调和 `{ onCleanup }` 生命周期参数类型（`0.11.7` 新增）。
- `MaybePromise<T>`：工具联合类型 `T | Promise<T>`。

## Mock 类型

在辅助函数中接收 mock 函数、spy 或 mocked 模块时，可以使用以下类型：

```ts
import type {
  Mock,
  MockContext,
  Mocked,
  MockInstance,
  MockResult,
  MockSettledResult,
} from '@rstest/core';
```

- `MockContext<T>`：`mock.mock` 的类型，包含调用参数、实例、上下文、`results` 和 `settledResults`。
- `MockResult<T>` / `MockSettledResult<T>`：`mock.mock.results` 与 `mock.mock.settledResults` 中记录的同步调用结果与异步 settled 结果联合类型。

### Mock

`Mock<T>` 表示由 [`rs.fn`](/api/runtime-api/rstest/mock-functions#rsfn) 创建的可调用 mock 函数，保留 `T` 的参数与返回值类型并附加 mock 控制方法。

```ts
import { rs } from '@rstest/core';
import type { Mock } from '@rstest/core';

type LoadUser = (id: string) => Promise<{ name: string }>;

const loadUser: Mock<LoadUser> = rs.fn<LoadUser>();
loadUser.mockResolvedValue({ name: 'Jack' });
```

### MockInstance

<ApiMeta addedVersion="0.10.1" />

`MockInstance<T>` 表示 `rs.fn()` 和 `rs.spyOn()` 共享的 mock 控制接口。当辅助函数只需要调用 `mockClear`、`mockReset`、`mockRestore` 等控制方法而无需直接调用函数本身时，可以使用该类型。

```ts
import type { MockInstance } from '@rstest/core';

function resetTrackedMock(mock: MockInstance) {
  mock.mockReset();
}
```

### Mocked

`Mocked<T>` 包装对象或模块类型，将其中的方法标注为 mock 类型，常配合 [`rs.mock`](/api/runtime-api/rstest/mock-modules#rsmock)、[`rs.mockObject`](/api/runtime-api/rstest/mock-functions#rsmockobject) 或 [`rs.mocked`](/api/runtime-api/rstest/mock-functions#rsmocked) 使用。

```ts
import { rs } from '@rstest/core';
import type { Mocked } from '@rstest/core';
import * as userApi from './userApi';

rs.mock('./userApi');

const mockedUserApi: Mocked<typeof userApi> = rs.mocked(userApi);
mockedUserApi.loadUser.mockResolvedValue({ name: 'Jack' });
```

## Reporter 与结果类型

编写自定义 Reporter 或消费 Rstest 测试结果时，可以使用以下类型。完整接口定义见 [Reporter](/api/javascript-api/reporter)。

```ts
import type {
  CoverageMapData,
  Duration,
  Reporter,
  ReporterContext,
  SerializedError,
  SnapshotSummary,
  TestCaseInfo,
  TestFileInfo,
  TestFileResult,
  TestInfo,
  TestResult,
  TestResultStatus,
  TestRunEndPayload,
  TestRunStartPayload,
  TestRunStatus,
  TestRunSummary,
  TestSuiteInfo,
  UserConsoleLog,
} from '@rstest/core';
```

- `Reporter` / `ReporterContext`：自定义 Reporter 接口及其构造函数上下文（`{ rootPath, config }`）。
- `TestFileInfo` / `TestSuiteInfo` / `TestCaseInfo` / `TestInfo`：传给 Reporter 开始与就绪钩子的任务信息。
- `TestResult` / `TestFileResult` / `TestResultStatus`：用例、套件和文件级的执行结果，以及状态联合类型（`'skipped' | 'passed' | 'failed' | 'todo'`）。
- `TestRunStartPayload` / `TestRunEndPayload` / `TestRunStatus` / `TestRunSummary`：运行级钩子参数、运行状态（`'passed' | 'failed' | 'error'`）及统计汇总。
- `Duration` / `SerializedError` / `UserConsoleLog`：各阶段耗时、可 JSON 序列化的错误对象和捕获的标准输出日志。
- `SnapshotSummary` / `CoverageMapData`：快照汇总与 Istanbul 覆盖率映射类型。

## Assertion 类型

为自定义断言辅助函数或扩展匹配器编写类型时，可以使用以下类型：

```ts
import type {
  Assertion,
  AsymmetricMatchersContaining,
  ExpectStatic,
  Matchers,
  MatcherState,
} from '@rstest/core';

function expectVisible(
  expect: ExpectStatic,
  value: HTMLElement,
): Assertion<HTMLElement> {
  return expect(value);
}
```

- `Assertion<T>`：`expect(value)` 返回的链式断言对象。
- `ExpectStatic`：可调用的 `expect` 函数类型，包含 `poll`、`soft`、`extend` 等静态方法。
- `Matchers<T>` / `AsymmetricMatchersContaining`：来自 `@vitest/expect` 的匹配器接口，用于模块扩展或自定义匹配器类型标注。
- `MatcherState`：`expect.getState()` 返回与 `expect.setState()` 接受的匹配器状态类型。

## Rsbuild 与插件类型

Rstest 从 `@rsbuild/core` 重新导出 `Rspack` 和 `RsbuildPlugin`，并导出 `RstestExposeAPI` 供 Rsbuild 插件通过 `api.useExposed('rstest')` 读取或修改已解析的 Rstest 配置。

```ts
import type { RsbuildPlugin, Rspack, RstestExposeAPI } from '@rstest/core';
```
